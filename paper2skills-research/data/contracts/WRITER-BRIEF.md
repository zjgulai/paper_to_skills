## 2 计数器会打红你的地方（逐条对照，别等跑完再改）

| 判据 | 会打红的写法 |
|---|---|
| **J5** | 五维缺项；① 获取路径不是 `自有埋点/平台后台/第三方 API/需授权/不可得` 五选一 |
| **J6** | ① 写「不可得」却把 `status` 标成 `可写`（必须 `数据待盘`） |
| **J7** | A 模板 §1/§3/§4 为空；段标题被改写（六段标题**逐字照抄**） |
| **J8** | B 模板 §3 一个 `AGT-0xx` 都没点名；点名了不存在的岗位号 |
| **J9** | 全文出现「**临时默认值**」；或 §3 出现「待标定/需重新标定/须重新标定」而**同一段里没点名数据源** |
| **J12** | `cards` 里的 slug 卡库里找不到；`status: 可写` 却没有 `cards`；`status: 待卡` 却有 `cards` |
| **J13** | §3（A）/§1（B）**只有算式没有取值**；写了缺口（暂无/尚未/不可得/未定名/待定/未知）却不写处置；**B §2 有任何一条 `- ` 开头却没有 `→ 替代路径：`**；五维取值为缺口时第三列为空 |
| **J3** | 正文引用了**不属于你**的格号；把 R/D 格说成「算法/模型接入」 |

### 2.1 三个具体陷阱（都是实测撞出来的）

1. **`→ 替代路径：` 是逐条计数**，按「以 `-`/`*`/`1.` 开头的行」数（B 模板 §2）。
   所以 §2 **不要用子项目符号** —— 每一条不可达都写成一条顶层 `- `，紧跟它自己的 `→ 替代路径：`。
2. **§3/§1 的「取值」必须是带标签的行**：`- 取值：…`、`- 阈值：…`、`- 区间：…`、`- 基线：…`、
   `- 目标值：…`、`- 容差档：…`、`- 分档：…`，且这一行要有数字。
   把数字写在散文里不算（校验器刻意只认带标签的行 —— 首版扫全段时把 §2 的「2 个完整年度」
   误当取值）。
3. **缺口必须接处置**：`暂无` → 同格/同段紧接着写「**先按什么顶替 + 什么条件下换成什么**」。
   只要写了处置词（替换/失效/改用/顶替/先行/暂按/到位后/接入后/上线后/补充后/生效条件），
   这一条就成立。**只写「暂无」就收尾 = v1 的失败形态，J13 直接红。**
4. **五维表必须是三列表**：`| ① 获取路径 | 取值 | 缺值处置 |` —— 校验器按
   `标签…|取值|处置` 的两段正则取值；只有两列的表会让第三列读成空，缺口行立刻判红。
5. **提到 R/D 格的那一行不许出现「算法」「模型」二字**（J3 判据是**逐行**查的）：
   R/D 格只能写判据、门禁、冻结条件。写「STG-06 接收门禁校验本次诊断的算法版本」这种句子
   会因为同行出现「算法」而判红 —— 改成「校验本次诊断所用的方法与版本号」。
6. **格号只能引用属于你自己的那些**（frontmatter 的 `method_cells` + `rule_cells`）。
   一条契约只属于它的岗位，引用别的 FLOW 的格（哪怕语义上相关）一律判红。

## 3 内容标准（计数器测不出来的那部分，但它是这份契约存在的理由）

- **卡供方法，契约供业务取值。** 你写的不是「这张卡讲了什么」，是「**这份工作该怎么干**、
  取哪个值、什么条件下不许自动走」。
- **A 模板 §1「不得移植的部分」必须逐条列出具体数值**（从你**实际读过的**全文卡里抄原值），
  不许写「卡里的数值都不得移植」这种通用免责条款。
  若候选只有 legacy 预览版（八段式，代码与论文出处是占位串），照实写：
  「本卡为 legacy 预览版，论文实验参数未随卡进入本包」+ 按**卡面可见数字**逐条列。
- **B 模板 §2「不可达」是分工不是免责**：每条都要说清谁在什么时点补上、补不上时先用什么、
  后果是什么。
- **§4/§6 是放行判据，不是写作提纲**：写「什么条件下不许自动进 STG-07 / 必须冻结」，
  条件要**可判定**（缺什么证据 / 超什么时限 / 命中什么规则），不许写「视情况」。
- **不要对冲。** 契约里可以写业务侧默认值 + 替换条件；**不许**说「需重新标定」「临时默认值」。
- **材料词汇逐字用**（STG 名、标准产物名、岗位号、规则号）。不要发明新产物名。
- 每条契约都要有一句：**本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变。**
