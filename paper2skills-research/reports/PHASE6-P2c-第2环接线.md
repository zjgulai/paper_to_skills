## 1. 接线：一句话与三个负向控制

**一句话**：`rank_candidates.py` 的输入从**未过滤**的 `arxiv_candidates.json`（1046 篇）
改为**三段式过滤器的产物** `arxiv_candidates_filtered.json`（772 篇）。

### 1.1 为什么「加一条 if」不是接线

断链这件事在 P2 批已经三条独立取证（`reports/PHASE6-P2-约束词显著性与过滤器未接线.md`）：
`关键词库-v2.md` §0 点名的两个函数**全仓库只出现一次就是那一行**；
`--apply` 的产物**从未生成过**；`rank_candidates.py` 读的是未过滤池。
⇒ 负向词与约束词当时只影响**一份报告与一道门禁**，不影响进入打分与短名单的论文集合。

本批把它接上，同时把**三条不许松的纪律**写进代码（`load_filtered_pool()`），每条都配**能打红的负向控制**：

| # | 纪律 | 负向控制（必须 exit 2，不许 exit 0） |
|---|---|---|
| ① | **没有静默回退**：过滤产物读不到 ⇒ exit 2 | 删掉产物跑一遍 |
| ② | **不许把未过滤池喂进来**：判据是「输入里有没有过滤器的自述块 `filter`」，**不是文件名对不对** | 把未过滤池**改名冒充**过滤产物 |
| ③ | **`unjudged_ids` 非空 ⇒ exit 2**（危险性 3 > 2 > 1 > 0：没测到比测了是红的更危险） | 造一份带 1 条 unjudged 的产物 |

> ⚠️ 纪律 ② 的措辞是刻意的：如果判据写成「文件名是不是 `arxiv_candidates_filtered.json`」，
> 那么**把未过滤池复制成这个名字就绕过去了** —— 那正是漏洞 #11「判据只认一种写法」的形态。

### 1.2 收缩必须**看得见**，不能只改数字

接线后 274 篇离开打分集合。只把数字从 1046 改成 772，下一个人只能看到「候选少了」，
看不到「少的是谁、为什么」。⇒ 产物里新增 `filter` 自述块：

```json
"filter": {
  "count_before": 1046, "count": 772, "judged": 1046,
  "unjudged_ids": [], "dropped_ids": [ ... 274 条 ... ],
  "drop_reasons": {"未命中约束词": 171, "标题否定词:clinical": 12, ...},
  "dropped": [{"arxiv_id": "2609.11872", "domains": ["03-时间序列","14-用户分析"],
               "reason": "未命中约束词"}, ...]
}
```

「274 篇去哪里了」在链上**可审计** —— 这是本批给下游留下的唯一凭据。

### 1.3 反向控制：接线只改**集合**，不改**判分**

| 判据 | 实得 |
|---|---|
| 剔除**墙钟项**（`days_old`/`s_fresh`/`score`，见 #103）后，772 条保留条目的元数据与九个分项 | **0/772 漂移** |
| 顺序 | ⚠️ **跨运行不可比** —— 总分含 `datetime.now()` 推出的时效项（#103，本批不修）。**如实登记，不假称「逐字节一致」** |
| `search-queries.json` 重生成 | `git diff` **恰好 2 行**，两条都是**自述指纹** ⇒ 派生取值一条未变 |

## 2. 链上第一颗地雷（#113）：**加守卫的那天起，`build_registry.py` 就无法运行**

### 2.1 发现方式

跑**全仓 import 普查**（不是读代码，是让解释器说话）：

```
可 import: 41
🔴 有 __main__ 守卫但 import 就炸（=死脚本）：1
    build_registry.py :: NameError: name 'DECISIONS' is not defined
无 __main__ 守卫（未测，import 会执行主逻辑）：0
```

42 个脚本，**恰好一个**是死的。P1（`4dfa9f2`）给 `DECISIONS` 加的域名守卫写在第 58 行，
而 `DECISIONS` 定义在第 62 行 —— 模块级前向引用。

### 2.2 为什么两天没人发现

**验收面 65 条门禁里没有一条跑过流水线脚本。** 所有下游读的是**已入库的产物**
`papers_registry.json`，不是生成器。与 #105（过滤器无消费者）同型，
与 #11/#23/#71/#78 同族 —— **「交付 ≠ 接线」的第六次**，而这次要补的一句话是：

> **「接线」也不是「跑得起来」。**

### 2.3 修一个死脚本时，只修「让它能跑」是不够的

修掉前向引用后，**它仍然跑不起来**：那条守卫的**适用范围被写成了整张表**，
而表里有两条占位行 `d=""` ⇒ 立刻撞上「非规范域名 `['']`」。

**两条缺陷叠在一起**：前向引用让脚本根本到不了第二层，
所以**第二层从来没有被人看见过**。修法拆成两条判据：

- **J-a**：只查**真正会被使用的**条目（排除已声明的 `PLACEHOLDER`）；
- **J-b**：「域名为空的行」必须**恰好是**已声明的占位集合。

少了 J-b，`d=""` 就是一个可以**随手扩大的豁免面**（「先留空，回头再填」永远不会被抓）。

> 📌 **修死脚本的纪律**：修完必须**真的跑一遍**。只修「能跑」而不跑，
> 等于把第二层缺陷从「被挡住」变成「被释放」。

## 3. 链上第二颗地雷（#114）：它跑起来**会毁数据**

### 3.1 现算的覆盖账

盘上 `papers_registry.json` 是**唯一事实源**，PHASE3–PHASE5 由人逐条补过；
而脚本里的 `DECISIONS` 停在「初版建档」那一刻的快照。默认跑一遍：

```
⚠️ 覆盖会改动 **39/45** 条记录（逐字段完全相同的只有 6 条），逐字段受影响记录数：
      31  venue_tier        ← venue 三词表统一的成果
      19  status / gates / outputs   ← 已交付卡回指、verified_at 锚点、quotes_verbatim 计数
       9  note              ← 段落级口径修正
       8  title/url/journal/venue/published/identifiers  ← **DOI 更正**
       7  venue_track(+note) ← R4 的 demo/workshop 降级
       3  decision_reason / data_availability
```

### 3.2 处置：默认**只对账、不写盘**

- 默认行为：现算覆盖账 → 打印 → **拒绝写盘**（exit 0，盘上原样）；
- 写盘：`--force-reinit --reason "<理由>"`，**且覆盖账非空时一律拒绝**（理由栏必须逐类给出处置）；
- **看行为不看措辞**：源码里写没写那句话只能证明「有人说了」，
  证明不了「跑一遍会不会毁数据」—— 而 #114 的全部危险恰恰在于后者。

> 📌 **「不能跑」不等于「安全」。** 一个不运行的破坏性脚本，和一个运行中的破坏性脚本，
> 危险性的差别是「多久被发现」，不是「会不会发生」。

## 4. 我自己的复核是假绿（#115）

本批第一版复核写的是：**跑生成器 → 剔掉 `generated_at` → 与盘上比 → 一致 ⇒ 报「可复现」**。
而生成器 `NameError` 在**模块级**，产物**从未被写** —— 比对的两侧**是同一份文件**。**报绿。**

与 **#23**（交付≠接线）、**#99**（没发生的事被判成通过）、**#34**（判据的动作与它声称的动作不是同一件事）同族 ——
**第四次**，而且是主控**自己**在给「能不能复现」下结论时踩的。

修法落成 `check_pipeline_chain.py` 的 **J3**：**先看退出码**，把「前后 sha 相等」当成**通过条件**，
而不是「跑过了」的证据。

> 📌 **「A 与 B 一致」只有在「A 与 B 是两个东西」时才有意义。**
> 任何「比对」都要先证明被比的两侧**真的来自两条路径**。

## 5. 守护这条接线的判据自己判了假红（#116）

### 5.1 形态

L19c 的双向锁靠 `_reads_file()` 回答「谁真的把过滤产物当成输入」。旧版只认
「**字面量**出现在读调用子树里」。而接线的**最自然写法**是：

```python
FILTERED_POOL = "arxiv_candidates_filtered.json"     # 模块常量
POOL_PATH = DATA / FILTERED_POOL
ap.add_argument("--pool", default=POOL_PATH)         # argparse 默认值
src = load_filtered_pool(args.pool)                  # 传给读取函数
def load_filtered_pool(path): ... path.read_text()   # 函数体内才读
```

旧版**看不见这种写法** ⇒ `wired=true` 被判成「无人读」⇒ **假红挡住接线**。

与 **#2 / #11 / #93 / #108** 同族 —— 「判据只认一种写法」的第 N 次。
区别是：**这次伤的是判据自己守护的那个接线**，而且方向是假红（安全方向）——
纯属运气；同样的局限在另一个方向就是**假绿**。

### 5.2 修法与反向控制（8 例全部进 `--selftest`）

补三种写法：① 字面量 · ② 模块级常量（**含传递绑定** `F = D / K`）·
③ 常量经 `argparse` 默认值变成 `args.<dest>`、再经**调用点 → 形参**接进读取函数体内。
连带修掉两处硬编码：**argparse 的取值变量名不是恒等于 `args`** ——
从 `X = parse_args()` 读出来，**取不到就不产生键**（不猜默认值）。

| 正向 3/3 判为「读者」 | 负向 0/5 判为「读者」 |
|---|---|
| ① 字面量在读调用子树里 | ✗-a 只提到名字、不做任何读 |
| ② 模块常量（含传递绑定） | ✗-b 读了别的文件 |
| ③ 常量经 argparse 默认值再传给读取函数 | ✗-c 常量与读调用无关（读的是第三条路径） |
| | ✗-d 参数化但默认值是**别的**常量 |
| | ✗-e 有 argparse 但读的是别的文件 |

外加**同码换 needle** 的反向控制：同一份代码换成别的产物名 ⇒ 必须判「不是读者」
（证明判据问的是「读的是不是**这一份**」，而不是「有没有在读文件」）。

> 📌 **判据的适用范围必须显式划出来，两个方向都要有反例。**
> 只钉正向 ⇒ 判据收窄到只认得自己写过的那个写法；
> 只钉负向 ⇒ 判据宽到把「提到过」当成「读过」。
