## 0. 用途：这个门禁存在的**唯一**理由

**139/139 全绿 ≠ 139 份都给了取值。** 契约的「数据要求」表里**已经有五维行**
（实测 `① 获取路径 139 · ② 粒度 139 · ③ 回溯深度 139 · ④ 新鲜度 139 · ⑤ 口径归属 139`），
而 `check_contracts.py` 的 **J5** 已经判「五维齐全 + ① 断言五选一」。
但 **J5 的颗粒度是「行」**：行在、格非空即过 —— J5 自己的注释里就写着实测边界：

```
`| ① 获取路径 | 本企业无自有埋点，实际全靠人工估算 | 非缺口 |` ⇒ exit=0
```

**本脚本把颗粒度从「行」降到「格」，只问一句：这一维，点名了吗？**
它**不替换** J5/J6/J13，是它们的下级颗粒度：

| 门禁 | 颗粒度 | 判什么 |
|---|---|---|
| `check_contracts.py` J5 | 行 | 五维行在不在 + ① 有没有断言枚举 |
| `check_contracts.py` J6 | 行 | ① 写了「不可得」时 status 是否如实记账 |
| `check_contracts.py` J13 | 段 / 条目块 | 缺口有没有带处置 |
| **本脚本 R1–R7** | **格** | **五个格子里有没有本维的点名** |

**五维判据的词汇不是本任务新造的。** 139 份撰写人**已经在用**这套词汇：

## 1. 五维判据表

五维取自材料与模板，**逐维问「点名了吗」**。每维三态：**正取值 / 缺口已处置 / 未点名**。

| 维 | 判什么算「点名」 | 判「未点名」的形态 |
|---|---|---|
| **① 获取路径** | 必须**断言**五选一之一（自有埋点 / 平台后台 / 第三方 API / 需授权 / **不可得**），且必须**再点名具体数据源**（材料命名法 `〈…〉` 或枚举词后的括注） | 「数据可得」「有数据」；枚举词写在**否定句**里（`本企业无自有埋点`）；只写一个光枚举词、没有任何源名 |
| **② 粒度** | 给**粒度轴**：`维度 × 维度 …`、`一条 ＝ …`，或点明粒度单位（SKU / 订单 / 用户 / 自然日 / 自然月 / 批次 / 字段 / 评估单元 …） | 「明细」「全部」「不限」「完整数据」 |
| **③ 回溯深度** | 给**可判定的深度**（N 个完整年度 / N 个自然月·日·周 / 全量 / 自…起 / 首笔）；**并与既有「2 个完整年度」口径对账** —— 深度 ≠ 2 年时必须点名来源 | 「有历史数据」；给了深度但既非 2 年口径、又没说这个深度从哪来 |
| **④ 新鲜度** | 给**节奏**（T+N / 当日 / 实时 / 每次进入某阶段前重读 / 按自然日回填 / 「截至前一日 24:00」快照 / 批次到达后 / 改版即时）（对应 AGT-046「带质量状态、来源和新鲜度」） | 「及时」「最新」 |
| **⑤ 口径归属** | 点名**AGT-045 的业务口径与主数据**为归属方（对应其职责「维护指标和业务对象契约」）；若声明未定名，必须点名归属方或缺口并给处置 | 「有口径」「按公司口径」 |
| **R7 缺口义务** | 任一维为缺口时，**整行**必须给「先用什么顶替 + 什么条件下换成什么」（处置写在第三列或取值格都算，但**缺口句不能自己救自己**） | 缺口 + 第三列空 |
| **R8 不可得合法** | **「不可得」是一个合法结论**：① 断言了「不可得」且五维齐全 ⇒ **判合格**，并单独入账 | ——（这是**反向控制**，不是打红项） |
| **R9 schema 隔离** | 本脚本、JSON 产物与**本报告**三处**一律不得出现论文侧字段名**（该名 = `data` ＋ `_` ＋ `availability`）；出现即判红 | —— |
| **R10 覆盖率双边** | 0 份契约 / 目录不存在 / 五维表抽不全 ⇒ **exit 2（不是 0）**；份数 **> 139 ⇒ 判红** | —— |

**三态定义（本任务的核心口径）**

- `五维齐全`：五维逐格均为「正取值」或「缺口已处置」
- `数据待盘`：**任一维未点名** ⇒ 标数据待盘 —— **不是默认其他四维成立**
  （来源：本仓库反复出现的「判据的适用范围被默认成了全体」）
- `不可得`：`五维齐全` 的**子类**。① 断言了「不可得」且五维齐全 ⇒ 合法结论、判合格。
  再分「本维主取值＝不可得」与「子缺口（其余路径仍可用）」两账，**混在一起报会把整条责任没数据平均掉**。

## 5. 反后门：R9「与论文侧字段 schema 互不引用」

### 5.1 三处（脚本 / 产物 / **本报告**）都刻意不写全这个词 —— 以及为什么

**本报告初稿把那个词逐字写了 5 处。** 改掉它不是因为洁癖，是因为本仓库最贵的一条教训：

> 上一轮污染源**就是我们自己的范本** —— `contracts/v2/B/CTR-B-023` 第 31 行把自造词写成「材料已定名的经营节奏」，
> 而**范本是被设计成会被抄的东西**，两天就长成 108 处 / 67 份。
> 仓库原话：**「冻结不等于无害：被设计成会被抄的东西，留在原地就会继续被抄。」**

一份专门讲「论文侧字段与业务侧字段必须分家」的报告，**恰恰是最容易被抄的那份东西**。

```

```

## 6. 仪器自己的三个缺陷（**这一节是本报告最该留的部分**）

新写一个门禁这个动作本身就会制造下一批缺陷。本轮自检抓出我自己 3 个，全部已修并配能打红的样本：

| # | 缺陷 | 方向 | 症状（实测） | 修法 |
|---|---|---|---|---|
| **S11-1** | **归一化只做了半边** | 🔴 假红（读成「语料有问题」） | `normalize()` 走 NFKC，而 **NFKC 会把带圈号 ① 折成数字 `1`**（① 是兼容字符）；首版只归一了左边，右边拿的是未归一的 `①获取路径` ⇒ **五维表一行都抽不到**，139 份全报「0/5 行」，看上去像契约写坏了 | 两边同尺（`nk = normalize(d)`）。**与仓库既有家族同源**：`normalize()` 先去空白、`MASK_RE` 后匹配，两边不同尺 ⇒ 9 条遮罩是死模式 |
| **S11-2** | **变异锚点被变异表自己抄了一遍** | 🟡 假仪表 | 变异表里存着锚点字符串，于是同一行文本在源码里出现 **2 次** ⇒ 每条变异都被误报「施不上力」；而 `replace(old,new)` 不限定范围时还可能改到**表里那份**（run_phase6_gates 的实测：锚点重复 ⇒ 变异从没被跑过，而读数看起来像「用例是摆设」） | 锚点只在**判据代码区**（`mutations = [` 之前）里计数；替换限定 `count=1` |
| **S11-3** | **判据是叠加的，样本没隔离 ⇒ 用例是摆设** | 🟡 假仪表 | R1 与 R2 叠加：用 `数据可得` 这种既缺枚举、又没括注的样本测 R1，**把 R1 改成恒真、用例照样红（被 R2 接住）** ⇒ 变异 1/2 抓不住 | 各配**只打其中一条**的隔离样本（`r1only`、`negparen`），并给变异层加**探针翻面**断言 |

> **另修两处「变异施不上力」**：
> ① `_reading()` 原先只比退出码 —— 把「缺一维 ⇒ 数据待盘」改成恒不触发后**退出码一个字都没变**
> （红因仍在 `reds` 里），只有三态的账变了 ⇒ 现改为对拍 **① 退出码 + ② 文案命中 + ③ 汇总账指纹**。
> ② 两条 exit 2（「目录不存在」与「0 份契约」）原先共用一份反向控制 ⇒ **互相顶账**，
> 删掉任一条自检都照样全绿（台账 #26 同型）⇒ 现各配红因文案断言。

**还有一个「已登记未修」的自省**：`_GRAIN_WORDS` 是一张**宽**表（按实测语料收），
所以判据抓不出「粒度写得过粗」这类**质量问题** —— 这是**有意**的取舍（宽表防假红），
代价是放过「粒度不合理」。这条边界写在下面 §8。
