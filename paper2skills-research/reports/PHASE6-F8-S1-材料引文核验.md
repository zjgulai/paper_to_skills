# PHASE6 · S1 收口期 · 材料引文核验

> 起因：S1 续批一位撰写人交活时报了一条「跨份发现」——**68 份契约引用材料「季度经营策略」，而材料 0 命中**。
> 我（主控）去复核，结果比它报的更大，而且**污染源是我们自己的 v2 范本**。
> 本报告记录：追到的根因、为此新造的仪器、仪器自己先后被修掉的 4 个缺陷、以及**没做**的部分。

---

## 1 一句话

> **139 份契约里有 125 条「材料『X』」式引文；其中 11 个词在材料里查无实据。**
> 而它们的**种子不在撰写人手里，在我们自己的模板与作业包里** ——
> 范本契约与作业包生成器把**我们自己的分析**标成了「材料原文」，139 位撰写人照抄了这个标签。

## 3 三种来源机制 —— 只有一种该怪撰写人

追每一处的出处，得到三种**完全不同**的机制：

### 机制 A · 种子在我们的 v2 范本里（`季度经营策略`，108 处 / 67 份）

```
git log -S "季度经营策略"  ⇒  79d4be0  feat(F7): 契约模板 v2 …
```

`contracts/v2/B/CTR-B-023-纠正预防措施.md`（**F7 交付的 v2 范本契约**）第 31 行：

> （a）材料已定名的经营节奏（「月度经营复盘」＝1 个自然月、**「季度经营策略」＝1 个自然季度**、材料阶段边界 STG-0x）；

**范本是设计上就会被抄的东西。** `WRITER-BRIEF.md` 第 3 行明确要求撰写人「照它的密度写」，
于是这个自造词在两天内长成 108 处。而这**不是第一次** —— `撰写规范.md` §2 记的
`业务规则字典` 事件是同一形态（自造词经两层传播后被当成材料词汇引用），只是规模小一个量级。

> ⚠️ 范本契约是 F7 实测的**冻结底本**（改它，F7 那三组中位判据就失去可复现性）。
> 故**本轮不动它**，改为把判据补上（见 §4）——下一次谁写「材料『X』」，闸门当场问他。

### 机制 B · 我们自己的分析被标成「材料」（`§F.3` / `§F.5` 那一族）

`build_contract_workpack.py` 生成给**每一位**撰写人的批次文件，其中一行原文是：

```
**本责任为什么是 {A/B} 类（材料 §F.3 原文，别改判）**：{rationale}
```

而 `§F.3` **不是材料的章节**：

- `build_gap_ledger.py:18` 自己写明 A/B/C 的来源是 **`reports/_survey_org_model.md` §F.3/F.5/F.6`**；
- `_survey_org_model.md:651` 的标题是 `### F.3 逐条判定（151 条，含 A/B 一行理由）`——**我们自己的综述**；
- 材料的 md 文件里 `§F.3` / `本次计入 A` 均 **0 命中**。

⇒ **139 份作业包全部把我们的二手判定标成了「材料 §F.3 原文」**，撰写人照抄，
于是写出了「材料 §F.3 原文写明『流程合理性须业务确认』」这类句子。

**已修**（本轮）：
- `build_contract_workpack.py` §F.3 行改为「来源＝本项目《经营侧组织模型精确抽取》§F.3 的判定，**二手来源，不是材料原文**」+ 引用纪律一句；
- §5 边界条目表头加来源标注：「**不是材料原文**……**不得写成『材料给了』**」；
- 8 个 FLOW 的作业包已全部重新生成，`--check` **1568/1568** 通过。

### 机制 C · 撰写人自己写的话标成「材料」（`合规判定须 DPO／法务` / `库存是否支撑该动作` / `缺一项即 HOLD`）

这三条在**材料与本仓库里都 0 命中** —— 它们是撰写人的业务判断，被写成了材料的账。
**这一种才是撰写人的问题**，但它只有 3 处，且已被判据抓住。

## 4 仪器：`check_material_citations.py`

判据只有一条：**契约里凡声称「材料『X』」的 X，必须在材料里真的存在**。
难点全在「哪些才算声称」。

### 第一版跑了 22 条「查无此词」，**其中大部分是仪器自己的假阳性**

逐条追上下文后发现，契约在写**自己的标签**（`外发材料只能写「非增量」`、`该对象的材料只能作「客户陈述」`）
或**自己的产物名**（`人工补录的材料清单`、`每一份材料登记成「对象×时间戳…」`），
`原材料成本冲击` 里的 `材料` 更是把整条引文劫持了。**照第一版报，会制造约 20 条假红。**

这与台账 #17（五维标签子串劫持）、D10（审查句误判）、#19（「模型」二字误杀）**是同一族**：
**判据的适用范围被默认成了全体，而它其实只覆盖一个子集。**

### 第二版把「三种判定 + 两种罪」拆开

| 判定 | 含义 |
|---|---|
| `attrib` | `材料` 确是引文来源 ⇒ 进入核验（实测 125 条 / 48 词） |
| `non_attrib` | `材料` 只是句子里的普通名词 ⇒ **不判**（实测 20 条 / 18 词，**份数与名单是一等输出**） |
| `unclassified` | 限定语形态从没见过 ⇒ **不猜**，单独报出并 **exit 3**（漏测 ≠ 通过） |

| 罪 | 判据 |
|---|---|
| `missing` | 引文在材料里找不到 |
| `altered` | 能找到近逐字原文但字面不同 —— **声称「原文」却在改字时必须报**，并**回捞材料原句**打印出来 |

### 仪器自己先后被修掉 4 个缺陷（全部由 selftest 或实测读数矛盾暴露）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 限定语窗口是「同一句内 20 字以内」，不看左邻 | `外发材料…只能写「X」` 被当成材料引文 ⇒ **约 20 条假红** |
| 2 | 一行多引号时，第 2 个引号的 head 片段把**第 1 个引号**也算了进去 | 形态白名单永远认不出 `为该格定的检查项里就有「A」与「B」` ⇒ 报成「未分类」 |
| 3 | `str.translate({c: None})` —— **`str.translate` 拿 dict 表是按 ordinal 查键的，字符键一个都命不中** | markdown 强调符**一个都没删**（而代码看起来完全正确）⇒ 7 个与材料**逐字相同**的引文被判成「改了字」。重写时把 `str.maketrans` 弄丢了，属**我自己引入的回归**；selftest 用例⑩改为直接断言 `normalize` 行为 |
| 4 | `context_of` 只给针去标点、**没给草垛去** | 「材料原句」回捞恒为空 ⇒ `altered` 退化成「只说不一样、不说哪不一样」。selftest 用例③当场抓住 |

另修一处**假绿风险**：材料目录 `/Users/lute/project/AI组织变革` **自己是个 git 仓库**，
首版 `load_corpus` 把 `.git/` 也读进了语料（实测 `grep -rl "F\.3"` 命中过 `.git/objects/...`）
⇒ 一个材料正文里没有的词，可能因为存在于某个历史 blob 里而被判「有据」。现已排除所有点开头路径。

### 纪律（照仓库既有台账）

1. **活体探针每次运行都跑**：阳性对照（`月度经营复盘` 等）必命中、阴性对照（`季度经营策略` 与一个必然不存在的词）必不命中；探针不通 ⇒ **exit 3**，绝不退化成 exit 0。
2. **材料根不存在 / 读空 ⇒ exit 2**，不是 0（`scan_secrets.py` 同一纪律；也是台账 #42「J12 依赖本机 HOME」的形状）。
3. **豁免必须可见**：`non_attrib` 的份数与名单是一等输出 —— 否则「我判它不算引文」就成了新后门。

`--selftest` **11/11**（含 ④「外发材料…只能写」必须判 non_attrib、⑤「原材料」子串劫持必须判 non_attrib、
⑦未见过的限定语必须 unclassified、⑧材料根不存在必须 exit 2、⑨材料读错必须探针失配、⑩⑪ 归一化回归守卫）。

## 5 这一轮**没有**做的事（必须跟着结论一起说）

1. **没有改 67 份契约。** 原因有二，且第二条是硬的：
   - `季度经营策略` 的 108 处里，两处形态不同（《取值来源纪律》白名单块 vs 行内 `（材料「季度经营策略」的经营节奏）`），
     而 v2 的义务是「**业务侧默认必须逐条附替换条件**」⇒ 正确的修法**必然逐份**，机械替换会把 67 份改成同一句话，
     正是同期「跨文件同质化」任务在治的病；
   - 收口期 **`497734f0` 正在逐格改写 136 份契约**（同质化整改），此时第三方批量改同一批文件是**写入冲突**。
2. **没有动 F7 的 v2 范本**（`contracts/v2/B/CTR-B-023`）。它是 F7 三组中位判据的冻结底本，改它等于让那批数字失去可复现性。
   替代方案是判据（§4）+ 本报告 + 后续工单。
3. **没有把 139 份判红。** 仪器目前是**只跑不进门禁**（未接进 `check_contracts.py`），
   因为「引用纪律」是 S1 收口后才立的，用它去追溯前一版底本会制造一批时间错位的红。

## 7 一条要写下来的口径

> 这次抓到的东西**不是「撰写人编了材料」**，而是：
> **我们发下去的模板里，有一行把「我们的分析」写成了「材料原文」。**
>
> 139 个人照着做，没有一个人有机会发现 —— 因为范本与作业包正是被设计成**不必怀疑**的东西。
> 这与台账反复记的那件事同一个结构：**判据的适用范围，被默认成了全体。**
> 这次的主语换成了**模板**：**模板的权威性被默认覆盖了它其实没覆盖的来源。**
