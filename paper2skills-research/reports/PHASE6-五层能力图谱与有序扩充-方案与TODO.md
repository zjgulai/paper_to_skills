## 1. 四个推翻既有假设的实测发现

**发现 1：论文卡页面已经存在，本期不是建页面。**
`packages/surfaces/dsh-algo-skills-local` 就是 paper→skills 页。探活 `GET /api/dsh-algo-skills/health` → HTTP 200：`skills:1338, placed:1327, unplaced:11, wired:127, wiredAnywhere:258, emptyRoles:2`。join 键 `card.l3_business → role.responsibilities`，源码明确「**owns no classification fact of its own … The card IS the data**」。
⇒ 接入缝改 **4 个文件**（`src/collect.ts` 的 `parseSkill()` 是唯一解析点）。**不要**扩建 `dsh-overseas-skills`（需 +1338 条 taxonomy mapping、会把 1338 张卡灌进每 2 秒轮询的 `/list`、两套 `wiredIndex` 语义打架）。

**发现 2：需求侧自报「Skill Contract = 0」。** 八条 FLOW 的 `required_skill_contract_refs` 全是空数组。**这就是本项目的真实定位：不是多出几张卡，是给 151 个责任建供给契约。**

**发现 3：解决方案层是孤儿。** `playbook/solutions/` 有 19 个方案页（L1–L6 架构 + 路线图 + 三大陷阱 + 194 卡位索引），grep `AGT-0` / `SCN-0` **零命中**。这是第四套平行分类。

**发现 4（Q6 探查时撞出）：已安装的 1338 张 p2s 卡全是源站预览版。** 含「原文引用」的 = **0/1338** —— PHASE4 建的 2,087 条逐字引文**一条都没进产品**。

## 3. MECE 设计（D1 + D2）

### 3.1 前两层是划分，后三层只能是覆盖

| 层 | MECE 性质 | 依据 |
|---|---|---|
| 50 岗位 / 8 域 | **划分** | 4 面 5+35+5+5=50；`domain` vs `group` 50/50 |
| **151 细分业务** | **划分**（缺口账级） | 151 条全局唯一、每条唯一属一岗 |
| **8 FLOW × 8 STG = 64** | **划分** | `flow_stage_bindings = 64`，已机读 |
| 20 SCN | **覆盖，多重数** | 118 vs 701；**降为标签** |
| N 个解决方案 | **覆盖** | 一个方案跨多格 |
| N 张卡 | **覆盖** | 一卡可挂 1–3 个 L3；1338 张里 **269 张跨面** |

### 3.2 64 格分型（本期最重要的设计结论）

64 格里**只有 24 格能挂算法模型**。按 `protocol.stages[].model_participation` 实测分型：

| 型 | 阶段 | 格数 | 该格放什么 |
|---|---|---:|---|
| **M · 方法格** | STG-04 证据收集与诊断 / STG-05 方案与标准产物 / STG-08 结果核验与异步学习 | **24** | 算法模型在此接入 |
| **R · 规则格** | STG-02 范围确定与Case创建 / STG-06 Assurance接收门禁 | **16** | 契约与判据；模型只做**有界分类** |
| **D · 确定性格** | STG-01 信号接收 / STG-03 上下文装配 / STG-07 受控动作 | **24** | 无模型参与，**不消耗检索预算** |

> ⚠️ 这推翻了「64 格 = 64 个解决方案」的直觉读法。已立为风险 N4：D/R 格出现算法模型即判错。

## 5. 必须直面的负结果

`dsh-paper2skills/docs/eval-report.md` 实测（**六组对比方向完全一致**）：

| 对比 | Δ(treat−control) | p |
|---|---:|---:|
| run1 holdout | **−0.85** | 0.0038 |
| v2 train · C-vs-S | −1.25 | 0.0245 |
| v2 holdout · C-vs-T | **−0.95** | 0.084 |
| v2 holdout · C-vs-S | **−1.95** | 0.0001 |

判官噪声 ±0.6~0.7 ⇒ 都是真信号。机制：**卡里装的是论文的方法与参数，而任务问的是这家公司该怎么干** —— 模型把「信息熵 ≥ 0.65」当业务阈值，把「欺诈召回由基线 42% 提升至 ≥60%」当事实（用户从未给过这个基线）。

SkillOpt 补丁被 held-out 门**拒绝并回滚**：它让 26/40 份产出挂上对冲措辞（对照组 0/40），Δ 从 −0.95 变成 **−1.10**。

⇒ **算法模型层不能直接对着交付物暴露。「解决方案」不是分类的一级，它是强制翻译层**：卡供方法，契约供业务取值与标定规则。这与 PHASE5 的 X1「作者外推」三态机制是**同一条纪律的反方向**，共用同一套 selftest 纪律。

### 6.3 四条纪律（决策过程中立下）

1. **决策前提可能被后续分析改写** —— D3 的原前提是「19 → 64」，而 D2 落地后实测为 M24/R16/D24。**前提变了就把问题重开**，不将错就错。

## 7. 最终交付物结构

```
L0 岗位        50 个 AGT（4 面 / 8 域）
L1 责任        151 细分业务（MECE 划分，每条唯一属一岗）
L2 场景        8 FLOW × 8 STG = 64 格（M24 / R16 / D24）
L3 方案        8 份方案域（= 8 FLOW）              ← 人类可读的长文
L4 契约        139 份标定契约（A73 + B66）           ← 机器可校验的短表
L5 模型        N 张算法卡（挂载点 = L4 契约）
```

**139 份契约的两种模板**

| | A 类契约（73） | B 类契约（66） |
|---|---|---|
| 拦什么 | **参数移植**（−0.95 的机制） | **完整性虚报**（算法只做一段，却宣称整条责任已覆盖） |
| 核心字段 | 方法来源（卡）/ **数据要求（五维）** / 标定规则 / 重标定触发条件 / 适用 FLOW（多值） | 算法可达部分 / 不可达部分 / **必须的外部证据与责任岗位** / **该格何时必须冻结** |
| 成本 | 高（每条要读卡、定标定规则） | 低（判定理由在 `_survey_org_model.md` F.3 已逐条写好，可半自动生成） |

**契约的两种状态**：`可写`（有卡，53 条 = A 37 + B 16）| `待卡`（无卡，86 条）。**「待卡」的契约就是扩充工单本身** —— 不需要另造 gap ledger。契约先存在，卡去认领（认领制为 Q4 放弃项，故仅登记不拦截）。

**数据可得性五维（Q12）**：① 获取路径（自有埋点/平台后台/第三方 API/需授权/不可得）② 粒度 ③ 回溯深度 ④ 新鲜度 ⑤ 口径归属（是否已被 AGT-045 主数据契约定名）。反后门：**不得只写「数据可得」，必须点名获取路径**；「不可得」是合法结论，不得被改写成「partial」。
