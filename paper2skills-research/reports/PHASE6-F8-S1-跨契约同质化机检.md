### 1.1 算法（确定性，可复核）

「n 字滑窗」：把每格文本归一化后枚举全部 n 字窗口，窗口逐字相同即视为重复。
**两格共享任一 n 字窗口 ⟺ 两格最长公共子串 ≥ n**（充要），所以判据没有阈值外的自由度。
报告里的「重复文本」取该对契约的**最长公共窗口**，由「左极大窗口」向右贪心扩展得到 ——
纯字符串比较，**同输入必同输出**，没有模糊匹配、没有语义相似度。

**独立复核**：另写一份**不复用检测器任何函数**的暴力实现（逐维建窗口集合、两两求交）重算 D1，
逐维数字与检测器**完全一致**（`① 83 · ② 17 · ③ 749 · ④ 194 · ⑤ 929`，合计 1972 —— 那是收紧归一化之前的同一语料）。

### 1.2 归一化（每一处都由实测逼出来，不是风格偏好）

`normalize()` = **NFKC** ＋ **去全部空白** ＋ **去 Markdown 强调符 `*`**。

- **去空白**：空格是排版，不是「字」。实测：整改第一批里有人把「，」后加空格当作改写。
- **NFKC 而不是 NFC**：`，`↔`,`、`（`↔`(`、`％`↔`%` 是同一句话的两种排版；只做 NFC 时**换一套标点即可绕过**。
- **去 `*`**：这是本轮**最重要的一个假绿修复**。首版只做 NFC，于是把 `替换` 写成 `**替换**`
  就能把 18 字窗口**切成两段**，检测器看不见 —— 措辞一个字没改，重复照旧。
  实测代价：补上这一条后同一语料的 D1 从 **1554 → 2074 对（+520）**。
  加粗是**表现**，不是**用词**。

仍然**不**做同义词替换、不做语义相似度、不剥行内代码（那三样会把「可复核」变成「可解释」）。

### 1.3 材料专名遮罩（**不是豁免，是修正判据的适用范围**）

判据问的是「同一句**处置**被抄了几遍」。但语料里有一批字符串**必须逐字重复**：材料的产物名、
协同协议术语、`AGT-0xx`/`FLOW-0x`/`STG-0y` 编号、决策号 `Q9–Q12`、开放事实 `O1/O2`、
数据源名 `〈…〉`、行内代码。规范明写「不要自己造词」，**改掉它们才是违规**；
不遮罩时判据会把 `StageAcceptanceRecord`（21 字）这种专名判成同质化，
**整改方向会被带偏成「把材料术语改写掉」**。

遮罩口径**故意收得很窄**：只遮标识符与专名，**不遮散文**，只遮必要词。

**实现不是「把专名替换成占位符再比」**（那会更瞎：只换专名、不换句式的两格会双双判绿）。
实现是：**一个 n 字窗口只有整窗都落在撰写人自己的用词上才算数**。
于是 ——

- 两格只共享 `StageAcceptanceRecord` ⇒ **不报**（那不是同一句话，是同一个词）；
- 两格共享的样板句里**含** `AGT-045` ⇒ **照报**（专名周围还有几十字散文）。

三道防倒灌（对应仓库纪律「新增豁免必须比拦截条款测得更严」）：

1. 遮罩量是一等输出（遮掉多少字、占比多少都打印）；**吃掉语料 > 35% 即判红** —— 遮太多说明白名单自己变成了后门；
2. selftest **反例**：含专名的样板句仍须判红（用例 25）；
3. selftest **反例**：只共享专名的两格必须判绿（用例 26），且**关掉遮罩的变异必须被它抓住**（变异 7/10）。

### 3.2 为什么默认取 n=18

- **曲线平滑，没有天然拐点** —— 如实登记：这不是一个「数据自己选出来的」阈值，
  任何「陡降点」的说法在这张表上都站不住（12→50 是单调衰减，无平台）。
- 取 18 的**唯一硬依据**是**规范与现场实测自己的口径**：同质化禁令是撰写人按
  「≥18 字完全相同」实测出来的，机检要与人的判断可比，就不能换尺子。
- 取更小（12–16）会把「同一类处置的正常行业表述」也算进来（如 ② 粒度在 n=12 时 548 对，
  n=18 时只剩 11 对），整改会被噪声吞掉；取更大（24+）会漏掉 ③ 那一族的主体。
- **阈值可配**（`--n` / `--n-body`），上表就是它可配的依据；换 n 跑一遍即可复核。

### 3.3 D3 为什么默认关闭（取舍，如实登记）

正文全扫在 n_body=30 时给出 **10236 条重复 / 833 种重复文本 / 涉事 139 份全覆盖**。抽样分类后：

- 主体是**模板／规范要求逐字写的句子**（「本契约对同族方法卡通用；换卡时只替换方法实现…」64 份、
  「族内各卡的方法实现可互换…」52 份、「同族已装卡（可整卡替换任一代表卡…）」40 份）
  与**材料已给出的开放事实复述**（「**主体变**：开放事实 O1（Amazon 65%/独立站 15% 之外的其余 20%…）」44 份）。
  **改这些等于违反模板义务**，且它们不是「缺值处置」这一列的重复 —— 不是本禁令的对象。
- 剔除「在模板／规范／公共材料里逐字出现」的句子后仍有 **6934 条**。
  残余里确实混着真同质化（如「提交起，至该 Case Charter 已写明的观察窗截止日仍未取得 §…」27 份），
  但**规模是 D1+D2 的三倍**，本轮**没有做**（见 §7 未做项）。

⇒ 处置：D3 **完整实现、可随时跑**（`--only D1,D2,D3`），但**默认不参与判红**，
且运行时会在输出里明写「D3 本次未启用」—— 不是静默丢弃。
本轮的整改范围锁定在 **D1 + D2**（这正是禁令的原文对象：「缺值处置」的重复）。

### 4.3 人造注入样本（在**真实语料**上做，不是只在沙盒里做）

「某个东西不存在」的结论，先要问「我用的仪器能看见它吗」。所以在宣布任何「0 重复」之前，
先把一份**人为注入的重复**放进**真实契约的副本**里，看检测器抓不抓得到：

```
做法：把 139 份契约复制到 /tmp/p2s-dedup/inject，把 CTR-A-007 与 CTR-A-008 的
      「③ 回溯深度 · 缺值处置」两格替换成同一句 55 字的人造句子，再跑 D1。

注入前 D1 对 = 1271
注入后 D1 对 = 1238     （Δ = −33：两格原文各自的旧重复被替换掉了）
其中注入本身贡献 = 1 条，被抓到：
    CTR-A-007-抽样审计.md ↔ CTR-A-008-需求分群.md · ③ 回溯深度 · 55 字
✅ 人为注入样本被检测器抓到
```

⚠️ 这条探针本身也踩过一次坑，如实登记：首版用 `POISON in h["text"]` 直接比对，
**判成「没抓到」并让脚本断言失败** —— 因为 JSON 里存的是**归一化后**的文本（NFKC 把 `：` 变成 `:`），
而未归一化的探针句里是全角冒号。**是断言写错了，不是检测器瞎了。**
（与仓库里「先问仪器能不能看见」同一条纪律 —— 但这次是「先问**断言**能不能看见」。）

### 7.3 判据自身的已知残留（登记不修）

1. **报告里的「N 字」是窗口长度，不是纯净的处置用词长度**：`pair_lcs` 由合格窗口向左右扩展时
   **不看遮罩**，所以窗口可能把材料专名也计进去（批次 04 用自己的实现复算，得到比报告**更小**的值，
   例 `CTR-A-029 ⑤ vs CTR-A-019`：报告 33、真值 29）。**方向偏保守（只会多报不会漏报）**，
   但**不要把它当精确值引用**。
2. **`mask_patterns_alive` 只验「模式能匹配」，不验「匹配位置正确」**（例如误遮普通散文）。
   误遮的闸门是 D4 的遮罩预算（>35% 判红），当前实测 D1 遮罩率 9.4%、D2 22.4%，都在闸内。
3. **跨维重复不报**（D1 只在同维内比较）：若某句话从 ③ 抄到 ⑤，本条判据看不见。
4. **D3 的模板排除只做到「命中模板原句」，不做「模板衍生句」识别** —— 「族内各卡的方法实现可互换，
   本契约取的是族骨架」这类**改写自模板**的句子不在排除集里，这也是残余 6934 条偏大的原因之一。

### 7.4 一条给续批的作业提醒（由撰写人实测撞出，会静默毁掉工单）
