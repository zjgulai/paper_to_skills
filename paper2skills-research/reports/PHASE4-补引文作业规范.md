# PHASE4 存量卡补引文作业规范（F3，子代理必读）

> 本文件是「给存量卡补逐字引文」这一步的**唯一作业规范**。目标不是把门禁变绿，
> 而是让每一条数字**真的**有出处；门禁变绿只是副产品。

## 0. 你要做什么（一句话）

给分配到的卡片**新增**引用块，使得卡片里的数字/结论能在论文全文中找到逐字出处；
**不得改写既有正文，不得删除既有数字**。

## 1. 绝对红线（违反即整卡作废）

| # | 红线 | 为什么 |
|---|------|--------|
| 1 | **禁止编造/转述引文**。引文必须是全文存档里**能整句连续找到**的原句 | `quote_check.py` 用「最长连续匹配段」判真伪；转述会被判 FABRICATED |
| 2 | **禁止把两句话缝成一句**。哪怕两个碎片都是真的 | 这是最难抓的失效模式，门禁专门有「拼接」检测 |
| 3 | **禁止为了让数字过闸而找个「包含同样数字」的无关句子**。引文必须**支撑那条断言的语义**，而不只是数字相同 | 否则证据链是装饰品 |
| 4 | **禁止改写、删除既有正文与数字**。发现既有数字与论文不符，**写进报告**，不改卡 | 存量卡是 v1 资产；「标注不删」是既定口径 |
| 5 | **禁止改 `paper_id`**。frontmatter 的 `paper_id` 是 arXiv ID | 改了会让 `quote_check` 找不到底本 |
| 6 | **只碰分配给你的卡片文件**。不要 import 其它卡、不要动 registry、不要 git commit | 多代理并发写同一文件会互相覆盖 |

## 2. 每张卡的标准动作

### 2.1 读底本，不读摘要
全文存档路径已在你的工单里（`paper2skills-vault/papers/<域>/<arXiv-ID>/fulltext.md`）。
**必须只引用这个文件里真实存在的句子。** PDF 转来的底本里，表格会变成 `| a | b |` 形式，
句子中间可能残留断行 —— 引用时选**完整、干净**的句子。

### 2.2 找出卡里最需要出处的断言
优先处理带度量语义的数字：`%`、`pp`、倍数、金额、准确率、提升/降低幅度。
用 `gate_check.py --card` 能看到具体哪些 token 被判无出处（`G2-UNSOURCED-METRIC`）。

### 2.3 补引用块的写法（v2 规范）

```markdown
⑥ 原文引用

> 原文:"<逐字摘录，必须与全文存档完全一致>"
> 出处：<arXiv ID> §<章节号>
```

- 引文**逐字**，不改标点、不改大小写（门禁会规范化空白与连字符，但**不规范化用词**）
- 章节号必须是底本里真实存在的（如 `§4.2`）；不确定就写 `§<章节标题原文>`
- **每张卡至少 3 条**；数字多的卡按「一条断言一条引文」补
- 若卡片已有 `⑥ 原文引用` 段，**追加**到该段末尾，不要新建重复标题
- 若卡片没有 v2 的 ⑥ 段（存量卡多为 v1 五段式），在正文末尾新增 ⑥ 段

### 2.4 frontmatter 补 `evidence_basis`
在 frontmatter 加一行（缺 frontmatter 就在文件开头补最小 frontmatter）：

```yaml
evidence_basis: paper-verbatim      # 已有逐字引文
# 或 paper-traceable                # 有来源但引文还没补全
```

## 3. 每张卡必须跑的三个命令（缺一不可）

```bash
cd /Users/lute/project/paper_to_skills
C=paper2skills-vault/<域>/<卡片文件名>.md
python3 paper2skills-skills/paper-审核/scripts/quote_check.py  --card "$C"
python3 paper2skills-skills/paper-审核/scripts/gate_check.py   --card "$C" --only G2
python3 paper2skills-skills/paper-萃取/scripts/verify_skill_code.py --card "$C"
```

**通过标准**：
- `quote_check`：`✅ VERBATIM`，`n_fabricated=0`，`n_fuzzy=0`
- `gate_check --only G2`：不再有 `G2-QUOTE-FABRICATED`；
  `G2-UNSOURCED-METRIC` 应显著减少（补不掉的要**在报告里逐条说明为什么补不掉**）
- 你的改动不得让 K1 结果变差（`verify_skill_code` 不该因你新增段落而失败）

> ⚠️ **不要用 `gate_check --all`**：全量要跑几分钟且会写 gates 目录。
> 单卡用 `--card`。另外门禁**不缓存**，改完必须重跑。

## 4. 常见坑（都是实测踩出来的）

1. **`> 原文:"..."` 的引号必须是直引号或 `""`/`「」`**，且 `>` 后面可以是 `原文：`。
   写 `> 原文: "..."`（冒号后多空格）也能匹配，但**不要**写成 `- 原文：...`（列表项不匹配）。
2. **引文里不要带 markdown 强调符**（`**`、`` ` ``）。规范化会剥掉，但表格行里的 `|` 会干扰。
3. **公式**：底本里是 `$...$` 形式。引用含公式的句子要小心，建议选不含公式的句子。
4. **数字格式差异**：底本写 `42.7%`，卡片写 `42.7 %` 会被规范化抹平；
   但底本写 `0.427` 而卡片写 `42.7%` **不会**被抹平 —— 这种请在报告里说明。
5. **`gate_check` 的 `--only G2` 不会跑 G1/G3**，所以不会覆盖 gates 目录里的全量报告。

## 5. 报告格式（你返回给我时必须严格按此结构）

```
## 交付卡
| 卡片 | 新增引文 | quote_check | G2 剩余红灯 | K1 |
|------|---------|-------------|------------|-----|
| <路径> | N 条 | ✅ VERBATIM | M 条（原因） | PASS/不变 |

## 未能补出处的断言（逐条列，必须诚实）
- <卡片>：`<token>` —— 原因：<论文里没有对应数字 / 论文口径不同 / 底本缺该表>

## 发现的既有断言问题（不改，只报告）
- <卡片>：卡片写「X」；论文实际写「Y」（出处 §N）
```

**最后一行必须写明**：`未 commit，未碰其他文件`（若确实如此）。
