# 生命周期分析 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，
> 并把规则落实成方案里的取值。§4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：产品生命周期阶段可用生长曲线 / 变点 / 生存分析识别，
> 并由此驱动清货时点。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度**＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月、
> 渠道构成 Amazon **65%** / 独立站 **15%**，其余 **20%** 未定名＝开放事实 O1）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）——**「季度经营策略」＝1 个自然季度计本档**；
> （材料未给季档）；替换条件 ＝ 〈平台后台〉库存账龄报表与〈独立站埋点〉销量序列逐期读满 2 个完整年度后，换成实测清货决策间隔的 P75，定为本档节拍；
> （c）§3 算式由命名数据系统直出。
> **卡上的案例数字不构成第四种来源**（逐条清单见 §1）。

## 1 方法来源（卡供方法）

- 方法族：**生命周期阶段识别与退出 / 清货时点**。族骨架四步：① 用销量、排名或搜索量的时序先剥离节假日脉冲与季节分量，只对趋势项取阶段判据；② 用趋势的斜率变化率与状态代理特征把序列切成「引入 → 成长 → 成熟 → 衰退」四段，并给出阶段置信度；③ 由衰退速度推出剩余有效生命期，与新品交付前置期比较后触发换代预警；④ 对有保质期的品类叠加批次效期分层、FIFO 执行率与库龄费用联动，把阶段标签落成清货、调拨、停止补货与减值预案。族内各卡的方法实现可互换，本契约取的是族骨架，不是某一张卡的实现。

## 3 标定规则

- 取值来源：平台后台（Amazon 卖家后台报表、库存台账、账号健康与政策通知）＋自有埋点（独立站埋点与 Case/Event Ledger）＋需授权（采购台账、财务系统对账表）；**不引用卡内任何案例数字**（清单见 §1）。
- **L1 阶段边界（本契约的取值出口）**：以平台后台的销量或 BSR（按 AGT-045 口径）作序列，先剥离节假日脉冲与季节分量，再对趋势项算斜率变化率：`k = (最近 3 个自然月趋势均值 − 前 3 个自然月趋势均值) ÷ 前 3 个自然月趋势均值`；`k > 成熟带上沿` 判成长、`|k| ≤ 成熟带` 判成熟、`k < 衰退线` 判衰退。
- 取值：阶段判定窗口 = **最近 3 个自然月对前 3 个自然月**；**成熟带 = |k| ≤ 5%（月度趋势变化率）**；**衰退线 = 月度趋势连续 2 个自然月下滑且累计降幅 ≥ 10%**；阶段置信度按趋势拟合的残差占比分档。这三个数系**业务侧默认**（经营者自述：「月度动 5% 以内算平，连续两个月掉一成算开始退」）。
- L1 替换条件：平台后台与独立站埋点跑满 2 个完整年度后，成熟带改用同品类近 2 个完整年度月度趋势变化率的 **P50**、衰退线改用该分布的 **P25**；替换前阶段标签一律标注「按本店口径估计」。
- **L2 有效生命期与换代预警**：`剩余有效生命期 = 当前趋势与衰退线的距离 ÷ 最近 3 个自然月的月均趋势降幅`；当 `剩余有效生命期 < 新品交付前置期` 时触发换代预警。
- 取值：**新品交付前置期 = 6 个自然月**（**业务侧默认**，来源＝经营者自述「打样到上架约 6 个月」）；**换代预警提前量 = 6 个自然月**（同上）；触发后动作只到「形成行动包条目」，不自动下单、不停产。
- L2 替换条件：采购台账接入并给出近 2 个完整年度实际前置期分布后，前置期改用该分布的 **P75**；替换前该值不得用于跨品类投产承诺。
- **L3 效期与 FIFO 联动（有保质期品类专用）**：按库存台账的批次到期日算 `临期批次 = 到期日距今 ≤ 剩余保质期 ÷ 3`；`FIFO 执行率 = 1 − 未按最早批次出库的发货单数 ÷ 当期发货单数`。
- 取值：**临期判定 = 剩余保质期 ≤ 1/3**（**行业惯例**：母婴食品类目的平台新鲜度门槛普遍落在剩余保质期的 **1/4–1/3** 区间）；**效期预警提前量 = 90 个自然日**（**业务侧默认**，来源＝经营者自述「提前三个月开始清」）；**清货触发线 = 临期批次货值 ≥ 该 SKU 当期库存货值的 10%**（**业务侧默认**）。
- L3 替换条件：平台后台的新鲜度政策原文与生效版本号到位后，临期判定改用该原文的剩余天数门槛（不再用比例口径）；采购台账与库存台账跑满 2 个完整年度后，清货触发线改用同品类实测临期库存货值占比的 **P75**；替换前清货结论只作建议、不进受控动作。
- **L4 库龄费用联动**：`费用率 = (仓储费 + 长库龄费 + 移除费) ÷ 该 ASIN 同期 GMV`，费用项逐条取平台后台账单（费率表版本随记录存档）。
- 取值：**费用率异常线 = 15%**（**业务侧默认**：经营者自述「仓储类费用吃掉一成半毛利就要处理」）；**长库龄观察线 = 180 个自然日**（**业务侧默认**，与 T+1 库存快照同口径）；两线同时命中才升级为「清货候选」。
- L4 替换条件：平台后台费率表与账单逐月接入满 1 个完整年度后，费用率异常线改用该 ASIN 所在品类实测费用率的 **P75**；替换前不得据其直接清货或移仓。
- **L5 季节性先验的缺口与处置（开放事实 O2）**：本业务**暂无已定名的品类 / 行业季节性先验来源**，而决策 Q11 给出的 **2 个完整年度**不足以稳健分离趋势与季节 —— 这正是 L1 阶段边界最容易被季节误伤的地方。
  处置：**先按**平台后台与独立站埋点近 2 个完整年度做**同比窗口对齐**（同一自然月对同一自然月）顶替季节分量，不引入任何外部季节参数；
  O2 定名（业务方给出品类或行业季节指数的取数来源）后**替换**为按该来源计算的季节指数；
  替换前阶段标签一律标注「季节分量按本店同比窗口估计、非品类先验」，且**不得**据本契约的阶段标签做跨品类季节对比或跨年清货承诺。
- **L6 产出（本规则定值的字段）**：以下标准产物里由本规则定值的字段如下。
- FLOW-01/STG-04 的〈经营证据与偏差诊断〉：阶段标签、阶段置信度与趋势项偏差由 L1、L5 定值。
- FLOW-01/STG-05 的〈联合经营行动包〉：调拨、停止补货与清货候选清单由 L1、L3、L4 定值。
- FLOW-01/STG-08 的〈经营关闭记录〉：阶段判定复核与清货结果由 L1、L4 定值。
- FLOW-03/STG-04 的〈供需证据与约束诊断〉：批次效期分布、FIFO 执行率与有效生命期由 L2、L3 定值。
- FLOW-03/STG-05 的〈供应计划与动作方案〉：清货时点、调拨方向与减值预案触发条件由 L2、L3、L4 定值。
- FLOW-03/STG-08 的〈供需关闭记录〉：清货与调拨的实测结果、剩余批次效期由 L3 定值。
- FLOW-07/STG-04 的〈事件范围与根因诊断〉：受影响批次与 SKU 的阶段标签、效期状态由 L1、L3 定值。
- FLOW-07/STG-05 的〈重大事件处置包〉：隔离与处置的批次范围、销毁或退回的候选集由 L3 定值。
- FLOW-07/STG-08 的〈重大事件关闭与全动作对账记录〉：批次处置的逐对象结果由 L3 定值。

## 4 重标定触发条件

- **口径变**：AGT-045 对销量、库存、批次、商品对象或 GMV 的分子分母与时间归属发布新版本；AGT-046 的质量状态、来源与新鲜度口径改版；阶段标签的枚举（引入 / 成长 / 成熟 / 衰退 / 数据不足）发生增删。
- **数据源变**：平台后台报表或库存台账字段改版；独立站埋点换版；Case/Event Ledger 首次上线或换版；采购台账与财务系统对账表的科目口径改版。
- **结构变**：新增渠道、站点、仓库或品类，使阶段判定与效期分层的对象集合变化；平台费率表结构变化（新增费用层级）；品类保质期结构变化（引入短效期或长效期品类）。
- **主体变**：开放事实 O1（Amazon 65% / 独立站 15% 之外的其余 20% 渠道构成未明）一旦定名，或新增渠道 / 店铺主体接入命名源 —— 适用渠道范围与阶段判定的分母随之重算。
- **周期到期**：每 2 个完整年度（决策 Q11 的历史长度）重算成熟带、衰退线、前置期分位、清货触发线与费用率异常线；每年首月按最新平台费率表版本重算 L4 的费用项。
- **告警触发**：L3 的清货触发线或 L4 的费用率异常线被连续 **2** 个自然月命中时，先回 STG-04 复核批次与费用口径；复核后仍命中才进入本节的结构变判定。

## 6 冻结与不许自动放行的情形

- 阶段判定缺项（趋势窗口、成熟带、衰退线、季节处置口径缺任一项），或时序长度不足而给出具体阶段标签 ⇒ 该结论不得进入 STG-07 受控动作，只能形成 NoActionRecord。
- 阶段标签为「衰退」而剩余有效生命期不可算（趋势降幅为零或样本不足）⇒ 不得据此启动停产或换代动作，只能出人工工单。
- 效期类动作（移除、销毁、召回、退回）缺批次级到期日证据，或台账新鲜度不满足 §2 ④ 的快照要求 ⇒ 相关批次的清货动作冻结，且不得判「无过期风险」。
- FIFO 执行率低于 **90%** 且临期品占比超过该 SKU 当期库存货值的 **10%** ⇒ 该 SKU 的补货与调拨动作冻结，回 STG-04 复核出库顺序后方可解冻。
- 费用率越过 L4 异常线但费率表版本与 AGT-045 口径不一致 ⇒ 清货与移仓类结论不得放行，只能写成待复核项。
- 清货候选同时命中「临期 + 高库龄 + 衰退」三者，而财务侧减值口径未由 AGT-041 出具 ⇒ 涉及减值与销毁的动作 HOLD，转人工裁决。
- 季节分量引用外部季节参数（开放事实 O2 尚未定名而其来源被自行指定）⇒ 该阶段结论不得放行；按 §3 的 L5 处置改为「本店同比窗口」口径重算。
- 引用 §1 清单中任一条卡面案例数字作为本业务取值（含斜率倍数、预警天数、临期占比、费率与金额）⇒ 该方案不得放行。
- 数据更新后原方案失效（新快照使原阶段标签或清货时点不再成立）⇒ 回 STG-04 重算，不得沿用旧取值；已成功动作不得随整单重跑。
- 本段落在规则格（STG-01 / STG-02 / STG-03 / STG-06 / STG-07）上的只是上列判据与门禁条件，不引入判别式或预测式。
