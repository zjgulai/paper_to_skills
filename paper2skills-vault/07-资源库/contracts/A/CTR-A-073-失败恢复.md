# 失败恢复 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，并把规则落实成方案里的取值。
> §4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**失败检测、幂等重放与回滚验证可规则化并自动执行。**
> 它的降级条件出自本项目综述 §F.5：**「若恢复动作须人工判断影响面，则降 B」**（**二手来源，不是材料原文**）—— 这句就是本契约的
> 自动／人工分界线：能自动走的是「幂等键可查、版本号可比对、动作在允许集内」的那一类；
> **影响面本身判断不了时，本责任不得代替人裁决**（见 §4 末条与 §6）。
>
> **本契约覆盖的格**：方法格为 FLOW-06/STG-04、FLOW-06/STG-05、FLOW-06/STG-08 与
> FLOW-08/STG-04、FLOW-08/STG-05、FLOW-08/STG-08（§3 的算式落在这些格上）；
> 规则格为两条 FLOW 的 STG-01（信号接收）、STG-02（范围确定与 Case 创建）、STG-03（上下文装配）、
> STG-06（Assurance 接收门禁）、STG-07（受控动作），**这些格只放判据与门禁条件**（§6 的落脚处）。
>
> **两条 FLOW 的分工**：FLOW-06 走「能力交付失败 → 恢复已知可用流程 → 交付结论」，落在〈数据/工具交付包〉与〈能力交付关闭记录〉；
> FLOW-08 走「能力退化或资源动作失败 → 回退版本 → 观察窗」，落在〈经营与能力变更建议〉与〈经营复盘关闭记录〉。
> 同一套幂等与回滚判据在两条 FLOW 上共用，**不各写一套**。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境与材料已给出的数（出海历史 2 个完整年度＝决策 Q11；经营节奏「月度经营复盘」＝1 个自然月；本项目综述 §E.2 的 Case 状态机与 §E.3 的异常与恢复条件表（**§E 的编号与状态名出自本项目综述，不是材料原文**）；PB-006 的「新工具失败时恢复已知可用流程并保留影响范围，不重写原始事实凑齐报表」；PB-008 的「能力新版本失败时回退版本并保留业务效果记录」）；
> （b）业务侧默认（材料已定名的门禁口径或行业惯例，逐条附替换条件）；
> （c）§3 算式的输出（由命名的数据系统直出）。**候选卡的卡面数字与论文参数不构成第四种来源**（逐条清单见 §1）。

## 1 方法来源（卡供方法）

- 方法族：**失败检测 → 幂等重放准入 → 回滚验证 → 恢复门禁与观察窗 → 失败边界保留**（把每一次执行尝试与它的外部状态登记清楚 → 只对幂等且可比对版本的尝试重放 → 回滚到已知可用版本并用双证据验证 → 过门禁后才算恢复 → 失败影响范围如实保留、不改写原始事实）。族内各卡的方法实现可互换，本契约取的是族骨架，不是某一张卡的实现。
- 代表卡（三张，取自本责任候选清单）：
  - `p2s-mas-orchestrator`（源卡号 `Skill-MAS-Orchestrator`，源域 10-MAS，图谱 L3 = 依赖协调 / 失败恢复）：承担「按 DAG 定序与并发调度 → 对超时与失败节点按策略重试或降级 → 汇总状态与进度」这条编排骨架，并明确「承载的是规则与契约产物，不是执行器」。

## 3 标定规则

- 取值来源：自有埋点（〈Case/Event Ledger〉的 Execution Attempt、Stage Acceptance Record、NoActionRecord 与 `REC-CASE-EXCEPTION`；〈运行状态与恢复证据〉）＋ 平台后台（外部动作的响应与权威回执页）＋ AGT-045 指标契约与主数据；**不引用卡内任何论文参数**（清单见 §1）。
- **T1 失败检测与失败登记**：`失败尝试数 = count(state ∈ {BLOCKED} ∨ 提供方请求引用为空 ∨ Stage Acceptance 处置 ∈ {RETURN, WAIT, FREEZE})`；`失败登记比 = REC-CASE-EXCEPTION 条数 ÷ 失败尝试数`（本项目综述 §E.3 记有：每次等待／返工／冻结都必须形成 `REC-CASE-EXCEPTION`；**§E.3 是本项目综述的编号，不是材料章节号**）。
- 取值：**失败登记比门禁取 1:1**，即一个失败尝试对应 **1** 条且仅 **1** 条异常记录；漏登 **1** 条即该批运行状态不得用于恢复判定。替换条件：〈运行状态与恢复证据〉覆盖满 **2** 个完整年度后改用**实测**漏登数逐月核对；替换前结论只能表述为「**未检出**漏登」。
- **T2 幂等重放的准入判据**：`可自动重放 = 幂等键非空 ∧ 对象版本号可比对 ∧ 该动作 ∈ STG-07 允许动作集 ∧ 已按幂等键查得外部终态`（四项同时成立才准入，缺一即转人工）。
- 取值：**同一 `idempotency_key` 的自动重放上限取 1 次**；第二次仍失败就置 FROZEN 并转人工，不得由本层自行加大轮次。依据＝本项目综述 §E.3 的 `query_external_state_by_idempotency_key_before_retry_compensation_or_close`（**该标识符与 §E.3 编号均出自本项目综述，不是材料原文**）与跨手册通用的工单规则「已成功动作不得随整单重跑」。**替换条件**：〈Execution Attempt〉与权威回执覆盖满 **2** 个完整年度后，按实测的重放成功率与二次失败率重定档；替换前重放只许在幂等、可比对版本、且在允许动作集内的尝试上进行。
- **T3 回滚验证判据**：`回滚验证通过 = 对象版本号已回到已知可用版本 ∧ 回滚动作的提供方请求引用齐备 ∧ 回滚后未新增对外承诺`（双证据：**版本号回退事实 ＋ 回滚动作回执**）。
- 取值：回滚验证取**二值**（通过／未通过），**不设部分通过档**；**回滚后未取得回执的对象数门禁取 0 个**，出现 1 个即判「回滚未验证」。替换条件：回滚回执逐对象落库并覆盖满一个完整审计周期后，改用实测回执覆盖率重算；替换前未验证的回滚一律不许作为关闭依据。
- **T4 恢复门禁与观察窗**：`任务成功率 = 成功尝试数 ÷ 尝试总数`（分母口径由 AGT-045 签发）；`同类失败复发数 = 观察窗内同 case_id × 同动作类型 × 同失败码 的失败次数`。
- 取值：恢复门禁取**三点同时成立** —— ① 任务成功率不低于失败前同口径基线（**容差档取 0**，不设放宽档）② 外部状态未决数 ＝ **0 个** ③ 观察窗内同类失败复发数 ＝ **0 次**。**观察窗**取该 Case 的〈能力交付Case Charter〉／〈经营复盘Case Charter〉已写明的观察窗；**两处都未写明时取 1 个自然月**（对齐材料经营节奏「月度经营复盘」＝1 个自然月）。替换条件：〈运行状态与恢复证据〉覆盖满 **2** 个完整年度后，用实测的成功率波动带定容差档、用实测复发间隔定观察窗；替换前恢复结论只能写「观察窗内未复发」，不得写「故障已根除」。
- **T5 失败边界与影响面保留**：`失败影响面 = 失败发生时点起、该 Case 内未闭合的对象集合`（按对象 ID 逐个列出，含未回填的动作尝试）。
- 取值：**失败影响面逐对象列出、条数不设上限、不截断**；**原始事实改写数门禁取 0 条** —— 依据＝PB-006 原文「新工具失败时恢复已知可用流程并保留影响范围，**不重写原始事实凑齐报表**」与 PB-008 的「能力新版本失败时回退版本并保留业务效果记录」。
- 产出（本规则定值的字段）：FLOW-06/STG-04 的〈能力缺口诊断〉的现有系统与复用可能段、失败边界段；FLOW-06/STG-05 的〈数据/工具交付包〉的运行恢复设计与失败边界条目；FLOW-06/STG-08 的〈能力交付关闭记录〉的运行结果段与失败影响面清单；FLOW-08/STG-05 的〈经营与能力变更建议〉的回退条件段；FLOW-08/STG-08 的〈经营复盘关闭记录〉的观察窗与回退证据段。

## 4 重标定触发条件

- **口径变**：AGT-045 对 Case 状态机、Stage Acceptance 处置或恢复计时口径发布新版本；AGT-046 的质量状态、来源、新鲜度口径改版；本责任对「任务成功率」的分母定义改版。
- **数据源变**：〈Case/Event Ledger〉首次上线或换版；某个外部接口的幂等语义声明首次取得或变更；外部回执字段（幂等键回显、重复请求拒绝码）新增或改名。
- **结构变**：CASE-PROTOCOL-8 的阶段推进条件或 STG-07 允许动作集变化；Role Release Bundle 生命周期（含 `QUARANTINED` 处置）变化；编排层由单 Agent 扩为多 Agent 并发写入（需要确定性的冲突消解语义）。
- **主体变**：开放事实 O1（Amazon 65% 与独立站 15% 之外的其余 20% 渠道构成未明）一旦定名，或新增渠道、店铺、账号主体 —— 纳入自动重放集合的接口与对象集合随之重算。
- **周期到期**：每 2 个完整年度（决策 Q11 的历史长度）重算重放成功率、二次失败率与观察窗复发间隔基线，并按 T4 决定容差档是否需要调整。

## 6 冻结与不许自动放行的情形

- 命中 `EXECUTION_ATTEMPT_STATE_UNKNOWN`（执行结果或外部状态未知）⇒ 立即置 FROZEN；恢复的唯一入口是按 `idempotency_key` 查得权威外部状态，查得之前既不许重放、也不许补偿、更不许关闭。
- 钉住的 Role Release Bundle 进入 `QUARANTINED` ⇒ 置 FROZEN，不得对同一对象发起新动作，只能走受控的 Bundle 迁移或另建 Case。
- 同一 `idempotency_key` 已重放过 1 次仍失败 ⇒ 不得由本层自动重放第二次，转人工裁决；两次之间不得更换幂等键重试同一动作。
- 对方系统的幂等语义尚未取得，而拟恢复的动作涉及资金、库存或对外承诺 ⇒ 该动作不得自动重放，只能出 NoActionRecord ＋ 人工工单。
- **恢复动作的影响面无法由本责任算出**（影响面仍为声明式清单、或闭包不唯一）⇒ 命中 §F.5 的降级条件，本次恢复不得自动执行，须转人工裁决影响面后再走受控动作。
- 回滚后未取得回执的对象数 > 0 个，或对象版本号无法指出回到了哪一个已知可用版本 ⇒ 判「回滚未验证」，不得关闭，也不得据此重放。
- 同类失败复发数 > 0 次，或观察窗未满 ⇒ 恢复结论只能写「观察窗内未复发」，不得进入 STG-07 宣布恢复、不得关闭 STG-08。
- 失败影响面被截断、原始事实改写数 > 0 条（含为凑齐报表回填非事实值）⇒ 立即冻结该 Case 的交付结论并登记自治异常。
- 已成功动作随整单重跑，或同一对象在当周内已有一次未回填的动作 ⇒ 不得对同一对象发起新动作。
- 引用 §1 清单中任一条卡面数字（阈值、退避序列、冷却时长、重放轮次、行数与金额）作为本业务取值 ⇒ 该方案不得放行。
