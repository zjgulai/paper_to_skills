## 3 标定规则

- 取值来源：〈平台后台〉的全量订单 / 批次 / 商品档案 +〈自有埋点〉的独立站订单与曝光记录 +〈标签分配结果表〉（仅偏见审计一类任务用），窗口 = 近 2 个完整年度。**本段不出现任何论文参数**：卡内 14 项数值见 §1 清单，全部不参与以下算式。
- 算式 / 规则（全部写成对上述源的可判定式，无一处凭空取值）：

**（A）风险得分 —— 谁进高抽检层**

```
risk_score(对象) = w1·r1 + w2·r2 + w3·r3
  r1 = 受害面（本次事件 / 复盘范围内）        r2 = 例外密度（本观察窗）        r3 = 缺陷率（上一观察窗）
  r1,r2,r3 先按本次观察窗全层取值做 min-max 归一（消除三者量纲差异，再线性加权）
w1,w2,w3 = 业务规则字典中「抽样审计」条目的风险权重档，按本次观察窗绑定版本号
```

  三项的定义式：`受害面 = 事件范围内该风险组的对象数 ÷ 同层对象总数`（FLOW-07 侧，对应「受影响批次/商品/账号、库存和客户范围」）；`例外密度 = 该风险组偏差绝对额 ÷ 该风险组经营规模`（FLOW-08 侧，对应「全成本、自治异常」）；`缺陷率 = 上一观察窗该风险组被判超容差的对象数 ÷ 该风险组被抽检对象数`（取自有埋点 / 平台后台的历史抽检记录）。**权重必须来自业务规则字典并带版本号** —— 无字典权重时允许唯一的无权重回退：归一后三项等权（各 1/3），这只是把「没有依据的加权」换成「可复核的等权」，不是默认值；min-max 归一由本次观察窗的实测取值算出，不引入外部常数。

**（B）逐层样本量 —— 抽多少**

```
准入条件：单层抽检单元数 n_h ≥ n_h*，使该层「观测分配率或缺陷率差异超出容差」这一判定
          在 95% 置信水平（双侧正态分位，即 α=0.05 的置信区间）下可判定；合并比例未知时按最保守的 p=0.5 代入
n_h* = ceil( (z_(1−α/2)² · p(1−p)) / e_h² )，取 p = 0.5、α = 0.05
e_h  = 该层容差（见 C）
⚠️ 此处的 α=0.05 是**置信区间的覆盖口径**，与卡内的显著性阈值 p<0.05（§1 清单第 3 条）不是同一件事：
   本契约不设「显著性检验」门槛，只设「差值的置信区间是否排除容差」这一个判据。
```

**（C）容差 —— 什么算超**

```
容差档 = 业务规则字典中「该标签 / 该风险组」的容差档（取本次观察窗绑定版本）；
业务规则字典**无该条目时按零容差**处理 ⇒ 观测差异超出「合并比例 95% 置信区间边界」即判超容差。
分级不引用任何固定小数：超容差记 1 级缺陷，超容差且该层 n_h < n_h* 记 2 级缺陷（须全查该层）。
```

**（D）层内样本不足时怎么办（决定性，不留白）**

```
若某层 n_h < n_h* ⇒ 不得以抽样结论替代该层结论：该层改为全查（抽检概率 = 1），
并把「全查」写入 ART-EVIDENCE-PACK 的该层记录；全查后仍超容差 ⇒ 转隔离与整改建议（§6 第 2 条）。
```

**（E）分层分配 —— 抽哪些**

```
逐层抽检数按 risk_score 成比例分配（PPS），每层至少 1 个单元；
同层内按对象 ID 升序做等距系统抽样（可复算，禁止人工挑样）。
本业务暂无「审计容量台账」，故不设容量上限约束 —— 分配结果由 (B) 的 n_h* 唯一决定。
```

**（F）偏见审计这一类专门任务怎么接（卡的方法在这里换装）**

```
本类任务适用的方法族卡：p2s-tag-fairness-bias-audit（代表卡）、p2s-ai-algorithmic-bias-audit、
  p2s-ai-ethics-fairness-audit、p2s-algorithmic-accountability-audit —— 换卡只换 (F) 内的实现，
  (A)~(E) 与 §4、§6 不变（见 §1 的族级约定）。
审计对象 = 标签分配结果表或推荐曝光分配记录时：
  分组维度  = 业务规则字典指定的敏感/业务相关属性（不默认「性别」）
  统计量    = 各分组分配率的极差 max_gap
  判偏边界  = (C)：有容差档照该档；无该档则零容差，即 max_gap 超出比例差 95% 置信区间边界才判偏
  修正建议  = 只是 ART-DIAGNOSIS-RECORD 里的一条 findings，不得直接改线上标签或曝光分配；
              要改必须走 STG-05 → STG-06 → STG-07 受控动作
卡内 78% / 35% / p<0.05 / 0.1 / 0.2 一律不进入本算式。
```

**（G）违规概率排序这一类专门任务怎么接（同族另一张卡换装，示范「换卡不重写契约」）**

```
本类任务适用的方法族卡：p2s-compliance-ml-risk-scoring（与本责任同映射 L3 DOM-01-122）、
  p2s-account-fingerprint-risk-scorer、p2s-category-compliance-prescan 等同族选样卡。
审计对象 = 商品 / Listing / 账号等全量对象时：
  实现替换  = (A) 的 r1/r2/r3 三项仍按原定义式取数（受害面 / 例外密度 / 缺陷率），
              仅把「风险得分」的实现由分组比例差换成该卡的违规概率排序 —— 层的定义不变；
  样本量    = 仍由 (B) 定，不采用卡内的审查批量或优先级档；
  判定      = 仍由 (C) 的容差档判，不采用卡内的概率阈值；
  输出用途  = 只排 STG-04 的抽检优先序与 STG-06 的复核输入，不得据分数自动下架商品或对外认定违规
              （接收该卡的安全边界；见 §6 第 8 条）
本类任务同样不启用卡内效果数字：3–5 倍、30–120 万元、35 个 SKU/月 见 §1 清单第 15–17 条。
```

## 4 重标定触发条件

- **① 口径变**：审计对象口径变（新增渠道 — 尤其开放事实 O1 里那 20% 未明渠道一旦明示；或新增一类抽样对象，如把标签分配结果表并入常规抽样框）⇒ 按新口径重新绑定业务规则字典版本，重算 §3 (A) 的 `受害面` 与 `例外密度`。
- **② 数据源变**：抽样框的获取路径变（平台后台接口换版、独立站埋点重布、动作回执改由授权通道读取）⇒ 重算 §3 (B) 的 `e_h` 与 (E) 的系统抽样间隔。

## 6 冻结与不许自动放行的情形

> 本段承接 `rule_cells` 的 10 个 R/D 格：**这些格只放判据与契约，不放算法模型**（风险 N4：D/R 格出现算法模型即判错）。下段引语取自 `TEMPLATE-A-标定契约.md` 第 6 段，其余每条都可判定为「缺什么证据 / 超什么时限 / 命中什么规则」。

- **1（缺证据 · 判据）**：抽样计划未版本化 —— `ART-EVIDENCE-PACK` 里没有「分层定义 + 逐层 n_h + 每层总体数与抽样概率 + 绑定的规则字典版本号」四项齐备的记录时，`FLOW-07/STG-06` 与 `FLOW-08/STG-06` 的 Assurance Decision **不得**返回 `ASSURANCE_PASSED`，挂 `WAIT:ASSURANCE_DEPENDENCY_PENDING`。
- **2（缺证据 · 判据）**：某层 `n_h < n_h*`（§3 (B)）而结论仍按抽样出 —— 该层不得自动进入 STG-07 受控动作：要么补抽到 `n_h*`，要么按 §3 (D) 全查该层；**全查后仍超容差则转隔离与整改建议**。本业务暂无审计容量台账，故**不得**以「容量不够」为由降 `n_h*` 或改写结论。
- **3（缺证据 / 外部状态 · 判据）**：`FLOW-07/STG-08` 的对账未完成 —— 存在「逐对象权威回执」缺失，或回执与外部权威状态不一致的动作对象时，按该格既定异常处置：`FREEZE:EXTERNAL_RESULT_UNRESOLVED`，先按 `case_dedupe_key` 查外部状态再做补偿或关闭，**不得**用抽样结论替代逐对象对账。动作回执级的取数口径未定名（§2 ⑤）在本条命中时，缺口如实登记、不改判据。
- **4（命中规则 · 时限）**：同一对象在同一观察窗内出现 ≥2 个口径版本时，按 `FLOW-08/STG-06` 的 `FREEZE:ASSURANCE_INTEGRITY_OR_SCOPE_INCIDENT` 冻结；并按材料既定处置**保留「无法比较」的结论**（PB-008 原话：数据口径未统一时保留无法比较的结论），不得为凑结论事后重写事实。
- **5（命中规则 · 关联关系）**：与本次独立复核对同一汇报线或存在关联关系时，`FLOW-08/STG-06` 的独立审计项判不通过（该格已定名的检查项之一），结果**不得**由本岗位出具，须按回避另指签署方 —— 依据：本责任在 PLN-CTL 独立控制平面，第 3 段独立性判据要求抽样执行与结论签署同属 AGT-005。
- **6（超时限 · 判据）**：§4 的重标定触发条件任一已命中而新版抽样计划尚未写入时，旧版计划不得继续用于 STG-06 接收 —— 否则命中该格的 `FREEZE:ASSURANCE_INTEGRITY_OR_SCOPE_INCIDENT`。
- **7（命中规则 · 不许自动放行）**：涉及标签分配或曝光分配的偏见审计 —— 修正方案必须附「修正前后标签准确率对账」，缺该对账记录的方案不得上线（本契约接收 §1 代表卡的边界声明：过度纠正导致标签准确率明显下降的方案不得上线）；且该项涉及线上标签系统或推荐分配，只能走 `FLOW-07/STG-07` 受控动作，**不得**由本岗位或本契约的任何算式自动执行。
- **8（命中规则 · 换卡后依然生效）**：同族卡凡自带「结果不得直接作用于业务对象」类边界的（如 §1 引的 `p2s-compliance-ml-risk-scoring`「评分只用于排定人工审查优先级，不得据分数自动下架商品或对外认定违规」），其**输出一律只作 STG-04 的抽样与排序依据、STG-06 的复核输入**；评分或抽样结论本身不得构成 STG-07 的动作意图。**本条不随 `cards` 换卡而失效** —— 换卡只换方法实现，不换本责任只出结论、不出线上动作的平面归属（PLN-CTL）。
