# 数据质量 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，并把规则落实成方案里的取值。
> §4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**数据质量规则、分布漂移与缺失检测是标准数据质量统计方法**。
> 岗位 AGT-046 清源 · 数据工程与质量（DOM-08 / PLN-PLT），适用 FLOW-06 需求到数据产品与业务工具（PB-006），场景 SCN-020。
> 本责任的产物是**带质量状态的数据产物**，考核口径是**新鲜度、完整性与故障恢复**。
>
> **⚠️ 本责任是别的契约「质量状态 / 来源 / 新鲜度」三件套的供值方。** 其他责任在其数据要求里只写一句
> 「记录随带 AGT-046 的质量状态、来源与新鲜度」，**不在自己的契约里另算一套质量分**；
> 这三个字段的定义与取值域由 AGT-045 指标契约与主数据签发（见 §3 T5），值由本责任产出。
>
> **本契约覆盖的格**：方法格 FLOW-06/STG-04（证据收集与诊断）、FLOW-06/STG-05（方案与标准产物）、
> FLOW-06/STG-08（结果核验、关闭与异步学习）—— §3 的 T1–T5 落在这些格；
> 规则格 FLOW-06/STG-01（信号接收）、FLOW-06/STG-02（范围确定与 Case 创建）、FLOW-06/STG-03（上下文装配）、
> FLOW-06/STG-06（Assurance 接收门禁）、FLOW-06/STG-07（受控动作）**只放判据与门禁条件**（§6 的落脚处）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个档位、倍数、时限与门槛，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；渠道四选一＝决策 Q9；经营节奏「月度经营复盘」＝1 个自然月）；
> （b）业务侧默认（经营者自述或工程惯例，逐条附替换条件）；（c）§3 算式的输出（由 §2 命名的数据系统直出）。
> **候选卡的论文实验参数与卡面案例数字不构成第四种来源**（逐条清单见 §1）。

## 3 标定规则

- 取值来源：平台后台（采集批次时间戳与报表数据日期）＋ 自有埋点（Case/Event Ledger 的 Stage Acceptance Record 与 Execution Attempt 时间戳）＋ 需授权（库存台账、财务对账表）＋ AGT-045 指标契约（字段定义与版本号）；**不引用卡内任何论文参数**（清单见 §1）。
- **T1 延迟与缺失判定**：`延迟 = 取数时刻 − 该源该表最后一次成功采集的 collected_at`；`缺失率 = 当期未产生记录的期望批次 ÷ 当期期望批次数`。
- 取值：告警档取 **2 档**（提醒档、冻结档），档位**不是分钟常数**而是该源期望批间隔的倍数 —— 提醒档 = 期望批间隔 × **2**，冻结档 = 期望批间隔 × **6**；该倍数系**业务侧默认**（经营者自述：两个批次没到要问、六个批次没到当停）。替换条件：本责任的采集日程台账跑满 2 个完整年度后，改用该源延迟分布的 **P95** 作提醒档、**P99** 作冻结档；替换前倍数档只用于告警与登记缺口，不用于冻结自动动作。
- **T2 分布漂移判定**：`漂移量 = KL(当期分布 ‖ 参考分布)`（分箱由该字段自身取值域定，等频分箱）；`PSI = Σ(实际占比 − 期望占比) × ln(实际占比 ÷ 期望占比)` 作为同一事实的第二种量法，两法结果不一致时**取更保守的那一档**。
- 取值：分档取 **3 档**（稳定 / 轻微漂移 / 严重漂移），边界取**该源自身漂移量的历史分位**而不是通用常数 —— 轻微档 = 超过参考窗口内该量的 **P95**，严重档 = 超过 **P99**；参考窗口取近 **2 个完整年度**内的同季节同月（决策 Q11）。替换条件：AGT-045 签发字段级漂移容差档后整档替换；替换前严重档只触发人工确认，不触发自动降级。
- **T3 质量分与门控（字段级 → 行级 → 表级）**：`字段质量分 = 通过规则的规则数 ÷ 参与评估的规则数`；`行级质量分 = 通过规则的字段数 ÷ 参与评估的字段数`；`表级完整率 = 通过行数 ÷ 总行数`。
- 取值：三层分都落在 **0 到 1**；**门控取二元规则「必需字段有任一未通过 ⇒ 阻断该行」**（不设自由阈值，因此不设容差档）；下发下游（属性图谱、经营报表、渠道模板）的门槛取 **1.0**（必需字段全通过）。替换条件：AGT-045 按对象类型签发必需字段清单与质量门槛后整档替换；替换前 < **1.0** 的记录一律标「未发布」，并在 FLOW-06/STG-04 的〈能力缺口诊断〉逐条登记为缺口项。
- **T4 分级告警与降级（本责任对模型侧的唯一放行口）**：`告警等级 = max(延迟档, 缺失档, 漂移档)`；降级动作 = 该源改用**上一次通过门控的完整快照**，并在记录上改写 `quality_status = degraded`、`freshness = 上次快照时点`。
- 取值：降级只允许到 **1 个**档位（上一次完整快照）；**不允许**把缺失值当零（含库存为 0、ROAS 为 0、销量为 0），**不允许**用外推或插值补全后再判定。恢复条件取**连续 2 个批次**通过门控（业务侧默认：经营者自述「一个批次可能还在抖」）。替换条件：采集日程台账跑满 2 个完整年度后，改用该源「故障后恢复所需批次数」的 **P95** 向上取整；替换前不得据单批恢复放行。
- **T5 三件套随带与产出定义（本责任的核心产出，别的契约的「质量状态 / 来源 / 新鲜度」引用此处）**：
- 三件套字段：`source_system`（来源）、`collected_at`（采集时点，供新鲜度）、`quality_status`（通过 / 阻断 / degraded）、`freshness`（上次完整快照时点）；字段名与取值域以 AGT-045 签发的 `指标契约` 为准，本责任只供值。
- 产出：以下标准产物里由本规则定值的字段 —— FLOW-06/STG-04 的〈能力缺口诊断〉的数据质量与缺口段；FLOW-06/STG-05 的〈数据/工具交付包〉里数据契约的质量门槛、降级规则与三件套字段定义；FLOW-06/STG-08 的〈能力交付关闭记录〉的质量验收结论（含未闭合的降级项）。
- 取值：三件套随带率取 **1.0（100%）** —— 缺任一项的记录不得进入下游、也不得作为 STG-08 关闭依据。替换条件：下游若只支持部分字段（如某报表无法展示 `freshness`），先在报表页脚集中列出并标「随带不全」，该报表接入三件套展示后替换；替换前该报表不得作为关闭依据。

## 4 重标定触发条件

- **口径变**：AGT-045 签发或改版 `指标契约`（必需字段清单、质量状态取值域、统计窗与时间归属）；本责任的采集日程或时区归一规则变化。
- **数据源变**：新增数据源或渠道接入（决策 Q9 渠道四选一之外的主体接入）；某源更换取数方式（批量 → 流式）使期望批间隔与延迟口径变化；平台报表版本变更使字段集合变化。
- **结构变**：分箱规则或参考窗口定义随对象类型变化（新增品类、新增字段族）；门控的必需字段清单按品类调整；告警档由倍数制改为分位制。
- **主体变**：开放事实 O1（Amazon 65% / 独立站 15% 之外的其余 20% 渠道构成未明）一旦定名 ⇒ 源清单、期望批次节律与参考分布随之重算。
- **周期到期**：每 2 个完整年度（决策 Q11）重算控制限、漂移分档边界与恢复批次数基线；每自然月按「月度经营复盘」节奏出一次质量状态汇总与降级清单。

## 6 冻结与不许自动放行的情形

- 必需字段未全通过（行级阻断）的记录 ⇒ 不得下发属性图谱、经营报表与渠道模板，不得进入 FLOW-06/STG-07 受控动作。
- 冻结档告警在 **2 个批次**内未恢复，而拟动作依赖该源 ⇒ 该对象一律出 NoActionRecord；人工动作不受限。
- 记录缺 `source_system` / `collected_at` / `quality_status` / `freshness` 任一项 ⇒ 该记录不得进入下游，也不得作为 FLOW-06/STG-08 关闭依据。
- 以 §1 清单里任一卡面数字（含 90 分钟 / 3 小时 / 0.3 / 0.6 / 0.1 / 0.25 / 0.724）充作本业务阈值 ⇒ 该方案不得放行。
- 数据空洞或降级期间按缺失值（如库存为 0、ROAS 为 0）继续决策 ⇒ 立即冻结该对象的自动动作并转人工。
- `指标契约` 未签发期间把跨源质量分用于经营验收、绩效核算或对外披露 ⇒ 该结论无效，相关 Case 的 FLOW-06 Assurance Decision 判 HOLD。
- 记录随带的质量状态版本号与 AGT-045 当前生效版本不一致 ⇒ 不得关闭 Case，先按版本号重算再核验。
- 同一对象在当周内已有一次未回填的质量处置（降级或恢复）⇒ 不得对该对象发起新动作；已成功动作不得随整单重跑。
- 把阻断行改标通过、或把 degraded 改标通过以凑齐报表 ⇒ 立即冻结该源的下发，并按缺口登记上报。
- 数据质量异常同时命中 FLOW-07 的质量或账号事件口径（明确质量异常、严重客诉或账号重大风险）⇒ 移交 FLOW-07 紧急保护通道（Emergency Guard），本格不得自行处置。
- 采集侧命中平台限流（429）或接口配额耗尽而未重试成功 ⇒ 该源的延迟与漂移判定转 WAIT，不得据未重试成功的数据出质量结论。
- 本段落在规则格（FLOW-06/STG-01、FLOW-06/STG-02、FLOW-06/STG-03、FLOW-06/STG-06、FLOW-06/STG-07）上的只是上列判据与门禁条件，不引入判别式或预测式。
