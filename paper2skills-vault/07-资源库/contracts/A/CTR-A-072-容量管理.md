## 3 标定规则

**容量口径（并发／吞吐／排队）**

- 取值来源：① 平台后台的本平台运行记录（任务与工具调用的时间戳、失败与重跑标记），每条记录带 AGT-046 清源的质量状态、来源与新鲜度；② 结构约束取材料已核实的两条平台事实 —— 消息只走直接父子、无持久父邮箱、不保证恰好一次投递；workflow 不设检查点、不支持重启续跑。
- 算式：
  1. 并发占用 `a(t)` = 同一时刻处于运行态的任务数（按主岗位／Role Release Bundle 分组统计）；
  2. 有效占用 = 任务数 ×（1 + 重跑率），其中重跑率 = 平台记录里被判需整段重跑的失败次数 ÷ 总任务数 —— 本平台无检查点，重跑是材料已核实的恢复方式，它直接吃掉容量；
  3. 到达率 `λ` 与平均服务时长 `W` 按同一观察窗内的任务开始／结束时间戳算，利用率 `ρ = λ·W ÷ a(t)` 取观察窗峰值；排队时长 = 任务入队到首次工具调用返回之间的间隔；
  4. **容量警戒线 `ρ*` = 平台记录中最近一次「资源争用」类冻结发生前一个观察窗的 `ρ` 实测值** —— 「资源争用」是材料对 Case 状态 Frozen 的定名原因之一，每次冻结都形成 REC-CASE-EXCEPTION；观测到 `ρ ≥ ρ*` 即判容量紧张；
  5. 上限来源：`a` 的物理上限取服务方账户的速率／并发限额（第三方 API 账户页），**不是任何卡里的数字**。
- 产出：FLOW-06/STG-04 的「能力缺口诊断」中运行侧那部分缺口（并发占用、排队时长、重跑率、限流失败）由本口径定值；FLOW-06/STG-05 的「数据/工具交付包」里工具的能力边界（配额、优先级、失败边界）由本口径定值。

**成本口径（单位任务成本／预算约束）**

- 取值来源：① 第三方 API 的服务方用量账单（账户／项目级金额）；② AGT-041 守金的经营预算与现金约束方案（额度）；③ AGT-040 清账的收入与费用核对（会计口径与对账差异）；分母用的「一次任务」口径由 AGT-045 指标契约给出。
- 算式：
  1. 单位任务成本 `c` = 同一观察窗内服务方账单金额 ÷ 同窗内本平台完成的任务数；
  2. 预算占比 = 该观察窗内实际费用 ÷ AGT-041 方案里已核定的该项额度；占比 ≥ 1 时，成本结论只能出诊断并转 AGT-041／AGT-001 裁决，不得自动进入受控动作；
  3. 可缓存比例 = 平台记录里「同一工具 ＋ 同一业务对象 ＋ 同一参数指纹」在观察窗内重复出现的调用数 ÷ 总调用数（不是卡里的 45%）；重复调用只能复用**该对象新鲜度窗口内**的结果，缓存条的过期时刻 = 该对象新鲜度要求窗口的到期时刻（TTL 由 AGT-046 的口径给出，不是卡里的 24 小时）；
  4. 降级候选比例 = 平台记录里落在 STG-01／STG-02／STG-03／STG-06／STG-07 这些格上的调用占比 —— 协议已定：这些格不消耗检索预算或只做有界分类，只有 STG-04／STG-05／STG-08 由模型作主引擎（不是卡里的 60%）；
  5. 按 Agent／岗位分摊的单位成本：**本业务暂无此数据** —— 材料 G.2 把「跨 Agent token 核算」明确记为未核实。故本责任不产出按岗位分摊的成本，也不据它分配预算；该缺口由 AGT-045 指标契约补上「任务 ↔ 岗位」映射后关闭，关闭前第 1 条的 `c` 只在账户级成立。
- 产出：FLOW-08/STG-04 的「经营与能力诊断」里 AI 运行成本与单位任务成本由本口径定值；FLOW-08/STG-05 的「经营与能力变更建议」里资源调整与停止事项只能引用本口径算出的 `ρ`、`c` 与预算占比，**不得引用同族卡里的任何区间**。

`ρ*`、`c`、预算占比三个量都必须先由 AGT-045 的指标契约定名口径（见第 2 段 ⑤），否则按第 6 段第 2 条冻结。

## 4 重标定触发条件

- **口径变**：AGT-045 的指标契约对「一次任务」「并发上限」「单位任务成本」的定义被修订；或 AGT-046 的新鲜度口径被修订（缓存条的过期时刻随之一并重算）。
- **数据源变**：服务方更换，或计费口径变更（缓存计价／峰谷价／阶梯价）使账单与任务数不再可比；或平台记录保留策略变更导致回溯深度变短、出现无法回溯的断档。
- **结构变**：材料已核实的平台事实发生变化 —— 消息语义（直接父子／持久父邮箱／恰好一次投递）、workflow 的检查点与续跑能力、并发与条目限制，任一变动即重标；同族卡的挂载面变动（换卡）时，须复核第 3 段的算式是否仍成立。
- **周期到期**：成本侧随服务方账单月结、与 AGT-040 的收入与费用核对同窗重算一次；容量侧随 FLOW-08 Case Charter 里定义的观察窗重算一次。观察窗不足一个完整账单月时，不得出月度成本结论。

## 6 冻结与不许自动放行的情形

- 记录超窗，或缺少 AGT-046 的「质量状态、来源、新鲜度」三件套 ⇒ 容量与成本结论不成立，Case 记 Rework Required，不得进入下一阶段。
- `ρ`、`c`、预算占比在 AGT-045 指标契约里尚无定名口径 ⇒ 不得作为受控动作依据；STG-07 只允许提交 Action Intent。
- 结论落在材料自己标注为**未核实**的声明上（G.2：「50 角色 × 1000 店铺容量」未核实，核实日期 2026-09-11）⇒ 该量级只能写进诊断的假设栏，不得进入容量结论与变更建议。
- `a(t)` 与重跑率无法由平台记录复算（记录断档，或平台记录里没有失败／重跑标记）⇒ 不出容量结论，转 AGT-047 接桥补可观测性后再出。
- 该账单月尚未与 AGT-040 清账的收入与费用核对对齐（差异未解释）⇒ 该月账单不得用于算单位任务成本。
- AGT-041 的经营预算与现金约束方案里没有这一项额度 ⇒ 成本结论只能出诊断，改动预算的受控动作一律转 AGT-041 立项，本责任不得自行给额度。
- 缓存或降级方案未经 STG-06 Assurance 接收门禁，且未经 AGT-048 的能力版本评估与 A/B 质量对照 ⇒ 不得上线；卡本身也只产出规则与预算判据，不改线上配置。
- 观察窗内存在「资源争用」类冻结、或 REC-CASE-EXCEPTION 未闭环 ⇒ 该观察窗的容量结论整体冻结，不得据它提出资源调整。
- 本责任在 STG-01／STG-02／STG-03／STG-06／STG-07 这些格上只提供判据与契约（范围与验收条件、接收门禁检查项、受控动作的放行条件），不提供任何算法或模型；需要计算的量（并发占用、排队时长、单位任务成本）只在 STG-04／STG-05／STG-08 三个格上产出。
