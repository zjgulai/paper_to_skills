# 算法评估设计 · 供给契约

> **本契约的两部分，用法不同。** §1 方法来源 / §2 数据要求 / §3 标定规则 / §5 适用 FLOW 是**作业口径** ——
> 据此产出方案，**并落实成方案里的取值**；§4 重标定触发条件 / §6 冻结与不许自动放行的情形是**放行判据** ——
> 它们规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> **本责任为什么是 A 类**（`_survey_org_model.md` §F.3 原文）：评估协议、离线指标与离线-在线一致性检验是标准机器学习评估工程。
> 岗位 AGT-012 软件算法与应用生态（DOM-02 / PLN-OPS），适用 FLOW-02 新品需求到商业验证与 FLOW-07 重大质量与账号事件。
>
> **本契约覆盖的格**：方法格 FLOW-02/STG-04、FLOW-02/STG-05、FLOW-02/STG-08 与 FLOW-07/STG-04、FLOW-07/STG-05、FLOW-07/STG-08（§3 的 T1–T6 落在这些格）；
> 规则格 FLOW-02/STG-01、FLOW-02/STG-02、FLOW-02/STG-03、FLOW-02/STG-06、FLOW-02/STG-07 与 FLOW-07/STG-01、FLOW-07/STG-02、FLOW-07/STG-03、FLOW-07/STG-06、FLOW-07/STG-07
> **只放判据与门禁条件**（§4 与 §6 的落脚处）——这些格**只放判据，不接算法模型**。
>
> **本责任的评估对象**：评估的是**别的责任接入的模型与 Agent**（FLOW-02 的〈机会与可行性诊断〉〈新品验证证据包〉；FLOW-07 的〈事件范围与根因诊断〉〈重大事件处置包〉），
> 不是替它们产出业务结论。本契约的产物是「能不能上线 / 能不能继续用」的**判定**，不是业务事实本身。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、样本量与时限，来源只有三类 ——
> （a）业务处境或材料已给出的数（出海历史 **2** 个完整年度＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月（材料侧无季度粒度 ⇒ 改记（b））；阶段边界 STG-01…STG-08）；
> （b）业务侧默认（经营者自述或行业惯例，**逐条附替换条件**）；（c）§3 算式的输出（由命名的数据系统直出）。
> **卡上的论文实验参数与卡面 ROI 不构成第四种来源**（逐条清单见 §1）。

## 3 标定规则

- 取值来源：`自有埋点`（独立站埋点事件流、Case/Event Ledger 的 Stage Acceptance Record 与 Execution Attempt）＋`平台后台`（Amazon 卖家后台与广告后台报表）＋`需授权`（人工金标集与其抽检记录）；**不引用 §1 清单中任何卡面数字与论文实验参数**。
- **T1 评估单元与打分口径（只定口径，不产生自由取值）**：评估单元 ＝ 版本 × 阶段（感知／规划／执行）× 任务；单元得分 ＝ 该单元**命中参考答案要素数 ÷ 参考答案要素总数**；参考答案一律取 `AGT-013`（产品验证与研发项目）与 `AGT-006`（消费者需求与VOC研究）会签的人工金标集，**禁止用被测模型自身的输出充当参考答案**。
- **T2 判定档（把分数变成「能不能上线」）**：`判定 = 新版本单元得分 ≥ 同任务基线得分 + 1 个标准差`；基线 ＝ 上一在用版本在同一评估单元上的得分，由〈Case/Event Ledger〉的 Stage Acceptance Record 直出。
- 取值：显著性水平取 **α = 0.05（双侧）**、功效取 **1 − β = 0.80**（**行业惯例**：评估协议的通行设定）；**基线未到位时先按「基线得分 + 0.07 分」暂按**（**业务侧默认**，经营者自述：同一版本重复评分的波动在一成以内）。**替换条件** ＝ 〈独立站埋点〉与 Stage Acceptance Record 覆盖满 **2** 个完整年度后，改用「同任务近 **2** 个完整年度月度得分的 **1** 个标准差」；替换前该判定档只用于候选排序，不得用于上线放行。
- **T3 样本量（每阶段每任务的最低评估单元数）**：`n_min = (z_{1−α/2} + z_{1−β})² × p̄ × (1 − p̄) ÷ δ²`，其中 `p̄` ＝ 该任务的基线得分、`δ` ＝ 需检出的得分绝对差。
- 取值：每阶段每任务先按 **20** 个评估单元暂按（**业务侧默认**，经营者自述：人工金标集一轮可稳定标注二十条左右）。**替换条件** ＝ 金标集按任务扩充到足以支撑上式直出后，改用直出的 `n_min`；替换前单元数 < **20** 的评估只出提示、不出判定。
- **T4 离线—在线一致性复检**：`一致性偏差 = |离线单元得分 − 上线后同口径实测单元得分| ÷ 离线单元得分`；两侧必须**同一金标版本、同一任务集、同一评分脚本版本号**，否则该次复检无效。
- 取值：容差档 ＝ 该任务近 **2** 个完整年度线上月度得分的 **1** 个标准差（由〈独立站埋点〉直出，无自由参数）；协议上线首 **1** 个自然季度内先按 **0.07** 暂按（**业务侧默认**，与 T2 的暂按档同源，便于跨责任比较）。**替换条件** ＝ 线上实测满 **2** 个完整年度后换成实测标准差；替换前超容差只触发复核，不直接宣布协议失效。
- **T5 上线前可靠性门禁（三维）**：一致性 ＝ 同一配置重复执行 **k** 次的通过率；鲁棒性 ＝ 措辞扰动下的得分保持率；故障容忍 ＝ 依赖接口故障下的降级完成率。故障注入**只许在隔离的 staging 环境**执行。
- 取值：`k` 取该任务在 **1** 个自然季度（**业务侧默认**＝材料只到月粒度，季度档不在材料里；替换条件 ＝ staging 故障注入能力到位后，按该任务实测执行次数分布定窗）内 Stage Acceptance Record 记录的**实际执行次数**（由台账直出，不取卡面的固定重复次数），判据为「全部已记录执行的成功率 ≥ 同任务基线成功率」，**不设部分通过档**；鲁棒性维的扰动集合取〈独立站埋点〉中该任务**真实出现的措辞变体**（按用户输入聚类直出），不取固定扰动幅度；故障容忍维的故障类型取该任务所依赖接口在〈平台后台〉政策与限流通知中的**实际故障记录**。**替换条件** ＝ staging 环境具备故障注入能力后，改用「按该任务近 **2** 个完整年度实际故障分布抽样」的注入配置；替换前故障容忍维一律标注「未测」，不得据此判可上线。
- **T6 产出（本规则定值的字段）**：
- FLOW-02/STG-04 的〈机会与可行性诊断〉：候选模型的离线评估口径与判定档（T1–T3）由本规则定值。
- FLOW-02/STG-05 的〈新品验证证据包〉：验证方案中的评估计划（评估单元、样本量、判定档、停止条件）由 T2、T3 定值。
- FLOW-02/STG-08 的〈新品验证关闭记录〉：继续／转向／停止结论所依据的得分与一致性偏差由 T3、T4 定值。
- FLOW-07/STG-04 的〈事件范围与根因诊断〉、FLOW-07/STG-05 的〈重大事件处置包〉、FLOW-07/STG-08 的〈重大事件关闭与全动作对账记录〉中凡涉及「模型判定是否可信」的字段，一律沿用同一套 T1–T5，**不另立第二套口径**。

## 4 重标定触发条件

- **口径变**：`AGT-045` 对阶段得分、要素命中率或评估单元的分子分母与时间归属发布新版本；`AGT-046` 的质量状态、来源与新鲜度口径改版。
- **数据源变**：独立站埋点换版或迁移（事件名、版本号字段、回填链路变化）；Case/Event Ledger 的 Stage Acceptance Record 首次上线或换版；金标集标注平台更换。
- **结构变**：被评估对象由单模型改为多 Agent 编排（阶段集合与任务边界变化）；新增任务类型；评分脚本的要素抽取规则换代（同一份答案的命中数会变）。
- **主体变**：开放事实 O1（Amazon 65% / 独立站 15% 之外的其余 **20%** 渠道构成未明）一旦定名，或新增渠道／店铺主体接入埋点 —— 样本量分母与基线随之重算。
- **前置能力变**：staging 环境具备故障注入能力（T5 的故障容忍维由「未测」转为实测）；金标集扩充到跨年多版本（T3 的 `n_min` 与 T4 的容差档随之直出）。
- **周期到期**：每 **2** 个完整年度（决策 Q11 的历史长度）重算基线得分、标准差、T3 的 `n_min` 与 T4 的容差档。

## 6 冻结与不许自动放行的情形

- 评估集版本号或评分脚本版本号缺位（同一份得分无法复算）⇒ 该结论不得进入 STG-07 受控动作，只能出 Action Intent 或 NoActionRecord。
- 参考答案由被测模型自身输出充当，或金标集未经 `AGT-013`／`AGT-006` 会签 ⇒ 该轮评估整体作废，不得用于任何放行判定。
- T4 的一致性偏差超容差档（实测标准差，或暂按 **0.07**）⇒ 宣布该任务的评估协议失效：得分不得用于上线放行与对外表述，须按 §4 触发重标定条件。
- 每阶段每任务的评估单元数 < **20**（T3 暂按档）、或未达直出的 `n_min` ⇒ 只出提示，不得写「能力提升」，也不得关闭 Case。
- 真实会话样本未脱敏，或含用户标识、育儿与健康类敏感信息 ⇒ 该批样本不得进入评估集，相关结论一并冻结。
- 拟上线对象未过 T5 的一致性维与鲁棒性维，或故障容忍维仍标「未测」⇒ 不得判「可上线」，只能出「有条件上线 ＋ 降级方案待补」，并由 `AGT-049` 复核运行前提。
- FLOW-07 场景下模型判定被当成实物回执或客户影响事实（材料口径：**不得把模型判断当实物回执**）⇒ 立即冻结该结论的放行效力，移交 FLOW-07 紧急保护通道（Emergency Guard）与人工裁决，本格不得自行处置。
- 任一记录缺统计窗与新鲜度（材料通用工单规则：每项记录统计窗和新鲜度，过期信息不能支撑决定）⇒ 该批证据不进入样本量分母，该 Case 冻结在 FLOW-02/STG-04 或 FLOW-07/STG-04。
- 同一评估单元在当周内已有一次未回填的评估或验证尝试 ⇒ 不得对该单元发起新一轮；**已成功动作不得随整单重跑**（材料通用工单规则）。
- 引用 §1 清单中任一条卡面数字或论文实验参数（**0.6**／**0.85**／**0.91**／**95%**／**23%**／**18%**／**14%**／**341** 倍等）作为本业务取值 ⇒ 该方案不得放行。
- 本段落在规则格（FLOW-02/STG-02 的〈新品验证Case Charter〉、FLOW-02/STG-06 的〈FLOW-02 Assurance Decision〉、FLOW-02/STG-07 的〈验证尝试或无动作记录〉，以及 FLOW-07 同名三格〈重大事件Case Charter与本地原子提交记录〉〈FLOW-07 Assurance Decision〉〈正常处置、恢复尝试或无动作记录〉）上的只是上列判据与门禁条件：这些格**只放判据与门禁，不含算法模型接入**，判据由本段与 §3 的 T4、T5 给出。
