# 资金预测 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，
> 并把规则落实成方案里的取值。§4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：现金流预测是标准时序预测加场景模拟问题（含汇率与账期）。
> 本责任由 `AGT-041` 经营财务与资金承担；§6 的判据落在 FLOW-01 / FLOW-02 / FLOW-03 / FLOW-07 / FLOW-08 五跳的规则格上
> （STG-01 信号接收、STG-02 范围确定与 Case 创建、STG-03 上下文装配、STG-06 Assurance 接收门禁、STG-07 受控动作）——
> **这些格只放判据与门禁条件**；本契约的取值出口在方法格 STG-04 证据收集与诊断、STG-05 方案与标准产物、STG-08 结果核验与关闭。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度**＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月、
> 「季度经营策略」＝**1** 个自然季度；渠道构成 Amazon **65%** / 独立站 **15%**，其余 **20%** 未定名＝开放事实 O1）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）；
> （c）§3 算式由命名的数据系统直出。**卡上的案例数字不构成第四种来源**（逐条清单见 §1）。

## 3 标定规则

- 取值来源：需授权（财务系统对账表、采购台账）＋平台后台（Amazon 卖家后台结算与回款报表）＋第三方 API（汇率与税费接口）＋ AGT-045 指标契约的指标口径；**不引用卡内任何案例或论文数字**（清单见 §1）。
- **C1 口径（只定口径，不产生取值）**：现金三口径 = 订货付款 / 平台结算 / **实际到账**，主口径取**实际到账**（以〈财务系统对账表〉的银行到账记录为准）；币种按「结算币种 → 折算币种」两列同时给出。C1 约束 C2–C6 全部算同一个口径。
- **C2 滚动窗与频率（本契约的取值出口之一）**：`滚动窗 = 未来 1 个自然季度`，按周切片；每周重算一次。
- 取值：滚动预测窗 = **13 个自然周（= 1 个自然季度，与材料已定名的经营节奏「季度经营策略」同粒度）**；重算频率 = **每周 1 次（周一）**；输出粒度 = **按周**（月度经营复盘取本月末快照，不另开一版口径）。
- **C3 回款到账日（族骨架的回款段）**：`预计到账日 = 销售截止日 + 基础结算周期 + 节假日延迟 + 退货率档加罚 + 账号健康档加罚 + Reserve 释放期`，争议挂起类单独成列、不并入上式；各加项一律按〈平台后台〉结算报表与〈财务系统对账表〉的实测值算，不取卡面默认值。
- 取值：到账日点估计取该渠道近 2 个完整年度**实测到账日的 P50**、区间取 **[P25, P75]**（实测到账日 =〈财务系统对账表〉银行到账日 −〈平台后台〉结算日）；**到账日区间宽度超过 7 个自然日**的回款项一律标「不可用于付款承诺」。区间宽度线 **7 个自然日** 系**业务侧默认**（经营者自述：付款周之内不允许存在说不清的到账日）。
- C3 替换条件：〈财务系统对账表〉逐笔到账日接入并跑满 2 个完整年度后，把 P50 / P25 / P75 换成按「结算周期 × 币种 × 账号」各自的分位数；替换前到账日只用于缺口区间，不得写入合同或对外承诺。
- **C4 缺口与融资窗口（族骨架的情景段）**：`周度现金头寸(t) = 期初可用现金 + Σ_{到账日 ≤ t} 回款 − Σ_{付款日 ≤ t} 付款`；`最大缺口 = min_t 周度现金头寸(t)`；`融资窗口起点 = 缺口首次出现的周次 − 采购付款须落定的提前期`（提前期按〈采购台账〉合同条款字段取）。
- 取值：缺口按 **P50 与 P90 两档**给出（P90 = 压力档，由 C3 的到账日区间与 C5 的汇率情景联合抽样得出）；**融资额度下限 = P90 档最大缺口的绝对值**；**付款承诺只允许在 P50 档缺口为 0 的周次作出**。两档口径系**业务侧默认**（经营者自述：融资按压力档申请、付款承诺按中位档给）。
- C4 替换条件：〈财务系统对账表〉与〈平台后台〉跑满 2 个完整年度后，压力档改用该 2 个完整年度内「周度头寸最低值」的 **P95**；替换前融资额度一律按 P90 申请，不得下调档位。
- **C5 汇率情景（族骨架的汇率段，邻接开放事实 O2）**：本业务**暂无已定名的远期锁汇台账**（远期汇率只能来自银行报价，属需授权）；处置：**先按**〈第三方 API〉汇率与税费接口的现货中间价，叠加〈财务系统对账表〉近 2 个完整年度逐月汇率算出的波动标准差做区间情景暂按，并逐行标「未锁汇」；锁汇台账或银行远期报价接入后**替换**为远期汇率；替换前汇率情景只用于缺口区间，不得用于利润承诺或对外报价。
- 取值：汇率情景 = **现货中间价 ± 1 个标准差**（标准差由〈财务系统对账表〉近 **2 个完整年度**逐月汇率算出）；敞口折算币种 = **结算币种与人民币 2 类**（渠道构成 Amazon 65% / 独立站 15% 见开放事实 O1，其余 20% 未定名渠道按〈平台后台〉实际结算币种归集，**不另设第五个渠道**）。
- **C6 账期与营运资金（族骨架的账期段）**：`CCC = DIO + DSO − DPO`，三项一律按〈财务系统对账表〉与〈采购台账〉近 2 个完整年度算、按金额加权取中位数。
- 取值：DSO 与 DPO 取**金额加权中位数**；**CCC 目标值 = 本业务近 2 个完整年度 CCC 的 P25**（由台账直出，非固定常量）；**DPO 上限 =〈采购台账〉合同条款字段写明的账期上限**（不自行设数）；延长账期的空间按该上限判定，超出即出 Action Intent 而非直接改付款条件。
- C6 替换条件：〈采购台账〉按供应商 × 批次归集跑满 2 个完整年度后，CCC 目标值改用同品类的近 2 个完整年度 CCC 的 P25；替换前只出集团口径、不得出分品类承诺。
- **C7 产出（本规则定值的字段）**：以下标准产物里由本规则定值的字段如下。
- FLOW-01/STG-04 的〈经营证据与偏差诊断〉：现金缺口项、回款偏差项与账期偏差项由 C3、C6 定值。
- FLOW-01/STG-05 的〈联合经营行动包〉：融资窗口、缺口档（P50 / P90）、付款节奏与停止条件由 C4 定值；资源类建议的资金约束由 C6 定值。
- FLOW-01/STG-08 的〈经营关闭记录〉：实际到账、汇兑损益与缺口闭合判定由 C3、C5 定值。
- FLOW-02/STG-04 的〈机会与可行性诊断〉、FLOW-02/STG-05 的〈新品验证证据包〉、FLOW-02/STG-08 的〈新品验证关闭记录〉：新品投入的资金占用与融资需求由 C2、C4 定值。
- FLOW-03/STG-04 的〈供需证据与约束诊断〉、FLOW-03/STG-05 的〈供应计划与动作方案〉、FLOW-03/STG-08 的〈供需关闭记录〉：现金约束、账期与起订量带来的付款节点由 C4、C6 定值。
- FLOW-07/STG-04 的〈事件范围与根因诊断〉、FLOW-07/STG-05 的〈重大事件处置包〉、FLOW-07/STG-08 的〈重大事件关闭与全动作对账记录〉：赔付、退款与冻结资金的现金影响由 C1、C4 定值。
- FLOW-08/STG-04 的〈经营与能力诊断〉、FLOW-08/STG-05 的〈经营与能力变更建议〉、FLOW-08/STG-08 的〈经营复盘关闭记录〉：全成本与现金口径、资源调整的资金可行性由 C1、C6 定值。
- 上述五跳凡涉及现金、汇率、账期与资金占用的字段，一律沿用同一套 C1–C6，不另立第二套口径。

## 4 重标定触发条件

- **口径变**：AGT-045 对可用现金、在途资金、冻结保证金、GMV 与费用的分子分母或时间归属发布新版本；AGT-046 的质量状态、来源与新鲜度口径改版；主口径在「订货付款 / 平台结算 / 实际到账」之间切换。
- **数据源变**：平台结算与回款报表字段改版；〈财务系统对账表〉科目或银行流水接口换版；〈采购台账〉账期字段改版；汇率与税费接口的报价口径由现货改为远期。
- **结构变**：平台结算规则变化（放款节奏、Reserve 政策、争议挂起规则）；新增市场或币种使折算集合变化；付款节点集合变化（新增关税、平台费用或渠道返利科目）。
- **主体变**：开放事实 O1（Amazon 65% / 独立站 15% 之外的其余 **20%** 渠道构成未明）一旦定名，或新增渠道 / 店铺主体接入命名源 —— 缺口分母、结算币种集合与融资额度随之重算。
- **周期到期**：每 2 个完整年度（决策 Q11 的历史长度）重算回款到账日分位、CCC 目标值、汇率波动标准差与 C4 的压力档。
- **告警触发**：实际到账日相对 C3 的区间连续 **1** 个自然月落在区间外，或 C4 的 P50 档缺口在下一次重算时转负 —— 先回 STG-04 重算口径；重算后仍越界，才进入本节的口径变或结构变判定。

## 6 冻结与不许自动放行的情形

- 资金计划缺项（滚动窗、缺口档、汇率情景、账期口径、停止条件缺任一项）⇒ 该计划不得进入 STG-07 受控动作，只能形成 NoActionRecord。
- C4 的 P90 档最大缺口 > 0 而融资尚未落定（额度、窗口、成本三项缺任一项）⇒ 采购付款、备货与大促资源类动作一律冻结，只能出 Action Intent。
- 回款到账日区间宽度 > §3 的 7 个自然日，而方案把它写成确定的付款安排 ⇒ 该安排不得写入标准产物，也不得作为对外承诺。
- 快照不满足 §2 ④（非「截至前一日 24:00」的对账快照，或存在未清对账差异）⇒ 该 Case 的 STG-06 接收门禁判 HOLD，转人工复核。
- 未锁汇而方案把汇率情景写成承诺汇率或利润承诺 ⇒ 不得放行；对外报价与保底承诺类动作全部停在 STG-06 之前。
- 现金或库存快照已过期（超出 §2 ④ 的重读要求）而方案仍据此加预算或扩投放 ⇒ 该结论无效（材料原文：过期库存信息不能支撑加预算决定）；已成功动作不得随整单重跑。
- 账期延长超出〈采购台账〉合同条款字段写明的上限而未取得 AGT-015 与 AGT-043 的书面确认 ⇒ 不得改动付款条件。
- 命中 FLOW-07 的账号或资金冻结类事件口径（平台冻结、争议集中爆发）⇒ 移交 FLOW-07 紧急保护通道（Emergency Guard），本格不得自行处置；退款与赔付只能在该通道的受控阶段执行。
- 引用 §1 清单中任一条卡面案例数字作为本业务取值（含 430 万、T+17、45 天、15–25 万元、14 天、200 万元、6–8%、70%、20–50 万元）⇒ 该方案不得放行。
- 自 §3 产物提交起，至该 Case Charter 已写明的观察窗截止日仍未取得 §2 五维任一项的命名源数据 ⇒ 判 HOLD 并转人工，不得默认放行。
- 本段落在规则格（STG-01 / STG-02 / STG-03 / STG-06 / STG-07）上的只是上列判据与门禁条件，不引入判别式或预测式。
