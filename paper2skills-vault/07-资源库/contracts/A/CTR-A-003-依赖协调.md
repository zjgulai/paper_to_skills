# 依赖协调 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，并把规则落实成方案里的取值。
> §4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**任务依赖与资源冲突是经典调度/约束满足问题（RCPSP/CP），
> 可输出可行序与预留方案。** 本契约承接的就是这一段：**可行序与预留方案**算得出来，
> 而「冲突该由谁让步、环该由谁裁决」不在本段内（见 §6）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；阶段边界 STG-01…STG-08；
> CASE-PROTOCOL-8 的接收条件名与 D-026 紧急保护通道）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）；
> （c）§3 算式的输出（由命名的数据系统直出）。**卡上的论文实验参数不构成第四种来源**（逐条清单见 §1）。

## 3 标定规则

- 取值来源：自有埋点（Case/Event Ledger 的 Case Charter 与 Stage Acceptance Record 事件流）＋ 平台后台与需授权台账的权威可用量（〈库存台账〉可售量、〈平台后台〉账号动作配额与广告预算余量、〈采购台账〉未占用产能与在途量、财务科目可用余额）；**不引用卡内任何论文参数**（清单见 §1）。
- **T1 依赖图（边从哪来，不含相似度分数）**：顶点＝未关闭 Case（状态 ∈ {OPEN, WAITING, REWORK_REQUIRED}）。边 b→a（b 等 a）成立当且仅当下列任一为真 —— (i) **对象重叠**：a 与 b 的 Case Charter 显式业务范围内、按 AGT-045 主数据标识的资源对象集合交集非空；(ii) **阶段产物依赖**：按 CASE-PROTOCOL-8 的阶段产物表，b 当前阶段待接收的产物类型由 a 的当前或更晚阶段产出；(iii) **预留覆盖**：b 待申领的（资源对象，时间窗）与 a 已占用的（资源对象，时间窗）重叠。三类之外的通信或相关关系**不建边**。
- T1 取值：**三类之外的边数 = 0 条**（硬约束，不设例外档）；同一对 Case 之间同类型的重边合并为 **1 条**；顶点点集 = 当期全部未关闭 Case，已关闭 Case 边数 = **0 条**。判等一律用「资源对象标识集合与时间窗的集合运算」，**不用文本相似度**（卡面 Jaccard 口径不得移植，见 §1 第 9 条）。
- **T2 冲突判定（口径与算式）**：对每个资源对象 r 与时间窗 W，`D(r,W) = Σ 所有未关闭 Case 的 resource_reservation_refs 中落在 (r,W) 的申领量`；`A(r,W)` 按对象类别取权威值 —— 预算科目＝〈财务科目台账〉可用余额（预算 − 已承诺 − 已执行）；可售库存＝〈库存台账〉可售量（**不含已预留、不含在途**）；账号动作配额＝〈平台后台〉当期可执行上限；供应商产能与采购在途＝〈采购台账〉未占用产能与在途量。
- T2 判定：`D(r,W) ≤ A(r,W)` ⇒ 直接写入预留、不排队；`D(r,W) > A(r,W)` ⇒ 命中 `resource_conflict_detected_before_reservation_or_external_attempt`，该 Case 置 WAITING 并生成 REC-CASE-EXCEPTION，**不得静默抢占**，也**不得**按先到先得放行。
- T2 取值：**容差档 = 0**（D 不得超过 A 一个单位），判定为**二值**、不设部分放行档；口径依据＝材料已定名的 STG-02 接收条件 `resource_reservation_refs_present_as_case_owned_list_even_when_empty` 与 `resource_conflict_inputs_recorded`；四类对象各自的 `A(r,W)` 取数口径逐字取上一条所列台账字段，不另立第二套口径。
- **T3 可行序与预留**：① 可行序＝对 T1 边集做拓扑排序并输出无环序；出现环（互相等待）即不输出序，置 WAITING 或 FROZEN 并把环上报，环内任何 Case 不得进入受控动作阶段。
- T3 取值：**环内 Case 的放行数 = 0 件**；**拓扑序的输出条件为边集无环**（有环时输出序条数 = 0 条，只出环报告）。
- T3 ② 冲突集内定序（字典序，逐级只读台账字段）：命中 D-026 紧急保护通道的 Case 优先；其次已产生不可逆外部承诺或已执行动作的 Case 优先（避免同一对象重复写入）；再次出度大者优先（按 T1 现算的依赖数，即阻塞下游更多者）；三级仍并列即判据不唯一，**不自动裁决**，置 WAITING 并上报该 FLOW 主岗位与人工。
- T3 取值：定序为**三级字典序**；三级恰好并列时的**自动裁决数 = 0 件**（一律置 WAITING 并转人工）；定序只读台账字段，**不读任何自评置信度**（卡面「按最高置信度选举组长」口径不得移植，见 §1 第 8 条）。
- T3 ③ 预留量与缓冲：`预留量`＝该 Case 在 STG-05 产物中申领的对象与量上限；`b(r) = 近 2 个完整年度已关闭 Case 在资源对象 r 上的 max[(申领量 − 实际执行量) ÷ 申领量]`（序列由各 FLOW 的关闭记录回写）；**仅当** `D(r,W) × (1 + b(r)) ≤ A(r,W)` 时批准预留。
- T3 取值：**缓冲项 b(r) 在本业务当前 = 0（不放宽）** —— 因为「预留 vs 实际执行」序列尚未产生（见 §2 ③）；先按 `D(r,W) ≤ A(r,W)` 的**硬约束路径**暂按，〈Stage Acceptance Record〉与各 FLOW 关闭记录回写满 **2 个完整年度**后替换为**实测 b(r)**；替换前预留审批只做二值判定，**不得**据任何外部来源的缓冲系数放宽，也**不得**据此推断本业务的补货或投放工期。
- T3 ④ 已写入预留后再出现资源所有权或外部状态不确定 ⇒ 置 FROZEN，按八阶段协议的 `reconcile_reservation_and_external_state_before_any_new_action` 先对账再动。
- T3 取值：**同一资源对象上「已写入预留」与「已执行但回执未对平」并存时，新预留批准数 = 0 件**（先对账、后审批）；FROZEN 期间的自动放行数 = **0 件**。
- **T4 产出（本规则定值的字段）**：以下标准产物里由本规则定值的字段如下。
- T4 产出：STG-02 的 **8 份 Case Charter**（经营Case Charter／新品验证Case Charter／供需Case Charter／市场进入Case Charter／客户Case Charter／能力交付Case Charter／重大事件Case Charter／经营复盘Case Charter）的 `resource_reservation_refs` 与 `resource_conflict_inputs` 两个接收门禁字段，由 T1、T2 定值。
- T4 产出：STG-04 的 8 份诊断产物（FLOW-01 经营证据与偏差诊断、FLOW-02 机会与可行性诊断、FLOW-03 供需证据与约束诊断、FLOW-04 市场进入诊断、FLOW-05 客户问题诊断、FLOW-06 能力缺口诊断、FLOW-07 事件范围与根因诊断、FLOW-08 经营与能力诊断）的依赖边集与冲突集，由 T1、T2 定值。
- T4 产出：STG-05 的 8 份方案产物（联合经营行动包／新品验证证据包／供应计划与动作方案／市场进入包／服务与留存方案／数据/工具交付包／重大事件处置包／经营与能力变更建议）的可行序、预留量与停止条件里的资源位，由 T3 定值。
- T4 产出：STG-08 的 8 份关闭产物（经营关闭记录／新品验证关闭记录／供需关闭记录／市场进入关闭记录／客户旅程关闭记录／能力交付关闭记录／重大事件关闭与全动作对账记录／经营复盘关闭记录）的「预留 vs 实际执行」偏差回写，构成 T3 的 b(r) 序列；**回写条数必须等于当期关闭 Case 数 × 申领对象数**，缺一条即该期 b(r) 不成立。

## 4 重标定触发条件

- **口径变**：AGT-045 对资源对象标识或可用量定义发布新版本；AGT-046 的质量状态、来源与新鲜度口径改版。
- **数据源变**：Case/Event Ledger 首次上线或换版（缓冲项必须由 T3 的「取 0 不放宽」改为按实测 b(r) 计算）；〈库存台账〉〈采购台账〉〈财务科目台账〉或〈平台后台〉任一被替换或改字段。
- **结构变**：CASE-PROTOCOL-8 的阶段产物表或接收门禁版本变化（新增／取消产物类型、增删阶段）；三条 FLOW 的主岗位 selector 由 `production_ready = false` 变为可唯一确定（FLOW-01／FLOW-05／FLOW-07），适用主岗位范围随之重算。
- **主体变**：开放事实 O1（Amazon 65% 与独立站 15% 之外的其余 20% 渠道构成未明）一旦定名，或新增市场／渠道／账号主体 ⇒ 资源对象集合与账号范围重算。
- **周期到期**：每 **2 个完整年度**（决策 Q11 的历史长度）重算一次 b(r) 与资源冲突频次。

## 6 冻结与不许自动放行的情形

- 资源冲突未解（`D(r,W) > A(r,W)`）且定序三级并列 ⇒ 不得进入受控动作，置 WAITING 并上报裁决；本责任只输出冲突集与可行序候选，**不得单方裁决**，裁决权在该 FLOW 的主岗位与人工。
- 依赖边集出现环（互相等待）⇒ 环内任何 Case 不得放行；环只上报，不得由本责任自选一个 Case 打破。
- 必需输入缺失、质量状态非可用或新鲜度超时（AGT-046 口径）⇒ 置 WAITING，依赖与新鲜度复核通过前不得推进。
- 已写入预留后资源所有权或外部状态不确定 ⇒ 置 FROZEN，须先完成预留与外部状态对账（`reconcile_reservation_and_external_state_before_any_new_action`）再动。
- 同一资源对象上存在已执行但回执未对平的动作 ⇒ 不得对该对象发起新动作；已成功动作不得随整单重跑（材料 PB-001 原文）。
- 过期库存信息、或未经 AGT-045 签发的可用量口径 ⇒ 不得支撑加预算与扩量类决定（材料 PB-001 原文：过期库存信息不能支撑加预算决定）。
- 跨 FLOW 争用同一库存或预算科目 ⇒ 本责任只输出冲突集与可行序候选，不得代替该 FLOW 主岗位下单或调拨。
- STG-06 接收门禁未通过、或仍有未解决的语义发现 ⇒ 不得放行；发起方不得覆盖拒绝结论（`initiator_cannot_override_rejection`）。
- Case 处于 FROZEN，或其固定的能力包进入 QUARANTINED ⇒ 不得发起新动作。
- 命中 D-026 的模型外紧急保护通道时，冻结与恢复、重新开放、扩大范围、外部承诺、退款、召回、销毁与永久变更只能在正常 STG-07 执行；本责任的可行序**不得**把紧急通道当成一条捷径。
- FLOW-01/STG-02 的接收门禁要求把 `resource_conflict_inputs` 记入 Case Charter；该字段缺失时不得把 Case 从范围确定推到下一阶段。
- 本段落在规则格（STG-01／STG-02／STG-03／STG-06／STG-07）上的只是上列判据与门禁条件，不引入判别式或预测式。
