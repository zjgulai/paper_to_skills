# 主数据治理 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，并把规则落实成方案里的取值。
> §4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：主数据去重、合并与质量度量为标准 MDM 算法。
> 岗位 AGT-045 业务口径与主数据（DOM-08 / PLN-PLT），适用 FLOW-01 联合经营、FLOW-06 数据与工具、FLOW-08 经营复盘。
>
> **⚠️ 本责任是别的契约「口径归属」维的落点。** 其他责任在其 §2 ⑤ 只写一句
> 「AGT-045 指标契约与主数据（指标名，版本号 `<签发日>-<序号>`）」，**不在自己的契约里另抄分子分母**；
> 本契约的 §3 T5 就是那个版本锚的定义处与引用规则的出处（含 AGT-046 随记录携带的质量状态、来源与新鲜度）。
>
> **本契约覆盖的格**：方法格 FLOW-01/STG-04、FLOW-01/STG-05、FLOW-01/STG-08、FLOW-06/STG-04、FLOW-06/STG-05、FLOW-06/STG-08、FLOW-08/STG-04、FLOW-08/STG-05、FLOW-08/STG-08（§3 的算式落在这些格）；
> 规则格 STG-01（信号接收）／STG-02（范围确定与 Case 创建）／STG-03（上下文装配）／STG-06（Assurance 接收门禁）／STG-07（受控动作）落在上述三跳上，**这些格只放判据与门禁条件**（§6 的落脚处）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；渠道四选一＝决策 Q9；经营节奏「月度经营复盘」＝1 个自然月、「季度经营策略」＝1 个自然季度）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）；
> （c）§3 算式的输出（由命名的数据系统直出）。**候选卡的论文实验参数不构成第四种来源**（逐条清单见 §1）。

## 3 标定规则

- 取值来源：平台后台（各渠道商品目录与库存导出）＋ 需授权（ERP 主数据、供应商档案、采购台账）＋ 自有埋点（独立站商品与订单事件携带的对象标识）＋ AGT-046 的质量状态／来源／新鲜度；**不引用卡内任何论文参数**（清单见 §1）。
- **T1 统一对象 ID 与三码映射**：`统一对象 ID = hash(规范化(品牌) ‖ 规范化(品类) ‖ 规范化(型号))`；规范化＝去首尾空格、统一大小写、剥渠道后缀（如 `-US`、`_B0`、`-B0`）。三码映射（渠道 SKU ↔ ASIN ↔ ERP 料号）随 `业务规则字典` 签发，映射表**一行一源**。
- 取值：统一对象 ID 下允许关联的源记录数上限取 **5**（＝ERP ＋ 决策 Q9 的渠道四选一：Amazon／独立站／其他平台／B2B 与零售，逐对象按实际在售渠道数取，最多 5）；超出即判「主键未归一」并登记为 FLOW-06/STG-04 的〈能力缺口诊断〉缺口项。替换条件：`业务规则字典` 按对象类型签发源清单后，上限改用签发值；替换前上限只用于发现异常，不得据其删除任何源记录。
- **T2 冲突消解（多源字段取值）**：`规范值(f) = 取 优先级(f, 源) 最高的源在该字段上的值`；同档并列时取该源记录的 `updated_at` 最新者；**同档且同一时刻并列时不自动合并**，一律进冲突列表并留痕。
- 取值：字段优先级取 **2 档（最高档、次高）** 并按**字段族**定 —— 成本与料号族以 ERP 为最高档、标题与品类族以实际在售渠道为最高档、重量与交期族以供应商档案为最高档；未落入这三族的字段一律取次高档（ERP 与渠道并列）。这 **2** 档系**业务侧默认**（经营者自述：成本只能来自 ERP，标题只能来自实际在售渠道）。替换条件：`业务规则字典` 按字段签发优先级后整档替换；替换前冲突消解结果只用于内部归并与排序，不得下发渠道模板。
- **T3 质量度量与下发门禁**：`字段质量分 = 通过规则的规则数 ÷ 参与评估的规则数`；`行级质量分 = 通过规则的字段数 ÷ 参与评估的字段数`；`表级质量分 = 通过行数 ÷ 总行数`。
- 取值：三个层次的分都落在 **0 到 1**；**阻断条件取二元规则「必需字段有任一未通过即阻断该行」**（无自由阈值，因此不设容差档）；下发渠道模板的门槛取 **1.0（必需字段全通过）**。替换条件：`业务规则字典` 按品类签发必需字段清单与质量门槛后整档替换；替换前 < **1.0** 的记录一律标「未发布」，并在 FLOW-06/STG-04 的〈能力缺口诊断〉登记缺口项。
- **T4 合并质量与回滚**：`重复率 = 同一统一对象 ID 下源记录数 > 1 的对象数 ÷ 对象总数`；`误合并率 = 经复核确认错误合并的对象数 ÷ 本批已合并对象数`。
- 取值：**误合并率上限取 0（零容忍）**；冲突项人工复核比例取 **100%（有冲突即逐条复核）**。任何一次误合并都必须**先回滚该版本号**再重新签发，不得在原版本上直接改写。替换条件：〈主数据变更台账〉跑满 2 个完整年度（决策 Q11）后可改为按批抽样复核，但零容忍上限不变；替换前不得放行任何未逐条复核的冲突项。
- **T5 版本锚与引用规则（本责任的核心产出，别的契约的 ⑤ 维引用此处）**：
- 版本锚：`业务规则字典` 与 `指标契约` 以版本号 `<签发日>-<序号>`（形如 `20260913-1`）为**唯一锚**；每次签发递增序号并写 `生效起止时间`（精确到自然日）；旧版本转「失效」而非删除，引用方能回查到当时用的那一版。
- 引用规则：其他责任在其「口径归属」维**只写**「AGT-045 指标契约与主数据（<指标名>，版本号 `<签发日>-<序号>`）」，不得另抄分子分母、不得另立第二套口径；口径变更由本责任递增版本号并通知引用方，引用方按版本号替换。
- 产出：以下标准产物里由本规则定值的字段 —— FLOW-06/STG-05 的〈数据/工具交付包〉里的指标契约与主数据条目、FLOW-06/STG-08 的〈能力交付关闭记录〉的口径验收结论；FLOW-01/STG-04 的〈经营证据与偏差诊断〉的对象映射段与口径一致性段；FLOW-01/STG-05 的〈联合经营行动包〉与 FLOW-01/STG-08 的〈经营关闭记录〉里的口径版本号字段；FLOW-08/STG-04 的〈经营与能力诊断〉与 FLOW-08/STG-08 的〈经营复盘关闭记录〉的口径一致性段。
- 取值：版本号形如 **20260913-1**（签发日-序号），每条契约条目与每条规范记录都带版本号与生效起止时间；首份 `业务规则字典` 与 `指标契约` 尚未签发（本业务暂无生效版本号）—— 处置：先由 AGT-045 按各来源系统现有字段清单出一版对照表并逐条标「口径未签发」，签发后以版本号整档替换；替换前引用方的口径只用于排序与内部判断，不得进入绩效核算与对外披露。

## 4 重标定触发条件

- **口径变**：`业务规则字典` 或 `指标契约` 发布新版本号（分子分母、时间归属、币种或汇率口径变化）；AGT-046 的质量状态、来源与新鲜度口径改版；必需字段清单按品类调整。
- **数据源变**：ERP 主数据换版或迁移（料号规则、字段族变化）；新增渠道的商品目录接入；供应商档案首次授权到本责任。
- **结构变**：新增业务对象类型（如把供应商、仓库也纳入主数据）使对象 ID 规则与映射表结构变化；字段族由 3 族扩为更多族使 T2 的档位划分变化；质量规则集合变化使 T3 的分母变化。
- **主体变**：开放事实 O1（Amazon 65% / 独立站 15% 之外的其余 20% 渠道构成未明）一旦定名，或新增渠道／店铺主体接入主数据 —— 源记录数上限、映射表与质量基线随之重算。
- **周期到期**：每 2 个完整年度（决策 Q11 的历史长度）重算重复率、字段冲突率与质量分基线，并按 T4 决定是否由逐条复核改为按批抽样。

## 6 冻结与不许自动放行的情形

- 必需字段未全通过（行级阻断）的规范记录 ⇒ 不得下发渠道模板、不得进入上架流程与属性图谱，只能登记为缺口。
- 指标契约或 `业务规则字典` 的版本号缺位（口径未签发）⇒ 引用方不得据该口径做绩效核算、对外披露或关闭 Case。
- 冲突项未经 100% 人工复核，或同一统一对象 ID 出现超出 T1 上限的源记录 ⇒ 该批合并不得发布，先回滚版本号再重签。
- 任一对象确认发生误合并 ⇒ 立即冻结该对象的对外下发，回滚该版本号；在重签之前不得对同一对象发起新动作。
- 三码映射表出现一行多源或源记录被静默删除 ⇒ 该批映射作废，改走人工裁决。
- 中间层不经 AGT-045 递增版本号而单独改口径 ⇒ 该引用无效，该 Case 的 Assurance 接收门禁判 HOLD 并转人工。
- ERP 主数据、供应商档案或采购台账未授权到本责任，而拟动作为成本入账、定价或补货 ⇒ 冻结至授权与档案到位。
- 主数据变更或质量分未带 AGT-046 的来源与新鲜度字段 ⇒ 该批记录不得进入下游（渠道模板、属性图谱、经营诊断）。
- 新鲜度超出 §2 ④ 的快照要求（如拿当日未归并的目录当已归并主数据）⇒ 该批结论只出提示，不得作为下发与关账依据。
- 同一对象在当周内已有一次未回填的下发或映射变更 ⇒ 不得对同一对象发起新动作；已成功动作不得随整单重跑。
- 主数据异常同时命中 FLOW-07 的账号或质量事件口径 ⇒ 移交 FLOW-07 紧急保护通道（Emergency Guard），本格不得自行处置。
- 引用 §1 清单中任一条卡面数字作为本业务取值（含阈值、分值、行数、概率与金额）⇒ 该方案不得放行。
- 本段落在规则格（STG-01／STG-02／STG-03／STG-06／STG-07）上的只是上列判据与门禁条件，不引入判别式或预测式。
