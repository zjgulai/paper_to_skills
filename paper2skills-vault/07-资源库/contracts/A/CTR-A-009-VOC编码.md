# VOC编码 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，并把它落实成方案里的**取值**；
> §4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，**不得**整句抄成交付物的内容。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**评论/工单编码可用弱监督多标签分类与 LLM+校验流水线，编码一致性可量化。**
> 分界线因此在「可量化的编码一致性」与「只能由受控外部验证证明的需求真实性」之间 —— 本契约只标定前者，
> 后者按 §6 交给 STG-06 与受控动作。

## 1 方法来源（卡供方法）

- 方法族：**弱监督多标签编码 + 抽取—校验流水线**（把非结构化的评论/工单文本编成可统计的标签与事件结构，再用人工抽检把「编码得对不对」做成一个可核验的量）。族内各卡的方法实现可互换，本契约取的是族骨架，不是某一张卡的实现。
- 代表卡 1（已装线）：`p2s-voc-proxy-nps-aipl`（源卡号 `Skill-VOC-Proxy-NPS-AIPL-统一萃取引擎`，源域 07-NLP-VOC；图谱 L3 含 `VOC编码`、`体验分析`、`指标契约`）——**统一萃取引擎**：品线隔离的标签种子库 + 多维标签匹配 + 情感校准，一条文本同时产出旅程阶段、产品问题标签、消费者画像三类标签，并把被高评分掩盖的问题单独拎出来。
- 代表卡 2（已装线）：`p2s-bert-srl-event-frame-extraction`（源卡号 `Skill-BERT-SRL-Event-Frame-Extraction`，源域 07-NLP-VOC；图谱 L3 含 `VOC编码`、`体验分析`）——**语义角色标注 + 事件框架**：先识别谓词与论元，再组装成事件四元组，最后按根因类型归类。
- 代表卡 3（精选线，引 `card_id`；**S5 换底后替换为已装 slug**）：`Skill-ALCHEmist-Weak-Supervision`（源域 07-NLP-VOC，论文 arXiv:2407.11004，NeurIPS 2024 Spotlight）——**弱监督**：让 LLM 生成「标注程序」而不是逐条标注，多个程序各自可弃权、再投票聚合。
- 可搬的部分（族级，一段话）：① 编码在**闭集标签字典**上做，不在自由文本上做 —— 一条文本可命中 0–N 个标签，命中不了就写「未编码」，**不回填默认标签**；② 「生成判定程序」与「逐条判定」两条路并存，按标签档位分工，两路输出进同一张编码表并记判定来源；③ 每个标签保留**弃权**档，弃权与低置信一律进人工抽检队列；④ 程序库与字典**版本化留痕**，编码结果随带版本号，否则跨期不可比；⑤ 编码只回答「这条文本在说什么」，**不回答「这个需求真不真」** —— 真不真由受控外部验证给回执（§6）。
- **不得移植的部分**（逐条列出我实际读过的三张卡内的数值，任一条都不得进入本业务口径；换入同族卡时，同样要逐条剔除该卡自身的数值）：

## 3 标定规则

- 取值来源：平台后台（Amazon 卖家后台评论报表）× 自有埋点（独立站评论与工单、Case/Event Ledger 的阶段产物）× AGT-006 自建的人工抽检集（抽检记录随〈机会与可行性诊断〉留档）。**不引用任何卡内示例数字**（黑名单见 §1）。
- **T1 分母与编码范围**：分母 = 编码窗口内该品线的**有效评论文本数**，按 `review_id` 去重后计（有效 = 正文非空、非平台系统模板、语种可判）；一条文本命中多个标签不改变分母。
  - 产出：〈机会与可行性诊断〉的「样本量与覆盖」栏由 T1 定值。
- **T2 标签分配（多标签 + 弃权）**：对每条文本，标签集 = { t : 判定来源给出 t 且置信度不低于该标签所在档的判定档 }；无命中即写「未编码」并进抽检队列，**不回填默认标签**。
  - 判定来源两路：高频档标签走程序化判定（可弃权），长尾档标签走逐条判定；两路输出写进同一张编码表并记 `判定来源 = 程序 / 逐条`。
  - 产出：〈机会与可行性诊断〉的「问题分布」栏只由 T2 的标签集统计得出，不得由自由文本摘要代替。
- **T3 档位划分（决定哪些标签走程序）**：按当期命中量降序累计，覆盖累计 **80%** 命中量的标签进**高频档**，其余进**长尾档**。
  - 分档：高频档 / 长尾档 **两档**；分档线 = 累计命中量占比 **80%**，逐品线各算一次。
  - 该 80% 线是**业务侧默认值**（来源＝行业惯例的帕累托分档；材料与此三张卡均未给该线）。**替换条件**：AGT-045 签发〈品线标签字典〉后，改用字典里每个标签自带的档位字段，本契约不再自算分档线。
- **T4 一致性校验（本责任唯一可量化的质量量）**：每批编码完成后按批抽检，`抽检一致率 = 抽检中机器标签与人工裁决一致的条数 ÷ 抽检条数`。人工裁决者须未参与该批判定程序与提示词的设计，独立性由 FLOW-02/STG-06、FLOW-05/STG-06 的接收门禁核对。
  - 取值：**抽检量 = 100 条/批**（**业务侧默认值**，来源＝经营者自述：AGT-006 现行人工编码复核即按每批百条量级抽检）。**替换条件**：AGT-005 抽样审计责任给出本项目的抽样方案后，按该方案的样本量与抽取比例替换。
  - 目标值：**抽检一致率 ≥ 0.80**（**业务侧默认值**，来源＝行业惯例：弱监督文本编码场景把 0.80 量级的人机一致率当作可交付下限；材料未给该阈值）。**替换条件**：抽检累计满 2 个完整年度（决策 Q11）后，改用实测一致率的区间下界替换。
  - 编码覆盖率：**取值 = 1.00（即 100%）**，即不留下「未编码」条数 —— 依据是材料口径下 STG-06 Assurance 接收门禁是**二值门禁**（缺一项即 HOLD，不设部分通过档），故本量只有满值一档。**替换条件**：抽检台账按批记录「未编码」条数满 2 个完整年度后，改用实测未编码率替换；未编码率 > 0 的批次按 §6 第 2 条处理。
- 产出（本规则定值的字段）：〈机会与可行性诊断〉（FLOW-02/STG-04、FLOW-05/STG-04）的「问题分布 / 样本量与覆盖 / 字典版本」三栏；〈新品验证证据包〉与〈服务与留存方案〉（FLOW-02/STG-05、FLOW-05/STG-05）中引用编码结论的段落；〈新品验证关闭记录〉与〈客户旅程关闭记录〉（FLOW-02/STG-08、FLOW-05/STG-08）的「编码口径是否变更」栏 —— 均由 T1–T4 定值。
- 规则只落在 M 格；判据格（FLOW-02/STG-01·02·03·06·07 与 FLOW-05/STG-01·02·03·06·07）上不放判别式，只放 §6 的门禁条件。

## 4 重标定触发条件

- **口径变**：AGT-045 签发或改版〈品线标签字典〉（新增 / 合并 / 停用标签、改标签定义、改档位字段）；AGT-046 的质量状态、来源与新鲜度口径改版。
- **数据源变**：Amazon 卖家后台评论报表的字段或导出口径变；独立站评论与工单的接入方式变；Case/Event Ledger 首次上线或换版。

## 6 冻结与不许自动放行的情形

- 抽检一致率 < 0.80（低于 §3 T4 的下限）⇒ 该批编码结果不得写进〈机会与可行性诊断〉的结论栏，只能作线索；重编码并复抽检合格后才放行。
- 编码覆盖率 < 1.00（存在「未编码」条数）而未逐条标注原因 ⇒ 不得从编码分布推出「优先改进方向」；未编码占比达到或超过 5.0% 时该批只进抽检队列，不得进〈新品验证证据包〉与〈服务与留存方案〉。
- `字典版本` 缺失，或与上一批不一致（口径漂移）⇒ 不得做跨期同比，也不得进入 STG-05 产物。
- 文本含客户姓名、地址、联系方式等个人信息而未脱敏 ⇒ 该批不得进入任何下游产物，先脱敏重跑（三张卡的安全边界均为「评论中的个人信息须脱敏、不得存 PII」）。
- 编码结论被用来表述**需求真实性**（「用户确实需要」）而没有受控外部验证的实物或回执 ⇒ 不得写入 STG-05 产物，只能写成「假设 + 证据等级」；材料口径明写「未经验证的实物与宣称不能进入销售动作」。
