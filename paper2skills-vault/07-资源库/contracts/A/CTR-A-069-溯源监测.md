# 溯源监测 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 是**作业口径** —— 据此产出方案，并把规则落实成方案里的取值。
> §4 / §6 是**放行判据** —— 它们规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**血缘追踪与溯源校验可用图分析与版本比对自动化。**
> 这句话划出本契约的边界：可算的是「一条产出往上追到哪些源、往下波及哪些对象、链路有没有断」；
> 算不出的是「这条产出在业务上算不算对」与「谁批准了这次口径变更」——后者不在本契约内，见 §6。
>
> **本契约覆盖的格**：本责任是 FLOW-06 独有的责任（岗位 AGT-046 数据工程与质量，只参与 FLOW-06）。
> 方法格为 FLOW-06/STG-04（证据收集与诊断）、FLOW-06/STG-05（方案与标准产物）、FLOW-06/STG-08（结果核验、关闭与异步学习），§3 的算式落在这些格上；
> 规则格为 FLOW-06/STG-01（信号接收）、FLOW-06/STG-02（范围确定与 Case 创建）、FLOW-06/STG-03（上下文装配）、
> FLOW-06/STG-06（Assurance 接收门禁）、FLOW-06/STG-07（受控动作），**这些格只放判据与门禁条件**（§6 的落脚处）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境与材料已给出的数（出海历史 2 个完整年度＝决策 Q11；「Amazon 65% / 独立站 15% 之外的其余 20% 渠道构成未明」＝开放事实 O1）；
> （b）业务侧默认（行业惯例或材料已定名的门禁口径，逐条附替换条件）；
> （c）§3 算式的输出（由命名的数据系统直出）。**候选卡的卡面数字与论文参数不构成第四种来源**（逐条清单见 §1）。

## 1 方法来源（卡供方法）

- 方法族：**血缘图的登记、反向溯源与链路健康监测**（把数据源、变换、产出登记为节点与有向边 → 按对象 ID 与时间窗做反向溯源 → 在图上做断链／版本不一致／新鲜度超期的监测与告警 → 沿血缘做影响分析）。族内各卡的方法实现可互换，本契约取的是族骨架，不是某一张卡的实现。

  - `p2s-argos-agentic-anomaly-detection`（源卡号 `Skill-Argos-Agentic-Anomaly-Detection`，源域 09-DataAgent-LLM，图谱 L3 = 运行监测 / 溯源监测）：承担「规则由 Agent 生成 → 语法修复 → 验证集评审 → 与既有统计基线融合抑制误报」这条可解释告警链。
  - `p2s-time-series-anomaly-detection`（源卡号 `Skill-Time-Series-Anomaly-Detection`，源域 03-时间序列，图谱 L3 = 运行监测 / 溯源监测）：承担「分解出趋势与周内季节后只看残差 → 排除节假日与已知促销 → 多指标交叉验证」这条降噪链。
- 可搬的部分（族级，一段话）：把「先登记再查询、先分解再判定、多信号才告警」这条骨架搬到本责任上 —— ① 每一个数据源、每一次变换、每一份产出都登记成节点与边，边必须带变换操作名与版本号，缺任一项该边视为不存在；② 溯源一律按对象 ID ＋ 时间窗反向可达，不做关键词匹配、也不靠人工回忆；③ 监测只看结构信号与残差（断链、版本不一致、新鲜度超期），不看业务量本身的涨跌（涨跌归对应 FLOW 的经营诊断）；④ 单信号只出提示，**≥2 类**信号同时命中才出告警；⑤ 血缘记录只追加不覆盖，回填只写新版本边、不改写历史边。

## 3 标定规则

- 取值来源：自有埋点（〈Case/Event Ledger〉的 Case Charter、Stage Acceptance Record、Execution Attempt 与 NoActionRecord）＋ 平台后台（Amazon 卖家后台与广告后台的报表导出与字段清单）＋ AGT-045 指标契约与主数据（统一对象 ID 与三码映射）；**不引用卡内任何论文参数**（清单见 §1）。
- **T1 血缘覆盖门禁**：`血缘覆盖率 = 已登记边的纳管字段数 ÷ 应纳管字段数`；**应纳管字段** ＝ 该 Case 的〈能力交付Case Charter〉与〈数据/工具交付包〉里点明的数据契约字段（对象 ID、指标名、来源系统、采集时点、版本号）；**已登记边** ＝ 该字段在图上同时存在上游来源边与下游写入边的条数（缺任一侧即不计入分子）。
- 取值：覆盖门禁取 **1.0（100%）**，即应纳管字段一条边都不许缺，缺任一条即判「断链」并按二值门禁处置、**不设部分通过档**。依据＝本项目综述 §E 的 STG-04 最低接收条件 `sources_and_versions_recorded`、`claims_trace_to_evidence` 与 STG-06 的 `deterministic_checks_pass`（**§E 的编号与这些标识符出自本项目综述，不是材料原文**）。**替换条件**：〈Case/Event Ledger〉覆盖满 **2** 个完整年度（决策 Q11）后改用**实测**覆盖率，并逐条列出未追溯字段清单；替换前本结论只能表述为「**未检出**断链」，不得表述为「链路完整」。
- **T2 溯源查询的要素齐备判据**：`要素齐备率 = 齐备要素数 ÷ 5`；五要素 ＝ ① 来源系统 ② 源字段名 ③ 采集时点 ④ 版本号（AGT-045 的 `<签发日>-<序号>` 锚）⑤ 变换操作名与版本号（对齐材料 STG-04 的 `sources_and_versions_recorded` 与 `freshness_and_quality_status_recorded`）。
- 取值：要素齐备率门禁取 **1.0**；五要素缺一不出具溯源结论，只出「要素缺口清单」，并把该字段登记为 FLOW-06/STG-04 的〈能力缺口诊断〉缺口项。
- **T3 断链与新鲜度监测（结构信号，不做业务量预测）**：`断链数 = count(来源系统标识为空 ∨ 变换版本号为空 ∨ 该字段的上游节点在图上不存在)`；`新鲜度超期数 = count(应纳管字段最近一次成功采集时点 晚于 该〈能力交付Case Charter〉写明的统计窗)`。
- 取值：**断链数门禁取 0 条**（零容忍硬门禁）；新鲜度按「**截至前一日 24:00** 的完整快照」判（对齐跨手册通用的工单规则「每项记录统计窗和新鲜度」），超期即置 WAITING 并记 `REC-CASE-EXCEPTION`，**不把缺失值当作零**。
- **T4 告警闸门与误报抑制**：`血缘告警 = 同一 Case × 同一自然日 内，{断链数 > 0、新鲜度超期数 > 0、要素齐备率 < 1.0} 三类信号同时命中 ≥ 2 类`；**告警合并窗口取 1 个自然日**。
- 取值：**告警闸门取 2 类同时命中**（业务侧默认，来源＝行业惯例的「双信号确认」；单一信号只出提示、不告警）。**替换条件**：〈Case/Event Ledger〉的信号序列满 **2** 个完整年度后，按实测误报数与漏报数重定档；替换前该闸门只用于派单排序，**不得单独作为冻结依据**（冻结一律见 §6）。
- **T5 影响分析与记录方式**：`影响面 = 沿血缘反向可达的节点集合`（上游＝该字段的全部来源；下游＝该字段被写入的全部对象与产出）；血缘记录 **append-only**：重填只追加新版本边，不改写历史边；同一 `idempotency_key` 的重复回填按新增版本处理，不覆盖。
- 取值：**影响面清单按对象逐条列出、条数不设上限、不截断**；**历史边改写数门禁取 0 条**（改一条即该批血缘作废）。
- 产出（本规则定值的字段）：FLOW-06/STG-04 的〈能力缺口诊断〉的数据来源与质量段、对象映射段；FLOW-06/STG-05 的〈数据/工具交付包〉里的数据契约条目（来源系统、版本号、新鲜度要求）；FLOW-06/STG-08 的〈能力交付关闭记录〉的质量与运行结果段（断链数、要素齐备率、影响面清单）。

## 4 重标定触发条件

- **口径变**：AGT-045 发布新版本号（统一对象 ID、三码映射、指标名或时间归属变化）；AGT-046 的质量状态、来源、新鲜度三件套的字段定义改版。
- **数据源变**：〈Case/Event Ledger〉首次上线或换版（血缘的边来源随之变化）；平台后台报表结构或字段清单变化；新增数据源被纳入纳管范围。
- **结构变**：CASE-PROTOCOL-8 的阶段产物表或接收门禁版本变化（应纳管字段集合随之重算）；血缘的节点／边类型扩充（例如把工具调用与凭据使用也纳入纳管）。
- **主体变**：开放事实 O1（Amazon 65% 与独立站 15% 之外的其余 20% 渠道构成未明）一旦定名，或新增渠道、店铺、账号主体 —— 纳管范围与断链率基线随对象集合重算。
- **周期到期**：每 2 个完整年度（决策 Q11 的历史长度）重算断链率与新鲜度超期率基线，并按 T4 决定告警档位是否需要调整。

## 6 冻结与不许自动放行的情形

- 断链数 > 0 条（存在来源系统标识为空、变换版本号为空或上游节点缺失的边）⇒ 不得进入 STG-07 受控动作，先补边，或把该 Case 降级为 NoActionRecord。
- 要素齐备率 < 1.0 的溯源结论 ⇒ 不得写入 FLOW-06 Assurance Decision 的接受项，也不得对外披露、不得作为回滚范围的依据。
- 新鲜度超期（未取得「截至前一日 24:00」的完整快照）⇒ 置 WAITING，不得据其关闭 STG-08、不得据其出具溯源结论。
- 影响面仍为「声明式、非读取事实」⇒ 影响面只能用于登记缺口与派单，不得作为回滚范围或对外披露的唯一依据。
- 历史边改写数 > 0 条（血缘记录被覆盖式修订或历史边被删除）⇒ 该批血缘作废并重出，不得在原记录上修订，同时登记为自治异常。
- 跨系统边仍为「弱链」（三码映射未签发到字段级）⇒ 该 Case 的跨系统溯源结论只出提示，不得作为跨系统对账或口径裁决的依据。
- 同一对象的血缘边在当周内已有一次未回填 ⇒ 不得对同一对象出具新的溯源结论、也不得发起新动作；已成功动作不得随整单重跑。
- STG-06 接收门禁未通过，或仍有未解决的语义发现（数据契约字段名与业务语义不一致）⇒ 本责任不得放行，发起方不得覆盖拒绝结论。
- 引用 §1 清单中任一条卡面数字（覆盖阈值、要素数、告警档位、行数与金额）作为本业务取值 ⇒ 该方案不得放行。
