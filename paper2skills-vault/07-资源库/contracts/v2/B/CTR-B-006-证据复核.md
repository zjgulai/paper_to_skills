# 证据复核 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：
> 可达段给算式与取值，不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：证据一致性与伪造检测可 NLP 预筛，
> 但**缺陷定性与结论须独立审计师判断** —— 这就是本契约可达段与不可达段的分界线。

## 1 算法可达部分

- **决策留痕链的完整性与要素齐备性机检**（落 FLOW-07/STG-04、STG-05、STG-08 与 FLOW-08/STG-04、STG-05、STG-08 六个 M 格）：对每一条自动决策留痕逐条重算哈希并比对链上指针，输出链完整率与要素齐备率两个可核验的量化值。
- 算式：`链完整率 = 1 − 断点数 ÷ 应留痕决策数`；其中**断点数** = 〈决策审计留痕表〉中相邻两条记录满足 `prev_record_hash ≠ 前一条 record_hash` 的对数，**应留痕决策数** = 同期 `who_agent_id`、`what_action_type` 非空且 `approval_level ∈ {AUTO, MANAGER, VP, LEGAL}` 的记录条数（含 NoActionRecord）。源字段：〈决策审计留痕表〉的 `record_hash` / `prev_record_hash` / `approval_level` / `estimated_impact`。
- 取值：**链完整率 = 1.000（即 100%）**，对应**断点 0 对**；**要素齐备率 = 1.000（即 100%）**，即八项要素 `who_agent_id`、`who_approval_level`、`what_action_type`、`what_parameters`、`why_trigger_tags`、`why_signal_scores`、`how_algorithm`、`how_algorithm_version` 全非空。
  这两个数是**业务侧默认值**、不是实测值：材料口径下 STG-06 Assurance 接收门禁是**二值门禁**（缺一项即 HOLD，不设部分通过档），故本段只有满值一档；当前取满值的依据是**经营者自述**「AI 动作只经 Case 的 STG-07 受控动作写入，无后台直改、无人工补录」。
  **替换条件**：〈决策审计留痕表〉接入并覆盖满一个完整审计周期后，改用**实测断点数**与**实测缺项数**重算；替换前该结论只能表述为「**未检出**断点」，**不得**表述为「不存在篡改」。
- **动作越权判定（二值）**：`越权动作数 = count(action_type ∉ STG-07 允许动作集)`；允许动作集逐字取材料已定名的 STG-07 动作清单（正常处置、恢复、重新开放、扩大范围、外部承诺、退款、召回、销毁、永久变更，以及 NoActionRecord），且执行时点必须落在 STG-07。
- 取值：**越权动作数 = 0 件**；该值同为**业务侧默认值**（来源同上：经营者自述「自动动作全部经策略闸出单」）。
  **替换条件**：留痕表接入满一个完整审计周期后改为**实测计数**；实测非 0 即触发 §4 冻结第 3 条。
- **待人工复核队列（排序）**：排序键 = （要素缺项数 desc，`|estimated_impact|` desc，`timestamp` asc）；**队列长度 = 当期 `approval_level = AUTO` 的记录全量**（业务侧默认值）。
  **替换条件**：AGT-005〈抽样审计〉责任给出本周期抽样方案后，按该方案的比例截取队列首段派单，其余留档不派单。
- **本段的能力边界**：只做四件事 —— 记录是否可复算、要素是否齐备、动作是否越权、按什么次序送人工；**不产出缺陷定性、不产出复核结论**（见 §2 第 1 条）。
- 本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变。

## 2 不可达部分

- 缺陷定性（判「控制设计缺陷」还是「执行偏差」）与复核结论的签署：算法只能给候选与排序，定性结论属**独立审计师的法定/治理签署**，不可由模型产出。
  → 替代路径：由 AGT-005 内控审计与独立复核岗的持证审计师在 STG-06 Assurance 接收门禁前签署〈复核结论与整改清单〉；补不上时先用「模型候选 + 待签」双栏交付，候选栏不得写入〈FLOW-07 Assurance Decision〉/〈FLOW-08 Assurance Decision〉的接受项，该 Case 只能停在 STG-06；后果是触发 §4 冻结第 1 条，该 Case 不计入本周期复核覆盖率。
- 链外事实：供应商真实产能与是否转包、平台规则原文与生效版本号、产品准入与宣称判定 —— 属**外部事实**，本司系统内不存在可复算字段。
  → 替代路径：由 AGT-014（STG-04 结束前）、AGT-027（STG-04 结束前）、AGT-044（STG-05 定稿前）分别出验厂报告与产能档案、平台政策原文与生效版本、合规矩阵与证据缺口；补不上时先用「平台后台公告截图 + 上一次已生效版本号」顶替并逐条标注「未核验」，凡以未核验规则为依据的动作一律不进 STG-07；后果是相关对象降级为 NoActionRecord 并留人工工单。
- 实物与回执：质量检测报告、到货/签收/退货回执、退款与召回的执行回执 —— 属**实物或回执**，无法由留痕表推出。
  → 替代路径：由 AGT-013、AGT-020、AGT-019 在 STG-08 关闭前逐对象提供；补不上时先用「出库/退款流水号 + 承运商轨迹」顶替为过程证据，关闭结论标注「回执未齐」；后果是 STG-08 只能出「未闭合」记录并留观察窗，不得判为「恢复已验证」。
- 复核独立性：复核人是否参与过被复核决策，属**治理事实**，留痕表只能记录 who、不能证明回避。
  → 替代路径：由 AGT-002 在 STG-03 上下文装配时出具该 Case 的角色清单，以证明复核人未参与原决策；补不上时由 AGT-001 在 STG-06 前指定另一名复核人重做；后果是独立性无法证明的 Case，其 Assurance Decision 判 HOLD 且不计入本周期复核覆盖率（§4 冻结第 5 条）。

## 4 该格何时必须冻结

- STG-06 前未取得 AGT-005 持证审计师签署的〈复核结论与整改清单〉⇒ 该格不得推进到 STG-07 受控动作（含 Approval 级动作），只能出 NoActionRecord。
- 链完整率 < 1.000（检出 ≥ 1 对断点），或要素齐备率 < 1.000（任一记录缺 `why` / `how` 要素）⇒ 冻结该 Case 的证据链部分：STG-08 不得关闭，且不得据该链出根因结论。
- 越权动作数 > 0 件（出现 STG-07 允许动作集之外的动作，例如在 STG-01/02/03 阶段直接改价、下架或退款）⇒ 立即冻结相关对象范围并升级 FLOW-07 紧急保护通道（Emergency Guard），24 小时内补〈Pre-Case Exception〉记录。
- 动作涉及对外承诺、退款、召回、销毁或永久变更，而 AGT-043 法律意见或 AGT-044 合规判定缺失 ⇒ 不得进入 STG-07，只能出 Action Intent + 人工工单。
- 复核人独立性无法证明（既无 AGT-002 的 STG-03 装配角色清单，AGT-001 也未在 STG-06 前指定替代复核人）⇒ 该 Case 的 Assurance Decision 判 HOLD。
- 外部证据时限：自 STG-05 产物提交起，至该 Case Charter 已写明的观察窗截止日仍未取得 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。

|---|---|---|
| ① 获取路径 | 自有埋点 | 非缺口。若某类决策（如线下手工特批）不在本司系统落库：先按〈Case 记录〉的人工备注顶替并标「非留痕」，该类决策纳管后替换为留痕记录；替换前不计入链完整率的分母。平台与供应商类证据不走本维，走 §3 |
