# 契约撰写规范

> 本文件是**作业规程**，不是理念说明。理念在 `README.md`，字段定义在两份 `TEMPLATE-*.md`。
> 一句话：**你写的是「这份工作该怎么干」的取值口径，不是「这张卡讲了什么」的摘要。**

> ### v2 总纲：**只写禁令不写义务，产出必然是留白**
>
> F6 实测：v1 只写了「不许凭空给数字」，没写「必须给出业务取值」，于是模型选择**不给数** ——
> 量化判据中位数 **3**（对照 19.5 / 单卡 22），弃权语中位数 **2**（其余两臂 0），
> 缺口句处置率 **0.000**（写了缺口，从不写「那先用什么」）。
> 它确实读了契约（6/10 用上契约算式）—— **是被说服了，不是忽略了**。
>
> ⇒ 本规范 v2 的每一处改动都是**补上与禁令对称的义务**。写作时请把它当成自检：
> **每写一条「不许 X」，就问一句「那必须 Y 是什么」；写不出 Y，那条禁令就不要写。**

## 1 输入（撰写前必须拿到的东西）

| # | 输入 | 从哪拿 |
|---|---|---|
| 1 | 责任名 / 岗位 / 域 / 平面 / 服务性 / flows / method_cells / rule_cells | `build_contracts.py --skeleton <责任名>` **直接生成 frontmatter** |
| 2 | 方法来源卡 | 卡库（vault 精选卡 `paper2skills-vault/<域>/Skill-*.md`，或已装 p2s 卡 `~/.dsh/skills/<slug>/SKILL.md`） |
| 3 | 业务处境 | 题面/任务原文，或 `_survey_org_model.md` 的岗位 title 与该责任的判定理由 |
| 4 | 该责任的 A/B 判定理由 | `_survey_org_model.md` §F.3 逐条表（一行） |
| 5 | 阶段的业务步骤与标准产物 | `capability-graph.json` 的 `cells[]`（`business_step` / `business_output_name`） |

**缺 2（没有卡）时不要硬写方法** —— 把 `cards` 留空、`status: 待卡`，
正文照模板写「本业务该怎么做」，方法来源段写「无卡，方法待认领」。
**「待卡」不是失败，它就是扩充工单。**

## 2 取值来源白名单（防编造的唯一防线）

契约要给出**本业务的取值或取值算式**。取值只能来自下列三类，**此外一律不许出现数字**：

| 允许 | 例子 | 形态 |
|---|---|---|
| ① 业务处境里**已经给出的**数字 | 「500 个 SKU × 10 个维度」「人工更新一轮 = 一周」「月账单 8000 美金」 | 可直接引用，注明「来自业务处境」 |
| ② 材料里**已定名的**规则 / 产物 / 岗位 | STG-06 Assurance 接收门禁、AGT-045 指标契约、`业务规则字典`、`经营证据与偏差诊断` | 引用其名，不引用其值 |
| ③ 命名的**数据系统** | 独立站埋点、平台后台报表、采购台账、财务对账表、库存台账、Case/Event Ledger | 写成**算式**：「按 <源> 的 <字段> 算 <量>」 |

> ⚠️ **示例里的名字必须能在材料里 grep 到**（2026-09-13 S1 实测教训）。
> 上表原把 `业务规则字典`、`标签分配结果表` 列为示例，**这两个名字在《AI组织变革》材料里 0 命中** ——
> 它们是 F6 小样本试点契约**自造**的拟建产物，经本规范与 S1 作业包两层传播，
> 一度被下游当成「材料词汇」引用（S1 逐份扫描：35 处命中、其中 6 份契约把它当作**尚未签发**的产物引用，
> 口径本身没错，错的是**来源标注**）。
>
> **规则**：**待建/未签发**的产物可以点名，但必须写成「〈X〉（**尚未签发**）」并给出替换条件，
> **不得**当成既有系统直出取值 —— 那是「凭空给数字」的更隐蔽形态（数字挂了一个不存在的源）。
> 示例一旦写进规范就会被下游当成事实引用，所以示例本身也要能被核。

**禁止的三种动作**：

1. ❌ **把卡里的论文参数写成本业务取值** —— 那是本模板要拦的东西本身。
2. ❌ **凭空给一个没有来源的数字**（「建议阈值取 0.75」而说不出它从哪来）。
3. ❌ **以「待标定 / 需重新标定 / 临时默认值」结案** —— 这三句是把判断推回给读者，
   SkillOpt 补丁正是死在这里（对冲措辞 26/40，Δ 从 −0.95 变 −1.10）。

**都必须做到的两种动作（v2 新增，与上面的禁令对称）**：

4. ✅ **给出取值或区间** —— 算式算得出来就写出来，**不许只写算式不给数**。
5. ✅ **缺口必须带处置** —— 任何一句「本业务暂无此数据 / 未定名 / 不可得 / 需授权」，
   **同段或同格**必须接着回答「**那先用什么**」和「**什么条件下换成什么**」。
   **缺口陈述不是结论的终点，是它的前半句。** 只写前半句 = v1 的失败形态（处置率 0.000）。

> ### ⚠️「临时默认值」为什么既在禁令里、又在义务里 —— 分界线在**取值从哪来**
>
> | 写法 | 判定 | 依据 |
> |---|---|---|
> | 「阈值取自论文实验条件，标定前当**临时默认值**」 | ❌ 禁止 | 把**论文参数**留作默认值 —— SkillOpt 补丁的死法，实测 Δ −1.10 |
> | 「暂无本业务数据，**先按**经营者自述的 30 天账期**暂按** 0.8 判，〈采购台账〉满 2 个完整年度后**替换**为实测值」 | ✅ 必须 | 默认值来自**业务侧**，且写明了替换条件 |
>
> 两条的分界**不是有没有写「暂」字**，而是**那个数从哪来**：
> 论文侧 ⇒ 禁止（那是移植）；业务侧 + 替换条件 ⇒ 必须（那是判断）。
> 只禁前者不禁后者，就是把判断权整个收走 —— v1 实测的后果。

**都没有的时候怎么办（v2 已收紧）**：先按上面第 5 条写「本业务暂无此数据」**加替代取值与替换条件**；
**只有连替代都举不出来时**，才允许只写缺口陈述，把 `status` 置 `数据待盘`，
并在 `blocked_by` 里写清缺哪一维（五维里的哪一维）**以及「连替代都举不出」的原因**。
**这是合法结论，且缺口进账** —— 但它现在是**最后手段**，不是第一反应。

## 3 硬规则（写错即被 `check_contracts.py` 判红）

| # | 规则 |
|---|---|
| R1 | **frontmatter 一个字符都不要手改。** 它由图谱生成；手改会造成第二份事实源 |
| R2 | 六段标题**逐字照抄模板**（校验器按标题定位；改标题等于删段） |
| R3 | `cards` 里的 slug 必须真实存在（J12）—— 不要写「某卡」或润色过的名字。**契约按「责任」建，不按「卡」建**：`cards` 是「同族方法卡」的清单，正文必须写一句「本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变」 |
| R4 | 「不得移植的部分」必须**逐条列出具体数值**（A 模板），不得写成通用免责条款 |
| R5 | 不可达部分必须至少一条命中三类（外部事实 / 实物回执 / 法定签署），否则复核 A/B 归属（B 模板） |
| R6 | 数据要求五维**每一维都要有值**；① 必须是五个枚举值之一；**第三列「缺值处置」在取值为缺口时必填**（v2 改） |
| R7 | 责任岗位必须是**图谱 50 岗位之一**（B 模板第 3 段） |
| R8 | 「冻结条件」必须可判定（缺什么证据 / 超什么时限 / 命中什么规则），不许写「视情况」 |
| R9 | **正面义务（v2 新增，J13 机检）**：A 模板 §3 必须产出**取值**（数字+单位）；B 模板 §1 必须写出**算式**并给出**取值**。若以缺口结案，则必须同时写出替换条件词（替换 / 失效 / 改用 / 顶替 / 先行 / 暂按 / 到位后） |
| R10 | **B 模板 §2 的每一条不可达都必须紧跟 `→ 替代路径：`**（谁在什么时点补上、补不上时先用什么）。缺一条即红 —— 「不可达」是分工，不是免责 |

## 4 `status` 的唯一口径（实测撞出来的口径分歧，先定死再写）

F6 小样本实测时，两位撰写人对同一批材料给出了**不同**的 status（一个判 `数据待盘`、一个判 `可写`），
理由都说得通 —— 这类分歧若不先定死，139 份契约会各写各的。故定死：

| status | 判据 |
|---|---|
| `待卡` | `cards` 为空（无方法来源卡）。**这不是失败，它就是扩充工单。** |
| `数据待盘` | 五维中**任一维只能写成缺口陈述**（如「尚无被 AGT-045 定名的统一口径」「字段集与保留期未定」）**且举不出替代取值**。`blocked_by` 必须点名是**哪一维**，并写明「连替代都举不出」的原因。⚠️ **v2 收紧**：写了缺口但**给了替代取值与替换条件**（R9/R10 的形态）**不算缺值**，不因此判 `数据待盘` |
| `方法待启用` | 方法本身缺前置能力（如 6 条增量测量类需先建独立站 holdback）。`blocked_by` 写清缺哪项能力。 |
| `可写` | 以上都不成立，且 §3 标定规则能当场写出算式**并给出取值**（v2：只写算式不给值不再是 `可写` 的充分条件）。 |

**两条不算缺值**：`需授权` 与 `不可得` 都是**合法取值**（「不可得」按 J6 记账）。
**一条算缺值**：某维的值本身是一句「尚未定名 / 待定 / 未知」—— 那不是取值，是缺口。

## 5 输出

一个 Markdown 文件，落到：
```
paper2skills-vault/07-资源库/contracts/A/CTR-A-0NN-<责任名>.md
paper2skills-vault/07-资源库/contracts/B/CTR-B-0NN-<责任名>.md
```

（`contract_id` 与文件名都由生成器给出，照抄即可。）

> ⚠️ **v2 期间的两个目录**：`contracts/v2/` 下放的是**按 v2 模板写的**契约（F7 实测的处理臂），
> 由生成器写入 `template_version: 2`；`contracts/A|B/` 下的无该字段 ⇒ 按 v1 口径核（J13 不适用）。
> S1 之后统一走 v2，两个目录合并。

写完自验：

```bash
python3 paper2skills-research/scripts/check_contracts.py --file <路径>
```

## 6 反面样例（这些写法在实测中都被判低分）

| 写法 | 为什么错 |
|---|---|
| 「阈值信息熵 ≥ 0.65」（照抄卡里论文实验参数） | 参数移植 —— 本模板拦的就是它 |
| 「阈值取自论文实验条件，须用我司数据重新标定，标定前当临时默认值」 | 对冲结案 —— SkillOpt 补丁的写法，实测 26/40 挂上对冲措辞、Δ 变 −1.10 |
| 「建议结合实际情况设置合适阈值」 | 既无来源也无算式，且不可判定 —— 比前两种更糟，因为它连「缺什么」都没说 |
| **「本业务暂无此数据」就收尾**（v2 新增的反面） | 缺口陈述不是结论 —— F6 实测：契约臂缺口句处置率 **0.000**，整份交付物停在缺口上。必须接着写「那先用什么、何时换」 |
| **只写算式不给数**（v2 新增的反面） | 「可复算」是形容词不是取值；模型照抄算式而不敢代入，产出仍是无判据的说明 |

**正确写法的样子**：`阈值 = 按〈标签分配结果表〉近 2 个完整年度的 <标签×分组> 分配率，取各分组分配率的最大差；
差值 > 业务规则字典里该标签的容差档时判为偏见。` —— 有源、有算式、可判定，且没有一个凭空数字。

**缺口带处置的样子**：`③ 回溯深度：本业务暂无 —— 先按经营者自述的「近 2 个完整年度」取，
〈采购台账〉接入后替换为台账实际首单日；替换前该值不得用于跨年同比。`
—— 前半句是缺口，后半句是判断；两句缺一不可。
