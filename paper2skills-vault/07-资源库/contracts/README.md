# 契约层（L4）

> **这一层存在的理由是一个实测负结果：给模型一张算法卡，交付物质量反而下降。**
> `dsh-paper2skills/docs/eval-report.md`：run1 holdout Δ=−0.85（p=0.0038）、v2 holdout C-vs-T Δ=−0.95、
> C-vs-S Δ=−1.95（p=0.0001），六个对比方向完全一致，判官噪声 ±0.6~0.7 ⇒ 都是真信号。
> 机制：**卡里装的是论文的方法与参数，而任务问的是这家公司该怎么干** ——
> 模型把「信息熵 ≥ 0.65」当业务阈值，把「欺诈召回由基线 42% 提升至 ≥60%」当既成事实。
>
> ⇒ **契约就是那个强制翻译层**：卡供方法，契约供业务取值与标定规则。

## 1. 规模与切分

```
L0 岗位    50 个 AGT（4 面 / 8 域）
L1 责任    151 细分业务（MECE 划分，每条唯一属一岗）
L2 场景    8 FLOW × 8 STG = 64 格（M24 / R16 / D24）
L3 方案    8 份方案域（= 8 FLOW）        ← 人类可读长文
L4 契约    139 份供给契约（A73 + B66）    ← 机器可校验短表  ← 本目录
L5 模型    N 张算法卡（挂载点 = L4 契约）
```

**139 = 151 − 12。** 减掉的 12 条是 C 类（难算法化：组织程序、人际协作、法定程序、创造性专业判断）。
**给 C 类建契约只会制造形式主义** —— 没有算法会来认领它，契约会退化成一张填满「不适用」的表。

### 1.1 两种模板，拦两种不同的错

| | **A · 标定契约**（73） | **B · 完整性契约**（66） |
|---|---|---|
| 对应责任 | 算法可服务性 = **A**（可作主引擎） | 算法可服务性 = **B**（需补外部证据后匹配） |
| 拦什么 | **参数移植** —— 把论文实验条件的取值当业务取值 | **完整性虚报** —— 算法只做了一段，却宣称整条责任已覆盖 |
| 必备字段 | 方法来源（卡）/ 数据要求五维 / **标定规则** / 重标定触发条件 / 适用 FLOW | 算法可达部分 / 不可达部分 / **必须的外部证据与责任岗位** / 该格何时必须冻结 / 适用 FLOW |
| 成本 | 高（每条要读卡、定标定规则） | 低（判定理由在 `_survey_org_model.md` §F.3 已逐条写好，可半自动生成） |

模板正文：`TEMPLATE-A-标定契约.md` · `TEMPLATE-B-完整性契约.md`。撰写作业规程：`撰写规范.md`。

### 1.2 契约的两种状态

> ⚠️ **本节 2026-09-13（S1 第一批）重写过一次，理由与 F3 §4.2 同型：上游变了 + 口径原先没写清。**
> 旧版记「可写 53（A 37 + B 16）/ 待卡 86」——那是 **F6 时点、且只认精选线**的快照。
> 现在两条都变了：① F5 给 53 张卡补了 L3（精选线口径 53 → **67**）；
> ② 契约的 `cards` 改按**消费口认的键**取（见下表口径说明），于是 67 → **127**。

**`cards` 的取值口径（S1 定死）：候选 = 已装线 ∪ 精选线，按 `id` 建联。**

| 线 | 事实源 | 规模 | 角色 |
|---|---|---|---|
| **已装线**（消费口） | `dsh-paper2skills/data/classification.json` | 1338 张 | `cards` 优先写它的 **slug**（S12 的预设白名单认这个键） |
| **精选线**（精选前台） | `card-classification.json`（F5） | 146 张 | 与之按 `id` 建联的是 **93 张**（正是 F5 逐字继承的那 93 张）；未换底的 53 张按卡名引，注明 S5 换底后替换 |

| 状态 | 判定 | 全库 139 | FLOW-01（54 份） |
|---|---|---|---|
| `可写` | 该责任在任一线有卡 | **127**（A 69 / B 58） | **52**（A 39 / B 13） |
| `待卡` | 两条线都没有 —— **这条契约本身就是扩充工单** | **12** | **2**（线索评估 · 渠道方案） |
| `数据待盘` | 五维任一维只能写成缺口陈述**且举不出替代取值** | 随盘 | 随盘 |
| `方法待启用` | 方法本身缺前置能力（如 6 条增量测量类需先建独立站 holdback） | 6 | 6 |

> 📌 **`cards` 的口径 ≠ 缺口账的口径，两者不要互相换算。**
> 缺口账（F3）问的是「**有没有精选卡**」（供给质量，分母 146 张精选卡 ⇒ 可写 67/待卡 72）；
> 契约问的是「**这份工作的方法可以从哪些卡来**」（可用方法，分母是消费口的 1338 张 ∪ 精选线 ⇒ 可写 127）。
> 混同会出现「127 可写」与「36 条靶区一零精选卡」看似打架的假冲突 —— 它们回答的不是同一个问题。
> 对照数字：**同一批 139 份契约，只认精选线时 67 可写 / 72 待卡。**

> **「待卡」不需要另造一份 gap ledger。** 契约先存在，卡去认领。
> 认领制是 Q4 明确放弃的强门槛，故只登记、不拦截。
> **但也正因如此，契约的「可写/待卡」状态不构成任何门禁放行依据** —— 它是缺口账，不是通行证。

### 1.2.3 「还剩多少份」也是算出来的（首归 FLOW 口径）

S1 第二批起，作业包不再装「本 FLOW 的全部契约」，而是**只装还没写的那部分**：

```sh
python3 paper2skills-research/scripts/build_contract_workpack.py --audit-pending
```

两条规则缺一不可：① 该契约**尚未撰写**（骨架里还有 `<!-- 待撰写 -->`）；
② 它**不属于任何更小编号 FLOW 的批次**。

> 第 ② 条不是洁癖：契约**按责任建、不按 FLOW 建**，一条责任可以同时属于多条 FLOW 的批次
> （8 条 FLOW 的批次规模相加 = **397**，而契约只有 **139** 份）。
> 没有第 ② 条，同一份契约会在两条 FLOW 的作业包里各出现一次，被两个撰写人**各写一遍**。

于是有一条恒等式，`--audit-pending` 把它当**可失败的判据**跑：

```
Σ_k pending(FLOW-k) = 139 − 已撰写
```

- 左 > 右 ⇒ 有契约被重复派工；左 < 右 ⇒ 有契约**一条 FLOW 都没认领**（永远不会被写，而账上看不出来）。
- ⚠️ **不要**拿「八个 FLOW 的批次规模之和（397）」当分母去算缺口 —— 那是**覆盖**不是**划分**，
  拿它算会得出「还差 258 份」这种假缺口（S12 报告里「127+978=1105≠1338」是同型）。

实测（2026-09-13 铺完 139 份骨架、写完全部 54 份之后）：

| FLOW | 批次 | 已撰写 | 归更小 FLOW | **待撰写** |
|---|---|---|---|---|
| FLOW-01 | 54 | 54 | 0 | **0** |
| FLOW-02 | 73 | 22 | 0 | **51** |
| FLOW-03 | 36 | 22 | 5 | **9** |
| FLOW-04 | 54 | 27 | 21 | **6** |
| FLOW-05 | 41 | 16 | 19 | **6** |
| FLOW-06 | 37 | 19 | 9 | **9** |
| FLOW-07 | 55 | 16 | 36 | **3** |
| FLOW-08 | 47 | 22 | 24 | **1** |
| **合计** | **397**（覆盖） | — | — | **85**（划分） |

> ⚠️ 读这张表最容易犯的错：以为「FLOW-07 只有 3 份契约」。
> 真意是「FLOW-07 批次里的 55 条责任，52 条已在别条 FLOW 的批次里写过，只剩 3 条没写」——
> **契约是责任的，不是 FLOW 的。**

## 3. 数据要求五维（Q12 / S11）

**与 registry 的 `data_availability` 彻底分开。** 那一个描述的是**论文自己的评测集/代码公不公开**；
本栏描述的是**本公司系统里有没有这份数据**。把两者混同是一个类别错误 ——
**论文数据公不公开 ≠ 本公司拿不拿得到。**

| 维 | 取值 |
|---|---|
| ① **获取路径** | `自有埋点` / `平台后台` / `第三方 API` / `需授权` / `不可得` |
| ② 粒度 | SKU / 订单 / 用户 / 日 / 月 …… |
| ③ 回溯深度 | 与 Q11 的「2 个完整年度」直接对账 |
| ④ 新鲜度 | 对应 AGT-046 清源的「带质量状态、来源和新鲜度」 |
| ⑤ 口径归属 | 是否已被 AGT-045 主数据契约定名 |

**三条反后门（豁免条款必须比拦截条款测得更严）**：

1. **不得只写「数据可得」** —— 必须点名 ① 的取值之一；未点名者**视同未填**。
2. **「不可得」是一个合法结论**，不得因「影响契约完成度」被改写成 `partial` 或 `可写`。
   写「不可得」时 `status` 必须为 `数据待盘`（缺口在账上可见），而不是在正文里留一句对冲。
3. 五维中任一维缺失 ⇒ 契约标为 `数据待盘`，**而不是默认其余四维成立**。

## 4. 反对冲纪律（本层最容易死的地方）

SkillOpt 补丁就是死在这里：它给 1338 张卡加了一句**全局对冲条款**
（「本卡正文出现的数值都是原论文实验条件下的取值……标定完成前只能当临时默认值」），
结果 **26/40 份产出挂上对冲措辞**（其他三臂 0/40），Δ 从 −0.95 变成 **−1.10** ——
**条款把「敢下判断的方案」变成了「处处留白的说明」**，判官否决理由直接引用了它自己写的话。

所以本层立三条：

1. **契约必须给出本业务的取值或取值算式**，不能只说「需重新标定」。要说清
   **用哪份数据、按什么口径、算出什么**。
2. **不许把论文参数留作「临时默认值」**。论文参数只有两种命运：写进「不得移植」清单，或被本业务取值取代。
3. **确实没有数据时，写「不可得」并置 `status: 数据待盘`** —— 这是合法结论，且有账可查；
   而「阈值待标定」不是结论，是把判断推回给读者。

> 这三条与 PHASE5 X1 的「作者外推」三态机制是**同一条纪律的反方向**：
> X1 是「论文里没有的事实不许当事实」，本层是「论文里的取值不许当本业务的取值」。

### 4.1 ⚠️ 上面三条**只有禁令、没有义务**，实测因此失败（F6 → v2 的由来）

F6 小样本实测（`PHASE6-F6-契约层小样本实测.md`）：契约臂是三臂里**最差**的一臂 ——
量化判据中位数从 19.5/22 掉到 **3**，弃权语中位数从 0 升到 **2**，缺口句「处置率」**0.000**。
模型确实读了契约（6/10 用上契约算式），**是被说服了，不是忽略了**：
读到「不许凭空给数字」+「这些数字是别人的」，它选择**不给数**。

> 📌 **只写禁令不写义务，产出必然是留白。**
> 这与「豁免条款要比拦截条款测得更严」同源 —— **义务条款也要比禁令条款测得更严。**

**v2 的三处补丁（补上与禁令对称的义务）**：

| # | v1 的形态 | v2 的要求 |
|---|---|---|
| 1 | §3/§1 只写算式，「取值」可留空 | 必须产出**业务取值**；算不出时给**业务侧默认值 + 替换条件**，不得留白 |
| 2 | 五维只有「取值」一列 | 加**第三列「缺值处置」**：缺口必须同格回答「先用什么 + 何时换」 |
| 3 | B §2 只写「不可达」 | 每条不可达必须紧跟 `→ 替代路径：`（谁在何时补、补不上怎么办） |

**分界线（写错就白写）**：把**论文参数**留作默认值 = 禁止（SkillOpt 补丁的死法）；
给**业务侧**默认值 + 写明替换条件 = 必须。分界不在有没有「暂」字，而在**那个数从哪来**。

对应判据 **J13**（只对 `template_version ≥ 2` 生效；v1 底本免检并由校验器**如实报出免检份数**）。
