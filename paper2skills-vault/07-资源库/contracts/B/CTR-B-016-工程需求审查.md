# 工程需求审查 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：
> 可达段给算式与取值，不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：需求追溯与冲突检测可半自动化，
> **但工程可行性判定需实物试验** —— 这句话就是本契约可达段与不可达段的分界线：
> **追溯、冲突与影响面可以算；「能不能做出来」不许算。**
>
> 本责任由 `AGT-011` 硬件结构与材料工程承担，在 FLOW-02（新品需求到商业验证）与
> FLOW-07（重大质量与账号事件）两跳上出现。§1 的算式落在两跳的方法格
> （FLOW-02 与 FLOW-07 的 STG-04 证据收集与诊断、STG-05 方案与标准产物、STG-08 结果核验关闭与异步学习）；
> §4 的判据落在两跳的规则格（FLOW-02 与 FLOW-07 的 STG-01 信号接收、STG-02 范围确定与 Case 创建、
> STG-03 上下文装配、STG-06 Assurance 接收门禁、STG-07 受控动作）—— **这些格只放判据与门禁条件**。
>
> **本责任没有候选方法卡 —— 本契约就是它的扩充工单**（`cards: []`、`status: 待卡` 如实记账，见 §1 第 1 条）。
> **取值来源纪律（全文适用）**：本契约出现的每个条数、比例与档位，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度** ＝ 决策 Q11）；
> （b）**业务侧默认值**（经营者自述 / 行业惯例 / 材料已定名的产物，逐条附替换条件）；
> （c）§1 算式由命名的数据系统直出。**本责任没有第四种来源可言 —— 因为它连一张卡都没有。**

## 1 算法可达部分

- **卡状态：无卡，方法待认领。** 本责任候选方法卡 **0 张**（作业包 `flow-02-batch-11.md` §CTR-B-016 记「候选总数 0」；有全文卡 0、legacy 预览版 0、仅精选线 0）。**这不是免责声明，本条就是这条责任的扩充工单** —— 下面 §1 的算式由**本业务台账与实物证据**定值，不依赖任何卡；方法到位后按同一份算式接管，数据要求、标定规则与冻结条件不变。
- **扩充工单（认领时应满足的方法族，逐条可核验）**：① **需求追溯矩阵** —— 建立「需求 → 设计规格 → 验证项」三段链接，输出孤儿需求清单与覆盖率；② **需求冲突检测** —— 把需求拆成可比较的区间（尺寸与公差、材料与工艺、电气与安规、包装与运输、成本上限五维），输出区间不相交或方向相反的需求对；③ **约束满足式可行性预筛** —— 在硬约束（安规限值、结构强度下限、成本上限）下判可行域是否为空，只出「可行 / 需放宽哪一条」，**不出**可行性结论；④ **变更影响传播** —— 沿 BOM 与规格依赖图算连通分量，输出受影响对象数与影响面；⑤ **失效模式到规格项的映射** —— 把 FLOW-07 的失效模式映射到具体规格项与公差，输出未落到规格项的清单。认领后方法只挂在方法格（FLOW-02 与 FLOW-07 的 STG-04 / STG-05 / STG-08），规则格仍只放判据。
- **可达段一（需求追溯覆盖率与孤儿需求）**
  - 算式：`追溯覆盖率 = 「需求 → 设计规格 → 验证项」三段链接齐全的需求条数 ÷ 应追溯需求条数`；`孤儿需求数 = 无下游规格或无验证项链接的需求条数`。
  - 产出：〈机会与可行性诊断〉的「需求与假设」栏、〈新品验证证据包〉的「产品定义与工程风险」段由本规则定值。
  - 取值：**追溯覆盖率 = 100%**、**孤儿需求数 = 0 条** —— 二值门禁，不设部分通过档。依据是材料口径「未经验证的实物与宣称不能进入销售动作」（PB-002 原文）：需求没有对应的验证项，等于把未验证项带进了销售动作。
  - 替换条件：〈工程需求台账〉（**尚未签发**）接入后改用台账实测条数；台账到位前该结论只能表述为「本 Case 内**未检出**孤儿需求」，**不得**表述为「需求已全覆盖」。
- **可达段二（需求冲突对数）**
  - 算式：`冲突对数 = count{ 需求对 (i, j) 在同一维度上区间不相交或方向相反 }`；比较维度五条：尺寸与公差、材料与工艺、电气与安规、包装与运输、成本上限。
  - 产出：〈新品验证证据包〉的「工程与供应风险」段、〈新品验证关闭记录〉的转向结论由本规则定值。
  - 取值：**冲突对数 = 0 对**方可进入 STG-05 定稿；**冲突对数 ≥ 1 对**即出冲突清单，逐对写清「哪两条需求、在哪个维度、各取什么值」，交 AGT-009 产品定义与商业立项裁决。
  - 替换条件：〈工程需求台账〉与实物试验数据接入后，冲突判定**替换**为「含实测值的比对」；替换前冲突结论一律标「待实物确认」，只能把该 Case 挂起（既不得据此终止工程方案，也不得据此判可行）。
- **可达段三（变更影响面）**
  - 算式：`受影响对象数 = 从变更需求出发、经 BOM 与规格依赖图可达的对象数`；`变更影响面 = 受影响对象数 ÷ 在产对象总数`。
  - 产出：〈机会与可行性诊断〉的范围栏、〈新品验证Case Charter〉的停止条件由本规则定值。
  - 取值：**变更影响面 ≤ 10%** 判局部变更（留在 STG-05 内做方案修订）；**> 10%** 判全局变更（回 STG-02 由 Case Control 重开范围）。10% 是**业务侧默认值**（来源＝经营者自述「一成对象被牵动就当整机重走一遍」）。
  - 替换条件：本岗 A 类责任〈BOM与材料分析〉给出本司实际 BOM 层级与在产对象数后，两档**替换**为按实际影响面分布的 **P75** 分档；替换前 10% 只作分级提示，不作重开立项的唯一依据。
- **可达段四（失效模式到规格项的映射率）**
  - 算式：`规格项命中率 = 已落到具体规格项或公差的失效模式数 ÷ 已确认失效模式数`。
  - 产出：〈事件范围与根因诊断〉的根因栏、〈重大事件关闭与全动作对账记录〉的恢复验证栏由本规则定值。
  - 取值：**规格项命中率 = 100%** —— 二值口径：未落到具体规格项或公差的失效模式只能写「假设」，不得写「结论」，故不存在「部分命中」这一档。
  - 替换条件：批次追溯与检测报告接入后改用系统直出的条目数；替换前「假设 / 结论」两栏不得省略、不得合并。
- **本段的能力边界**：只做四件事 —— 需求是否可追溯、需求对是否冲突、变更影响面多大、失效模式能否落到规格项；**不做工程可行性判定、不出验证通过结论、不判供应商能不能做出来**（见 §2 第 1–6 条）。
- **认领时的准入条件**：方法卡到位后，必须在 §1 补出该卡卡面全部带数字段落的清单并逐条标注「不得移植」；**本契约现在没有这张清单，因为候选卡为 0，没有任何卡面数值可移植**。
- **本契约对同族方法卡通用；换卡时只替换方法实现，数据要求、标定规则与冻结条件不变。**

## 2 不可达部分

- 不可达①（需**实物试验**）—— 工程可行性判定：结构强度、公差可达性、材料在真实工况（跌落、拉力、老化、温升、清洁与消毒）下的表现，只能由实物实测给出。
  → 替代路径：由 AGT-013 产品验证与研发项目在 STG-05 定稿前出手板/试产测试方案与实测报告、AGT-018 生产协同与质量控制出产线实测与批次不良数据；补不上时先按「同类在产型号的既有实测数据 ＋ 供应商规格书」顶替并逐条标「非本机实测」，后果是可行性结论一律标「待实物验证」，模具与量产类动作冻结在 STG-06 之前。
- 不可达②（需**外部事实**）—— 供应商真实工艺能力与产线公差（能否做到图纸公差、是否转包、产能节拍）。
  → 替代路径：由 AGT-014 OEM供应商开发与协同在 STG-04 结束前出产能与工艺能力档案、必要时附验厂结论；补不上时先按供应商规格书与历史来料检验记录顶替并标「供方声明未核」，后果是该供应商不进模具与量产候选集，只能并行设计。
- 不可达③（需**外部事实 ＋ 法定签署**）—— 材料与安规合规判定：母婴品类的材料证书、可迁移元素与邻苯限值、燃烧与结构安全要求、目标市场的准入清单。
  → 替代路径：由 AGT-044 产品合规与隐私在 STG-05 定稿前出准入证据矩阵与证据缺口，证书由具备资质的第三方实验室出具、由 AGT-044 判定适用性；补不上时先拿上一版已生效证书与供应商声明顶上去，逐条注明「未覆盖新料号」；缺了它，涉新材料与新市场的需求落不到实做上，本 Case 的工程方案只能悬着。证书与准入证据矩阵补齐后整批替换；在此之前这类动作只出意图，不落到 STG-07
- 不可达④（需**治理签署**）—— 需求方意图与商业取舍：成本上限与性能指标之间的让渡、公差能否放宽、功能能不能砍。
  → 替代路径：由 AGT-009 产品定义与商业立项在 STG-02 / STG-05 出产品需求定义与取舍记录，涉成本让渡由 AGT-041 经营财务与资金出经济性结论；补不上时先按〈新品验证Case Charter〉已写明的验证目标与停止条件顶替并把冲突挂起（**不得擅自选一边**），后果是该 Case 停在 STG-06 判 HOLD。
- 不可达⑤（需**实物或回执**）—— 模具与工装的实物状态：试模件、首件检验报告、封样件与签样记录。
  → 替代路径：由 AGT-014（模具与工装方）与 AGT-018（首件检验）在 STG-08 关闭前逐对象提供试模件、首件检验报告与封样记录；补不上时用模具图与供应商自检记录先当过程证据，逐对象注明「无实物回执」；缺了它，STG-08 的验证通过集合里分不清「真做出来了」与「图纸上说能做出来」，本 Case 的关闭也就没有实物支撑。试模件与首件报告交齐后整批替换；在此之前关闭栏只写「未闭合」并留观察窗
- 不可达⑥（需**实物回执**）—— 失效件的实物证据：跌落/拉力/老化后的失效件、客诉退回实物、现场使用痕迹。
  → 替代路径：由 AGT-013 与 AGT-038 体验洞察与质量反馈在 FLOW-07 的 STG-04 结束前提供失效件与检测报告，退货侧由 AGT-020 仓储履约与退货处置出退回与签收回执；补不上时把客诉文字与用户上传的图片编成一份失效模式候选清单并挂「无实物」标记；缺了它，§1 可达段四的规格项命中率没有可落点的实物项，FLOW-07 的〈事件范围与根因诊断〉只能停在假设栏，STG-08 的恢复验证栏也无从判。实物件与检测报告补齐后整份替换；在那之前不得判「已恢复」

## 4 该格何时必须冻结

- 需求冲突对数 ≥ 1 对且未取得 AGT-009 的取舍记录 ⇒ 不得推进到 STG-07 受控动作，只能出 NoActionRecord。
- 追溯覆盖率 < 100%（存在孤儿需求：无设计规格或无验证项链接）⇒ STG-05 的〈新品验证证据包〉不得定稿。
- 工程可行性结论只有供方声明或自评判断、没有手板/试产实测报告 ⇒ 冻结模具、工装与量产类动作。
- 涉新料号或新材料，而无 AGT-044 的合规结论或第三方材料证书 ⇒ 不得进入 STG-07 的送样与量产类动作。
- 供应商工艺能力只有供方声明而未核（无产能档案或验厂结论）⇒ 该供应商不进模具与量产候选集，可并行设计。
- FLOW-07 侧根因未落到具体规格项或公差（只有描述性表述）⇒ STG-08 不得关闭，只能写「未闭合」并留观察窗。
- 实物回执缺失（试模件、首件检验报告、封样件、失效件）⇒ 该对象不进本 Case 的验证通过集合，STG-08 不得判「恢复已验证」。
- 同一对象在当周已有未回填的工程变更 ⇒ 不得重复发起；已成功的验证动作不得随整单重跑。
- 命中 FLOW-07 的质量异常、严重客诉或账号重大风险口径 ⇒ 移交 FLOW-07 紧急保护通道（Emergency Guard），本格不得自行处置。
