# 接口契约 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：
> 可达段给算式与取值，不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**契约生成与兼容性检查可工具化，但语义与责任边界须双方确认**
> —— 这就是本契约可达段与不可达段的分界线。岗位 AGT-047 接桥 · 系统集成与业务工具（DOM-08 / PLN-PLT），
> 适用 FLOW-06 需求到数据产品与业务工具（PB-006），场景 SCN-020；本责任的产物是**工具能力与验收包**，
> 考核口径是**需求到验收时间和复用率**。
>
> **本契约覆盖的格**：方法格 FLOW-06/STG-04、FLOW-06/STG-05、FLOW-06/STG-08 —— §1 的三条算式落在这些格；
> 规则格 FLOW-06/STG-01、FLOW-06/STG-02、FLOW-06/STG-03、FLOW-06/STG-06、FLOW-06/STG-07 **只放判据与门禁条件**（§4 的落脚处）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个门槛、容差与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；渠道四选一＝决策 Q9；经营节奏「月度经营复盘」＝1 个自然月）；
> （b）业务侧默认（经营者自述或工程惯例，逐条附替换条件）；（c）§1 算式的输出（由 §5 命名的数据系统直出）。
> **候选卡的论文实验参数与卡面案例数字不构成第四种来源**（逐条清单见 §1 末尾）。

## 1 算法可达部分

- **接口契约的字段差异比对与兼容性判定**（落 FLOW-06/STG-04、STG-05、STG-08 三个方法格）：把上游新旧两版的字段集逐字段比对，输出「破坏性变更清单」「必须补默认值的字段清单」与「可自动生成的兼容层范围」三项可核验结果。
- 算式：`破坏性变更 = 命中三类之一的字段数`，三类为「删除字段」「收窄类型或取值域」「新增无默认值的必需字段」；`兼容层覆盖字段数 = 旧版字段集中可由默认值或类型转换补齐的字段数`。
- 取值：**破坏性变更容差取 0 件**（零容忍：任一字段命中三类之一即判不兼容，业务侧默认 —— 经营者自述「上游变更必须走双写过渡，不允许下游静默适配」）；**新增字段带默认值的比例取 100%**（无默认值即判 breaking）；**可自动生成的兼容层范围**取「类型可直接转换或可补默认值」的那一部分，其余一律进人工改写清单。
  **替换条件**：AGT-045 签发字段级兼容规则（哪些字段允许收窄、默认值取值域）后整档替换；替换前凡判 breaking 的变更一律走双写过渡，**不得**直接改消费方解析逻辑。
- **工具描述质量评分与发布门控**（本责任对模型目录的唯一放行口）：工具描述按六维打分 —— 用途 / 参数 / 约束 / 示例 / 副作用 / 返回；分量分取**二值**「该维是否齐备且可判定（有内容且能回答"这条工具在什么条件下不许调用"）」。
- 算式：`工具质量分 = Σ(六维分量分 × 权重)`；权重**不取卡面权重**，按本业务「该工具族近 2 个完整年度的调用失败归因占比」反推（源字段：〈Agent 运行台账〉与 Case/Event Ledger 里 Execution Attempt 的失败原因）。
- 取值：进入模型目录的门槛取**二值规则**「六维任一分量为 0 ⇒ 该工具不得发布」（不设自由阈值，因此不设容差档）；发布后按「月度经营复盘」＝**1 个自然月**复评一次；复评后仍缺维的工具退回沙箱信任域。
  **替换条件**：AGT-048 的 Playbook 版本给出六维判定细则后替换为细则口径；替换前二值门槛不变，只允许复评频率按 Playbook 调整。
- **工具调用效率审计（可复算）**：以沙箱 + mock 工具跑领域测试集，采每一次执行的工具集合与步数轨迹。
- 算式：`TFS = 成功任务数 ÷ 任务总数`；`TEFS = 同时满足「成功 ∧ 实际工具集 ⊆ 期望工具集 ∧ 实际步数 ≤ 期望步数」的任务数 ÷ 任务总数`；另输出**缺失工具数、多余工具数与步骤冗余**三项明细。
- 取值：**期望工具集与期望步数由〈能力交付Case Charter〉的完成条件对应的最小工具链定义**（不引用卡面步数系数）；接收入线取**上一版实测值**（回归基线），新版本不得低于上一版；首期无基线时先按 **1.0（100%）** 记为待达标线，并逐条登记未达标任务。
  **替换条件**：评测插桩（沙箱 + mock）上线并跑满 2 个完整年度（决策 Q11）后，基线改用上一版实测值并按「月度经营复盘」滚动更新；替换前**不得**据首期 **1.0** 判定某工具不合格、也不得据它放行。
- **本段的能力边界**：只做三件事 —— 字段差异与兼容性判定、描述质量评分与发布门控、调用效率度量与审计；**不产出**字段业务语义的最终解释、不签署责任边界、不替代真实业务验收（见 §2）。
- 候选卡与本清单完备性声明：代表卡为 `p2s-mcp-a2a-protocol-stack`（源卡号 `Skill-MCP-A2A-Protocol-Stack`，源域 16-智能体工程，L3 = 接口契约 / 集成验证；承担「工具注册 + Agent 间路由 + 三类治理通道」的协议骨架）、`p2s-tool-description-audit`（源卡号 `Skill-Tool-Description-Audit`，L3 = 接口契约 / 业务工具实现；承担六维描述评分与 smell 扫描）、`p2s-mcp-tool-use-benchmark`（源卡号 `Skill-MCP-Tool-Use-Benchmark`，L3 = 运行监测 / 接口契约；承担 TFS/TEFS 双指标与工具选择审计）。三张**全部是 legacy 预览版（八段式）**：卡页第 ④、⑤ 两段是占位串，代码以同目录 `references/implementation.py` 形式随卡且为节选，⑧ 段有已核验出处但 **论文实验参数未随卡进入本包**。**不得移植的部分**（逐条，任一条都不得进入本业务取值；换入同族卡时同样逐条剔除该卡自身数值）：① 协议栈卡面「接入周期 **10 天 → 2 天**、年化省 **22 万元**」与「**8** 个国家法规 / **5** 个平台 API / **30** 个产品类目 / **3** 类治理通道」；② 同卡「**4** 层架构 + **2** 类协议」的分层口径；③ 同卡卡页声明 `references/implementation.py` **54 行**（包内实物 **59** 行）、代码块 **4** 个，示例值 `msg_id = "msg-001"`、`qty: 120`、`sku "B08XY"`；④ 描述审核卡的「**97.1%** 描述至少含一个 smell」「**56%** 目的不清晰 / **89%** 缺使用指南」「成功率 **70% → 95%**、任务失败率 **30%**」「**+5.85pp** 准确率 / **+67.46%** steps」「ROI **15.12%**」；⑤ 同卡六维**权重**（`purpose` **0.25** / `parameters` **0.25** / `constraints` **0.15** / `examples` **0.15** / `side_effects` **0.10** / `output_format` **0.10**）、分量长度阈值 **50 / 80 / 40 / 60 / 30 / 30**、smell 判定 **< 0.3**、grade 分界 **0.8 / 0.6** —— 本契约的门槛是**二值**，不采用加权分与分界；⑥ 同卡卡页声明 `references/implementation.py` **45 行**（包内实物 **50** 行）、代码块 **3** 个，示例 `quantity=500`、`supplier_id='S01'`、MOQ 与「delivery_date 不早于今天 +14 天」；⑦ 基准卡的 **TEFS 步数系数 `× 1.5`**、示例轨迹步数 **3→4 / 2→5 / 1→3**、模型对比表里的 TFS/TEFS/Token Eff. 排序；⑧ 同卡卡页声明 `references/implementation.py` **46 行**（包内实物 **51** 行）、代码块 **3** 个；⑨ 三张卡共有的性质 —— 卡面所有百分比、倍数、金额与行数都是**卡面案例口径或实现体量**，本业务的容差、门槛与接收入线一律由本节三条算式在本业务数据上算出。同族候选（也在本责任候选清单内，本契约**未逐卡读全文**）：`p2s-schema-evolution-data-contract`、`p2s-tool-auto-discovery`、`p2s-llm-schema-inference`、`p2s-sc-agent-mcp-erp-integration`、`p2s-sc-ontology-schema-versioning`、`p2s-amazon-sp-api-data-pipeline`、`p2s-advertising-api-unified-schema`、`p2s-skill-card-api-serving`、`p2s-ldp-identity-aware-protocol`、`p2s-tool-call-decision-framework`。
- 本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变（具体不变的是可达段的三条算式、不可达段的分工、外部证据清单与冻结条件）。

## 2 不可达部分

- 字段的业务语义与**责任边界**（同一个名字在两个部门指不同口径、谁说了算）：属双方确认的业务事实，算法只能标记「同名不同义」，不能裁决归属。
  → 替代路径：由 AGT-045 在 FLOW-06/STG-04 结束前按 `指标契约`（版本锚 `<签发日>-<序号>`）出具字段口径与归属；跨部门争议按场景契约由 AGT-002 在 FLOW-06/STG-02 分诊，未定名前该字段只允许单源消费、禁止跨系统拼接，并在〈能力缺口诊断〉逐条登记；后果是相关工具只能以只读方式发布，不得进入 FLOW-06/STG-07 的写入类受控动作。
- 第三方平台的**接口政策原文与配额、限流规则**：属外部事实，本司系统内不存在可复算字段，平台可随时变更且不承诺提前通知。
  → 替代路径：政策原文、配额与限流规则由 AGT-021、AGT-023、AGT-024 按渠道在 FLOW-06/STG-04 结束前交出并附生效版本号；版本号缺失时，`TEFS` 里的「期望步数」与「多余工具数」两项失去外部依据 —— 限流规则没核验，一次被 429 截断后的重试算不算步骤冗余判不出来，评测会把平台挡下来的调用记成工具自己选错。故先按平台后台公告逐条登记「本文未核验」并把该渠道单列一栏、不并进 TFS/TEFS 的分子；带版本的规则文本到位后改用其错误码与配额重跑该栏。替换前该渠道的工具只出沙箱结论，不进生产工具注册表。
- 承运商与第三方物流接口的**联调回执与限流实测**：属实物或回执，只能由对方系统给出，本司无法自行生成。
  → 替代路径：由 AGT-019 跨境物流与关务、AGT-020 仓储履约与退货处置在 FLOW-06/STG-05 定稿前提供承运商接口回执样本与限流实测；补不上时先用 mock 回执顶替，工具只允许发布到测试信任域；真实回执到位后替换；后果是相关工具不进入生产工具注册表，验收结论标「回执未齐」。
- 跨系统读写的**访问边界**与第三方数据**使用范围**：属治理与法定签署，须由门卫与合规两侧签发，模型不得自行扩权。
  → 替代路径：由 AGT-050 信息安全与权限签发访问边界与权限矩阵、AGT-044 产品合规与隐私签署数据使用与隐私范围，两者须在 FLOW-06/STG-06 接收门禁前到位；补不上时工具只能以「只读 + 沙箱 + 最小字段集」发布且不得触达客户个人信息字段；后果是该 Case 的 FLOW-06 Assurance Decision 判 HOLD，工具不进生产工具注册表。
- 工具失败时的**业务影响面判定**（哪些对象必须停、哪些可继续）：属治理判断，算法只能给影响清单与候选范围。
  → 替代路径：由 AGT-002 在 FLOW-06/STG-08 前按〈能力交付Case Charter〉已写明的范围裁定影响面，并由 AGT-049 按运行状态与恢复证据确认回退范围；补不上时先用「该工具的全部调用对象」顶替为影响面（宁大勿小）并留人工工单；后果是该 Case 的关闭记录只能出「未闭合」并留观察窗。
- 真实业务**验收结论**（工具是否真的让业务更快、复用率是否真的上升）：属业务事实，只能在真实任务上验证，沙箱评测替代不了。
  → 替代路径：由本责任在 FLOW-06/STG-08 前按〈能力交付关闭记录〉核对**需求到验收时间**与**复用率**，业务侧由该 Case 主岗位按渠道四选一（AGT-021 / AGT-023 / AGT-024）确认；补不上时先用「沙箱评测 + TFS/TEFS」顶替为过程证据并标「未经真实任务验收」；后果是不得据此关闭 Case，也不得把该工具计入复用率。

## 4 该格何时必须冻结

- 破坏性变更未走双写过渡即提交、或新增字段无默认值即上线 ⇒ 不得进入 FLOW-06/STG-07 受控动作。
- 工具描述六维任一分量为 0（例如没写「什么条件下不许调用」）⇒ 不得发布到模型目录；模型目录是消费口，描述是模型选工具的唯一依据。
- 未取得 AGT-050 访问边界签发或 AGT-044 隐私判定，而工具涉跨系统写或个人信息字段 ⇒ 判 HOLD，不得发布。
- 平台政策原文与生效版本号、承运商回执样本在〈能力交付Case Charter〉已写明的观察窗截止日前仍未取得 ⇒ 判 WAIT 并转人工，不得默认放行。
- TFS 或 TEFS 低于上一版实测基线 ⇒ 冻结该版本并回退到上一版，不得带回归发布。
- 契约字段与 AGT-045 当前生效口径版本号不一致、或引用的是已失效版本 ⇒ 不得写入生产契约注册表，先按版本号重算。
- 在沙箱外调用生产接口，或评测/联调产生真实下单、扣款、退款等副作用 ⇒ 立即冻结该工具的发布并升级 FLOW-07 紧急保护通道（Emergency Guard）；评测必须在沙箱内以 mock 工具完成。
- 同一工具在当周内已有一次未回填的发布尝试（含失败与回退）⇒ 不得重复发布；已成功动作不得随整单重跑。
- 工具以「改工具实现」来绕过描述质量门控或兼容性判定 ⇒ 该版本作废，退回 FLOW-06/STG-05 重出方案。
- 契约缺 `来源系统` / `变更版本号` / `生效起止时间` / `口径版本号` 任一项 ⇒ 不得发布，也不得作为 FLOW-06/STG-08 关闭依据。
- 以卡面数字（§1 末清单任一条，含 97.1% / 0.3 / 0.8 / 1.5 / 15.12%）充作本业务门槛或验收线 ⇒ 该方案不得放行。
