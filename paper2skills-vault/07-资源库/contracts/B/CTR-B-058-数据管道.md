# 数据管道 · 供给契约

## 1 算法可达部分

> **方法族**：混合置信度打标流水线族（规则层兜底 → 统计层 → 语义抽取层 → 人工复核队列，产出带来源与置信度的标签结果）；**代表卡**：`p2s-auto-tagging-pipeline-rule-ml-llm`。
> 同族另含通用 ETL 卡 `p2s-agentic-etl-data-pipeline` 与平台 API 专用管道卡 `p2s-amazon-sp-api-data-pipeline`（三张卡在图谱/卡库里的 `l3_business` 逐字都是「数据管道」）。
> **本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变** —— 外部证据要求、冻结条件与数据要求随责任走，不随卡走。
>
> 以下取值只落在本契约的方法接入格 FLOW-06/STG-04、FLOW-06/STG-05、FLOW-06/STG-08 上：算法承接的是「把数据质量诊断算成可复算的量化值」这一段，不是整条数据管道责任。

- **覆盖率与未命中分层**（按〈标签分配结果表〉算）：对每个 `tag_id`，覆盖率 = `value` 非空的对象数 ÷ 该标签适用对象数（适用对象集取自 AGT-045 定名的对象契约）；同时输出 `source` 缺失的对象清单，按「规则层漏出 / ML 层未覆盖 / LLM 层未抽到」三档分层 —— 即「哪些对象没打上标」。
- **置信度分位与复核队列容量**（按〈标签分配结果表〉算）：以 `tag_id × source` 分组对 `confidence` 取分位（低分位与中位），计 `needs_review=True` 的条数，按分位排序给出复核队列的工作量与优先级排序。
- **复核触发线**（本业务自标定，不用卡内参数）：取同 `tag_id × source` 分组内〈人工复核队列〉中已被复核判为正确的记录里 `confidence` 的最小值；该分组尚无已复核记录时**一律按未复核处理**（从严，不给默认值）。
- **断点定位与容量排序**（按〈管道运行记录〉算）：逐节点比较本节点 `输出行数` 与上游节点 `输出行数`（首节点与源表行数比），输出首次出现非零差值的「节点 × 分区」，即断点；并按同表 `结束时间 − 开始时间` 与 `输入行数` 拟合单位行耗时，给出节点并发与调度窗口的排序 —— 这是判定理由里「DAG 调度与容量规划」能承接的那一段。
- **来源 / 输入版本 / 新鲜度三件**（按〈管道运行记录〉读出）：每个产物出厂随附 `输入版本` 与 `最近成功运行时间`；重跑同一区间应得同一行数与同一版本号，复算不成立即判该产物不可用。

## 2 不可达部分

- **① 需要外部事实 —— 口径归属**：同一个 `tag_id` 在 Amazon 平台后台、独立站与其余 20% 渠道里是否**同名同义**，只有 AGT-045（业务口径与主数据）能定名。算法至多产出「语义冲突候选清单 + 冲突对象清单」，**不得宣布口径一致**，也不得在未定名前做跨渠道合并。
- **① 需要外部事实 —— 其余 20% 渠道构成未明（开放事实 O1）**：这些渠道的取数面与对象范围无从确定，覆盖率分母天然不完整；不得用推断或模型补全渠道构成 —— 那会把一条已登记的开放事实变成伪造事实。
- **需要业务确认 —— 业务语义**：某个标签在本业务上成不成立、该不该存在，由业务方与 AGT-045 确认；算法只能算清「哪些对象没打上标」，不能判定「这个标签本身是否成立」。
- **③ 需要治理签署 —— 上线验收**：交付关闭与经营验收由工单的 AI 结果负责人（FLOW-06 记为 AGT-047）与工单定义的独立复核机制给出；管道自证「质量合格」不构成验收。STG-06 的 Assurance 接收门禁在管道之外执行，发起者不能覆盖拒绝。

## 4 该格何时必须冻结

- **口径未定名 ⇒ 冻结跨渠道口径**：同一 `tag_id` 在 Amazon 平台后台与独立站的语义未经 AGT-045 定名时，该标签不得进入跨渠道合并口径，**不得作为推荐、投放、结算的输入**；冻结范围 = 该标签 + 涉事两个渠道，待 AGT-045 出定名后解冻。
- **三件不齐 ⇒ 不得出厂**：数据产物缺「来源 / 输入版本 / 新鲜度」任一件，即未过 STG-06 Assurance 接收门禁，不得被判可用、下游不得消费；消费方按本岗位原则「数据不可用必须让消费方知道」处理。
- **超期 ⇒ 一律判过期**：〈管道运行记录〉的 `最近成功运行时间` 超出 AGT-045 数据契约里该对象声明的更新周期，该产物带过期标记出厂，不得被下游当当期事实消费；对象**未声明更新周期**时按「新鲜度未声明」标记，同样不得被判为新鲜。
- **授权范围外 ⇒ 不读也不出厂**：AGT-050 给定访问边界之外的账号 / 站点 / 字段一律不读（未经授权不复制或扩大敏感数据访问）；越界事实本身写入自治异常账。
- **低置信 ⇒ 不得进高风险用途**：`needs_review=True`、或低于第 1 段复核触发线且尚未复核的标签，不得用于结算、合规声明等高风险用途，只能进复核队列（取卡声明的安全边界）。
- **受控动作另走 FLOW-06/STG-07**：本契约的产物只作判据输入；触发结算、投放、退款等受控动作须由 FLOW-06/STG-07 提交提案、经策略门禁与实际可用策略后由受控执行主体执行 —— 数据管道不持有执行身份。

**R/D 格判据（STG-01/02/03/06/07 只放判据，不挂方法）**：

- FLOW-06/STG-01 接收需求信号：只判「能否落成一个取数对象 + 一个验收者」，两者缺一即记为不可执行信号，不进管道取数。
- FLOW-06/STG-02 能力交付 Case Charter：只判数据条款是否齐（对象、范围、时限、验收者、访问范围、质量判据），缺项退回。
- FLOW-06/STG-03 Context Manifest：只判取数所需的接口边界、访问边界、质量判据、集成与治理条目是否已装配并留痕，缺一即冻结该范围取数。
- FLOW-06/STG-06 Assurance 接收门禁：只判硬校验项与语义争议是否已闭合；门禁在管道之外执行，发起者不能覆盖拒绝。
- FLOW-06/STG-07 受控发布：只判提案的幂等键、回执核对方式与回退条件是否齐；管道不持有执行身份。

## 5 数据要求（五维）

| 维 | 取值 |
|---|---|
| ① 获取路径 | 需授权（Amazon Seller Central 平台后台、独立站、自研 ERP/QMS/WMS 三个取数面都须先有服务身份与范围授权；材料 F-019 记「OAuth/服务身份、权限、读写能力尚未核实」） |
| ② 粒度 | 对象 × 标签 × 渠道 × 日：〈标签分配结果表〉一行 = 一个对象（SKU / 账号 / 站点）× 一个 `tag_id`；运行侧到 节点 × 分区（〈管道运行记录〉） |
| ③ 回溯深度 | 2 个完整年度（决策 Q11）；O1 的其余 20% 渠道构成未明，其可取数区间不在内 |
| ④ 新鲜度 | 按〈管道运行记录〉的 `最近成功运行时间` 与 AGT-045 数据契约里该对象声明的更新周期比对：周期内为新鲜，超出即判过期并随产物标注；未声明周期者标「新鲜度未声明」，不得被判为新鲜 |
| ⑤ 口径归属 | 对象与指标口径归 AGT-045 定名（账号商品映射 = 跨渠道同一 SKU）；标签语义是否同名同义**未定名前不得跨渠道合并**，也不得作为推荐 / 投放 / 结算输入 |
