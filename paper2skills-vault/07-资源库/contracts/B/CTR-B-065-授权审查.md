# 授权审查 · 供给契约

> **本契约的两部分，用法不同。** §1 算法可达部分 / §2 不可达部分 / §3 必须的外部证据与责任岗位 /
> §5 数据要求 / §6 适用 FLOW 是**作业口径** —— 据此产出方案：可达段给算式与取值，不可达段给替代路径；
> §4 该格何时必须冻结是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> **本责任为什么是 B 类**（`_survey_org_model.md` §F.3 原文，别改判）：授权漂移与越权可检测，
> **但撤权与例外批准属安全治理决定** —— 这条理由与本岗位的材料边界完全同向：
> AGT-050 **只能提出**数据、Tool、Identity 和 Policy 边界、**发起撤权**，
> **不能**持有业务凭据、**不能**给自己或其他 Agent 最终授权（材料〈五份管理契约〉中的 Access Contract：
> 「AGT-050 提出；模型外 Case Control、Policy Gate 与 Execution Broker 执行」）。
> 所以本契约的可达段只覆盖**检测与记账**，不可达段整段是**批准与撤权本身**。
> 本责任的标准产物是〈**权限矩阵与访问证据**〉（含范围、输入版本、依据、建议或实际动作、结果与未解决项）；
> 岗位指标逐字为**「越权拒绝与授权漂移」**，核心判断原则逐字为**「岗位人格不能扩大权限」**。
>
> **格子边界**：本责任在 FLOW-04（〈市场进入诊断〉〈市场进入包〉〈市场进入关闭记录〉）、
> FLOW-06（〈能力缺口诊断〉〈数据/工具交付包〉〈能力交付关闭记录〉）、FLOW-07（〈事件范围与根因诊断〉
> 〈重大事件处置包〉〈重大事件关闭与全动作对账记录〉）、FLOW-08（〈经营与能力诊断〉〈经营与能力变更建议〉
> 〈经营复盘关闭记录〉）十二个方法格上作诊断段、方案段与关闭段；
> 四个 FLOW 的 STG-01/02/03/06/07 是规则格，只放判据与门禁条件（含 STG-06 的 Assurance 接收门禁），
> 不承载本契约的任何方法实现。
>
> **卡侧口径声明**：代表卡 `Skill-SQL-Agent-Access-Control` 目前只在**精选线**（`paper2skills-vault/09-DataAgent-LLM/`），
> 尚未换底进产品线，故此处引其 `card_id`；**S5 换底后替换为已装 slug**，其余要求不变。
>
> 本契约对同族方法卡通用（代表卡 `Skill-SQL-Agent-Access-Control`；同族另有 `p2s-progent-privilege-control`、
> `p2s-kb-rbac-access-control`）；**换卡时只替换方法实现，算式、取值、外部证据与冻结条件不变。**

## 1 算法可达部分

- **本条责任里算法能承接的那一段**：把「授权有没有漂、有没有越权」压成四样可核验产物 ——
  ① **授权漂移清单**（现网权限集与已批准基线的差集，逐对象列出多出的范围／Tool／Action Intent 类别）；
  ② **越权尝试数与过度拒答数**两个必须同时报的指标（只报一个会放过退化策略：一律拒答者越权数为零、
  一律照答者过度拒答数为零）；③ **到期与失效清单**（有效期已过而权限仍生效的对象；动作策略未同时绑定
  范围、工具、参数与回执四要素的动作）；④ 拟扩权请求的**「属扩大资产权限」标记**。
  四样写入〈权限矩阵与访问证据〉，并在四个 FLOW 的 STG-08 作关闭段提交。
- 算式：`漂移对象数 = count((账号, 角色, 对象, 操作) ∈ 现网权限集 且 ∉ Access Contract 解析后的有效版本引用)`；
  其中 Access Contract 的必要内容逐字取材料：数据范围、可见 Tools、Action Intent 类别、Policy 引用、有效期、撤权和审计要求。
- 算式：`越权尝试数 = count(请求的 (角色, 对象, 操作) ∉ 该角色已批准权限集 Π_role)`；
  `过度拒答数 = count(请求 ∈ Π_role 但被 Policy Gate 拒绝)`；两者分母同为当期请求数，**必须并列报出**，不得合成单一总分。
- 算式：`失效绑定数 = count(动作策略未同时绑定 范围、工具、参数、回执 四要素的动作)`（材料原话：动作策略必须绑定具体范围、工具、参数与回执）。
- 取值：**漂移对象数 ＝ 0 件**（二值判定，不设容差档；判据字段为现网权限集与 Access Contract 的有效版本引用）。
- 取值：**越权尝试数 ＝ 0 件**（二值；来源＝治理惯例「任何越权成功即事故」，与岗位指标「越权拒绝与授权漂移」同向）。
  **替换条件**：〈权限矩阵与访问证据〉接入并覆盖满 **2 个完整季度**后，改用**实测**越权尝试分布定档；
  替换前只报检出数、不报概率。
- 取值：**过度拒答率容忍线 ≤ 5%**（＝每 **20** 次请求至多 **1** 次被误拒）。该数是**业务侧默认值**
  （来源＝经营者自述「被误拒的取数要人工兜底拉表，超过这个比例业务就不用了」）。
  **替换条件**：Case/Event Ledger 的 Policy Decision 记录满 **2 个完整季度**后，改用实测人工兜底工单占比的上界；
  替换前该线只用于派单排查，不作岗位考核项。
- 取值：**失效绑定数 ＝ 0 件**（二值，直接取材料原话作判据，不设分档）。
- 取值：**「属扩大资产权限」的自动发布数 ＝ 0 件**（二值）。判据取材料规则：拟变更超出既有公司目标、
  Access 上限或 Assurance 门槛（尤其**扩大资产权限**）时，只能**保持草稿并等待新的公司级契约**，
  在本 Case 内自行放宽一律不作数。同一规则下，修改任一契约都产生**新候选版本、不覆盖已运行版本**，
  历史 Case 继续引用启动时的版本集合。
- 取值：**撤权时延上限 ＝ 1 个工作日**（来源＝**行业惯例**：人员离岗或角色变更当日发起撤权、次日核对生效）。
  **替换条件**：AGT-004 的人员与角色变更事实（入离调转，其标准产物为〈能力矩阵与组织调整建议〉）接入后，
  改用**变更事件时点 → 权限矩阵生效时点**的实测中位时延；
  替换前该上限只用于派单与告警，不作合规声明。
- 取值：**例外（临时扩权）批准的最长有效期 ＝ 5 个工作日**（来源＝**行业惯例**，且材料把「有效期」列为
  Access Contract 的必要内容之一，故每一项例外都必须带有效期字段）。
  **替换条件**：例外记录累计满 **2 个完整季度**后，改用实测「例外到期未回收」分布的上界；替换前超期一律按 §4 冻结。
- **不得移植的部分**（逐条来自实际读过的三张卡；任一条都不得作为本业务的判定线或阈值）：
  代表卡 `Skill-SQL-Agent-Access-Control`（arXiv 编号 2607.22115；卡页自承 venue 存疑、按 `venue_tier: preprint` 记）
  的论文与卡面数字 —— 越权率 `(|VC|+|VW|)/N`、过度拒答率 `|OR|/N`、`AC-F1`、`Safe-EX`、`Safe-Deny` 的定义可搬
  （它们就是本契约 §1 第二个算式的口径来源），但**下列数值一律不得移植**：Role-Schema 下 GPT-5-mini 的越权数
  **148.6 → 379.2**、增加 **14.2 个百分点**；Snowflake-R1-7b 在 BIRD 上录得 **63.77%**；few-shot 使
  DeepSeek-Coder 的 AC-F1 掉近 **9 个点**；合成角色由 **4 位标注员**在数据库级配置上复核；Table 3 的
  单次查询 token 成本。⚠️ 该卡 ⑤ 明确「**不给收益金额结论**」—— 本契约同样不得引用其任何货币化数字，
  也不得把 **63.77%** 当本司越权率的上界或预测。
  同族卡 `p2s-progent-privilege-control` 为 **legacy 预览版**（八段式，④⑤ 段是占位串、代码以
  `references/implementation.py`（**22 行**）随卡且为节选、⑧ 段只记 arXiv:2504.11703 未记录可核验出处）
  ⇒ **论文实验参数未随卡进入本包**；其卡面可见数字（`purchase_order.create` 的 `amount ≤ 1000 USD`、
  拟扩到 **5000 USD**、权限滥用风险降低 **80%**、年化风险规避 **30-80 万元**、集成 Z3 约 **2-3 天**）
  一律不得作为本业务阈值 —— 本业务的扩权判定是**二值**的（超出 Access 上限即保持草稿），不设金额档。
  同族卡 `p2s-kb-rbac-access-control` 同为 **legacy 预览版**（④⑤ 为占位串、`references/implementation.py`
  （**223 行**），卡页自承其 60 行节选语法不完整、不能直接运行）⇒ **论文实验参数未随卡进入本包**；
  其卡面可见数字（越权访问事故降低 **90%**、单次泄密损失 **500 万元**、实施 **2 周**、年化风险降低 **90%**）
  一律不得移植 —— 本业务的越权与漂移取证不依赖任何风险折减率。
- 本段的能力边界：只做四件事 —— 权限集与基线差在哪、请求越没越界、误拒了多少、拟变更算不算扩权；
  **不产出撤权决定、不批准任何例外、不代签 Access Contract**（见 §2 第 1 条）。
- 本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变。

## 2 不可达部分

以下六段是算法到此为止的地方：三段属外部事实，一段属实物或凭据的回执，一段属法定与治理签署，一段属治理事实。

- 撤权与例外批准本身（谁还能拿到什么、临时扩权批不批、批多久）：属**安全治理决定加法定/治理签署**，
  本岗位按材料只能**提出**边界与**发起**撤权，**不能**给自己或其他 Agent 最终授权。
  → 替代路径：由模型外 Case Control、Policy Gate 与 Execution Broker 执行已发布规则，由公司级契约签署扩权；
  补不上时先出「草稿 + 待签」双栏〈权限矩阵与访问证据〉，草稿栏**不得**计入
  〈FLOW-04 Assurance Decision〉〈FLOW-06 Assurance Decision〉〈FLOW-07 Assurance Decision〉〈FLOW-08 Assurance Decision〉
  的接受项，该 Case 只能停在 STG-06；后果是相关动作只出 Action Intent 或 NoActionRecord，
  并计入本期**未闭环授权项**。
- 业务侧「谁应该有什么权限」的真相（某个岗位是否真的需要这个数据范围）：属**外部事实**，
  是业务治理事实而不是可从访问日志推出的结论。
  → 替代路径：由 AGT-004 组织能力与人事行政提供人员与角色变更事实（入离调转）、由各业务范围负责岗位在 STG-04 结束前确认
  范围必要性、由 AGT-045 给出字段级口径；补不上时先按「上一版已批准基线」顶替并标「必要性未复核」，
  任何**扩大**范围的候选一律保持草稿；后果是未复核范围内的新授权不进 STG-07。
- 平台侧账号与子账号的真实授权（平台后台的角色配置、主体资质、是否有代运营账号）：
  属**外部事实**，只有各渠道主体能给出权威版本。
  → 替代路径：按决策 Q9 的渠道四选一分别由 AGT-021 Amazon业务经营、AGT-023 独立站经营与转化、
  AGT-024 其他平台与新市场经营、AGT-025 零售渠道与B2B拓展提供该渠道的子账号清单，
  平台规则侧由 AGT-027 店铺账号健康与规则提供；补不上时先用「上一次已核对的子账号清单 + 平台公告截图」
  顶替并标「未核验」，该渠道的新增子账号一律冻结；后果是该渠道只做只读核对、不开新授权。
  （渠道四选一是一条规则：**不得**把某一个渠道实例的负责人写成整条 FLOW 的负责人。）
- Service Identity 凭据、密钥与工具凭据的持有与轮换：属**实物或凭据回执**，
  且材料明令**密钥不进入提示词**，本责任只能核对「有没有、在不在有效期内」，不能持有或代管。
  → 替代路径：由 AGT-049 Agent平台与可靠运行在〈运行状态与恢复证据〉中提供凭据托管状态与轮换回执；补不上时先把相关对象的授权标记为
  「凭据状态未核实」并只出草稿，涉及凭据的动作一律不进 STG-07；后果是相关 Case 的 Assurance 接收门禁判 HOLD。
- 是否真的发生了数据泄露、影响面有多大：属**外部事实**，授权审查只能看到权限差集与请求越界，看不到外泄后果。
  → 替代路径：命中即移交 FLOW-07 紧急保护通道（D-026，Emergency Guard）作独立判定，
  并把守卫候选条件（**逐字取材料**：authoritative machine verifiable signal、fixed policy ref and version、
  dispatch TTL、idempotency rule、maximum blast radius）交由模型外组件生成 —— 本责任**不选、不扩**守卫动作与参数；
  补不上时先按**最小可疑范围**冻结
  （账号 + 对象 + 操作三级），由 AGT-005 内控审计与独立复核在 24 小时内补〈Pre-Case Exception〉记录；
  后果是解除冻结必须走 FLOW-07 的逐对象权威回执，不得由本责任自行解冻。
- 合规判定与罚则（个人信息处理的法定要求、跨境传输限制）：属**法定签署**，本责任无权解释法规。
  → 替代路径：由 AGT-044 产品合规与隐私出具合规判定、涉对外声明的由 AGT-043 法务与知识产权出法律意见；
  补不上时先用〈Access Contract〉已写明的数据范围与保留要求顶替并标「合规未判定」，
  涉及个人信息的对象只做只读核对；后果是相关授权候选保持草稿，不得进 STG-07。

| 法律意见（对外声明与责任边界） | AGT-043 | 涉对外声明的 STG-05 前 | 无法律意见时不得做对外承诺类表述，相关动作停在 Action Intent |
| 〈数据口径与对象关系契约〉（对象、操作、角色、有效期的口径归属与版本号） | AGT-045 | STG-04 判定漂移前 | 未签发时先按〈Case Charter〉已写明的字段清单顶替并标「口径未签发」；签发后替换，替换前差集只用于排查 |
| 带质量状态的数据产物（权限记录与日志的来源、质量状态、更新时间） | AGT-046 | STG-04 判时点前 | 缺来源标识或新鲜度字段的记录不进漂移分母，该 Case 冻结在 STG-04 |
| 资金与凭据边界判定（付款、退款类动作的金额与凭据边界） | AGT-041 经营财务与资金 | STG-06 前 | 缺口时资金类动作（付款、退款、销毁）HOLD，只能出 NoActionRecord |
| STG-03 装配的角色清单与主岗位选择记录 | AGT-002 | STG-06 前 | 缺口时由 AGT-001 指定替代复核人；仍无则判 HOLD |

## 4 该格何时必须冻结

- 漂移对象数 > 0 件（现网权限集存在 Access Contract 有效版本之外的范围、Tool 或 Action Intent 类别）⇒
  立即冻结该对象范围，不得推进到四个 FLOW 的 STG-07 受控动作，只能出 NoActionRecord + 人工工单。
- 越权尝试数 > 0 件（出现 `(角色, 对象, 操作) ∉ Π_role` 且被放行的请求）⇒ 立即冻结相关对象并升级
  D-026 紧急保护通道（Emergency Guard），24 小时内补〈Pre-Case Exception〉记录；解除须走 FLOW-07 逐对象权威回执。
- 任何一项授权/例外的**有效期已过而权限仍生效** ⇒ 冻结该对象的全部动作，直到撤权生效时点被记录进〈权限矩阵与访问证据〉。
- 拟变更属于**扩大资产权限**（或超出既有公司目标、Access 上限、Assurance 门槛）而只在单一 Case 内批准 ⇒
  该变更**必须保持草稿**并等待新的公司级契约；不得以任何理由在本 Case 内先行生效。
- 人员离岗或角色变更已超过 **1 个工作日**而撤权未生效 ⇒ 该 Case 的 Assurance 接收门禁判 HOLD，
  相关对象的动作不得自动放行。
- 例外（临时扩权）超过 **5 个工作日**有效期或未附有效期字段 ⇒ 自动失效并冻结，不得续期补记。
- 动作策略未同时绑定 范围、工具、参数、回执 四要素（失效绑定数 > 0）⇒ 该动作不得进入 STG-07；
  发现密钥或 Service Identity 凭据出现在提示词、交付物或日志中 ⇒ 立即冻结并升级 FLOW-07 紧急保护通道。
- 权限矩阵只到表级（§5 ② 的缺口）而结论要对外声称列级或行级合规 ⇒ 不得作该声明，
  该结论只能标「表级口径」，且不得写进〈市场进入包〉〈数据/工具交付包〉〈经营与能力变更建议〉的可执行项。
- 授权变更史缺失（§5 ③ 的缺口）而结论要追责到人或要判定漂移时长 ⇒ 冻结该用途，只报「检出不一致」。
- 命中材料 EXC-WAITING-INPUT（必需输入缺失、过期或不可用）⇒ 该 Case 状态置 WAITING，
  依赖项与新鲜度复核通过后方可回到**同一**阶段，不得以跳过阶段的方式继续。
- 命中材料 EXC-POLICY-DENIED（Policy Gate 拒绝 Action Intent）⇒ 该 Case 状态置 REWORK_REQUIRED，
  退回 STG-05 或出 NoActionRecord 关闭，**不得以任何方式绕过拒绝**。
- 命中材料 EXC-RECEIPT-UNKNOWN（执行结果或外部状态未知）⇒ 该 Case 置 FROZEN，
  须按幂等键查证外部状态后方可重试、补偿或关闭；在此之前不得发起新动作。
- 外部证据时限：自 STG-05 产物提交起，至〈Case Charter〉写明的观察窗截止日仍未取得 §3 所列任一必需证据 ⇒
  判 HOLD 并转人工，不得默认放行。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | `需授权`（〈权限矩阵与访问证据〉；Access Contract 的解析后有效版本引用；企业身份与密钥托管状态 —— 后者按材料记为「当前未核实目标部署的控制」）＋`平台后台`（平台侧子账号与角色配置清单、账号健康与政策通知）＋`自有埋点`（Case/Event Ledger 的 Policy Decision、Stage Acceptance Record、Execution Attempt） | 非缺口。凭据本身不走本维：按材料**密钥不进入提示词**，本司只取「托管状态与轮换回执」这一布尔与时间戳，凭据值一律不落交付物；若某渠道的授权只存在于平台侧、本司无 API：先用公告截图与子账号清单人工核对并标「非权威副本」，接入后替换 |
| ② 粒度 | 目标粒度 ＝ 账号 × 角色 × 对象 × 操作（对象含库/表/列三级，操作含读/写/执行），键为 `subject_id` + `object_ref` + `action`；但〈权限矩阵与访问证据〉**尚未**下到列级与行级，现存台账只到**表级** | 缺口：缺列级与行级就算不出「该拒却答」的精确判定，越权数会系统性**低估**，且只能对整表判而不能对字段判。处置：**先按**表级门禁运行、逐条标「表级口径、不得对外声称列级合规」；权限矩阵补到列级后**替换**为列级粒度；**替换**前只报表级越权与漂移，不报字段级结论 |
| ③ 回溯深度 | 可用的日志与 Policy Decision 记录为 **2 个完整年度**（业务处境给出的出海历史长度，决策 Q11）；但权限数据只有**快照**、变更史链**尚未**建立 | 缺口：只有快照就算不出**授权漂移的时点与责任归属** —— 能比出「现在不一致」，比不出「何时漂的、谁批的」。处置：**先按** Case/Event Ledger 的 Policy Decision 与 Stage Acceptance Record 时间序拼出该 Case 生命周期内的**近端**变更序并标「非全量变更史」；权限矩阵按材料口径**版本化**（每次变更产生新候选版本、不覆盖已运行版本，历史 Case 继续引用启动时的版本集合）后**替换**；**替换**前漂移只报「检出不一致」，不报漂移时长与责任归属 |
| ④ 新鲜度 | 权限变更须 T+0 可查；进入 STG-04 前重读；全量权限复核每 **1 个自然季度**一次，例外与撤权随发生时点即时记 | 非缺口。权限矩阵若 T+1 批量落地，迟一天不是晚一天看到，而是两边各错一天：漂移对象数比的是现网权限集与 Access Contract 有效版本引用的差集，拿昨天的现网对今天的契约，昨天刚收紧掉的条目会留在现网侧被算成漂移、今天刚收回的又看不见；撤权时延那头更硬 —— 上限 1 个工作日、时延取「变更事件时点 → 矩阵生效时点」，T+1 天然多算一天，正常撤权也会被 §4 判成超期 HOLD。先按〈平台后台〉子账号清单与 Policy Decision 的当次快照顶替做存在性核对并标「晚一日」，矩阵按日可读后替换。替换前漂移只报「检出不一致」，不报时点 |
| ⑤ 口径归属 | `AGT-045`（业务口径与主数据）为对象、操作、角色、有效期与「越权／误拒」分子分母的口径归属方；Access Contract 的版本归属由 AGT-050 提出、AGT-049 保存；每条权限与日志记录随带 `AGT-046` 的来源、质量状态与新鲜度 | 非缺口。未签发时缺的是 Access Contract 的「有效版本引用」那一列：漂移对象数的减号右边本该是解析后的有效版本，没有它只剩上一版已批准基线，于是本期走正常流程新批的权限全落进差集，报出来的漂移里混着一大半是合法新增，真越出边界的那几条反被淹掉。先按材料给出的六要素（数据范围、可见工具、动作类别、Policy 引用、有效期、撤权与审计要求）逐项登记「本项基准取自哪一版」，把差集拆成新增与越界两栏顶替；口径契约与版本引用签发后按版本号整栏替换。替换前差集只作排查，不用于对外表述 |
