# 技能版本 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，不可达段给替代路径。
> §4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> **本责任的判定理由**（本项目综述 §F.3 的判定，**二手来源，不是材料原文**，别改判）：**版本比对与回归评测门禁是标准 MLOps 评估工程，但属制品治理管道。**
> 这句话就是本契约可达段与不可达段的分界线：**版本之间能不能比、比出来退没退化，算法能做；
> 一个版本的业务验收与发布权，不在算法手里**（§2 第 2、4 条）。
>
> 本契约只属于 `AGT-048` 知识技能与Playbook治理（DOM-08 / PLN-PLT），适用 FLOW-02 新品需求到商业验证、
> FLOW-06 业务需求到数据产品与工具、FLOW-08 经营资源与组织能力复盘。方法格是这三条 FLOW 的
> STG-04 证据收集与诊断、STG-05 方案与标准产物、STG-08 结果核验与异步学习（§1 的四个可达段落在这些格）；
> 判据格是这三条 FLOW 的 STG-01 信号接收、STG-02 范围确定与 Case 创建、STG-03 上下文装配、
> STG-06 Assurance 接收门禁、STG-07 受控动作 —— **这些格只放判据与门禁条件**（§4 的落脚处）。
>
> **本责任治理的对象是材料已定名的** `Playbook`／Skill 制品与 `Bundle` 生命周期（D-023）：
> 换版、发布、回退都走受控发布 Change Proposal，不在本格直接改线上目录。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、窗口与比例，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度**＝决策 Q11；经营节奏「月度经营复盘」＝**1 个自然月**；
> 阶段边界 STG-01…STG-08；PB-001 通用工单规则）；
> （b）业务侧默认（治理岗自述或行业惯例，逐条附替换条件）；
> （c）§1 算式在本司命名数据源上算出的值。**候选卡的论文实验参数与实现默认值不构成第四种来源**（逐条清单见 §1 末尾）。

## 1 算法可达部分

- **候选卡状态（先读这一条再用本段）**：本责任 **22 张候选卡中 5 张是有全文卡**（⑧ 段有出处与核验口径），**17 张是 legacy 预览版**（八段式：④、⑤ 两段是占位串，代码只以同目录 `references/implementation.py` 形式随卡且为节选，⑧ 段出处为「不可采信」或「未自动抽取」）。本段取三张全文卡作代表，**但可达写法一律由本业务算式定值**：卡只供方法骨架，**卡面与论文里的实验数字一条都不得移植**（逐条清单见本段末尾）。
- **可达段一（版本可比与回归门禁 · 方法格 FLOW-02/STG-05、FLOW-06/STG-05、FLOW-08/STG-05）**：同一场景的 oracle 用例集在**基线版本**与**候选版本**上各跑一遍，输出「回归通过率」与「退化量」两个可复算量，作为换版请求的附件。
- 可达段一算式：`回归通过率 ＝ 通过用例数 ÷ 用例总数`（基线版与候选版**同一用例集、同一批次、同一执行环境**）；`退化量 ＝ 候选版本通过率 − 基线版本通过率`，以 **pp** 为单位。
- 取值：**回归门禁线 ＝ 0 pp**（候选版本通过率不得低于基线版本，即退化量 **≥ 0 pp**；来源 ＝ **业务侧默认**，治理岗自述：技能换版只许不许退，没有「小幅退步可接受」这一档）；**单次回归最小用例数 ＝ 20 条**（来源 ＝ **业务侧默认**，治理岗自述：少于 20 条分不清退化与噪声）。**替换条件** ＝ 该场景的 oracle 用例集定名并跑满 **2 个完整年度**（决策 Q11）后，最小用例数替换为该场景实测用例规模分布的 **P50**；门禁线**始终不得放宽到 0 pp 以下**，只允许随实测收紧。用例集尚未定名时，**先按该 Skill 的案例集 ＋ 历史人工判定结论顶替**并标「用例集未定名」。
- **可达段二（生命周期阶段跃迁 · 方法格 FLOW-02/STG-04、FLOW-06/STG-04、FLOW-08/STG-04）**：把「这个技能还该不该留在库里」化为两个可比量，再按材料已定名的观察窗判阶段。
- 可达段二算式：`调用条数 ＝ 窗口内该 Skill 的调用条数`（取 Agent 运行日志与 Case/Event Ledger 的 Execution Attempt）；`成功率 ＝ 成功执行条数 ÷ 调用条数`；两条都按 **Skill × 版本 × 场景 × 自然月**统计。
- 取值（**分档**，来源 ＝ **业务侧默认 ＋ 材料已定名的经营节奏**）：**淘汰候选** ＝ 连续 **2 个自然月** 调用条数 ＝ **0**（「月度经营复盘」＝ 1 个自然月，取连续 2 个月为最小观察窗）；**演化候选** ＝ 命中 **≥ 1 条异步学习候选**（材料已定名产物，由 FLOW-06/STG-08 发出）或连续 2 个自然月成功率低于**该 Skill 首次发布版本的实测基线**；**可发布候选** ＝ 退化量 **≥ 0 pp** 且版本链完整率 ＝ **100%**。**替换条件** ＝〈Skill 版本登记表〉与 Agent 运行日志跑满 **2 个完整年度**后，观察窗替换为实测零调用间隔的 **P50**、成功率基线替换为该 Skill 首版实测通过率；替换前阶段跃迁只作队列排序，不触发自动下线。
- **可达段三（版本登记与可追溯 · 方法格 FLOW-02/STG-08、FLOW-06/STG-08、FLOW-08/STG-08）**：把每个 Skill 的版本历史做成一条可核验的链，输出版本链完整率与断链清单。
- 可达段三算式：`版本链完整率 ＝ 1 − 断链数 ÷ 应登记版本数`；一条登记记录 ＝ 技能标识 × **语义化版本号（主.次.修订）** × 内容哈希 × 依赖卡清单 × 生效时间 × 回退目标；断链 ＝ 六项中任一为空、或上一版本的回退目标指不到实存版本。
- 取值：**版本链完整率 ＝ 1.000（即 100%）**（来源 ＝ **业务侧默认**：材料口径下接收门禁是**缺项即 HOLD 的二值门禁**，不设部分通过档）；**回退窗口 ＝ 1 个自然月**（来源 ＝ 材料「月度经营复盘」＝ 1 个自然月 —— 上一个自然月内的版本必须仍可回退）；**主版本升级必须同时带回归结论与回退目标**（二元规则，不含自由阈值）。**替换条件** ＝〈Skill 版本登记表〉接入并跑满 **2 个完整年度**后，改用**实测断链数**与实测回退耗时的 **P95** 重算；替换前版本链完整率只能表述为「**未检出**断链」，不得表述为「不存在失效版本」。
- **可达段四（跨模型与跨环境迁移 · 方法格 FLOW-06/STG-05、FLOW-06/STG-08）**：同一套 oracle 用例在源模型与目标模型上各跑一遍，判定该技能包能不能跟着模型换。
- 可达段四算式：`迁移差 ＝ 目标模型通过率 − 源模型通过率`（同集、同批、同执行环境）；判定为二元：迁移差 **≥ 0 pp** 才可按源模型结论发布，迁移差 **< 0 pp** 判「不可迁移」。
- 取值：**迁移差门槛 ＝ 0 pp**（来源 ＝ **业务侧默认**，治理岗自述：跨模型只许平移或更好，负迁移一律回到源模型或重做用例）；目标模型跑不了同一套用例时，**先按同一用例的等价改写子集顶替**并标「用例集不等价」，等价子集到位后替换；替换前迁移结论只作提示，不得据此发布。
- **本段的能力边界**：只做四件事 —— 版本间通过率比较与退化判定、生命周期阶段跃迁的判定、版本链完整性核算、跨模型迁移差比较；**不产出技能内容质量结论、不产出业务验收、不发布不上下线**（见 §2 第 1、2、3、4 条）。
- **卡面与论文可见数字清单（逐条，全部不得移植）**：
  1. `p2s-skill-lifecycle-design` 卡面 ① 段：四元组 header（能力／触发／效果／版本）、无效 Skill **下线率提升 60%**；同卡 ③ 段现状：**15+ 领域、80+ 张 Skill 卡**；

## 2 不可达部分

- 不可达①（需**外部事实**）—— 技能带来的经营效果归因：技能发布后经营指标变好，未必是技能所致；本格只能读调用与成功率，读不到反事实。
  → 替代路径：由 `AGT-035` 增长实验与增量评估在 STG-05 前给出实验设计与增量判定口径，`AGT-048` 只出技能侧可比量；拿不到时先用「同场景历史同期经营指标」顶替为方向提示并标「无对照」，后果是该技能的效果**不得**写入〈能力交付关闭记录〉的验收结论，只能记「技能侧回归通过」。
- 不可达②（需**法定或治理签署**）—— 业务验收的实质结论：技能到底有没有解决业务问题，须由该能力交付 Case 的业务验收人签署，模型只能给候选。
  → 替代路径：业务验收的实质结论：技能有没有解决业务问题，得由该能力交付 Case 的业务验收人签，模型只能给候选。签署人按〈能力交付 Case Charter〉点名（FLOW-02 侧是 AGT-008／AGT-009，FLOW-06 侧是 AGT-047），并由 AGT-001 在 FLOW-08/STG-06 前复核。签不下来时，交付物改为左右两栏：左边模型候选、右边空着等签，左边一栏不许写进关闭记录的验收项，该 Case 就地停在 STG-06／STG-08 不闭合。
- 不可达③（需**人的专业判断**）—— 技能内容与触发条件的语用正确性：措辞歧义、触发条件过宽或过窄，只有真实的误用与漏用案例能证，回归用例覆盖不到。
  → 替代路径：由 `AGT-048` 在 STG-04 前汇总误用／漏用案例，被服务岗位（如 `AGT-038` 体验洞察与质量反馈、`AGT-036` 售前服务与购买指导）出使用反馈；拿不到时先用「调用日志的成功／失败分布」顶替为可疑清单并标「未定性」，后果是该 Skill 只能判「待观察」，不得据此判退役或下线。
- 不可达④（需**法定或治理签署**）—— Playbook／Skill 的发布、下线与回退权：属治理动作，算法只能出结论、不能出动作。
  → 替代路径：Playbook／Skill 的发布、下线与回退权：属治理动作，算法给得出结论、按不下按钮。本岗按 D-023 在 FLOW-06/STG-07 提受控发布 Change Proposal，上线执行与回退回执由 AGT-049 出。授权未到位时，该版本只能停候选区，不写进生产 Skill 目录，工具侧至多发一条 Action Intent 等签。
- 不可达⑤（需**外部事实**）—— 调用日志的完整性与覆盖面：Agent 内部调用是否全部留痕、是否覆盖所有入口与所有租户，本格无法自证。
  → 替代路径：调用日志的完整性与覆盖面：Agent 内部调用是不是全都留了痕、有没有漏掉某个入口或某个租户，本格自己证明不了。来源标识、新鲜度与缺填率由 AGT-046 给，取数权限由 AGT-050 给。这两项缺席时，成功率与调用条数先在单 Case 内部用，标「未全量」；跨 Skill 的退役排序一律不据此出，因为少记一次调用与没人调用在日志上长得一模一样。
- 不可达⑥（需**外部事实**）—— 被服务岗位的实际使用意愿：技能被绕开（人不用、Agent 不选）的动机读不出来，日志只显示次数下降。
  → 替代路径：由 `AGT-004` 组织能力与人事行政在 FLOW-08/STG-04 提供岗位能力与使用反馈，各被服务岗位在「月度经营复盘」节奏的复盘会上确认；拿不到时先用「调用条数下降」顶替为线索，后果是不得仅凭调用条数下降判淘汰，必须先走完 §1 可达段二的连续 2 个自然月观察窗并留观察记录。

## 4 该格何时必须冻结

- 候选版本的回归通过率低于基线（退化量 **< 0 pp**），或跨模型迁移差 **< 0 pp** ⇒ 该版本不得进入 STG-07 的受控发布动作，只能出 Action Intent 或 NoActionRecord。
- 版本链不完整（内容哈希、依赖卡清单、生效时间或回退目标任一为空），或上一版本的回退目标指不到实存版本 ⇒ 冻结该 Skill 的发布与下线，只能出 Change Proposal。
- **主版本**升级而回退目标缺位，或回退窗口已超过 **1 个自然月** ⇒ 冻结该次升级。
- 用例集仍处于「用例集未定名」的顶替状态（§1 可达段一）⇒ 该版本只能判「可试点」，不得判「可发布」；也不得据其判旧版本可以退役。
- 成功率或调用条数取自**未全量留痕**的样本（§2 第 5 条）⇒ 不得据此判退役，只能判「待观察」并留观察窗。
- 业务验收签署缺位而拟动作是发布、下线或回退 ⇒ 冻结并转人工，不设部分通过档。
- 同一 Skill 在当周内已有一次未回填的发布或回退动作 ⇒ 不得重跑；**已成功动作不得随整单重跑**（PB-001 通用工单规则）。
- 命中 FLOW-07 的事件口径（技能导致对外动作错误、批量客诉或账号风险）⇒ 移交 FLOW-07 紧急保护通道（Emergency Guard，D-026），本格不得自行处置，也不得先下线了事。
- 缺 §3 中任一项证据，而在途已超过该 Case 的〈能力交付 Case Charter〉或〈经营复盘 Case Charter〉写明的观察窗截止日 ⇒ 判 HOLD 并转人工，不得默认放行。
- 引用 §1 清单中任一条卡面数字、第三方基准或实现默认值（含 60%、80+ 张、+16.2pp／−1.3pp、0.8／0.5／5／50／0.6、10%→2%、14 万元、1–2 周→2 天、+18pp～+40pp、+36～+44pp、30–100 个、0.3／0.7／3 轮、200–500 个、+4.3pp／+9–12pp、5–8%、TOP 5／6 条）作为本业务取值 ⇒ 该方案不得放行。
- 本段落在规则格（三条 FLOW 的 STG-01、STG-02、STG-03、STG-06、STG-07）上的只是上列判据与门禁条件，不引入判别式或预测式。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | `自有埋点`（Case/Event Ledger 的 Stage Acceptance Record 与 Execution Attempt）＋`需授权`（〈Skill 版本登记表〉、Agent 运行日志、oracle 用例集） | 非缺口。若版本登记表或运行日志尚未开通取数权限：先用 Case/Event Ledger 里被引用的版本号与执行记录顶替并逐条标「非权威副本」，权限开通后替换为登记表与日志口径；替换前只作单 Case 内比较，不出跨版本与跨 Skill 结论 |
| ② 粒度 | 一条 ＝ **一个 Skill 的一个版本**（技能标识 × 语义化版本号 × 生效时间）；指标一条 ＝ Skill × 版本 × 场景 × 自然月 | 非缺口。若日志只到 Skill 级、不带版本号：先按 Skill 级顶替并标「未到版本级」，**当期内只要有换版就不出通过率结论**；版本号随日志落库后替换为版本级粒度 |
| ③ 回溯深度 | 缺口：**同一 Skill 的跨版本对照历史取不到**（首个版本之前的对照按定义不存在）—— 能取到的部分是近 2 个完整年度（业务处境给出的出海历史长度，决策 Q11），用于零调用间隔与通过率基线的分布 | 缺的是一条能定位到版本的链。退化量是两个通过率相减，只有现行版与上一版时，这个差里同时混着「用例集本身换过没有」的差：判不出 −3pp 是换版换退的，还是这一版把场景分布改了；回退目标也只能指回唯一那个上一版，版本链完整率的断链清单无从核对，回退窗口那 1 个自然月里究竟有几个可选版本更是数不出来。先按现行版与上一版的对照单顶替、逐条标「对照仅两版」，〈Skill 版本登记表〉接入并跑满 2 个完整年度后改用完整版本链重算。替换前回归结论只作两版之间的比较，不写成趋势 |
| ④ 新鲜度 | 每次进入 STG-04 前重读；调用与成功率按**自然日**刷新；进入接收门禁前须为「截至前一日 24:00」的完整快照；连续 **2 个自然月**零调用即进淘汰观察窗（材料「月度经营复盘」＝ 1 个自然月） | 非缺口。运行日志若是离线批量 T+1，缺的不是今天这一格，而是窗口右端点的确定性：淘汰观察窗要的是「连续 2 个自然月调用条数 ＝ 0」，而批量日志里最近一天永远是空的 —— 这条空档会被当成零调用，把一个其实还在用的 Skill 推早一步进淘汰候选；成功率按自然日刷新时，分母也少一天。先按〈Skill 版本登记表〉里该版本的生效时间与上一份批量快照的截止日取交集顶替，把观察窗右端钉在快照截止日并标「右端点非当日」；日志改成当日可查后替换。替换前零调用只出线索，不触发淘汰候选排序 |
| ⑤ 口径归属 | 缺口：「**一次调用**」的计量单位**尚未定名**（Agent 在一次任务里对同一 Skill 的多次引用算 1 次还是 N 次没有定），本维因此缺「调用分母」的口径 —— 已定名的部分是：`AGT-045` 业务口径与主数据（「发布版本」「调用条数」「成功率」的定义与时间归属，按版本号引用），每条记录随带 `AGT-046` 的质量状态、来源与新鲜度，本责任自身归属 `AGT-048` | 缺它算不出成功率与调用条数的**分母**，分母不稳则退化量与零调用观察窗都不可比。先按「一次任务算 1 次」的口径**顶替**为**单 Case 内可比**并逐条标「口径未签发」，`AGT-045` 签发调用计量口径后**替换**；替换前调用条数只作单 Case 内比较，不得据此做跨 Skill 退役排序与资源削减 |
