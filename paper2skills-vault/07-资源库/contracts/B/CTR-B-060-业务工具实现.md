# 业务工具实现 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，
> 不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**实现与回归测试可自动化，但业务语义验收须真实任务验证。**
> 这半句就是本契约可达段与不可达段的分界线：**能自动判的是「接口契约齐不齐、调用合不合规、抽查查询同不同口径」；
> 判不了的是「这件工具在真实业务任务里有没有解决那件事」** —— 后者必须由主岗位用一件真实任务验收（见 §2 不可达②）。
>
> **本契约覆盖的格**：方法格为 FLOW-06/STG-04（证据收集与诊断）、FLOW-06/STG-05（方案与标准产物）、
> FLOW-06/STG-08（结果核验、关闭与异步学习），§1 的算式落在这些格上；
> 规则格为 FLOW-06/STG-01（信号接收）、FLOW-06/STG-02（范围确定与 Case 创建）、FLOW-06/STG-03（上下文装配）、
> FLOW-06/STG-06（Assurance 接收门禁）、FLOW-06/STG-07（受控动作），**这些格只放判据与门禁条件**（§4 的落脚处）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境与材料已给出的数（出海历史 2 个完整年度＝决策 Q11；材料 §E 的 STG-04／STG-06／STG-07 最低接收条件；PB-006 的「新工具失败时恢复已知可用流程并保留影响范围，不重写原始事实凑齐报表」与必须回放的六类场景：两部门 GMV 口径冲突／SKU 映射缺失／过期数据／跨账号读写拒绝／外部接口限流／工具版本回退）；
> （b）业务侧默认（材料已定名的门禁口径或行业惯例，逐条附替换条件）；
> （c）§1 算式的输出（由命名的数据系统直出）。**候选卡的卡面示例值与实现默认值不构成第四种来源**（逐条清单见 §1 末）。

## 1 算法可达部分

- **候选卡状态（先读这一条再用本段）**：本责任的三张代表卡都是**全文卡**（八段俱全、含 ⑧ 已核验或已判定的出处与同目录 `references/implementation.py`），但**第 ④／⑤ 两段仍是占位串**，卡面给的是**示例规模与实现默认值**，**论文实验参数未随卡进入本包** —— 故本段的可达写法由**本业务算式**定值，卡只供方法骨架；卡面可见数字逐条列在本段末尾，**任一条不得移植**。
- **可达段一（工具接口契约的可核验部分，落 FLOW-06/STG-04、STG-05、STG-08 三个 M 格）**：对纳入本 Case 的每一个工具，机检其接口契约六要素（用途、参数、约束、示例、副作用、返回格式）是否齐备，并算回归用例通过率，产出〈数据/工具交付包〉里的工具能力条目与〈能力交付关闭记录〉的验收结论。
- 算式：`描述齐备率 = 六要素齐备的工具数 ÷ 纳管工具数`；`回归通过率 = 通过的注册用例数 ÷ 注册用例数`。**纳管工具**＝该 Case 的〈能力交付Case Charter〉点名的工具；**注册用例**由本责任按接口契约登记，来源＝〈工具能力与验收包〉。
- 取值：`描述齐备率门禁 = 1.0（100%）`、`回归通过率门禁 = 1.0（100%）`，两者都是**二值门禁**（缺一项即 HOLD，**不设部分通过档**），依据＝材料 §E 的 STG-06 最低接收条件 `deterministic_checks_pass` 与 STG-04 的 `sources_and_versions_recorded`。**替换条件**：〈工具能力与验收包〉签发并覆盖满 **2** 个完整年度后，改用**实测**的缺项分布与用例失败分布定档；替换前结论只能表述为「**未检出**缺项」。
- **可达段二（调用行为的可复算部分）**：按「推理—行动交替」把一件真实业务任务拆成工具调用序列（先推理需要什么信息，再取数，再据观测继续推理），用〈Case/Event Ledger〉的 Execution Attempt 记录算调用质量，产出失败边界条目。
- 算式：`无效调用率 = 入参 schema 校验失败或被策略门拒的调用数 ÷ 调用总数`；`工具调用成功率 = 成功调用数 ÷ 调用总数`（成功＝有提供方请求引用且外部状态可查）。
- 取值：**无效调用率上限取 0 次**（依据＝材料 STG-07 最低接收条件 `idempotency_and_object_version_checked_before_execution`：入参不合 schema 的调用一次都不许进受控动作）；**注册用例上的工具调用成功率门禁取 1.000（100%）**，生产调用不按此门禁判（按 §5 ③ 的基线累计后再定档）。
- **可达段三（只读取数类工具的口径可核验部分）**：对自助取数一类的工具，抽查其生成的查询是否与 AGT-045 的指标契约口径一致，并把「只读、禁写」作为硬约束。
- 算式：`口径一致率 = 与指标契约口径一致的抽查查询数 ÷ 抽查查询数`。
- 取值：**口径一致率门禁取 1.0** —— 任一抽查查询与指标契约口径不符即判不通过并登记缺口；**只读约束按二值判**（出现写操作或 DDL 即判失败，无中间档）。
- **本段的能力边界**：只做三件事 —— 接口契约是否齐备、调用是否合规、抽查查询是否同口径；**不产出业务语义验收结论、不产出权限授予、不代替外部系统的真实行为**（见 §2 三条）。

## 2 不可达部分

- 不可达①（需**外部事实**）—— 外部系统（平台接口、ERP、物流承运商、支付渠道）的真实行为、限流策略与版本变更：本司只能看到自己的请求与响应，看不到对方侧的限流规则、字段变更与灰度节奏。
  → 替代路径：由 AGT-021（Amazon 侧）、AGT-023（独立站侧）、AGT-015（采购与合同履约）、AGT-019（跨境物流与关务）在 STG-04 结束前提供各自与外部系统既有对接的事实与接口文档版本；由本岗把限流与退避写成回归用例并标注「按文档假设」；补不上时先用「最近一次成功调用的响应头 ＋ 对方文档快照」顶替并标「未核验」，后果是该工具只能在沙箱跑回归、不得进入生产 Bundle（§4 第 1 条）。
- 不可达②（需**真实任务验证**）—— 业务语义验收：这件工具在真实业务任务里有没有解决那件事、口径争议算不算解决，属 §F.3 明文写出的不可自动化段。
  → 替代路径：由该 Case 的主岗位（FLOW-06 默认 AGT-047，涉口径争议时 AGT-045、涉数据质量时 AGT-046）在 STG-08 关闭前用**一件真实业务任务**做验收并签〈能力交付关闭记录〉的业务验收栏，由 AGT-003 出经营验收记录；补不上时先交付「回归用例全过 ＋ 沙箱观察」并标「业务验收未完成」，后果是该 Case 只能出「部分交付」结论（材料关闭结果六档的 `PARTIAL`），不得计入复用率。
- 不可达③（需**实物或回执**）—— 外部写操作的真实凭据（下单、改价、退款、入库、清关的真实回执）：工具自身的测试无法产生这些凭据。
  → 替代路径：下单、改价、退款、入库与清关的真实凭据由 AGT-021／AGT-023（渠道侧动作）、AGT-020（仓储履约与退货处置）、AGT-040（GMV 结算与会计对账）在 STG-08 关闭前逐对象交出；交不出时只能用工具日志里的提供方请求引用先垫着当过程证据并逐条标「凭据缺席」，后果是该对象的关闭结论写不进验收栏，只能挂「未闭合」并留观察窗，不得判为交付成功。
- 不可达④（需**法定或治理签署**）—— 访问边界与权限授予（这件工具能读写哪些账号、哪些字段、凭证由谁托管）：STG-06 明确要检查 Access，这项检查的结论不在算法侧。
  → 替代路径：由 AGT-050 在 STG-06 前签发权限矩阵与访问证据、涉客户数据或隐私字段时由 AGT-044 在 STG-05 定稿前出隐私需求分析；补不上时该工具一律按只读最小权限上线并置 HOLD，后果是该 Case 不得进入 STG-07 受控动作（含 Bundle 变更的发布生命周期），只能出 NoActionRecord。

## 4 该格何时必须冻结

- 描述齐备率 < 1.0 或回归通过率 < 1.0（工具未过二值门禁）⇒ 不得提交 STG-07 的发布尝试或变更提案；Bundle 变更一律转入发布生命周期，不在本格内加急。
- STG-06 前未取得 AGT-050 的访问边界与权限矩阵，或未取得 AGT-049 的运行恢复设计与失败边界 ⇒ 该 Case 的 Assurance Decision 判 HOLD，工具只许只读运行。
- 工具调用出现无效调用（入参不合 schema 或被策略门拒）而仍写入生产对象，或出现写操作与 DDL（自助取数类工具）⇒ 立即冻结该工具并登记自治异常，相关对象按 §2 不可达③ 走人工对账。
- 工具失败后未恢复已知可用流程、或为凑齐报表回写非事实值（PB-006 原文口径）⇒ 冻结该 Case 的交付结论，保留失败影响范围，不得关闭 STG-08。
- 命中外部接口限流而未经退避与幂等键核对就重试 ⇒ 不得进入受控动作，转人工恢复；涉及资金与库存的动作一律先查权威外部状态。
- 工具版本回退之后未重跑注册用例集 ⇒ 该版本不得放行；回退只写新版本记录，不改写原尝试记录。
- 抽查查询与 AGT-045 指标契约口径不一致（口径一致率 < 1.0）而该工具输出被用于对外披露或绩效核算 ⇒ 判 HOLD 并转人工裁决口径。
- 业务语义验收未完成（无真实任务验收记录）而拟宣布交付完成 ⇒ 关闭结论只能写「部分交付」，不得写入〈FLOW-06 Assurance Decision〉的接受项。
- 引用 §1 末「卡面可见数字清单」中任一条（权重、长度阈值、金额、行数与示例参数）作为本业务取值 ⇒ 该方案不得放行。
- 外部证据时限：自 STG-05 产物提交起，至该 Case 的〈能力交付Case Charter〉已写明的验收截止日仍未取得 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。
