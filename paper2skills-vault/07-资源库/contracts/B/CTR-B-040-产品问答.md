# 产品问答 · 供给契约

> **本契约的两部分，用法不同。** §1 算法可达部分 / §2 不可达部分 / §3 必须的外部证据与责任岗位 /
> §5 数据要求 / §6 适用 FLOW 是**作业口径** —— 据此产出方案：可达段给算式与取值，不可达段给替代路径；
> §4 该格何时必须冻结是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> **本责任为什么是 B 类**（`_survey_org_model.md` §F.3 原文，别改判）：事实型问答可 RAG 覆盖，
> **但功效与健康类专业问题须受控知识源与人工兜底** —— 这句话就是本契约可达段与不可达段的分界线：
> 命中〈商品主数据〉与图谱现存事实的产品事实型问句走可达段（算式 + 取值）；
> 功效、健康与医疗类问句**整段**落不可达段，输出形态是「转人工 + 待专业确认」，不由本责任出结论。
> 本责任的标准产物是 AGT-036 的〈有依据的售前答复与线索〉（岗位指标：问题解决与购买体验）；岗位人格边界逐字为
> **「不作无依据医疗判断或功效承诺」**。
>
> **格子边界**：本责任在 FLOW-04（〈市场进入诊断〉〈市场进入包〉〈市场进入关闭记录〉）、
> FLOW-05（〈客户问题诊断〉〈服务与留存方案〉〈客户旅程关闭记录〉）、FLOW-07（〈事件范围与根因诊断〉
> 〈重大事件处置包〉〈重大事件关闭与全动作对账记录〉）九个方法格上作诊断段、方案段与关闭段；
> 三个 FLOW 的 STG-01/02/03/06/07 是规则格，只放判据与门禁条件（含 STG-06 的 Assurance 接收门禁），
> 不承载本契约的任何方法实现。
>
> 本契约对同族方法卡通用（代表卡 `p2s-kgqa-question-answering`；同族另有 `p2s-medrag-domain-vertical-rag`、
> `p2s-ai-parenting-advice-hallucination-guard`）；**换卡时只替换方法实现，算式、取值、外部证据与冻结条件不变。**

## 1 算法可达部分

- **本条责任里算法能承接的那一段**：把「这条答复有没有依据」压成三样可核验产物 ——
  ① 每条答复的**依据路径命中状态**（命中须给出 `(实体, 关系, 目标)` 全链；否则记「未收录」）；
  ② 每条答复的**问句关系归类**（含有什么／适合谁／品牌／价格／对比五类，对齐材料「核对…商品主数据…宣称」的口径）；
  ③ 未收录与命中受控知识源之外的答复，按风险优先级排出的**人工兜底队列**。
  三样随答复记录写入本 Case 的标准产物（FLOW-04 落〈市场进入诊断〉与〈市场进入包〉；
  FLOW-05 落〈客户问题诊断〉与〈服务与留存方案〉；FLOW-07 落〈事件范围与根因诊断〉与〈重大事件处置包〉），
  并在三个 FLOW 的 STG-08 作关闭段提交。
- 算式：`依据覆盖率 = 有依据路径的答复数 ÷ 当期答复总数`；其中「有依据路径」＝该答复引用的**每一个**三元组
  都命中〈商品主数据〉与图谱的现存节点与边，且路径上每个节点带 `AGT-046` 的来源与新鲜度字段。
  `未收录率 = 命中状态为「未收录」的答复数 ÷ 当期答复总数`。两个率的分母同为当期答复总数，不设例外。
- 算式：`受控知识源外命中数 = count(答复所引知识源 ∉ 〈受控知识源清单〉)`；该清单**尚未签发**
  （来源逐字取 AGT-044 的宣称审查结论，其标准产物为〈合规矩阵与证据缺口〉，与岗位人格边界所允许的来源合并而成），
  **不由本契约另造一份清单**；AGT-044 签发后以它的名称替换本契约对该清单的引用。
- 取值：**依据覆盖率目标线 ＝ 1.00（100%）** —— 即每条对外答复都必须带至少一条现存三元组路径。
  该数是**业务侧默认值**（来源＝经营者自述「产品参数只经商品主数据与图谱出，不允许凭记忆作答」，
  与岗位人格边界同向）。**替换条件**：答复留痕按「问句 × 答复 × 依据路径」落库并跑满 **1 个自然月**后，
  改用**实测**依据覆盖率与实测未收录率两值并列；替换前该结论只能表述为「**未检出**无依据答复」，
  **不得**表述为「零幻觉」或「不存在编造」。
- 取值：**未收录率容忍线 ≤ 5%**（等价于每 **20** 条答复至多 **1** 条以「未收录」收尾）。
  该数是**业务侧默认值**（来源＝经营者自述「超过这个比例就该开补录工单，而不是让坐席一直答不知道」）。
  **替换条件**：图谱按 `AGT-045` 口径签发并覆盖本期在售 SKU 后，改用本业务实测未收录问句占比的月度上界；
  替换前该线只用于**开补录工单**，**不得**用于坐席考核。
- 取值：**受控知识源外命中数 ＝ 0 件**（二值判定，不设打分档）。判据＝问句或答复草稿涉及
  喂养、睡眠、健康、剂量、过敏、用药任一话题，**或**引用来源不在〈受控知识源清单〉内；
  命中即**转人工**，该类问句的人工兜底率取 **100%**。判据由 `AGT-044` 的宣称审查结论与岗位人格边界共同构成。
- 取值：**兜底队列长度 ＝ 当期「未收录 ∪ 受控知识源外命中」的答复全量**；排序键 ＝
  （风险话题命中 desc，未收录 asc，会话进入时间 asc）；三档优先级的判定词随〈客户Case Charter〉的完成条件写定后冻结。
- **不得移植的部分**（逐条来自实际读过的三张卡；任一条都不得作为本业务的判定线或阈值）：
  代表卡 `p2s-kgqa-question-answering` 的卡面示例值 ——「响应从 **10 分**压到 **1 分**」「年化省 **14 万元**」
  「**2 分钟**查资料 → **5 秒**自动回答」「培训成本降低 **60%**」「**80%** 的电商问题由 **10 种**查询模式覆盖」
  「客服效率提升 **3-5 倍**」，以及卡内代码写死的置信度档 `confidence = 0.95`／`0.3`／`0.9`、
  示例价格 `$35`／`$32`／`$120`、示例月龄 `12-36个月`。该卡 `evidence_basis: author-practice`，
  卡页自承**无对应论文来源**，② 场景数字与 ⑤ ROI 均为作者举例。
  同族卡 `p2s-medrag-domain-vertical-rag` 为 **legacy 预览版**（八段式，④⑤ 段是占位串、代码以
  `references/implementation.py`（**238 行**）随卡且为节选）⇒ **论文实验参数未随卡进入本包**；
  其卡面可见数字（准确率 **+35%**／通用 LLM **60~70%**／日均 **3000+** 咨询／响应 **8-12 小时**／
  准确率 **92%**／月人工 **15 万元**／目标 **98%+**／**<2 秒**／年化 **180 万元**／满意度 **82%**／
  月成本 **800 元**／下降 **94%**／图谱过时风险 **8%**／翻译偏差 **5%**／审核周期 **30 天**→**3 天**／
  错误率 **12%**／销售损失 **800 万元**／年化 ROI **620 万元**）同为示例场景，一律不得作为本业务取值。
  同族卡 `p2s-ai-parenting-advice-hallucination-guard` 同为 **legacy 预览版**（④⑤ 为占位串、
  `references/implementation.py`（**26 行**））⇒ **论文实验参数未随卡进入本包**；其卡面可见数字
  （漏出率 **12%**→**<1%**／年化法律风险 **50-200 万元**／**1 人/季度**／**0.01 元/次**）与代码里写死的分档
  `safety_score = max(0, 100 − len(risks) × 40)`、`BLOCK < 60`、`WARN < 80` 一律不得移植 ——
  本业务的功效与健康类判据是**二值**的（命中即转人工），**不采用任何打分阈值**。
- 本段的能力边界：只做四件事 —— 依据路径是否现存、问句关系归到哪一类、有没有命中受控知识源之外、
  按什么次序送人工；**不产出功效与健康类结论、不产出对外宣称、不替代坐席的兜底答复**（见 §2 第 1 条）。
- 本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变。

## 2 不可达部分

以下五段是算法到此为止的地方：两段属外部事实，一段属实物回执，一段属法定与治理签署，一段属治理事实。

- 功效、健康与医疗类结论的定性，以及这类问句的对外答复：属**人的专业判断加法定/治理签署**（宣称边界），
  判定式只能判别是否命中话题、不能给出结论，本责任也无权代签（岗位人格边界：不作无依据医疗判断或功效承诺）。
  → 替代路径：由 AGT-036 售前服务与购买指导的人工坐席在 STG-06 的 Assurance 接收门禁前承接该类问句，
  由 AGT-044 产品合规与隐私在 STG-05 方案定稿前出具宣称审查结论（其标准产物为〈合规矩阵与证据缺口〉）；补不上时先用「逐条引用〈受控知识源清单〉
  内的权威来源 + 不做结论」的模板答复顶替，并在答复上加「待专业确认」标记，该类答复**不得**计入
  〈FLOW-04 Assurance Decision〉〈FLOW-05 Assurance Decision〉〈FLOW-07 Assurance Decision〉的接受项；
  后果是命中该话题的会话只能出 Action Intent + 人工工单，并计入本期**未闭合**答复数。
- 平台规则原文与宣称限制的真相（哪些成分不能标、哪些话不能说、何时改口径）：属**外部事实**，
  本司系统内不存在可复算字段。
  → 替代路径：由 AGT-027 店铺账号健康与规则在 STG-04 证据收集开始前提供〈账号健康与政策通知〉的公告原文
  与生效版本号；补不上时先用「公告截图 + 上一次已生效版本号」顶替并逐条标「未核验」，
  凡以未核验规则为依据的答复一律不进自动放行、也不改〈商品主数据〉；后果是相关商品在 STG-05 只出「有条件上架」包。
- 商品主数据与合规文件的原件（配方表、检测报告、上市许可或注册号、适用月龄的文件依据）：属**实物或回执**，
  图谱只能引用编号、不能证明原件仍然有效。
  → 替代路径：由 AGT-013 产品验证与研发项目配合 AGT-044 在 STG-04 结束前逐 SKU 提供原件编号与有效期；
  补不上时先用〈商品主数据〉现有字段作过程证据、把该 SKU 的成分与月龄类答复标「未持证」，
  仅可回答品牌与价格两类；后果是该 SKU 不进 FLOW-04 的上架 Intent，也不出功效类答复。
- 客户侧事实（宝宝实际月龄、过敏史、已购型号、是否在哺乳期）：属**外部事实加需授权数据**，
  只能由客户自述或订单事实得到，图谱与埋点都推不出。
  → 替代路径：由 AGT-034 CRM留存与复购在 STG-03 上下文装配时提供该客户的许可状态与〈订单事实〉字段清单；
  补不上时先在会话内向客户直接询问，把答案记为「客户自述」并与〈订单事实〉**分开存放**，
  二者冲突时以订单事实为准并转人工；后果是缺这些槽位的会话只能做通用答复，不得作适用性判断。
- 图谱与商品主数据的覆盖是不是完整（「未收录」是真的没有，还是**根本没建**）：属**治理事实**，
  判定式只能观测到未命中，区分不了这两种，而这两种对应的处置完全不同。
  → 替代路径：由 AGT-048 知识技能与Playbook治理在 FLOW-08 的经营与能力诊断中把未收录答复聚类成
  「未建节点」清单，由 AGT-047 系统集成与业务工具在 STG-05 给出补录方案（数据/工具交付包）；
  补不上时先用〈平台后台〉商品页问答与〈独立站埋点〉会话事件里的高频未收录问句人工聚类顶替为补录线索；
  后果是未收录率在替换前只报不考核，且未闭环项按材料规则**不把缺失值当作零**。

## 4 该格何时必须冻结

- STG-06 前未取得 AGT-044 的宣称审查结论，而答复涉及功效或健康表述 ⇒ 该格不得推进到
  FLOW-04/STG-07 与 FLOW-05/STG-07 的受控动作，只能出 NoActionRecord。
- 依据覆盖率 < 1.00（检出 ≥ 1 条无依据路径的对外答复）⇒ 冻结该批答复的自动放行，逐条回查并转人工；
  重算前不得把任何一条写入本 Case 方案段的可执行项。
- 未收录率 > 5% 且该商品对应的图谱节点未补齐 ⇒ 该 SKU 的成分与月龄类答复不得自动放行，只出「未收录」模板答复。
- 受控知识源外命中数 > 0 件（涉及喂养、睡眠、健康、剂量、过敏、用药任一话题）⇒ 立即转人工并交 STG-06 复核；
  命中 FLOW-07 的质量或账号口径时移交 D-026 紧急保护通道（Emergency Guard），24 小时内补〈Pre-Case Exception〉记录。
- 商品合规文件原件缺失或已过期（AGT-013），而答复要引用其结论 ⇒ 冻结该 SKU 的全部成分与月龄表述。
- 客户许可缺失（AGT-044）而拟动作含主动触达 ⇒ 不得进入 STG-07，只能出 Action Intent + 人工工单。
- 命中材料 EXC-WAITING-INPUT（必需输入缺失、过期或不可用）⇒ 该 Case 状态置 WAITING，
  依赖项与新鲜度复核通过后方可回到**同一**阶段，不得以跳过阶段的方式继续。
- 命中材料 EXC-POLICY-DENIED（Policy Gate 拒绝 Action Intent）⇒ 该 Case 状态置 REWORK_REQUIRED，
  退回 STG-05 或出 NoActionRecord 关闭，**不得以任何方式绕过拒绝**。
- 答复所用主数据/图谱节点缺少版本时点（§5 ④ 的缺口）而该答复要作跨 Case 复用的历史结论 ⇒ 冻结该次复用。
- 外部证据时限：自 STG-05 产物提交起，至〈Case Charter〉写明的观察窗截止日仍未取得 §3 所列任一必需证据 ⇒
  判 HOLD 并转人工，不得默认放行。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | `自有埋点`（独立站埋点的会话与答复事件；Case/Event Ledger 的 Case Charter、Stage Acceptance Record、Execution Attempt）＋`平台后台`（Amazon 卖家后台的买家消息与商品页问答；账号健康与政策通知）；〈商品主数据〉、合规文件原件与客户明细为 `需授权` | 非缺口。平台站内信只留在平台侧时，答复里引用的三元组回指不到本司节点，`依据覆盖率` 的分子分母都取不到 —— 这批答复既证明不了「有依据」，也不该被记成「未收录」。故先按〈市场进入 Case Charter〉写明的渠道与时间窗导出平台侧消息，只拼问句与答复文本、不带客户明细，另列一栏注明「未落本司留痕」，该栏先只作占位；等该渠道写入 Case/Event Ledger 之后，改用本司自存的答复留痕顶掉它、并回分子分母重算。在此之前该批答复只进兜底队列排队，不进覆盖率。 |
| ② 粒度 | 一条 ＝ 一次问答（问句 + 答复 + 依据路径 + 关系归类 + 命中状态），键为 `case_id` + 会话序号 | 非缺口。若某源只按会话或工单汇总：先按「会话级」顶替并把该批标「粒度不足、不可作单条依据判定」，逐条落库到位后替换为单次问答粒度 |
| ③ 回溯深度 | 答复留痕按「问句 × 答复 × 依据路径」**尚未**落库；存量可用的独立站会话与平台消息为 **2 个完整年度**（业务处境给出的出海历史长度，决策 Q11），用于高频问句与未收录聚类 | 先用〈Amazon 卖家后台〉买家消息与〈独立站埋点〉的会话事件文本拼出「问句—答复」对顶替，并标「粒度不足、不可作依据覆盖率的分母」；逐条落库跑满 **1 个自然月**后替换为答复留痕；替换前依据覆盖率只报「未检出」、不报百分比 |
| ④ 新鲜度 | 要求 ＝〈商品主数据〉与图谱节点的 `updated_at` 须为截至**前一日 24:00** 的完整快照、进入 STG-04 前重读；但该字段**尚未**落库，当前可证明的时点只有该 Case 的 STG-04/STG-05 时点 | 缺口：主数据没有版本号与 `updated_at`，`依据覆盖率` 只能证明三元组现存，证明不了「答复那一刻它还有效」—— 跨 Case 复用的历史答复会把已下架成分当作现役事实引出去。处置：先拿该 Case 的 Stage Acceptance Record 落库时点当这条答复的时间锚，逐条注明「主数据未落戳」；主数据补上版本号字段后，锚点改用该节点的版本时点。换锚之前，这类答复的时效栏只能写「读取于本 Case 的 STG-04/STG-05 时点」，不得写「答复时仍有效」。 |
| ⑤ 口径归属 | `AGT-045`（业务口径与主数据）为成分、适用月龄、依据覆盖率与未收录率分子分母的归属方；每条答复与节点记录随带 `AGT-046` 的来源、质量状态与新鲜度 | 非缺口。要定的是「两个率的分母算不算同一批答复」：`依据覆盖率` 与 `未收录率` 的分母写法上同为当期答复总数、不设例外，可「当期」按会话进入日切还是按答复落库日切没有归属方 —— 两种切法下这两个率会互相矛盾。故先按〈有依据的售前答复与线索〉的落库时点各切一版、两版并列；〈数据口径与对象关系契约〉签发后，改用其定义单出一版。改用之前未收录率只用来开补录工单。 |
