# 证据复核 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，不可达段给替代路径。
> §4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3，逐字）：证据一致性与伪造检测可 NLP 预筛，但缺陷定性与结论须独立审计师判断。
> ⇒ 这条理由直接规定了本契约的分界：**「这条声明能不能回到证据」是可达段，「这条缺陷该定成什么性质」是不可达段**。把后者写进 §1，就是本模板要拦的完整性虚报。
>
> **本契约覆盖的格**：方法格为 FLOW-07/STG-04、FLOW-07/STG-05、FLOW-07/STG-08 与 FLOW-08/STG-04、FLOW-08/STG-05、FLOW-08/STG-08 —— §1 的四段算式落在这些格上；
> 规则格为两个 FLOW 的 STG-01／STG-02／STG-03／STG-06／STG-07，**这些格只放判据与门禁条件**（§4 的落脚处），本层不在其上选参。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；本项目综述 §E 的 STG-04 最低接收条件 `sources_and_versions_recorded`／`freshness_and_quality_status_recorded`／`conflicts_and_missing_data_explicit`／`claims_trace_to_evidence`／`uncertainty_explicit`，§E.2 的 Case 状态机与关闭结果六档，§E.3 的异常与恢复条件，PB-007／PB-008 的责任与产物；**§E 的编号与这些标识符出自本项目综述，不是材料原文**）；
> （b）业务侧默认（经营者自述、平台规则或行业惯例，逐条附替换条件）；
> （c）§1 算式的输出（由命名的数据系统直出）。**候选卡的卡面数字不构成第四种来源** —— 逐条清单见 §1 末尾。

## 1 算法可达部分

- **候选卡状态（先读这一条再用本段）**：本责任 9 张候选卡**全部是 legacy 预览版**（八段式）—— 卡页第 ④、⑤ 两段是占位串，代码只以同目录 `references/implementation.py` 形式随卡，第 ⑧ 段或写「未自动抽取」或自述出处不可采信，**论文实验参数未随卡进入本包**。故本段的可达写法由**本业务算式**定值，卡只供方法骨架；卡面可见数字逐条列在本段末尾，**任一条不得移植**。
- 方法族：**证据一致性与伪造检测的机检三层** —— ① 声明能不能逐条回到证据（对齐核验）；② 同一事实在多个源之间是否打架（冲突检出）；③ 引文是不是逐字来自底本（连续度判定）；外加 ④ 复核覆盖率与派单排序（业务侧口径）。三张代表卡各承担前三层中的一段，第四层由本业务定值。
- 代表卡（三张，均取自本责任候选清单的「只有 legacy 预览版」那一支）：
  - `p2s-decision-audit-trail-ontology`（源卡号 `Skill-Decision-Audit-Trail-Ontology`，源域 24-标签工程，图谱 L3 = 证据复核 / 溯源监测）：承担第 ① 层的记录侧 —— 一次自动决策的 who／what／why／how 要素是否齐备、记录能否按前序哈希串成可回溯的链。
  - `p2s-llm-hallucination-detection-bi`（源卡号 `Skill-LLM-Hallucination-Detection-BI`，源域 09-DataAgent-LLM，图谱 L3 = 数据质量 / 证据复核）：承担第 ① 层的文本侧 —— 从结论文本里抽出带度量语义的声明，逐条与基准数据比对后给可信／存疑／错误的标注。
  - `p2s-explainable-review-adjudication`（源卡号 `Skill-Explainable-Review-Adjudication`，源域 19-风控反欺诈，图谱 L3 = 体验分析 / 证据复核）：承担第 ③ 层的表达纪律 —— 结论必须附证据引用与可追溯的相似案例，**不得只给真或假的二元标签**（该口径被本契约整体采纳）。
- 同族可整卡替换（同在本责任候选清单内，同为 legacy 预览版）：`p2s-sensitivity-analysis-rosenbaum`、`p2s-sensitivity-analysis-causal`、`p2s-partial-identification-bounds`（把「证据不足时结论有多大摆动空间」量化）、`p2s-glass-box-mas-observability`、`p2s-human-in-loop-approval-gate-tag`、`p2s-llm-uncertainty-quantification-bi`。
- **可达段一（声明—证据对齐，落 FLOW-07/STG-04、FLOW-07/STG-05、FLOW-07/STG-08 与 FLOW-08/STG-04、FLOW-08/STG-05、FLOW-08/STG-08 六个方法格）**：把被复核标准产物（〈事件范围与根因诊断〉〈重大事件处置包〉〈经营与能力诊断〉〈经营与能力变更建议〉）里每一条带度量语义的声明，逐条回到〈证据包〉与源系统的同口径、同时间窗字段去核，输出「未对齐声明清单」。
- 可达段一算式：`未对齐声明数 = count(声明 : 该声明在〈证据包〉或源系统里找不到同口径且同时间窗的可复算字段)`；`声明对齐率 = 1 − 未对齐声明数 ÷ 应核声明数`，其中**应核声明数** ＝ 被复核产物中同时含数值与单位的声明条数（无度量的定性表述不进分母）。源字段：〈Case/Event Ledger〉的 `case_id`、`entity_id`、`metric_name`、`observed_at`、`value`，以及〈平台后台〉报表的同口径字段。
- 取值：**声明对齐率 = 1.000（100%）**、**未对齐声明数 = 0 条**。这两个数是**业务侧默认**、不是实测：材料口径下 STG-04 的最低接收条件已含 `claims_trace_to_evidence`（声明须逐条可回溯到证据），故本段只有满值一档；当前取满值的依据是**经营者自述**「诊断与根因结论只经 Case 的 STG-04 产物写入，无表外结论、无口头补充」。
  **替换条件**：〈证据包〉与〈诊断记录〉逐条落库并覆盖满一个完整审计周期后，改用**实测未对齐条数**重算；替换前该结论只能表述为「**未检出**未对齐声明」，**不得**表述为「证据完整」或「结论已核实」。
- **可达段二（多源冲突检出）**：同一事实在三个来源之间做逐字段比对，输出「冲突字段对清单」。
- 可达段二算式：`冲突条数 = count(字段三元组 : 同一 metric_name + 同一 entity_id + 同一时间窗下，〈Case/Event Ledger〉、〈平台后台〉报表、〈财务系统对账表〉三源中存在取值不一致或时点归属不一致的组合)`；时间归属与口径版本一律取 AGT-045 指标契约的版本号，**不用**三源自带的默认时区或自然月切分。
- 取值：**冲突条数 = 0 条**（**业务侧默认**，来源同上：经营者自述「三源经 AGT-045 统一口径后落库」）；**替换条件**：三源对账覆盖满一个完整审计周期后改用**实测冲突条数**；实测 > 0 条即触发 §4 冻结第 2 条，替换前「0 条」只能写成「未检出冲突」。
- **可达段三（引文级伪造与拼接检测）**：对每一条引用块算它与被引底本的**最长连续匹配段占比**，输出三档判定。
- 可达段三算式：`连续度 = 引文与被引底本的最长连续匹配段长度 ÷ 引文长度`；**不用**全文档碎片覆盖率 —— 把两句话缝成一句时碎片仍能各自找到，覆盖率仍是满分，只有连续性能把它打下来。
- 取值：**连续度 ≥ 0.85 判「逐字」；0.60 ≤ 连续度 < 0.85 判「需人工复核」；连续度 < 0.60 判「伪造或拼接」**（**业务侧默认**：行业惯例的文本比对三档界）；**替换条件**：〈复核结论与整改清单〉累计满 2 个完整年度的实测误判率后，改用「使误判率 ≤ 5%」的连续度界；替换前「需人工复核」档一律不得直接判为缺陷，只能出提示。
- **可达段四（复核覆盖率与待人工复核队列）**：按（未对齐声明数 desc，冲突条数 desc，`|estimated_impact|` desc，`observed_at` asc）排序派单，并用两个可核验的分母报覆盖率。
- 取值：**队列长度 = 当期命中「未对齐或冲突」的记录全量**（不截断、不设上限，超长队列分批派单）；**本期复核覆盖率 = 已签署〈复核结论与整改清单〉的 Case 数 ÷ 当期应复核 Case 数**，目标 **1.000（100%）**（**业务侧默认**：材料口径下 FLOW-08/STG-06 的检查项含独立审计与观察窗口，故本责任对 FLOW-07 与 FLOW-08 的当期 Case 全覆盖）。
  **替换条件**：AGT-005〈抽样审计〉责任给出本周期抽样方案（含各层 `n_h`）后，按该方案的比例截取队列首段派单、其余留档不派单，覆盖率改用**抽样覆盖率**口径并在〈复核结论与整改清单〉里同时报出未派单对象数；替换前不得把「未派单」写成「无问题」。
- **本段的能力边界**：只做四件事 —— 声明是否可回溯、多源是否一致、引文是否逐字、按什么次序送人工；**不产出缺陷定性、不产出复核结论的签署**（见 §2 第 1 条）。

## 2 不可达部分

- 不可达①（需**法定或治理签署**）—— 缺陷定性与复核结论的签署：机检只能给出「哪条声明对不上、哪条引文不逐字、哪两个源打架」，判「这是控制设计缺陷还是执行偏差、该由谁整改、整改到什么程度算关闭」属**独立审计师的判断与签署**，不可由本层产出。
  → 替代路径：由 AGT-005 内控审计与独立复核岗的持证审计师在 FLOW-07/STG-06 与 FLOW-08/STG-06 接收门禁前签署〈复核结论与整改清单〉；补不上时改用「候选 ＋ 待签」两栏交付，候选那一栏不列入〈FLOW-07 Assurance Decision〉与〈FLOW-08 Assurance Decision〉的接受项，该单停在本门禁；后果是本周期 `复核覆盖率` 的分母里它只能记「未签署」，不得记为已复核。
- 不可达②（需**外部事实**）—— 链外事实：供应商真实产能与是否转包、平台规则原文与生效版本号、产品准入与宣称判定、关联方登记与股权结构。本司系统内不存在这些字段的可复算副本，机检最多证明「本司记录自洽」。
  → 替代路径：由 AGT-014 在 STG-04 结束前出验厂报告与产能档案、AGT-027 在 STG-04 结束前提交平台政策原文与生效版本、AGT-044 在 STG-05 方案定稿前出合规矩阵与证据缺口、AGT-043 在涉对外声明的 STG-05 前出法律意见；补不上时退到平台公告页的留档截图，并逐条钉「未取得原文」，链外事实一律只作线索；后果是凡依据这类材料的处置不进受控动作，相关对象只登记为待人工处置。
- 不可达③（需**实物或回执**）—— 实物级证据：质量检测报告与批次质检记录、到货／签收／退货入库回执、退款与召回的执行回执、销毁现场记录。这些事实**无法由留痕表、报表或文本比对推出**，伪造检测也替代不了原件。

- 不可达④（需**外部事实 ＋ 治理事实**）—— 证据的权威副本归属与复核独立性：同一份证据的权威原件在谁手里（平台、承运商、银行、供应商、工商登记），以及**复核人是否参与过被复核的那次决策**，都不是本司数据能自证的事实；留痕表只能记录 who，不能证明回避。
  → 替代路径：由 AGT-002 在 STG-03 上下文装配时出具该 Case 的角色清单（主岗位、复核人与各自参与动作），由 AGT-050 在 STG-06 前提供访问控制与账号责任人清单以反查参与关系；补不上时退到 AGT-001 在 STG-06 前指定另一名复核人重做这一步；后果是独立性举不出证的 Case，接收门禁一律判 HOLD，本周期 `复核覆盖率` 也不把它算进分母（§4 冻结第 5 条）。
- 不可达⑤（需**人的专业判断 ＋ 外部事实**）—— 底本可得性：引文级核验要求被引底本在包内可读；本包的卡与论文存档并不总齐（多数候选卡自述「未自动抽取」「出处不可采信」「论文全文尚未入库」），此时「连续度」算不出来，只能算「引文长度」这一半。
  → 替代路径：由 AGT-048 知识技能与Playbook治理在本 Case 进入 STG-04 前补齐被引底本或出具「底本不可得」的书面结论；补不上时先把该条引文判为「**底本未入库、不可核验**」（**不是**「伪造」、也**不是**「逐字」），并在〈复核结论与整改清单〉里单列不可核验条数；后果是凡以不可核验引文支撑的数字，不得进入对外表述与绩效核算。

## 4 该格何时必须冻结

- STG-06 前未取得 AGT-005 持证审计师签署的〈复核结论与整改清单〉⇒ 该格不得推进到 STG-07 受控动作（含 Approval 级动作），只能出 NoActionRecord。
- 冲突条数 > 0 条（三源在同一 `metric_name` 与同一时间窗上取值或时点不一致）⇒ 冻结该 Case 的证据链部分：STG-08 不得关闭，也不得据该链出根因结论，先回 STG-04 重核。
- 声明对齐率 < 1.000（检出 ≥ 1 条未对齐声明）而产物仍以「已核实」表述 ⇒ 该结论不得进入 STG-05，只能标注为「未对齐候选」。
- 引文连续度 < 0.60（判「伪造或拼接」）⇒ 立即冻结该 Case 的对外表述与全部引用该引文的动作，升级到 FLOW-07 紧急保护通道的判定流程（由模型外的 Guard 依据已发布规则处理），24 小时内补 `REC-CASE-EXCEPTION` 记录。
- 复核人独立性无法证明（既无 AGT-002 的 STG-03 装配角色清单，AGT-001 也未在 STG-06 前指定替代复核人）⇒ 该 Case 的接收门禁判 HOLD。
- 动作涉及对外承诺、退款、召回、销毁或永久变更，而 AGT-043 法律意见或 AGT-044 合规判定缺失 ⇒ 不得进入受控动作阶段，只能出 Action Intent ＋ 人工工单。
- 以「底本未入库、不可核验」的引文支撑关键决策数字 ⇒ 该数字不得进入对外表述与绩效核算；涉及该数字的动作按 NoActionRecord 处理。
- 以未核验的平台规则版本（仅截图 ＋ 上一次已生效版本号）为依据发起账号类动作 ⇒ 该动作降级 NoActionRecord ＋ 人工工单，不得默认放行。
- 同一对象已有一次未回填的动作尝试或未闭合的复核 ⇒ 不得对该对象发起新动作；**已成功动作不得随整单重跑**。
- 外部证据时限：自 STG-05 产物提交起，至该 Case Charter 已写明的观察窗截止日仍未取得 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。
- 已写入〈复核结论与整改清单〉的未派单对象被计为「无问题」⇒ 该清单作废重出，当期覆盖率不得上报。

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | 自有埋点（〈Case/Event Ledger〉的 Case Charter／Stage Acceptance Record／Execution Attempt／NoActionRecord）＋ 平台后台（Amazon 卖家后台报表、账号健康与政策通知）＋ 需授权（财务系统对账表、采购台账、海关与合规条款库）＋ 第三方 API（物流承运商轨迹接口） | 非缺口。若某类证据只有 PDF、扫描件或邮件附件（检测报告、法律意见、平台政策原件）：先按〈Case Charter〉的附件登记项顶替并标「非结构化、未核验」，OCR 或人工录入完成并回填原件哈希后替换为结构化记录；替换前该类证据不得进入声明对齐率与冲突条数的分母 |

| ③ 回溯深度 | 近 2 个完整年度（业务处境给出的出海历史长度，决策 Q11），用于选可比的同口径历史案例与底本 | 非缺口。真正缺的是**够长的历史可比案例库**，不是窗长本身：不满 2 个完整年度时 `连续度` 逐条仍算得出，但「同一处缺陷过去是否出现过、上一轮是怎么定性关闭的」无参照，可达段四的派单排序也就只剩「未对齐声明数」一列在动，`p2s-explainable-review-adjudication` 要求的相似案例引用随之落空。在攒够 2 个完整年度之前，暂按首笔记录以来的自然月当比较窗并标「短于出海历史」；攒够之后整窗换成完整窗。在此之前只出单条判定与「未检出」，不得写模式性结论。 |
