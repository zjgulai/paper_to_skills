# Playbook评估 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，
> 不可达段给替代路径；§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> **本责任的判定理由**（`_survey_org_model.md` §F.3 原文）：**效果可用回放与指标对比评估，但流程合理性须业务确认。**
> 这句话就是本契约可达段与不可达段的分界线：**效果差可以算，这份流程合不合理不许算。**
>
> **本责任由 `AGT-048` 积知·知识技能与Playbook治理承担**（材料给本岗位的标准产物 ＝「**能力版本与评估记录**」，
> 考核口径 ＝「**复用效果和过期知识控制**」），跨 **FLOW-02 / FLOW-06 / FLOW-08** 三条流程，落点是材料 PB-008 的那句
> 「**AGT-048 将通过评估的经验变成能力版本**」：FLOW-02/FLOW-06 的产物要用到 Playbook 与技能卡，
> FLOW-08 的经营复盘要把「这一轮验证过的经验」变成能力版本 —— 本责任是这三处**版本进出的计量口**。
> ⚠️ 本责任只管**评估与记录**：改写 Playbook 内容、改版本号属同岗位的〈技能版本〉责任；本责任**不代替任何主岗位**
> （渠道按材料四选一：Amazon→AGT-021；独立站→AGT-023；其他平台→AGT-024；B2B/零售→AGT-025）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三类 ——
> （a）业务处境或材料已给出的数（出海历史 **2** 个完整年度＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月；渠道构成 Amazon **65%** / 独立站 **15%**、其余 **20%** 未定名＝开放事实 O1）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）——**「季度经营策略」＝1 个自然季度并归本档**；
> （季度档不由材料给出）；替换条件 ＝ 按 Playbook 版本归集满 2 个完整年度后，回放窗换成实测版本上线到效果稳定间隔的 P75；
> （c）§1 算式的输出（由命名的数据系统直出）。**三张代表卡的卡面案例数字与论文参数都不构成第四种来源**（逐条清单见 §1 末）。

## 1 算法可达部分

- **可达段一（回放：同一批历史 Case 上的版本效果差）**：把同一 Playbook（或同族技能卡）的**当前版本与上一版本**，在**同一批**已关闭 Case 上对齐比较，输出一个可核验的差值，而不是两个各自好看的绝对值。
- 算式：`版本效果差 Δ = 该 Playbook 当前版本在回放集上的通过率 − 上一版本在同一回放集上的通过率`；**回放集** ＝ 〈Case/Event Ledger〉中该 Playbook 适用范围内、近 1 个自然季度已关闭 Case 所对应的 Stage Acceptance Record（阶段接收事实）与 Execution Attempt（执行尝试与回执）；`通过率 = 阶段接收记录里未被返工的阶段数 ÷ 该 Case 的阶段总数`；同批复算的另两项为 `返工率` 与 `自治异常数`（分子分母与时间归属由 `AGT-045` 的指标契约签发）。
- 取值：回放窗口 ＝ **最近 1 个自然季度**（**业务侧默认**——季度档不由材料给出；按 Playbook 版本归集满 2 个完整年度后，回放窗换成实测版本上线到效果稳定间隔的 P75）。
- 取值：回放集样本下限 ＝ **30 个**已关闭 Case（**业务侧默认**，来源 ＝ **经营者自述**「一个季度里同类 Case 一般不止三十单，少于这个数只看方向、不下结论」）；**替换条件** ＝〈Case/Event Ledger〉按 Playbook 版本归集稳定后，改用「该 Playbook 一个自然季度实测调用量的 P10」作下限；替换前样本不足只出「样本不足」标注。
- 取值：分 **3** 档 —— Δ ≥ **+5pp** 判**升级候选**；**−5pp < Δ < +5pp** 判**保持当前版本**；Δ ≤ **−5pp** 判**回退候选**。**+5pp / −5pp** 系**业务侧默认**（来源 ＝ **经营者自述**「半个季度看不出五个点以上的差，就不值得动版本」）；**替换条件** ＝〈能力版本与评估记录〉跑满 **2** 个自然季度后，改用实测 Δ 分布的 **P75 / P25** 作上下档；替换前该分档只决定「提交不提交变更建议」，不决定发不发版本。
- 取值：**三项指标同看** —— 通过率、返工率、自治异常数中任一恶化 ≥ **5pp** 且无另一项改善 ≥ **5pp** ⇒ 一律判**回退候选**（与 Δ 的符号无关）。该规则为**业务侧默认**（来源 ＝ **经营者自述**「有一项明显变差就不能算改好了」）；**替换条件** ＝ 同上（改用以三项实测分布构造的联合判据）。
- **可达段二（触发条件校准）**：按 `p2s-skill-lifecycle-design` 卡面的「**能力／触发／效果／版本**」四元组（另两张代表卡各用触发条件与版本字段的相近形态）把每个 Playbook 的触发条件写成可判定字段，再用实际调用记录校准 ——
- 算式：`误触发率 = 该 Playbook 被调用但适用条件不成立的次数 ÷ 被调用总次数`；`漏触发率 = 适用条件成立但未被调用的次数 ÷ 应调用总次数`（应调用总次数按该 Playbook 适用范围内当期已关闭 Case 数计）。
- 取值：误触发率与漏触发率门禁各 ≤ **10%**（**业务侧默认**，来源 ＝ **经营者自述**「十次里错一次以上，一线就不信这张卡了」）；**替换条件** ＝〈能力版本与评估记录〉跑满 **2** 个自然季度后，改用实测两个率的 P75；替换前超门的只出「触发条件待改」建议，不直接改内容（改内容属〈技能版本〉责任）。
- **可达段三（生命周期阶段与淘汰候选）**：按五档登记每个资产的阶段 —— **在用／观察／待复评／待下线／已下线**；`待下线候选 ⇔ 连续 1 个自然季度调用次数 = 0 且 该季度复评未通过`。
- 取值：无调用窗口 ＝ **1 个自然季度**（**业务侧默认**＝季度档不由材料给出；换法同本行末的调用到停用间隔分布）；复评节奏 ＝ 每 **1 个自然季度** 一次、每次覆盖全部在用资产（与 §5 ④ 同一节奏）；分 **5** 档的边界为**业务侧默认**；**替换条件** ＝ 两轮季度复评完成后，改用实测「调用 → 停用」间隔分布定窗口，替换前「待下线」只出候选清单，不下线。
- **本段的能力边界**：只做三件事 —— 版本效果差与分档、触发条件校准的两个率、生命周期阶段与淘汰候选；**不产出流程合理性结论、不改写 Playbook 内容、不签发版本号**（见 §2 第 1、4 条）。

## 2 不可达部分

- 流程合理性（步骤顺序是否合真实业务、是否与合规与平台规则相容、这份 Playbook 该不该继续存在）属于**人的专业判断**：本项目综述 §F.3 写明「流程合理性须业务确认」（**二手来源，不是材料原文**），回放只能证明「有效果差」，不能证明「流程对」。
  → 替代路径：由该 Playbook 所在流程的主岗位与责任岗位在 STG-06 接收门禁前出具书面确认 —— FLOW-02 由 `AGT-008` 产品组合与新品孵化会同 `AGT-013` 产品验证与研发项目，FLOW-06 由 `AGT-047` 系统集成与业务工具，FLOW-08 由 `AGT-001` 经营目标与资源统筹会同 `AGT-004` 组织能力与人事行政；补不上时只出「效果已评估、流程未确认」双栏结论；后果是该 Playbook 不得进入 STG-07 的发布类动作，版本保持在用版本。
- 平台与法规规则原文及其生效版本属于**外部事实**：规则一变，上一版 Playbook 里的判定条件可能当场失效，而本司只读得到公告与执行后果。
  → 替代路径：平台与法规规则原文及其生效版本：规则一改，上一版 Playbook 里的判定条件可能当场失效，而本司只读得到公告与执行后果。规则监测结论与公告原文版本号由 AGT-027 在 STG-04 结束前交，涉合规与宣称的适用条款结论由 AGT-044 给。版本号缺席时，「仍有效」这三个字写不出来，相关条目只能标「待核」并冻住对外分支；也不许拿它当依据开新版本。
- 真实执行回执与运行证据（工具是否真的被调用、动作是否真的落地、失败边界是什么）属于**实物或回执**：记录里存在一次调用不等于那次动作成功。
  → 替代路径：真实执行回执与运行证据：工具到底有没有被调用、动作有没有落地、失败边界在哪 —— 记录里有一次调用，不等于那次动作成了。工具执行回执与接口契约由 AGT-047 出，运行状态、接管与恢复证据由 AGT-049 出。这两样没到齐时，回放集里那些「成功」的阶段只能先当作未经外部确认的中间态，三个 STG-08 的关闭段因此挂不上日期，只能写成观察中的状态并留着窗口。
- 能力版本的发布与回退属于**法定或治理签署**：版本号、生效时点与回退决定要有人签字，材料 PB-008 原文要求「**能力新版本失败时回退版本并保留业务效果记录**」。
  → 替代路径：由 `AGT-048` 作为本岗位结果负责人签署〈能力版本与评估记录〉，FLOW-08 场景另需 `AGT-005` 内控审计与独立复核出具复核结论、由 `AGT-001` 裁定资源与停止事项；补不上时保持当前版本并写「版本未签发」；后果是不得发布新版本，评估结论也不得写进对外表述或绩效核算。
- 跨场景复用效果属于**外部事实**：同一个 Playbook 在别的场景、别的渠道表现如何，取决于那些场景的 Case 记录，而本业务只按本 Case 的范围归集数据。
  → 替代路径：由 `AGT-002` 场景自主编排与异常协调在 STG-03 装配本流程的 Context Manifest 时给出跨场景对象清单，`AGT-046` 数据工程与质量供数与质量状态；补不上时只在本场景出效果结论并标「复用面未测」；后果是不得把本场景结论外推成「通用能力升级」，`FLOW-08` 的资源与能力变更建议里相关表述只能写成待验证假设。
- 评估独立性属于**治理事实**：评估方与被评估资产的作者若是同一个执行主体，回放会被写成自证（`p2s-co-evolutionary-skill-verification` 卡面明写生成方与验证方须在隔离沙箱中执行、不得共享上下文；`p2s-auto-skill-synthesis` 卡面要求自动生成的技能上线前须经人工审核；`p2s-skill-lifecycle-design` 卡面要求元数据须与实际能力一致）。
  → 替代路径：由 `AGT-002` 在 STG-03 给出该 Case 的装配角色清单以证明评估方未参与该 Playbook 的编写或本 Case 的执行；补不上时由 `AGT-005` 指派独立复核人或改用上一季度已复核的评估记录；后果是独立性无法证明的资产，其评估结论判 HOLD，不进版本建议。

## 4 该格何时必须冻结

- 回放集样本 < **30** 个已关闭 Case，或回放窗口未满 **1** 个自然季度 ⇒ 不得出「升级候选／回退候选」结论，只能出「样本不足 · 仅方向」，且不得据其提交变更建议。
- 流程合理性未取得业务确认（§3 第一行）⇒ 不得进入 STG-07 的发布类动作，版本保持当前在用版本。
- Δ ≤ **−5pp**，或三项指标中任一项恶化 ≥ **5pp** 且无另一项改善 ≥ **5pp** ⇒ 必须启动回退：按材料 PB-008 原文「**能力新版本失败时回退版本并保留业务效果记录**」，不得以「观察一段时间」替代回退。
- 触发条件未随版本更新（新版本已发布而四元组里的「触发」字段仍是上一版的）⇒ 冻结该 Playbook 的发布与调用推广，先补触发条件再评估。
- 涉规则或涉宣称的 Playbook 未取得 `AGT-027` 的规则原文版本或 `AGT-044` 的合规判定 ⇒ 冻结对外分支，只留内部观察。
- 评估独立性无法证明（无 `AGT-002` 的装配角色清单，且 `AGT-005` 未指派独立复核人）⇒ 该资产的评估结论判 HOLD，不进版本建议。
- 元数据与实际能力不一致（评估记录里的能力、触发、效果、版本与实际调用日志互相对不上）⇒ 冻结该资产的版本动作；`p2s-skill-lifecycle-design` 卡面边界原文：**元数据须反映真实能力与效果，不得虚报以通过评估**。
- 同一个 Playbook 的两个版本在同一时间窗里都被调用 ⇒ 冻结版本切换，先归并到一个版本；已成功动作不得随整单重跑（材料 PB-001 原文）。
- 缺 `AGT-050` 的访问控制结论而需取用未授权的调用日志 ⇒ 该 Case 的 Assurance Decision 判 HOLD，转人工复核。
- 方案里出现 §1 卡面数字清单中任一条（pp 增量、周期、样本量、阶段枚举与推进阈值、实现行数）作为本业务的评估门槛、回放样本或淘汰判据 ⇒ 该方案不得放行。
- 自 STG-04 评估开始写起，至该 Case Charter 已写明的观察窗截止仍缺 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | `自有埋点`（Case/Event Ledger：Case Charter、Stage Acceptance Record、Execution Attempt）＋ 资产侧取自〈Skill 卡片库〉与〈契约库〉（**本业务的知识资产台账**，与卡片、契约文件同址保存）的版本与四元组字段 | 非缺口。换底期间同一份资产会有两个键（已装线 1338 张的 slug 与精选线 146 张的 id，其中 93 张两张皮指同一物），而回放集是把 Case 记录挂到版本上去的：键不唯一时一次归并会把同一部 Playbook 拆成两条序列各自跑分，Δ 成了它跟自己比、恒等于零；四元组里的「触发」也会取到两份互不相同的副本，误触发率与漏触发率的分母跟着翻倍。先只认 slug 这一路顶替，两键同指的资产合成一条并标「命名空间未归一」；S5 换底把 id → slug 归一后改用单一键。替换前这批资产的 Δ 只进内部记录，不提交变更建议 |
| ② 粒度 | **本业务暂无「Playbook 最小评估单元」的定名口径**：卡片是整卡粒度、SOP 是步骤序列，材料只定名了产物「**能力版本与评估记录**」，未定名单元粒度 | 先按**整卡／整 Playbook 粒度**顶替并逐条标「粒度不足」，步骤级归因留空；`AGT-048` 会同 `AGT-047` 按〈接口契约〉对齐工具清单、把单元定名到步骤级之后替换；替换前**不得**据本轮评估做出「删掉某一步」的结论，只能出整卡级升级／保持／回退 |
| ③ 回溯深度 | 近 **2** 个完整年度（业务处境给出的出海历史长度，决策 Q11）用于估历史通过率与返工率基线；版本侧取该 Playbook 的**当前版本 ＋ 上一版本** | 非缺口。历史不满 2 个完整年度时真正塌掉的是回放集里落在上一版本那一侧的 Case 数：Δ 要求同一批已关闭 Case 在两个版本上都留下 Stage Acceptance Record，而上线首日至今的 Case 大半堆在当前版本，上一版本一侧只剩个位数 —— 返工率与自治异常数的分母薄到「任一项恶化 ≥ 5pp」这条判据随时会被一两个 Case 触发，三档跟着乱跳。先按上线首日至今的全部已关闭 Case 建集、把落在上一版本一侧的逐条标「前半段缺席」，只报方向不报档；按 Playbook 版本归集稳定后改用完整两版回放集。替换前不进变更建议 |
| ④ 新鲜度 | 每 **1** 个自然季度对在用 Playbook 复评一次（**业务侧默认**（即季度档不由材料给出）：换法同 §1 可达段三的调用到停用间隔分布）；进入 STG-06 接收门禁前须为「截至前一日 24:00」的调用与执行记录快照，并随带 `AGT-046` 的质量状态与来源 | 非缺口。若调用日志只能按自然月批量导出：先用上一自然月的完整快照顶替并标「非当日」，本轮评估只出「保持」与「回退候选」，不出「升级候选」；按日可读后替换 |
| ⑤ 口径归属 | `AGT-045` 指标契约与主数据（通过率、返工率、自治异常数的分子分母与时间归属）；每条记录随带 `AGT-046` 的质量状态、来源与新鲜度 | 非缺口。未签发前缺的是「返工」这个词的边界：通过率的分子是未被返工的阶段数，而同一份 Stage Acceptance Record 里「被返工」既可以读成有一条返工记录、也可以读成返工之后仍未通过，被跳过的阶段算不算进阶段总数也没定；读法一飘，Δ 就成了两个不同分母相减，升档降档跟着翻。先按〈Case Charter〉已写明的阶段清单与返工字段名逐条登记「本条按哪种读法」，随记录标「口径未签发」；指标契约签发后按版本号整条替换。替换前这三个率只进排序表，不进版本决定，也不写进对外表述 |

说明：② 是本责任唯一真正的缺口，它缺的不是数据、而是**单元的定义** —— 缺了它，本责任算不出「是哪一步把返工带上来的」，所以替换前的结论只能停在整卡级；这个缺口与本 FLOW 其它责任的缺口不同维（不是采集路径、也不是回溯深度），它随〈接口契约〉的落地而闭合。
