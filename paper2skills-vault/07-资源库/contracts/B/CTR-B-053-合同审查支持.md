# 合同审查支持 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：
> 可达段给算式与取值，不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：条款抽取与风险条款识别可 NLP 化，
> **但法律结论须律师判断** —— 这句话就是本契约可达段与不可达段的分界线：
> **条款可以抽、可以分级、可以排优先级；「有没有效、能不能签、算不算违约」不许算。**
>
> 本责任由 `AGT-043` 法务与知识产权承担，出现在四条 FLOW 上：FLOW-02（新品需求到商业验证——
> 研发与代工协议）、FLOW-04（市场进入与合规上架——平台协议与本地化条款）、
> FLOW-07（重大质量与账号事件——对外承诺、召回与和解条款）、FLOW-08（经营资源与组织能力复盘——
> 条款兑现与争议结果）。§1 的算式落在四条 FLOW 的方法格
> （FLOW-02 / FLOW-04 / FLOW-07 / FLOW-08 的 STG-04 证据收集与诊断、STG-05 方案与标准产物、STG-08 结果核验关闭与异步学习）；
> §4 的判据落在四条 FLOW 的规则格（STG-01 信号接收、STG-02 范围确定与 Case 创建、STG-03 上下文装配、
> STG-06 Assurance 接收门禁、STG-07 受控动作）—— **这些格只放判据与门禁条件**。
>
> **取值来源纪律（全文适用）**：本契约出现的每个条数、比例与档位，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度** ＝ 决策 Q11）；
> （b）**业务侧默认值**（经营者自述 / 行业惯例 / 材料已定名的产物，逐条附替换条件）；
> （c）§1 算式由命名的数据系统直出。**卡里的数字一律不是取值来源** —— 逐条清单见 §1 末条。

- **代表卡**：`p2s-llm-contract-compliance-review`（vault 卡号 `Skill-LLM-Contract-Compliance-Review`，技术族 21-合规决策，已装 slug —— `cards` 里的这一条是 S12 消费口的 join 键）。

- **可达段一（条款抽取与定位）**
  - 算式：`条款定位率 = 定位到「条款号 ＋ 原文片段」的风险条款命中数 ÷ 风险条款命中总数`；命中按 **7 个条款族**逐族比对：付款、质量责任、知识产权归属、争议解决与管辖、独家与排他、保密、不可抗力（族清单取方法卡的风险规则库，**属方法、不属取值**）。
  - 产出：〈新品验证证据包〉的合同侧条款栏、〈市场进入包〉准入证据矩阵里由合同承担的证据项、〈重大事件处置包〉的对外承诺条款栏、〈经营与能力变更建议〉的条款兑现口径 —— 这四处由本规则定值。
  - 取值：**条款定位率 = 100%**（二值门禁：未定位到条款号与原文片段的命中不进交付物）；**单份合同应覆盖的条款族 = 7 族**；**一条记录 = 一条条款**（不按合同整体出一条记录）。
  - 替换条件：〈合同与条款库〉（**尚未签发**）接入后改用「与库内标准条款模板逐条比对」的定位率与缺项清单；替换前命中一律标「词典命中、未比模板」。
- **可达段二（风险分级与送律师门槛）**
  - 算式：`整体风险档 = 高（任一「法定签署类」条款族命中，或 HIGH 命中条数 ≥ 1）｜中（仅 MEDIUM 命中）｜低（无命中）`；`送律师 = 整体风险档为高`。「法定签署类」＝对外承诺、争议管辖与仲裁、赔偿上限、独家与排他、知识产权归属五族。
  - 产出：审查结论的「是否送律师」字段与〈市场进入包〉里合同侧的可签性提示由本规则定值。
  - 取值：**送律师门槛 = 任一法定签署类条款族命中，或 HIGH 命中 ≥ 1 条**（**业务侧默认值**，来源＝经营者自述「凡是动到赔偿上限、独家与管辖的，一律先送律师」）；**条款级分级 = 高 / 中 / 低三档**；**送律师结论 = 是 / 否两值**（不设「可选送审」这一档）。
  - 替换条件：积累 ≥ 2 个完整年度（决策 Q11）的合同审查与事后争议记录后，用「实际发生争议的合同在审查当时的命中分布」重标分级与门槛；替换前该门槛仍是送律师的触发条件（不因参数未定而静默放宽），但对外表述只能写「按内部口径」。
- **可达段三（抽取范围与版本锚定）**
  - 算式：`可抽取文本覆盖率 = 能解析出条款结构的页数 ÷ 合同总页数`；`版本锚点 = 合同版本号 ＋ 签署日 ＋ 语言版本数`。
  - 产出：审查结论的「未审页清单」与风险清单的适用版本由本规则定值。
  - 取值：**可抽取文本覆盖率 = 100%**（二值：出现扫描件无法解析的页，该页条款判「未审」并列出页号，**不得以「已审」计入**）；**语言版本 = 逐版本独立出结论**（中英双版本合同两版分别出风险清单，不得审一版推另一版）。
  - 替换条件：OCR 与电子签记录接入后改用实测解析覆盖率；替换前未解析页只做「未审」登记，不得据该合同出整体风险档。
- **可达段四（条款兑现核对，FLOW-08 侧）**
  - 算式：`条款兑现率 = 已按合同执行的批次或订单履约事实条数 ÷ 应兑现条款条数`。
  - 产出：〈经营与能力变更建议〉的差异栏与复盘观察窗口径由本规则定值。
  - 取值：**兑现率偏差 > 0 的条款逐条进差异清单**（二值口径：任何一条未兑现都要进差异栏，不做「影响不大就不列」的取舍）；**观察窗 = 该 Case Charter 已写明的观察窗**（不自设时限）。
  - 替换条件：〈合同与条款库〉与对账表接入后改用系统直出的兑现条数；替换前兑现结论只用于内部复盘，不得作为索赔、扣款或终止合作的依据。
- **本段的能力边界**：只做四件事 —— 条款是否抽到并可定位、风险条款分级与送律师触发、抽取范围与版本锚定、条款兑现偏差清单；**不构成法律意见、不代签、不代谈判、不判条款有效性**（见 §2 第 1–7 条）。
- **本契约对同族方法卡通用；换卡时只替换方法实现，数据要求、标定规则与冻结条件不变。**

## 2 不可达部分

- 不可达①（需**法定签署**）—— 法律结论与法律意见：条款是否有效、是否构成违约、这份合同能不能签。
  → 替代路径：由 AGT-043 法务与知识产权在 STG-06 接收门禁前出具法律意见并由有权人签署；补不上时先用「风险提示 ＋ 待签」双栏交付，风险提示栏不得写入〈FLOW-02 Assurance Decision〉/〈FLOW-04 Assurance Decision〉/〈FLOW-08 Assurance Decision〉的接受项；后果是该 Case 停在 STG-06 判 HOLD。
- 不可达②（需**外部事实 ＋ 原件**）—— 对方主体资格与签署授权：对方是否真有权签、签署人是否有授权、是否转委托。
  → 替代路径：由 AGT-015 采购与合同履约在 STG-05 定稿前取证照、授权书与签署人权限文件，跨境主体由 AGT-042 税务与跨境实体协作核对；补不上时先按对方官网与工商公示信息顶替并标「未验原件」，后果是不得进入 STG-07 的签署与付款类动作。
- 不可达③（需**外部事实**）—— 适用法域与法规原文：目标市场的强制性规定、格式条款限制、争议解决的承认与执行。
  → 替代路径：由 AGT-044 产品合规与隐私与 AGT-042 在 STG-05 定稿前提供目标市场规则原文与生效版本；补不上时先用「上一版已生效文本 ＋ 平台公告」顶替并标「未核版本」，后果是不得据未核规则出「可签」结论，也不得把它写进〈市场进入包〉的准入项。
- 不可达④（需**实物或回执**）—— 合同原件的真实性与同一性：有无篡改、印章与签字是否真实、是不是同一份。
  → 替代路径：由 AGT-015 在 STG-04 结束前提供盖章原件或可核验的电子签记录，与合同相对方核对由业务侧主谈人完成；补不上时先按 PDF 文本层抽取并标「未见原件」，后果是抽取结果只做线索，不得作为签署依据。
- 不可达⑤（需**实物或回执**）—— 履约事实与款项回执：是否按合同交付、发票与付款是否对得上。
  → 替代路径：由 AGT-015 与 AGT-040 GMV结算与会计对账在 STG-08 关闭前逐对象给回执与对账表；两样未齐时，可达段四的 `条款兑现率` 分子先只认出货单与付款流水能对上的条数并逐条标「回执侧未闭」，对账表到位后改用对账口径重算该比值。在此之前 FLOW-02 与 FLOW-04 侧不得关闭，差异栏也只能出候选，不得作为索赔或扣款的依据
- 不可达⑥（需**治理签署**）—— 谈判与让步的商务意图：哪些条款可以让、让到什么程度、要不要为签约放弃某条。
  → 替代路径：由 AGT-015 出具报价与谈判纪要与立场记录，涉对外承诺与资源让渡由 AGT-001 经营目标与资源统筹签署；纪要未出时，可达段二的风险分级与「是否送律师」字段照旧计算，但条款替换文本建议只能按现文本假设让步空间为零、逐条挂起，立场记录到位后按实际让步空间重出建议。在挂起期间不得把任何条款写成已谈定条件，也不得代相对方承诺
- 不可达⑦（需**授权 ＋ 治理签署**）—— 商业机密与数据处理边界：合同文本与对方商业信息的处理、存储与外传范围。
  → 替代路径：由 AGT-050 信息安全与权限与 AGT-044 在取用前出授权与处理范围结论；补不上时不得把合同文本送入未授权环境，只做人工阅读，后果是该 Case 的 Assurance Decision 判 HOLD。

## 4 该格何时必须冻结

- 无 AGT-043 的法律意见或签署，而拟动作涉签署、对外承诺、赔偿上限、独家与排他、争议管辖 ⇒ 不得进入 STG-07 受控动作，只能出 Action Intent。
- 命中任一「法定签署类」条款族（对外承诺、争议管辖与仲裁、赔偿上限、独家与排他、知识产权归属）而无法律意见 ⇒ 该 Case 的 Assurance Decision 判 HOLD。
- 未见合同原件或可核验的电子签记录 ⇒ 不得据抽取结果进入签署与付款类动作。
- 目标市场规则版本未核（无 §3 的规则原文与生效版本）⇒ 不得出「可签」结论，不得写入〈市场进入包〉的准入项。
- 对方主体资格或签署人授权缺失 ⇒ 不得进入签署、付款与上架类动作。
- 履约回执与对账未齐 ⇒ STG-08 不得关闭，只能写「未闭合」并留观察窗，该对象不进本周期兑现率。
- 合同文本被送入未授权环境，或未取得 AGT-050 的授权与处理范围结论 ⇒ 立即冻结该批文本的处理并升级信息安全流程。
- 审查人与相对方存在利益冲突且未完成回避 ⇒ FLOW-08 侧判 HOLD，且不得计入本周期审查覆盖（材料 PB-008 必须回放项：审查者存在利益冲突）。
- 同一对象在当周已有未回填的合同动作 ⇒ 不得重复发起；已成功的动作不得随整单重跑。
- 自〈新品验证证据包〉（FLOW-02 侧）或〈市场进入包〉（FLOW-04 侧）提交起，至该 Case Charter 已写明的观察窗截止日仍缺 §3 所列任一项外部证据 ⇒ 判 HOLD 并转人工，不得默认放行。
- 本段落在规则格（FLOW-02 / FLOW-04 / FLOW-07 / FLOW-08 的 STG-01 / STG-02 / STG-03 / STG-06 / STG-07）上的只是上列判据与门禁条件，不作方法落点。
