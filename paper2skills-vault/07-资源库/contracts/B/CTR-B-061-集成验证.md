# 集成验证 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，
> 不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**契约测试、幂等与回执核对可完全自动执行，但属工程管道，算法非责任实质。**
> 这句话就是本契约可达段与不可达段的分界线：**「这条接口按不按契约办事、重复调用会不会重复生效、回执有没有对上」可以算；
> 「对方系统里那条记录的真实状态是什么」不许算。**
>
> 本责任由 `AGT-047` 系统集成与业务工具承担，只属 FLOW-06（业务需求到数据产品与工具）。
> §1 的算式落在方法格 FLOW-06/STG-04 证据收集与诊断、FLOW-06/STG-05 方案与标准产物、FLOW-06/STG-08 结果核验、关闭与异步学习；
> §4 的判据落在规则格 FLOW-06/STG-01 信号接收、FLOW-06/STG-02 范围确定与 Case 创建、FLOW-06/STG-03 上下文装配、
> FLOW-06/STG-06 Assurance 接收门禁、FLOW-06/STG-07 受控动作 —— **这五个格只放判据与门禁条件。**
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度**＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月；渠道四选一＝决策 Q9；渠道构成 Amazon **65%** / 独立站 **15%**、其余 **20%** 未定名＝开放事实 O1）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）；
> （c）§1 算式的输出（由命名的数据系统直出）。**候选卡的论文与案例参数不构成第四种来源。**
>
> **⚠️ 本责任与同 FLOW 邻位的分界（先读这一条）**：本契约只承接「**接得对不对、重不重、回执对不对得上**」这一段。
> 字段的业务含义由 AGT-045 业务口径与主数据裁定；数据有没有按约到位由 AGT-046 数据工程与质量负责；
> 接口跑起来之后在运行面上达标与否由 AGT-049 Agent平台与可靠运行监测；跨系统写动作的授权范围由 AGT-050 信息安全与权限签发。
> 四者不得互相代答，本契约的结论只在「契约测试 + 幂等 + 回执」三项上成立。

## 1 算法可达部分

- **可达段一（契约测试与幂等的四个可核验量）**：对每个「接口 × 对象类 × 用例类」逐轮算四个量，四项都是拿调用记录就能复算的比值或计数。
- 算式：`契约通过率 = 通过用例数 ÷ 设计用例数`；`幂等一致率 = 同幂等键重复提交后状态未发生变化的次数 ÷ 重复提交次数`；`回执核对率 = 有对应回执的写类调用数 ÷ 应回执的写类调用数`；`未核对率 = 未核对调用数 ÷ 应核对调用数`。
- 取值：**契约通过率目标 = 1.000（100%）**（二元门禁：任一条用例不过即不放行，不设部分通过档）；**幂等一致率目标 = 1.000（100%）**；**回执核对率目标 = 1.000（100%）**（写类调用逐条必须有回执；读类调用不要求回执，**不计入分母**）；**未核对率目标 = 0**。用例覆盖取：每个写接口至少 **3** 类用例 —— 正常、越权、超时后重复提交（**3** 类系业务侧默认，来源＝经营者自述「最怕的就是重复下单和越权改状态」）。**替换条件**：〈接口契约〉（尚未签发，见 §5 ⑤）签发并跑满 2 个完整年度（决策 Q11）后，用例集按其错误码表与方法清单重定；替换前这四个量只用于排序与告警，不得作为 FLOW-06/STG-08 的关闭依据。
- **可达段二（重试与超时的可核验门限）**：`重试上限 = 3 次`（超过即转人工，不无限重试）；`退避 = 基数 2 倍`（首次失败后等 1 秒，再 2 秒、再 4 秒）；`单次调用超时 = 30 秒`。
- 取值：重试上限 **3** 次、退避基数 **2** 倍、单次调用超时 **30 秒**，三项均为业务侧默认（来源＝经营者自述「采购与改状态的调用超过半分钟就没人等了，重试三次还不过就叫人工」）。**替换条件**：〈接口契约〉签发后按该契约声明的超时与调用配额整档替换；替换前这三项只用于联调期判定，不得写进对外承诺。
- **可达段三（跨系统写动作的受控判据）**：`受控放行 = 调用金额 ≤ 该对象在〈能力交付Case Charter〉写明的授权阈值 ∩ 目标对象在授权清单内 ∩ 该幂等键此前未被使用过`。三项同时成立才放行，任一项不成立即出 Action Intent ＋ 人工单。
- 取值：金额阈值**不在此处另设数** —— 逐对象取该 Case 的〈能力交付Case Charter〉已写明的授权阈值；**未写明时取 0**（即一律不放行、只出 Action Intent）。**0** 是「未写明即不放行」的判定值，不是折扣也不是容差档。**替换条件**：AGT-050 信息安全与权限签发分对象的授权额度后，按该额度替换；替换前凡未写明额度的对象一律走人工审批。
- **可达段四（集成验收的产物定值）**：由本规则定值的字段 —— FLOW-06/STG-04 的〈能力缺口诊断〉里的「接口与复用面」段与复用结论；FLOW-06/STG-05 的〈数据/工具交付包〉里的接口契约条目、错误码表与调用次序；FLOW-06/STG-08 的〈能力交付关闭记录〉的「集成结果」验收结论与异步学习候选。
- 取值：每条集成验收记录必须带四项可核验数 —— 契约通过率（**%** 与用例条数）、幂等一致率（**%** 与重复提交次数）、回执核对率（**%** 与应核对调用条数）、未核对调用条数（**条**）；缺任一项，该记录不得判「集成已验证」。
- **本段的能力边界**：只做四件事 —— 跑契约测试并给四个量、给重试与超时门限、判跨系统写动作是否受控放行、把缺口写成工单；**不产出**字段的业务含义与口径定义、**不产出**对方系统里记录的真实状态、**不产出**任何授权额度（见 §2）。

## 2 不可达部分

- 不可达①（需**外部事实**）—— 外部系统字段的真实业务语义与取值域：契约测试只能证明「按我们写的 schema 能解析」，不能证明「对方那个 `stk_qty_avail` 到底是不是可售库存」。
  → 替代路径：外部系统字段的真实业务语义与取值域：字段说明由 AGT-045 在 STG-03 装配 FLOW-06 Context Manifest 时随指标契约与主数据条目一并签发，渠道侧由 AGT-021、AGT-023、AGT-024、AGT-025 分别补充。拿不到时，幂等一致率的「状态未发生变化」一句就没有可比对的语义 —— 对方的 `stk_qty_avail` 究竟是可售还是账面，判不出来，同幂等键两次提交后的状态差可能只是字段含义不同。故先只按调用日志反推该字段的取值集合，标「语义未签发」，该接口只许只读验证，不进 STG-07 受控动作。
- 不可达②（需**外部事实**）—— 外部接口文档原文、错误码表与生效版本：本司拿到的是对接人给的样例与公告，不是对方可追责的契约文本。
  → 替代路径：接口文档原文、错误码表与生效版本：本司手里只有对接人给的样例与公告，不是对方可追责的契约文本。由 AGT-027、AGT-024 在 STG-04 结束前把原文与生效版本号交上来，涉数据与授权范围的另由 AGT-044 出结论。拿不到错误码表时，「3 类用例」里的越权与超时重复提交两条就没有可对照的拒绝码，契约通过率会把对方明确拒绝也算成未通过；故先按公告截图把这批用例标「未核验」，只留正常路径一类跑分，涉写回的一律停在 Action Intent。
- 不可达③（需**法定或治理签署**）—— 跨系统写权限、凭证与分对象授权额度：集成测试能跑通调用，但「允许以什么身份改哪个对象的什么字段」必须由治理方签发。
  → 替代路径：跨系统写权限、凭证与分对象授权额度：集成测试能把调用跑通，但「以什么身份改哪个对象的什么字段」只能由治理方签字。该签字与账号责任人清单由 AGT-050 在 STG-06 前出具，凭证不落 Agent 侧。拿不到时，`受控放行` 三项里的「调用金额 ≤ 授权阈值」退化成未写明即取 0，凡未写明额度的对象一律走人工审批；联调也只能读不能写，该 Case 的 FLOW-06 Assurance Decision 判 HOLD，不得推进到 STG-07。
- 不可达④（需**实物或回执**）—— 采购单确认、入库预约回执与签收回单：调用返回成功码只证明报文被受理，不证明对方系统里真的建了单、真的留了仓位。
  → 替代路径：采购单确认、入库预约回执与签收回单：调用返回成功码只说明报文被受理，不说明对方系统里真建了单、真留了仓位。这些凭据由 AGT-015、AGT-020、AGT-019 在 STG-08 关闭前逐对象交出，金额侧由 AGT-040 出对账表。回执缺口时，回执核对率的分母里那几条写类调用没有可核对的对方状态，只能拿返回码与物流轨迹号先当过程证据垫着；该对象的关闭记录因此写不成「已闭环」，观察窗继续挂着。
- 不可达⑤（需**人的专业判断**）—— 「这条集成值不值得做、要不要自建还是复用既有交付」的取舍：四个量能告诉人现状，不能替人决定投入。
  → 替代路径：「这条集成值不值得做、自建还是复用既有交付」的取舍：四个量只描述现状，投不投产能得由人拍。书面结论由本岗 AGT-047 在 STG-04 前给出，AGT-048 核对该能力是否已有同类交付，取舍写进 STG-02 的〈能力交付 Case Charter〉。取舍未定时，复用率这一项没有共同的分母可比，只能先拿既有〈数据/工具交付包〉的条目清单当候选池垫着并标「复用面未核」，该需求不进 STG-07 的发布类动作。
- 不可达⑥（需**治理签署**）—— 集成验收的最终放行签署：契约通过率满值只说明测试过了，不说明可以上线对生产系统执行写动作。
  → 替代路径：由 FLOW-06/STG-06 的 Assurance 接收门禁按 Access、数据质量、运行恢复、安全与经营验收设计五项判 HOLD 或放行，运行面结论由 AGT-049 Agent平台与可靠运行提供；拿不到门禁结论时该 Case 停在 STG-06、只出 NoActionRecord，后果是不得以「测试全绿」替代门禁。

## 4 该格何时必须冻结

- 契约通过率 < **1.000**（任一条用例不过，含越权与重复提交两类）⇒ 该接口不得进入 FLOW-06/STG-07 受控动作，只能出 Action Intent。
- 幂等一致率 < **1.000**（存在同幂等键重复提交后状态发生变化）⇒ 立即冻结该接口全部写类动作，先修幂等键定义再重跑用例。
- 写类调用的回执核对率 < **1.000**（存在应回执而无回执的调用）⇒ 该批不得判「集成已验证」，关闭记录写「未闭合」并留观察窗。
- 未核对调用条数 > **0** 且涉及金额或库存数量 ⇒ 冻结至核对完成，不得以「对方返回成功」为由放行。
- 同一调用重试超过 §1 的 **3** 次仍失败 ⇒ 转人工，**不得**继续重试，也**不得**改用手工补录绕过幂等校验。
- 〈接口契约〉未签发（§5 ⑤）而拟动作是跨系统写回 ⇒ 冻结至契约签发；替换前只允许只读验证。
- 分对象授权额度未写明（§1 取 **0**），或凭证落在 Agent 侧 ⇒ 该对象一律不放行，走人工审批。
- 缺 AGT-050 的访问控制结论而该接口可触达客户级数据 ⇒ 该 Case 的 FLOW-06 Assurance Decision 判 HOLD。
- 自 FLOW-06/STG-05 的〈数据/工具交付包〉提交起，至该 Case Charter 已写明的观察窗截止日仍缺 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。
- 同一幂等键对应的动作已成功完成而再次提交（材料原文：已成功动作不得随整单重跑）⇒ 冻结该键的后续动作，先核对再重出。
- 集成异常由外部平台的政策或账号类事件引起 ⇒ 移交 FLOW-07 紧急保护通道（Emergency Guard，D-026），本格不得自行处置。
- 引用 §1 清单中任一条卡面数字（百分比、时长、金额、条数、超参）作为本业务取值 ⇒ 该方案不得放行。
- 上列各条落在规则格（FLOW-06/STG-01、FLOW-06/STG-02、FLOW-06/STG-03、FLOW-06/STG-06、FLOW-06/STG-07）上时只是放行判据与门禁条件，**不产出取值**，也不承接任何算式。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | 自有埋点（Case/Event Ledger 的 Execution Attempt 与 Action Intent）＋第三方 API（外部系统调用的返回与错误码）＋平台后台（后台操作日志与报表）＋需授权（ERP、WMS 与财务系统的对接凭证） | 非缺口。开放事实 O1 里那几个未定名渠道若既无接口也无后台日志，缺的不只是调用记录：它连「接口名 × 对象类 × 用例类」这个聚合键都凑不齐，幂等一致率更无从谈起 —— 人工台账里没有幂等键字段，重复提交与状态未变配不成对。先按该渠道人工台账逐单登记「提交时刻、操作人、对象、是否重复」四项顶替并标「非系统」；该渠道定名、接口或后台日志接入后改用调用级记录。替换前该渠道只出说明，不进契约通过率的分母，也不并列进集成结果栏 |
| ② 粒度 | 单次调用一条记录（一次工具调用或一次接口调用，字段含接口名、对象、成功与否、延迟、时间戳、幂等键）；聚合成「接口 × 对象类 × 用例类」 | 非缺口。若某外部系统只给批次级回执而无逐次调用记录：先按批次粒度顶替并标「无逐次记录」；逐次调用日志到位后替换，替换前该接口只出回执核对率，不出幂等一致率 |
| ③ 回溯深度 | 近 2 个完整年度（业务处境给出的出海历史长度，决策 Q11）用于算契约通过率与幂等一致率的基线；⚠️ **集成侧的用例台账本业务尚无** —— 〈接口契约〉（**尚未签发**）未建立，错误码表与用例集**未定名**，故基线**取不到** | 缺的是分母那一半：契约通过率里的「设计用例数」由错误码表与方法清单定义，〈接口契约〉未签发、错误码表还没有条目，用例集就是个随人随手扩的开口集合 —— 今天 12 条、下轮 20 条，通过率跟上一轮不可比，退化也看不出来。先冻结一张「现有 OpenAPI / MCP schema 里已出现的错误码」清单当分母顶替，逐轮只在这张冻结清单上跑，并标「分母未定名」；〈接口契约〉签发后改用其错误码表与方法清单重定分母。替换前这四个量只进联调排序表，不进关闭依据 |
| ④ 新鲜度 | 联调与验收期实时读（调用返回即写 Execution Attempt）；进入 FLOW-06/STG-06 的门禁前须为「截至前一日 24:00」的完整快照（当日 T+0 可查） | 非缺口。某外部系统若只能离线批量回传，判错的不是「有没有回执」而是回执在不在途：回执核对率一头要满值、未核对率一头要归零，按调用发起时刻回看会把当天在途的回执一律记成缺失，未核对调用条数随即被判成大于零，冻的是一个其实没问题的接口。先按回传批次切分 —— 只对「上一批已核对到本批开始」这个时点之前的写类调用判回执，逐条标「在途未计」；该系统的回传改成当日可查后改用实时口径。替换前这两个率只进联调告警，不作关闭判据 |
| ⑤ 口径归属 | 接口契约（含错误码表、超时、调用配额与幂等键定义）由本岗 AGT-047 系统集成与业务工具签发；字段口径引 AGT-045 指标契约与主数据（版本号 `<签发日>-<序号>`）；授权额度由 AGT-050 信息安全与权限签发 | 缺口：〈接口契约〉本业务**尚未**签发，幂等键定义与错误码表**未定名**，缺它算不出跨接口可比的幂等一致率。处置：先按现有 OpenAPI / MCP schema 与调用日志顶替并标「契约未签发」；签发后整档替换；替换前只允许只读验证，写类动作一律停在 Action Intent |
