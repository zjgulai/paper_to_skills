# 利益冲突检查 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，不可达段给替代路径。
> §4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3，逐字）：关联方可用图挖掘发现，但冲突披露与回避决定属治理判断。
> ⇒ 这条理由把本契约的分界钉死：**「这两家是不是同一批属性」是可达段，「这算不算冲突、谁必须回避」是不可达段**。把后者写进 §1，就是本模板要拦的完整性虚报。
>
> **本契约覆盖的格**：方法格为 FLOW-07/STG-04、FLOW-07/STG-05、FLOW-07/STG-08 与 FLOW-08/STG-04、FLOW-08/STG-05、FLOW-08/STG-08 —— §1 的四段算式落在这些格上；
> 规则格为两个 FLOW 的 STG-01／STG-02／STG-03／STG-06／STG-07，**这些格只放判据与门禁条件**（§4 的落脚处），本层不在其上选参。FLOW-08/STG-06 的检查项本身就逐字含「利益冲突」与「独立审计」，本契约是该项的供给方。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；材料 §E.2 的 Case 状态机与关闭结果六档、§E.3 的异常与恢复条件、§E.4 的 D-026 紧急保护通道；PB-008 的必须回放场景「审查者存在利益冲突」）；
> （b）业务侧默认（经营者自述、平台规则或行业惯例，逐条附替换条件）；
> （c）§1 算式的输出（由命名的数据系统直出）。
> **本责任无候选卡**，故不存在「卡面数字」这第四种可能来源 —— 见 §1 第一条。

## 1 算法可达部分

- **候选卡状态（先读这一条再用本段）**：本责任在两条卡语料里**都没有候选方法卡（候选总数 0）**，故 `cards` 为空、`status: 待卡`。**这不是失败 —— 它就是缺口账里的一条扩充工单**：需要认领的候选方法族是「关联方图挖掘（实体消解 ＋ 共同属性连边 ＋ 环与社区检测）」与「披露登记完整性核对」，两者目前都无卡可挂。因此本段的可达写法**全部由本业务算式定值**，不引用任何卡；扩充工单兑现、本责任挂上卡之后，**本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变**（§2 的数据要求、§4 的冻结条件与 §5 的五维一字不改）。
- 方法族（待认领）：**关联方发现 ＋ 回避核对 ＋ 披露完整性核对**。三段骨架：① 把同一属性落在两个对象上的情形连成边，按命中属性数排序出「疑似关联方对」；② 反查审查与复核人员同本 Case 对象的活动交集，判断是否需要回避；③ 核披露登记的要素是否齐备、回避是否留痕。三段都只产候选与缺口，产不出冲突认定与回避决定（见 §2 第 1 条）。
- **可达段一（关联方对候选，落 FLOW-07/STG-04、FLOW-07/STG-05、FLOW-07/STG-08 与 FLOW-08/STG-04、FLOW-08/STG-05、FLOW-08/STG-08 六个方法格）**：对同一观察窗内的对象两两比对共同属性，输出「疑似关联方对清单」。
- 可达段一算式：`关联命中数 = count(属性 p : 对象 A 与对象 B 在属性 p 上取值相同且两边均非空)`，属性集取材料与主数据已定名的字段共 **6** 类 —— 收货地址、收款账户、营业执照或公司注册号、联系电话、操作人（`who_agent_id` 或账号责任人）、物流账号。源：〈需授权〉采购台账与供应商产能档案、〈平台后台〉店铺与账号资料、〈自有埋点〉〈Case/Event Ledger〉的 `who_agent_id`。
- 取值：**关联命中数 ≥ 3 项**判为「疑似关联方对」，进披露核对队列（**业务侧默认**：经营者自述「六类属性里三项以上同时相同，不像巧合」）；该判据只用于**排队**，不得单独作为冲突认定依据。
  **替换条件**：〈关联方登记与供应商主数据表〉（**尚未签发**）接入并覆盖满 2 个完整年度后，改用该表实测的判别界；替换前该队列只能出候选，不得出「存在利益冲突」的结论。
- **可达段二（回避核对）**：反查审查与复核人员是否参与过本 Case 的对象、供应商或账号的动作，输出「活动交集清单」。
- 可达段二算式：`活动交集数 = count(x : x ∈ 审查或复核人员参与过的动作 ∧ x ∈ 本 Case 的对象、供应商或账号)`；人员与动作的对应关系取〈Case/Event Ledger〉的 `who_agent_id` 与 `approval_level`，权限面取 AGT-050 的访问控制与账号责任人清单。
- 取值：**活动交集数 = 0 件**才允许在本 Case 出「未发现需回避情形」记录（**业务侧默认**：经营者自述现有人工纪律「复核人不得参与被复核动作」）；**替换条件**：Ledger 的 `who_agent_id` 与审批人字段覆盖满一个完整审计周期后改用**实测交集数**；替换前交集栏只能写「**未检出**」，**不得**写「已回避」。
- **可达段三（披露登记完整性）**：对每一个进队列的疑似关联方对，核披露登记的要素是否齐备。
- 可达段三算式：`披露完整率 = 已登记字段数 ÷ 应登记字段数`；应登记字段 ＝ 本契约定名的 **8** 项要素 —— 对象、关系类型、关系起始时点、金额影响、披露时点、回避方式、复核人替代、留档位置（源：〈关联方披露登记表〉**尚未签发**，签发前这 8 项逐字写进〈经营与能力诊断〉与〈重大事件处置包〉的备注栏，签发后以该表为准；若表内要素集与本契约不同，以表为准并同步重标本契约）。
- 取值：**披露完整率 = 1.000（8 项字段全非空）**（**业务侧默认**：二值门禁，不设部分通过档）；**替换条件**：该表接入并覆盖满一个完整审计周期后，改用**实测缺项数**重算；替换前该结论只能表述为「**未检出缺项**」，**不得**表述为「无利益冲突」。缺任一项即触发 §4 冻结第 2 条。
- **可达段四（队列与本期覆盖率）**：按（关联命中数 desc，`|estimated_impact|` desc，`observed_at` asc）排序派单。
- 取值：**队列长度 = 当期命中「关联命中数 ≥ 3」的对象对全量**（不截断、不设上限）；**本期检查覆盖率 = 已出具披露核对记录的 Case 数 ÷ 当期应检查 Case 数**，目标 **1.000（100%）**（**业务侧默认**：FLOW-08/STG-06 的检查项含利益冲突与独立审计，故当期 Case 全覆盖）。
  **替换条件**：AGT-005〈抽样审计〉责任给出本周期抽样方案后，按该方案比例截取队列首段派单、其余留档不派单，覆盖率改用**抽样覆盖率**口径并在记录里同时报出未派单对数；替换前不得把未派单写成「无关联」。
- **本段的能力边界**：只做四件事 —— 属性是否同一、活动是否交集、披露要素是否齐、按什么次序送人工；**不产出冲突认定、不产出回避决定、也不代替被审查人做申报**（见 §2 第 1、3 条）。
- **卡面数字清单**：本责任**无候选卡**，故本段**不存在卡面数字清单** —— 这不是遗漏，是 `cards: []`／`status: 待卡` 的事实。扩充工单兑现后，清单按新卡的卡面逐条补齐，且同样**一条都不得移植**；在那之前，§1 出现的全部数字（6 类属性、3 项判别界、8 项要素、队列与覆盖率）都是**本业务侧取值**，没有一个是论文参数。

## 2 不可达部分

- 不可达①（需**治理判断与签署**）—— 冲突认定与回避决定：机检只能给出「这三项属性同时相同」「这两人都碰过这个对象」，判「这构成利益冲突、谁必须回避、回避到什么程度、要不要换人或终止本 Case 的复核」属**治理判断**，必须由治理方签署，不可由本层产出。
  → 替代路径：由 AGT-001 经营目标与资源统筹在 FLOW-07/STG-06 与 FLOW-08/STG-06 接收门禁前指定回避安排并签署回避决定，由 AGT-005 内控审计与独立复核岗的持证复核人签署〈复核结论与整改清单〉；补不上时改用「疑似关联方对 ＋ 待裁决」两栏交付，候选那一栏不列入两份 Assurance Decision 的接受项；后果是本门禁不放行，本期 `检查覆盖率` 的分母里它只记「待裁决」。
- 不可达②（需**外部事实**）—— 关联关系的法定事实：工商登记的实际控制人与股权结构、亲属关系、代持与一致行动、历史更名与注销。本司系统内不存在这些字段的可复算副本，连「同一营业执照号」也只是登记信息的一部分，证明不了控制关系。
  → 替代路径：由 AGT-014 OEM供应商开发与协同在 STG-04 结束前出供应商股权与产能档案、AGT-043 法务与知识产权在涉关联交易的 STG-05 前出登记信息核查意见、AGT-015 采购与合同履约提供合同签署主体与收款账户一致性核对；补不上时退到店铺资料与采购台账开票主体这两份旁证，逐条钉「未取得登记核查」，关联关系一律只作待核线索；后果是据此发起的资源动作不进受控动作，相关对象只留待核标记。
- 不可达③（需**当事人的事实申报**）—— 披露的事实基础：某人是否实际存在利益关系，只有本人申报或调查取证才能确立；共同属性反查只能发现「可能有关」，**发现不了没有共同属性的关联**，也**证不出当事人未申报的那部分**。这是本责任最容易被算法结果掩盖的一段。
  → 替代路径：由 AGT-004 组织能力与人事行政在 FLOW-08/STG-03 上下文装配前组织本 Case 参与人员的年度与专项披露申报，由 AGT-002 在 STG-03 装配角色清单时把申报结果随 Case 落库；补不上时先用「未取得披露」标记该 Case 的全部参与人并要求逐人补签，补签完成前该 Case 的复核结论不得签署；后果是缺披露的参与人不得担任本 Case 的审查或复核角色。
- 不可达④（需**法定判读**）—— 回避义务的边界与对外披露义务：是否构成关联交易、是否须向平台或监管披露、回避是否会与平台规则或合同义务冲突，属**法律与合规判读**，不是数据问题。
  → 替代路径：由 AGT-043 法务与知识产权在涉对外披露或关联交易的 STG-05 前出法律意见，由 AGT-044 产品合规与隐私在 STG-05 方案定稿前出合规判定（是否落入平台规则与准入要求）；补不上时退到只做内部提示：不得做任何对外披露类表述，也不得发起关联交易类动作，这类动作只留在意向层；后果是该 Case 的接收门禁判 HOLD。

## 4 该格何时必须冻结

- STG-06 前未取得 AGT-001 签署的回避安排与回避决定，或未取得 AGT-005 持证复核人签署的〈复核结论与整改清单〉⇒ 该格不得推进到 STG-07 受控动作（含 Change Proposal 与 Approval 级动作），只能出 NoActionRecord。
- 进队列的疑似关联方对（关联命中数 ≥ 3）其披露完整率 < 1.000（8 项要素任一为空）⇒ 冻结该 Case 的复核结论与涉该对象对的资源动作，先补齐披露再过门禁。
- 活动交集数 > 0 件（审查或复核人员参与过本 Case 的对象、供应商或账号的动作）⇒ 立即冻结该 Case 的复核结论并经接收门禁判 HOLD，由 AGT-001 在 STG-06 前指定替代复核人重做；本层不得自行换人。
- 参与人员存在「未取得披露」标记 ⇒ 该人员不得担任本 Case 的审查或复核角色，其已出具的复核结论作废重出。
- 关联关系仍标「未核验」（缺供应商股权档案、工商登记核查意见或合同主体核对）而方案已按「无关联」推进 ⇒ 该方案不得进入 STG-07，相关动作降级 NoActionRecord ＋ 人工工单。
- 动作涉及关联交易、对外披露或对外承诺，而 AGT-043 法律意见或 AGT-044 合规判定缺失 ⇒ 不得进入 STG-07，只能出 Action Intent。
- 关联交易的金额影响只取 Ledger 预估字段、未经 AGT-040 对账表核对 ⇒ 不得据其定金额档；资金类动作（退款、召回、销毁）一律 HOLD。
- 以共同属性反查得到的候选直接写成「存在利益冲突」或「已回避」⇒ 该结论作废重出，按 §1 的口径只能写「疑似」与「未检出」。
- 同一对象对已有一次未回执的披露核对或回避动作 ⇒ 不得对该对发起新动作；**已成功动作不得随整单重跑**。
- 材料 §E.3 与 PB-008 列明的必须回放场景「审查者存在利益冲突」未纳入本期回放 ⇒ 本期结论不得关闭，只能留观察窗并登记自治异常。
- 外部证据时限：自 STG-05 产物提交起，至该 Case Charter 已写明的观察窗截止日仍未取得 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。
