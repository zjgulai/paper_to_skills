# 异常冻结与恢复 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，
> 不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：异常检测可用统计/时序离群方法，
> 但**冻结范围与恢复门禁是确定性治理规则，模型不得选参**。这句话就是本契约可达段与不可达段的分界线，
> 也是 §4 必须写严、§1 只许给闸门与闭包、不许出现「按场景选择冻结力度」这类表述的理由。
>
> **本契约覆盖的格**：方法格为 FLOW-01/STG-04、FLOW-01/STG-05、FLOW-01/STG-08，
> 以及 FLOW-02…FLOW-08 各自的同名三格（§1 的算式落在这些格上）；
> 规则格为 STG-01／STG-02／STG-03／STG-06（Assurance 接收门禁）／STG-07（受控动作）落在 FLOW-01…FLOW-08 八跳上，
> **这些格只放判据与门禁条件**（§4 的落脚处）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；经营节奏「月度经营复盘」＝1 个自然月；材料 §E.2 的 Case 状态机、§E.3 的异常与恢复条件表、§E.4 的 D-026 紧急保护通道 9 条候选条件与 TTL 语义；PB-007 的 15 类回放场景）；
> （b）业务侧默认（经营者自述、平台规则或行业惯例，逐条附替换条件）；
> （c）§1 算式的输出（由命名的数据系统直出）。**候选卡的卡面示例值不构成第四种来源。**

## 1 算法可达部分

- **候选卡状态（先读这一条再用本段）**：本责任 9 张候选卡**全部是 legacy 预览版**（八段式）—— 卡页第 ④、⑤ 两段是占位串，代码只以同目录 `references/implementation.py` 形式随卡，论文出处为「未自动抽取」或「不可采信」，**论文实验参数未随卡进入本包**。故本段的可达写法由**本业务算式**定值，卡只供方法骨架；卡面可见数字逐条列在本段末尾，**任一条不得移植**。
- **可达段一（异常识别与偏离度打分）**：对〈Case/Event Ledger〉与〈平台后台〉的当期经营指标逐口径算**偏离度**，产出「经营信号记录」的量化项，并把命中项按偏离度降序形成 FLOW-01/STG-04 的待诊断队列，写入各 FLOW 的〈诊断〉标准产物（经营证据与偏差诊断／机会与可行性诊断／供需证据与约束诊断／市场进入诊断／客户问题诊断／能力缺口诊断／事件范围与根因诊断／经营与能力诊断）。
- 可达段一算式：`偏离度 z = (当期值 − 同口径滚动基线均值) ÷ 滚动基线标准差`；基线窗口取〈…Case Charter〉已写明的观察窗，**未写明时取最近 1 个自然月**（对齐材料经营节奏「月度经营复盘」＝1 个自然月）。源字段：〈Case/Event Ledger〉的 `case_id`、`entity_id`、`metric_name`、`observed_at`、`value`，以及〈平台后台〉同口径报表字段。
- 取值：**异常闸门 = 3 倍基线标准差（3σ 控制限）**，即 `z ≥ 3` 判为异常、`z < 3` 不产信号。该数是**业务侧默认**（来源＝行业惯例的 3σ 控制限）；候选卡 `p2s-transaction-anomaly-detection` 卡面另给一个 z 阈值 **3.5**，**不得移植**。**替换条件**：〈Case/Event Ledger〉累计满 2 个完整年度后，改用该口径近 2 个完整年度实测的**最小真阳性偏离度**为闸门；替换前闸门只用于排序与派单，**不得**单独作为冻结依据（冻结依据一律见 §4）。
- 取值：**单次诊断的待处理队列长度 = 命中 `z ≥ 3` 的信号条数**，按 `case_id` 去重后取值；队列不设固定上限、不截断，超长队列按偏离度降序分批派单。
- **可达段二（冻结范围的确定性闭包计算）**：按事件对象算**冻结闭包**，输出「受影响对象集合」，作为 FLOW-01/STG-05 处置方案与受控动作的范围输入。
- 可达段二算式：`冻结范围 = { x : x.case_id = 本 Case ∧ x.guard_rule_id = 命中规则 ∧ x.state ∉ 终态 }`；`扩围对象数 = count(冻结范围 ∩ 闭包外对象)`；终态取材料 §E.2 的 Case 状态机 `CLOSED` 与关闭结果六档（`SUCCESS`／`PARTIAL`／`NO_ACTION`／`STOPPED_VALID_RESULT`／`FAILED`／`CANCELLED`）。
- 取值：**冻结闭包 = 1 个**、**扩围对象数 = 0 件**；来源＝材料已定名的 D-026 约束（紧急通道允许的效果仅限定死的、最小范围、可逆的敞口收窄），**不是本层的可调参数**，任何时点都不得由本层放大或按场景自选。
- **可达段三（恢复门禁的可复核判定）**：按冻结闭包逐对象核**权威回执齐备率**与**幂等键查得的终态**，输出「恢复可否提交受控动作」的二值判定与未闭合对象清单，写入各 FLOW 的关闭记录。
- 可达段三算式：`回执齐备率 = 已取得权威回执的对象数 ÷ 冻结闭包内对象总数`；`外部状态未决数 = count(按 idempotency_key 查外部状态返回「未知」或「无终态」的对象)`。
- 取值：**恢复门禁 = 回执齐备率 1.000（100%）且外部状态未决数 0 件**，二者同时成立才可判「可提交恢复」；该门禁是**二值**的、不设部分通过档（来源＝材料 §E.2：FLOW-01/STG-08 的 `FREEZE:EXTERNAL_RESULT_UNRESOLVED` 与 §E.3「按幂等键查得权威外部状态后才可重试、补偿或关闭」）。**替换条件**：〈Execution Attempt〉与权威回执逐对象落库并覆盖满一个完整审计周期后，改用**实测**回执齐备率与**实测**未决数重算；替换前该结论只能表述为「**未检出未决对象**」，**不得**表述为「外部状态已确认」。
- **可达段四（异常回放用例集）**：按材料已定名的场景集做状态机回放，输出逐场景通过/失败清单，作为规则版本发布的准入项。
- 取值：**回放用例 = 15 类场景**（材料 PB-007 已定名：误报／零匹配／多匹配／残缺 Case／非权威信号／事务中断／Outbox 重复派发／TTL 过期／模型改参／紧急通道尝试恢复等）；**失败场景数 = 0 类**才允许该次规则版本发布，失败 ≥ 1 类一律按回滚处置。
- **本段的能力边界**：只做四件事 —— 信号是否偏离、冻结范围是哪一闭包、恢复门禁是否满足、回放是否全过；**不产出冻结范围的扩缩裁决、不产出恢复放行结论、不代替平台与承运商的权威状态**（见 §2）。

## 2 不可达部分

- 不可达①（需**法定或治理签署**）—— 冻结范围的扩缩裁决与恢复放行：哪些对象进冻结闭包、何时解除、要不要扩大范围，属治理裁决；本层只能算闭包与门禁，不能自行选参或扩围。
  → 替代路径：由 AGT-050 信息安全与权限在 FLOW-07/STG-02 原子提交前给出 D-026 Guard 规则版本与 9 条候选条件的绑定证据、由 AGT-001 经营目标与资源统筹在 FLOW-07/STG-06 前指定放行责任人签署；补不上时只记 `Pre-Case Exception` 并冻结信号范围，不创建 Guard Decision、残缺 Case 或任何动作记录；后果是该信号转正常建单流程，本 Case 不进紧急通道、不计入异常闭环时间。
- 不可达②（需**外部事实**）—— 平台侧、承运商侧与支付渠道侧的权威外部状态：账号是否真被暂停、签收是否真已发生、退款是否真已到账，本司系统只能看到本地记录与截图，看不到对方系统的权威终态。
  → 替代路径：由 AGT-027 店铺账号健康与规则（账号类）、AGT-019 跨境物流与关务与 AGT-020 仓储履约与退货处置（履约类）、AGT-040 GMV结算与会计对账（资金类）在 FLOW-01/STG-08、FLOW-07/STG-08 关闭前逐对象提供权威状态或回执；补不上时先按〈Execution Attempt〉的本地记录 + `idempotency_key` 顶替并标「外部状态未确认」，后果是该 Case 停在 `FROZEN`、只能出「未闭合」记录，**不得**按「恢复已验证」关闭，也不得重试或补偿。
- 不可达③（需**实物或回执**）—— 质量检测报告、批次质检记录、退货入库与销毁现场回执：这些事实无法由留痕表或平台报表推出。
  → 替代路径：由 AGT-013 产品验证与研发项目出检测报告、AGT-018 生产协同与质量控制出批次质检记录、AGT-020 在 FLOW-07/STG-08 关闭前逐对象提供入库与销毁回执；补不上时先用「出库/退款流水号 + 承运商轨迹」顶替为过程证据并标「回执未齐」，后果是相关批次只能扩大冻结范围至同批次全量、不得收窄，关闭结论标「未闭合」。
- 不可达④（需**外部事实 + 治理签署**）—— 平台规则原文、生效版本与 TTL 语义的最终确认：TTL 只决定「首次派发资格」，永不构成自动恢复，这一条只能由平台规则与 Guard 版本共同证明，本层不能从内网数据推出。
  → 替代路径：由 AGT-027 在 FLOW-07/STG-04 结束前提交平台政策原文与生效版本号、由 AGT-044 产品合规与隐私在 FLOW-07/STG-05 方案定稿前出具适用性判读；补不上时先按「平台后台公告截图 + 上一次已生效版本号」顶替并逐条标注「未核验」，后果是以未核验规则为依据的动作一律不进受控动作阶段、账号类动作降级 NoActionRecord + 人工工单，且 TTL 到期后禁止首次执行、不得自动恢复。
- 不可达⑤（需**人的专业判断**）—— 根因定性与责任归属：偏离度能指出「哪一项指标异常」，不能判定「这是控制设计缺陷还是执行偏差、该由哪个岗位担责」。
  → 替代路径：由 AGT-005 内控审计与独立复核在 FLOW-08/STG-06 前签署〈复核结论与整改清单〉、由对应事件类型的结果负责人（质量 AGT-018、账号 AGT-027）在 FLOW-07/STG-05 前出根因判定；补不上时先按「预筛候选 ＋ 待签」双栏交付，候选栏不得写入 Assurance Decision 的接受项，后果是该 Case 只能停在接收门禁、不计入本周期异常闭环率。

## 4 该格何时必须冻结

- STG-06 前未取得 AGT-050 签署的 Guard 规则版本与绑定证据，而拟动作来自紧急通道 ⇒ 该格不得推进到 STG-07 受控动作（含 Approval 级动作），只能出 NoActionRecord。
- 命中 `EXECUTION_ATTEMPT_STATE_UNKNOWN`（执行结果或外部状态未知）⇒ 立即置 `FROZEN`；唯一恢复条件是按 `idempotency_key` 查得权威外部状态，查得之前不得重试、不得补偿、不得关闭。
- 预留或外部尝试之后，资源占用或外部状态变得不确定 ⇒ 置 `FROZEN`，先完成预留与外部状态对账；对账前不得发起任何新动作（材料 §E.3）。
- 钉住的 Role Release Bundle 进入 `QUARANTINED` ⇒ 置 `FROZEN`，不得发起新动作，只能走受控 Bundle 迁移或新建 Case。
- 已确认的 Case 存在紧急执行或回执状态未知 ⇒ 置 `FROZEN`，先取权威外部状态、再过恢复门禁，才可恢复或重放。
- Guard 规则多匹配，或主场景／业务范围／模板／Policy 在建单前不唯一，或本地事务提交未被证明 ⇒ **只记 `Pre-Case Exception` 并冻结信号范围**，不创建 Guard Decision、残缺 Case 或任何动作记录；零匹配记 `NO_MATCH` 后继续正常建单。
- 冻结范围出现扩围对象（扩围对象数 > 0 件）⇒ 立即冻结该次处置并转人工裁决；紧急通道的效果只许是定死的、最小范围、可逆的敞口收窄。
- TTL 过期 ⇒ 禁止首次执行，且**不自动恢复**；不得以 TTL 到期或超时为由判恢复（材料 §E.4）。
- 恢复、重新开放、扩大范围、外部承诺、退款、召回、销毁库存与永久变更，出现在 STG-07 之外的阶段 ⇒ 一律冻结该 Case，相关动作转 NoActionRecord ＋ 人工工单。
- STG-08 命中 `EXTERNAL_RESULT_UNRESOLVED`（外部结果未决）⇒ 不得关闭，只能出「未闭合」记录并留观察窗，不得判「影响受控」。
- 外部证据时限：自 STG-05 产物提交起，至该 Case Charter 已写明的观察窗截止日仍未取得 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。
- 同一对象已有一次未回填的动作尝试 ⇒ 不得对该对象发起新动作；**已成功动作不得随整单重跑**。
- 异常回放失败场景数 ≥ 1 类（15 类场景中任一类未过）⇒ 该次规则版本不得发布；已发布的按回滚处置，并在 FLOW-08/STG-04 登记自治异常。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | 自有埋点（〈Case/Event Ledger〉：Case Charter／Stage Acceptance Record／Execution Attempt／NoActionRecord／`REC-CASE-EXCEPTION`）＋ 平台后台（账号健康页、政策通知与报表快照） | 非缺口。若某类冻结是线下口头或邮件触发的（如仓库电话通报、平台电话通知），本维取不到：先按〈Case Charter〉的人工备注与邮件留档顶替并标「非留痕」，该类事件纳管进 Ledger 后替换为事件级记录；替换前该类事件不计入异常闭环时间的分母，也不得据其判定扩围 |
| ② 粒度 | 一条 ＝ 一次 Case 状态迁移或一次 Execution Attempt（字段含 `case_id`、`entity_id`、`guard_rule_id`、`idempotency_key`、`state`、`observed_at`），按 `case_id` + 时序串成链 | 非缺口。若某源只按日汇总（如按日导出的账号健康报表）：先按「Case × 自然日」粒度顶替并标「粒度不足、不作闭包判定」，状态迁移级落库到位后替换为单次迁移粒度；替换前该源不得用于判定冻结范围，只可作偏离度基线的输入 |
| ③ 回溯深度 | 近 2 个完整年度（业务处境给出的出海历史长度，决策 Q11），用于算滚动基线均值、标准差与闸门分位 | 非缺口。若某渠道或某市场在 Ledger 上线不足 2 个完整年度（如新开的其他平台账号）：先用该渠道上线首日起的全部自然日顶替并标「样本不足」，满 2 个完整年度后替换为完整窗；替换前该渠道的基线只用于同渠道内比较，不得跨渠道合并算闸门 |
| ④ 新鲜度 | 异常信号按接收时点实时入账（FLOW-01/STG-01 当日可查）；进入 STG-06 接收门禁前须为「截至前一日 24:00」的完整快照 | 非缺口。若 Ledger 为离线批量 T+1 且当日不可查：先用受控动作阶段当日的动作尝试实时代理日志顶替做存在性判定并标「口径非权威」，Ledger 当日可查后替换；替换前只许置 `WAITING`，**不得**据此解除 `FROZEN`、也不得关闭 Case |
| ⑤ 口径归属 | AGT-045 业务口径与主数据（Case 状态机与迁移条件、Stage Acceptance 处置、异常闭环计时起止、未归属 Case 数与装配错误率的分母） | 非缺口。若指标契约尚未签发状态与计时口径：先按材料 §E.2／§E.3 已定名的状态名与迁移条件暂按口径并逐条标注「口径未签发」，AGT-045 签发后替换；替换前 `FROZEN`／`WAITING` 的计数只在本 Case 内有效，不得进入阶段返工率与异常闭环时间 |
