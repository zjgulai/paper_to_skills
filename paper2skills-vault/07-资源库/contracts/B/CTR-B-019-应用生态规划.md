# 应用生态规划 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，
> 不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**生态适配可用依赖图与兼容性矩阵分析，但伙伴策略与路线选择属战略判断。**
> 这句话就是本契约可达段与不可达段的分界线：**适配缺口与集成就绪可以数出来，伙伴与路线不许算。**
>
> 本责任由 `AGT-012` 灵枢·软件算法与应用生态承担，只在 FLOW-02（新品需求到商业验证）与 FLOW-07（重大质量与账号事件）
> 两跳上出现，交付物是「软件方案与验证证据」，衡量口径是「用户任务成功与软件质量」。
> §1 的算式落在两跳的 STG-04 证据收集与诊断、STG-05 方案与标准产物、STG-08 结果核验与关闭，共 **6** 个方法接入格；
> §2 与 §4 的判据落在两跳的 STG-01 信号接收、STG-02 范围确定与 Case 创建、STG-03 上下文装配、
> STG-06 Assurance 接收门禁、STG-07 受控动作 —— **这五格只放判据与门禁条件**。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个门槛、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度**＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月、
> 渠道构成 Amazon **65%** / 独立站 **15%**，其余 **20%** 未定名＝开放事实 O1）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）——**「季度经营策略」＝1 个自然季度属本档**；
> （材料未给自然季档）；本档换法 ＝ 〈软件版本与接口台账〉连续可读满 2 个完整年度后，换成按实测接口与版本评审节奏，取作本档；
> （c）§1 的算式由命名的数据系统直出。
> **本责任没有第四种来源可言 —— 因为它连一张卡都没有**（见 §1 第 1 条）。

## 1 算法可达部分

- **卡状态：无卡，方法待认领。** 本责任候选方法卡 **0 张**（作业包 `flow-02-batch-14.md` §CTR-B-019 记「候选总数 0」；`cards: []`、`status: 待卡` 如实记账；缺口账 `gap-ledger.json` 记该责任 `supply.status = zero`、`structural_blank = true` —— 连 legacy 预览卡都没有，与 AGT-009/010/011/013 同属结构性空白岗位，处置栏写「走 SOP，不占检索预算」）。**这不是免责声明：本条契约本身就是这条责任的扩充工单** —— 下面的可达写法由**本业务算式**定值，不依赖任何卡；方法到位后按同一份算式接管，数据要求、标定规则与冻结条件不变。
- **扩充工单（认领时该满足的方法族，逐条可核验）**：① **依赖图构建与冲突检测** —— 把平台、接口、版本区间、硬件与第三方 SDK 建成有向依赖图，检出循环依赖、版本互斥与单点依赖；② **兼容性矩阵与缺口计数** —— 平台 × 系统版本 × 协议的支持声明矩阵，输出缺口项与缺口率；③ **约束下的可行组合求解** —— 在版本、接口配额、认证与隐私约束下给出可用组合集与每一项的不可行原因；④ **生态对象分级评分** —— 接口与集成对象的成熟度/影响面评分，权重须来自台账事实（联调回执、历史中断时长），**不得**来自沟通印象；⑤ **路线选择的判据化** —— 把「走哪条路线」写成可判定的条件（缺什么证据即不可选），**算法只判条件、不判路线**。
- **认领时的准入条件**：方法卡到位后，必须在 §1 补出该卡卡面全部带数字的段落清单并逐条标注「不得移植」（与其他契约同位置的要求）；本契约现在**没有**这张清单，因为候选卡为 0，**没有任何卡面数值可以移植**。
- **可达段一（兼容缺口率）**：`兼容缺口率 = 未声明支持的目标项数 ÷ 目标项总数`；目标集合逐案取〈新品验证Case Charter〉或〈重大事件Case Charter与本地原子提交记录〉写明的目标平台与系统版本集合；源字段取〈软件版本与接口台账〉的 `平台` / `版本区间` / `支持声明`。落 FLOW-02/STG-04 与 FLOW-07/STG-04 两个方法接入格。
- 取值：放行线 ＝ 兼容缺口率 **0%**（二值判定，与材料已定名的 STG-06 Assurance 接收门禁口径一致：缺一项即 HOLD，不设部分通过档）；同时给出**覆盖窗 ＝ 每个目标平台最近 2 个大版本**（**业务侧默认**，来源＝经营者自述「App 只承诺最近两个大版本，更老的版本只保证不崩溃、不保证功能」）。**替换条件** ＝ 〈软件版本与接口台账〉接入并跑满 **1** 个完整自然季度后，改用该产品线**在装版本分布的 P90** 定覆盖窗；替换前覆盖窗只写进内部说明，不写进标准产物的对外承诺项。
- **可达段二（集成就绪率）**：`集成就绪率 = 已通过联调的目标接口数 ÷ 目标接口总数`；「联调通过」的定义取 AGT-047 系统集成与业务工具出具的回执，回执须带接口名、环境、日期与结论**四项**，缺一项不计入分子。落 FLOW-02/STG-05 与 FLOW-07/STG-05 两个方法接入格。
- 取值：放行线 ＝ 集成就绪率 **100%**；接口清单以本案 Charter 写明的集成为准，**本契约不自建第二张接口清单**。**替换条件** ＝ 联调回执按接口逐项齐备后改用「回执日期 + 环境」判就绪；替换前只认「联调中」标记，**不得**据「测试环境通过」宣布上线就绪。
- **可达段三（接口失效影响面排序）**：`接口失效影响面 = 受影响对象数 × 无替代路径系数`；系数分档 ＝ 有替代路径取 **0**、替代路径需改造取 **1**、无替代路径取 **2**（**业务侧默认**分档，来源＝经营者自述「没有备选就得先有回退方案」）；按影响面降序出清单。落 FLOW-02/STG-08 与 FLOW-07/STG-08 两个方法接入格。
- 取值：排序前 **30%** 的接口进「必须先有回退方案」清单（**业务侧默认**起点）；**替换条件** ＝ 台账跑满 **1** 个完整季度后，改用「按接口历史中断时长加权」排序；替换前该清单只作 STG-06 的检查项与 §4 的判据输入，不单独构成上线阻断。
- **本段的能力边界**：只做三件事 —— 兼容缺口的计数、集成就绪的计数、接口影响面的排序；**不选伙伴、不定路线、不签协议、不承诺排期**（见 §2）。
- 本契约对同族方法卡通用；换卡时只替换方法实现，数据要求、标定规则与冻结条件不变。

## 2 不可达部分

- 不可达①（需**外部事实**）—— 平台与合作方的接口开放范围、调用配额与商务条件（能不能接、以什么条件接、要不要付费档）：本司只有对方公开文档与已获批权限，拿不到对方的商务意图与内部排期。
  → 替代路径：由 AGT-012 向平台方索取接口文档与权限申请、由 AGT-021 Amazon业务经营 / AGT-024 其他平台与新市场经营在 STG-04 结束前提供账号侧权限与政策通知、由 AGT-043 法务与知识产权审协议条款；补不上时先用「公开文档所载能力 + 上一次已获批的权限」顶替并逐条标「未获授权」，后果是只出集成清单与影响面排序、不出排期，相关调用一律停在 Action Intent。
- 不可达②（需**实物或回执**）—— 真机与固件级验证回执（App 商店审核回执、平台接口联调回执、固件 OTA 验证回执）：兼容与就绪的最终事实由回执证明，测试环境的自测记录不能替代。
  → 替代路径：由 AGT-013 产品验证与研发项目在 STG-08 关闭前逐对象给出回执、由 AGT-047 系统集成与业务工具给出接口联调回执；补不上时把测试环境通过截图与自测记录先当过程证据，逐项挂「非权威回执」；缺了它，§1 可达段二的集成就绪率里会混进没跑过真机的项，就绪率虚高。逐对象回执收齐后整批替换；在此之前该集成项不进本周期就绪率的分母，关闭栏只写「未闭合」并留观察窗
- 不可达③（需**法定或治理签署**）—— 生态伙伴的选择、独家与排他条款、对外路线承诺：属战略判断与合同让渡，任何依赖图或兼容矩阵都算不出来。
  → 替代路径：由 AGT-012 出候选与判据、AGT-029 品牌战略与传播核对对外表述、AGT-043 法务与知识产权签协议、AGT-001 经营目标与资源统筹签资源与优先级；补不上时退到「不带独家条款的试点集成」先跑，注明「未签」；缺了它，路线与排期都只能停在草案上，本阶段给不出可对外说的集成方案。协议与资源签署齐后整批替换；在此之前对外承诺与排他类动作只记意图、另开人工工单
- 不可达④（需**外部事实**）—— 平台与系统方的路线图与弃用时间表（何时停用旧版本接口、何时强制新政策、何时改审核口径）：对方单方发布、随时更新，本司只能取回执与公告。
  → 替代路径：由 AGT-027 店铺账号健康与规则、AGT-024 其他平台与新市场经营在 STG-04 收口之前取回政策原文与其生效版本号；取不回时退到「平台后台公告快照 + 上一次已生效版本号」，逐条注明「未核验」；缺了它，§1 可达段一的覆盖窗没有权威的弃用时间表可依，兼容性结论只能当内部预警。政策原文与生效版本号取回后整批替换；在此之前此类结论写不进〈新品验证证据包〉的可执行项，也不得据此停更或强推版本
- 不可达⑤（需**外部事实 ＋ 需授权**）—— 第三方 SDK 与外部服务的真实数据用途、驻地与合规边界（是否回传用户数据、能否出境、合成内容如何标注）：属外部事实且须按授权口径取用，本司台账里没有可复算字段。
  → 替代路径：由 AGT-044 产品合规与隐私在集成前出判定、AGT-050 信息安全与权限出取用与权限结论；补不上时先用「对方公开隐私条款 + 上一版已集成 SDK 的旧判定」顶替并标「未判」，后果是该 SDK 不得集成、相关集成项只出 Action Intent，该 Case 的接收门禁判 HOLD。

## 4 该格何时必须冻结

- 兼容缺口率 > **0%** 或集成就绪率 < **100%** ⇒ 该格不得推进到 STG-07 受控动作（含对外发布与集成上线），只能形成 NoActionRecord。
- 调用超出已获批权限或配额（无平台书面许可）⇒ 立即冻结该批调用，并按 FLOW-07 的紧急保护通道（Emergency Guard，D-026）升级账号与信息安全流程。
- 涉第三方 SDK 的隐私与数据边界未由 AGT-044 与 AGT-050 判定 ⇒ 不得集成、不得上线，只能出 Action Intent。
- 出现「无替代路径」的接口（§1 可达段三系数 = **2**）而本案没有回退方案 ⇒ STG-06 的〈FLOW-02 Assurance Decision〉或〈FLOW-07 Assurance Decision〉判 HOLD。
- 生态伙伴选择、独家条款或对外路线承诺尚未签署（无 AGT-043 法律意见或无 AGT-001 资源签署）⇒ 不得进入 STG-07，只能出 Action Intent + 人工工单。
- 平台政策原文与生效版本未取回，却按「兼容性无缺口」出具结论 ⇒ 判 HOLD 并转人工。
- 台账未接入而把「上一版发布记录」的推算值写成实测缺口率，或把缺失值当作零 ⇒ 该结论不得进入任何标准产物。
- 命中 FLOW-07 的质量、严重客诉或账号重大风险口径 ⇒ 移交紧急保护通道，本格不得自行处置。
- 外部证据时限：自本案方案产物提交起，至该 Case Charter 已写明的观察窗截止日仍缺 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。
- 本段落在规则格（STG-01 / STG-02 / STG-03 / STG-06 / STG-07）上的只是上列判据与门禁条件，不引入判别式或预测式。
