# 素材版本管理 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：
> 可达段给算式与取值，不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**版本血缘与素材-效果关联可自动化，
> 但交付物是素材制品与版本治理对象，算法非责任实质** —— 这就是本契约可达段
> （血缘与唯一性机检、素材-效果回填、清单要素齐备）与不可达段（版权与肖像授权、平台判定回执、
> 宣称签署）的分界线。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度**＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月、
> 「季度经营策略」＝**1** 个自然季度；渠道构成 Amazon **65%** / 独立站 **15%**，其余 **20%** 未定名＝开放事实 O1，
> 见 common §2.1）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）；
> （c）§1 / §5 的算式由命名数据系统直出。
> **卡上的案例数字不构成第四种来源**（逐条清单见 §1 末）。

## 1 算法可达部分

- **素材版本的血缘完整性与唯一性机检**（落 FLOW-01/STG-04、FLOW-02/STG-04、FLOW-04/STG-04 三个 M 格）：
  对在册的每一个素材版本逐条重算指纹并回溯其上级版本，输出「版本唯一度」与「血缘缺口数」两个可核验的量化值。
- 算式：`版本唯一度 = 1 − 重复指纹版本数 ÷ 在册素材版本数`；`血缘缺口数 = 派生记录中 parent_version_id 为空或指向不存在版本的条数`。
  指纹 = **内容哈希（SHA-256）与感知哈希（pHash）的二元组**，两值都相同才判为重复（同图不同裁切、同视频不同码率不算重复）。
  源字段：〈素材版本台账〉的 `asset_version_id` / `parent_version_id` / `content_hash` / `phash` / `channel` / `market` / `effective_from` / `compliance_status` / `perf_pointer`。
- 取值：**版本唯一度 = 1.000（即 100%）**、**血缘缺口数 = 0 条**。
  这两个数是**业务侧默认值**、不是实测值：依据一＝材料已定名的接收门禁（FLOW-01/STG-06 的〈FLOW-01 Assurance Decision〉）只有**放行与 HOLD 两态**，不设部分通过档；依据二＝**经营者自述**「素材上线前逐版登记、同一版本不重复入库、换版走派生而不是覆盖母版」。
  **替换条件**：〈素材版本台账〉接入并覆盖满 **1 个自然季度**后，改用**实测**重复指纹版本数与**实测**断链条数；替换前该结论只能表述为「**未检出**重复版本」，**不得**表述为「不存在未登记的版本」。
- **素材-效果关联与换代排序**（落 FLOW-01/STG-05、FLOW-01/STG-08、FLOW-02/STG-05、FLOW-02/STG-08、FLOW-04/STG-05、FLOW-04/STG-08）：
  把每一个素材版本的投放结果按版本号回填，输出可复算的衰退幅度与排序。
- 算式：`版本衰退幅度 = (基准期 CTR − 统计窗 CTR) ÷ 基准期 CTR`；基准期 = 该版本**首次投放所在自然月**的 CTR；统计窗 = 该版本投放的自然日按**自然周**汇总；
  `版本效果分 = 统计窗内按〈广告后台〉回填的 ROAS`；排序键 =（衰退幅度 desc，花费 desc，版本上线日 asc）。
- 取值：**统计窗 = 1 个自然月**（来源：材料已定名的经营节奏「月度经营复盘」＝ 1 个自然月）；**换代提示线先按 10%（经营者自述「CTR 相对基准期下滑一成即报」）暂按**。
  **替换条件**：〈广告后台〉在该渠道跑满 **2 个完整年度**（决策 Q11）后，替换为该渠道逐月 CTR 的 **1 个标准差**；替换前 10% 只触发**提示与排序**，不得单独触发换代动作。
- **素材版本清单的要素齐备率**（落 FLOW-01/STG-05 与 FLOW-04/STG-05 的素材清单字段）：
  `要素齐备率 = 六项要素全非空的版本数 ÷ 在册素材版本数`；六项要素＝版本号、上级版本、渠道与市场、生效日、合规状态（宣称与版权标记）、效果回填指针。
- 取值：**目标值：要素齐备率 = 1.000（六项全非空）**；缺任一要素的版本**不进**〈联合经营行动包〉与〈市场进入包〉的素材清单可执行项（这一条同时约束 §2 第 1 条与 §3 的 AGT-044 行）。
- **本段的能力边界**：只做四件事 —— 血缘是否闭合、指纹是否重复、效果能否按版本回填、清单要素是否齐备；**不产出授权结论、不产出平台判定、不签署宣称**（见 §2）。
- **不得作为本业务取值的卡面数字**（逐条列出本次实际读到的三张代表卡的卡面与随卡实现的数值，任一条都不得进入本业务口径；换入同族卡时同样要逐条剔除该卡自身的数值）：
  1. `p2s-creative-fatigue-detection` 卡面示例：初始 ROAS **4.2**、第 **21** 天起下滑、月均素材疲劳损失 **$3,000–6,000**、检测后月均节约 **$2,000–4,500**、实施成本 **20** 小时；示例规模为 **5** 款 Meta 素材、每支生命周期 **2–4 周**、**3** 支 Amazon SB 视频；
  2. 同卡随卡实现（实测 **435 行**，卡面 ⑦ 段声明 **430 行**）行内默认值：`ctr_ratio_threshold=0.55`、`hazard_threshold=2.5`、`signature_threshold=−0.002`、`fatigue_score_threshold=0.60`、`baseline_days=3`、`min_days_for_eval=5`、权重 `w1=0.40 / w2=0.35 / w3=0.25`、`max_age=30`，示例 `base_ctr=0.035`、`fatigue_start_day=15`、`fatigue_rate=0.05`、`seed=42` —— 这些是**卡面实现默认**，本业务的换代线一律取 §1 上文的业务侧取值与替换条件；
  3. 同卡 ⑧ 段出处 arXiv:2509.09758（路径签名素材疲劳检测）**是本责任候选卡中唯一有已核验论文出处的卡**；该论文的实验条件同样不得作为本业务阈值（论文数据可得性 ≠ 本司拿得到，决策 Q12）；
  4. `p2s-visual-data-collection` 卡面：产品摄影 **¥15,000/次**（**6–8** 张主图）、周期 **2 周**、素材库构建成本 **¥2,400**、AI 生成 **20 秒**视频 **¥800/条**（传统 **¥8,000/条**）、首年节省 **¥50,400**；随卡实现（实测 **399 行**，卡面声明 **394 行**）行内默认 `threshold=0.55`、`quality_threshold=0.65`、参考素材库 **0.40**，示例 `generate_mock_assets(n=100)`；该卡 ⑧ 段所记 arXiv 编号与卡页主题不符 ⇒ 该卡**无可引用的论文实验参数**；
  5. `p2s-cross-platform-video-repurposing` 卡面：单位内容成本 **$400 → $80**、**5** 平台复用、年化产量 **5 倍**、渠道 GMV 增量 **20–35 万元**、月产 **4 条 → 20 条**；随卡实现（实测 **158 行**，卡面声明 **153 行**）的平台规格表（TikTok 9:16 / 1080×1920 / 15–60 秒 / 最优 30 秒；Reels 与 Shorts 最优 45 秒；Amazon PDP 16:9 / 1920×1080；Pinterest 2:3 / 1000×1500）与 `cost_per_adaptation=15.0`、`avg_gmv_per_platform=8000.0`、示例 `source_cost=400.0, n_platforms=5, avg_gmv_per_platform=6000`、母版 **60 秒 / 1920×1080** —— 平台规格可作**投放侧规格事实**引用，其中的成本与 GMV 数字一律不得移植；
  6. 三张卡均为 **legacy 预览版**形态：④/⑤ 段是占位串，代码以 `references/implementation.py` 随卡且为**节选**（对 60 行上限；其中 fatigue-detection 与 cross-platform 两张的节选在断点处语法不完整）—— 卡面数字与实现体量均不得作为本业务的取值、工期或实现规模依据。
- 清单完备性声明：以上六条覆盖本次实际读到的三张卡的卡面 ①–⑧ 段与随卡实现中**已核对到**的全部带数字段落；三张卡卡面均**未出现**消融设置与置信区间。本清单**不是**对未读卡片的声明 —— 换入其他同族卡时按同一纪律逐条补列。

## 2 不可达部分

- 素材的**版权与肖像授权链**（母版由谁拍摄、素材是否含第三方音乐与字体、竞品素材只可作风格参考而不得直接上架、AI 生成素材的商用授权范围）：系统内没有任何字段能证明授权存在，属**外部事实 + 法定签署**。
  → 替代路径：由 AGT-043 法务与知识产权在 FLOW-04/STG-06 前出具〈素材授权清单〉（母版来源、授权范围与到期日），由 AGT-044 产品合规与隐私核验宣称与隐私标记；补不上时先用「母版拍摄合同号 + 上一次已生效授权记录」顶替并逐条标「授权未核验」，凡未核验的版本只出 Action Intent、不进 STG-07 上架动作；后果是该版本降级为「仅内部参考」并从可投放清单移除，该 Case 的素材部分只能形成 NoActionRecord。
- 素材是否被平台判定为**合成 / 误导性内容**，以及平台素材规格与审核口径的当期原文：属**外部事实**，本司系统只能看到判定结果、看不到判定依据。
  → 替代路径：由 AGT-027 店铺账号健康与规则在 STG-04 结束前提供平台政策通知与生效版本号，由 AGT-021 / AGT-023 / AGT-024（按渠道）提供该渠道素材位规格；补不上时先用「平台后台最近一次生效的规格页快照 + 该版本的审核状态截图」顶替并标「未核验」，合成类素材不得用于主图位；后果是相关版本在判定未出前只能作备选，且不进本周期素材清单的可执行项。
- **宣称与合规的法定签署**（功效宣称、婴幼儿用品安全表述、达人内容需标注广告、跨境市场的本地化合规限制）：属**法定或治理签署**，模型不得代为出具。
  → 替代路径：由 AGT-044 在 STG-06 前签署宣称矩阵（逐条对应证据与适用市场）；补不上时该版本不进该市场的素材清单，先用同族已过审版本顶上架位并标「替代版本」；后果是缺签署的市场本次不投放该版本，交付物里只能写缺口与替代版本，不得写「待补宣称后投放」这类未定条件。
- **母版原始文件与拍摄记录**（判断在架素材与母版是否同一制品、是否被二次编辑）：属**实物或回执**，平台侧只存转码后的成品。
  → 替代路径：由 AGT-031 视觉视频与素材生产在 STG-04 前提供母版原始文件及拍摄记录（拍摄日、设备、布景）；补不上时先用「在架素材反查 + 文件属性比对」顶替为过程证据并标「原件未取得」；后果是该版本不得作为主图位候选，也不能作为内容实验的对照基线。
- **达人 / 合作内容的肖像与使用范围**（期限与地域范围写在与第三方的合同里，系统内无字段）：属**外部事实**。
  → 替代路径：由 AGT-033 达人与联盟合作在 STG-05 前提供合作授权期限与内容使用范围，由 AGT-043 复核合同条款；补不上时按「授权到期日 = 合作结束日」推定并标「推定到期」，推定到期前 **1 个自然月**停止投放；后果是推定到期的版本不得写进跨年度素材计划，也不得作为长期品牌资产登记。
- 「该素材版本更优」的**增量结论**（版本换代是否真的带来增量，而不是被同期流量与预算变化带动）：属**外部事实**，本契约的版本效果关联只能给出相关观察。
  → 替代路径：由 AGT-035 增长实验与增量评估在涉此结论的 STG-05 前给出验证设计（独立站的增量验证通道按决策 Q10 **须先建**）；补不上时该结论只能写成「相关观察、非增量结论」，只能用于排序；后果是不得据该结论做跨渠道素材预算的增减。

## 4 该格何时必须冻结

- 版本唯一度 < 1.000（检出 **≥ 1 对**重复指纹）或血缘缺口数 > 0 条 ⇒ 冻结该渠道的素材换代动作，回 STG-04 重新登记版本，该 Case 不得推进到 STG-07 受控动作。
- 六项要素缺任一项（尤其缺 `compliance_status` 或 `perf_pointer`）⇒ 该版本不得进入 STG-07 的上架与投放动作，只能形成 NoActionRecord。
- 版本涉对外宣称、肖像或儿童形象，而未取得 AGT-044 的宣称签署 ⇒ FLOW-01/STG-06 或 FLOW-04/STG-06 判 HOLD，转人工裁决。
- 版本涉第三方素材（竞品图、达人内容、外部音乐与字体），而未取得 AGT-043 的〈素材授权清单〉 ⇒ 不得进入 STG-07，只能出 Action Intent + 人工工单。
- 推定到期日在 **1 个自然月**内（按 §2 第 5 条的推定口径计）⇒ 该版本不得排入下一个自然季度的素材计划。
- 效果回填指针缺失（版本无法关联到广告后台的投放结果），而交付物仍给出「该版本更优」或排序结论 ⇒ 该结论不得写入〈联合经营行动包〉或〈市场进入包〉。
- 素材指标超出 §5 ④ 的新鲜度要求（例如用上一个自然季度的素材指标支撑本自然季度的加预算决定）⇒ 不得进入 STG-07（PB-001 通用工单规则：过期信息不能支撑加预算决定）。
- 命中平台规则中关于合成内容、宣称或素材规格的限制，或该版本已收到平台政策通知 ⇒ 不得执行换版，改走人工裁决；情形达到重大事件候选条件时交由 FLOW-07 紧急保护通道（Emergency Guard / D-026）评估，24 小时内补〈Pre-Case Exception〉记录。
- 数据更新使原登记失效（重新登记后该版本号已被替换或母版已变更）⇒ 回 STG-04 重新登记，不得沿用旧登记；已成功的上架动作不得随整单重跑。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | 平台后台（Amazon 卖家后台的商品图与 A+ 素材版本、广告后台的素材级投放报表）＋自有埋点（独立站埋点的素材位曝光与点击）＋需授权（财务系统对账表的素材制作与投流费用） | 非缺口，但有一段须显式降级：开放事实 O1 的其余 **20%** 渠道未定名 —— 其素材先按平台后台报表导出后人工登记顶替，逐条标「非留痕、版本号由平台生成」；该渠道定名、且其素材接入本维命名源后，换为事件级登记，此前这些版本只作参考、不进素材清单的可执行项 |
| ② 粒度 | 素材版本 × 渠道 × 市场 × 自然日（投放侧）；素材制品（图片 / 视频）× 派生批次（一份母版派生出的各渠道版本，按 `parent_version_id` 串成血缘） | 非缺口。若某渠道只回填到 campaign 级、不区分素材版本：先按 campaign × 自然日粒度顶替并把该段标「版本不可分、不作版本效果判定」；素材级回填到位后替换，替换前该渠道只能出提示，不得据其判版本换代 |
| ③ 回溯深度 | 近 **2 个完整年度**（业务处境给出的出海历史长度，决策 Q11），用于算版本效果基线与换代提示线 | **本业务暂无「素材版本台账」的实测起始日** —— 先按平台后台与广告后台**可拉取的最早日期**顶替（两者取较晚者），并在台账接入后替换为台账实际的首个版本登记日；替换前该回溯深度只用于算版本效果基线，不得用于跨年素材策略对比 |
| ④ 新鲜度 | 每次进入 STG-04 前重读一次；投放侧素材指标按 T+1 回填；换版当日的曝光与点击按平台「素材生效时间」切分归属 | 非缺口。若平台未给素材生效时间戳：先用「投放计划改动时间」顶替并标「归属非权威」，换版当日跨版本的数据不计入任一版本；平台时间戳可用后替换，替换前换版当日的效果不进换代判据 |
| ⑤ 口径归属 | AGT-045 指标契约与主数据（素材版本标识、渠道归属、CTR 与 ROAS 的分子分母与时间归属）；每条记录随带 AGT-046 的质量状态、来源与新鲜度；合规状态另归 AGT-044（宣称与版权标记） | **缺口**：素材版本号与派生关系的统一口径**尚未**由 AGT-045 签发 —— 先用〈素材版本台账〉的字段清单（`asset_version_id` / `parent_version_id` / `content_hash` / `phash`）暂按口径，并逐条标「口径未签发」；AGT-045 签发后替换为该契约口径，替换前版本号只用于内部检索与排序，不进入对外表述与绩效核算 |

说明：① 的三段来源中，平台后台与独立站埋点是本企业现存系统，财务系统对账表属需授权取得；〈素材版本台账〉的落库是**须先建的一段**（与决策 Q10「独立站 holdback 须先建」同源）—— 本契约不掩盖该前置，但它不使本责任缺值：上表第三列与 §3 首行都给了替代口径与替换条件。
