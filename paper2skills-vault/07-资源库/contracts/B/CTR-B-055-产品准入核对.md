# 产品准入核对 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，
> 不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：准入矩阵可规则化 ＋ 法规库匹配，但**最终准入须法定依据与外部认证**。
> 这句话就是本契约可达段与不可达段的分界线 —— **本层能把「还缺哪一项、缺到什么时候」算到格子上，
> 不能把「这一项已经取得了」算出来**：发证与注册的事实只在发证方手里。
>
> 岗位 AGT-044 产品合规与隐私（DOM-07 / PLN-CTL），岗位产物「合规矩阵与证据缺口」，
> 结果指标「覆盖完整性与违规阻断」；适用 FLOW-02 新品需求到商业验证、FLOW-04 市场进入与合规上架、
> FLOW-05 服务留存与复购、FLOW-06 业务需求到数据产品与工具、FLOW-07 重大质量与账号事件。
> 本岗位是**独立控制面（PLN-CTL）**上的核对方：结论只用于阻断与放行判据，**不代替**任何渠道经营负责人做进入决策。
>
> **本契约覆盖的格**：方法格 = 上述五跳各自的 STG-04、STG-05、STG-08（§1 的四个算式落在这些格上）；
> 规则格 = 五跳各自的 STG-01／STG-02／STG-03／STG-06（Assurance 接收门禁）／STG-07（受控动作），
> **这些格只放判据与门禁条件，不挂载任何判别式**（§4 的落脚处）。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例与时限，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 **2 个完整年度**＝决策 Q11；经营节奏「月度经营复盘」＝**1** 个自然月；
> 渠道四选一＝决策 Q9；其余 **20%** 渠道构成未定名＝开放事实 O1）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）；（c）§1 算式由命名数据系统直出。
> **候选卡的卡面案例数字不构成第四种来源**（逐条清单见 §1）。

## 1 算法可达部分

- **候选卡状态（先读这一条再用本段）**：本责任候选清单共 **46** 张，**全部是 legacy 预览版**（八段式：④、⑤ 两段是占位串，代码以同目录 `references/implementation.py` 随卡且为节选，⑧ 段出处写「不可采信」或「待人工判定」），**有全文卡 0 张、精选线未换底卡 0 张** ⇒ **论文实验参数未随卡进入本包**。故本段的可达写法由**本业务算式**定值，卡只供方法骨架（矩阵扫描、逐项打分、缺口清单、修复工单四件事）；卡面可见数字逐条列在本段末尾，**任一条不得移植**。
- **可达段一（准入矩阵扫描：把「缺什么」算到格子上）**：以**单 SKU × 单市场 × 单要求项**为一格，逐格判「是否必需 / 是否已取得原件 / 凭证是否有效」，输出准入证据矩阵、阻塞项清单与合规状态标签，写入 FLOW-04/STG-04 的〈市场进入诊断〉与 FLOW-02/STG-04 的〈机会与可行性诊断〉准入栏。
- 可达段一算式：`要求项命中率 = 已录入要求项数 ÷ 要求库中「该市场 × 该类目」的应有要求项数`；`合规覆盖率 = 已取得原件的必需要求项数 ÷ 该 SKU × 该市场的必需要求项总数`；`阻塞项数 = count(必需项 ∧ 未取得原件)`。
- 取值：**合规覆盖率 = 1.000（即 100%）且阻塞项数 = 0 项** 才判「可上市」；**任一必需项未取得原件 ⇒ 判「不可上市」**，该判定是**二值**的、不设部分通过档（**业务侧默认**，来源＝经营者自述「缺一张证就是不能发」）。**要求项命中率 < 1.000 时，矩阵结论一律判「不可采信」**，不得当作准入结论（这是本责任最容易虚报的地方：漏项会被读成合规）。**替换条件**：〈准入证据矩阵〉与认证台账接入并覆盖满 **2 个完整年度**（决策 Q11）后，改用**实测**覆盖率与实测漏项率重算；替换前该结论只能表述为「**未检出错漏项**」，**不得**表述为「该 SKU 合规」。
- **可达段二（凭证有效性：证书在不在有效期内、是不是这个主体的）**：对每一项已取得的凭证算剩余有效期、主体一致性、版本时效三个可核验量。
- 可达段二算式：`剩余有效期 = 证书到期日 − 本次核对日`；`主体一致性 = (证书持有人 ≡ 店铺主体或授权链上的被授权人)`（二值）；`版本时效 = (要求库版本日期 ≥ 最近一次法规变更的生效日)`（二值）。
- 取值：**临期线 = 剩余有效期 < 90 个自然日**（**业务侧默认**，来源＝经营者自述「证快到期前三个月就得动手续」）；**主体不一致 ⇒ 一律判「不可上市」**（二值，不与有效期做加权）；**版本时效不满足 ⇒ 矩阵结论判「不可采信」并触发重扫**。**替换条件**：各市场的续期实际办理周期由认证台账跑满 **2 个完整年度**后，临期线改用「该市场实测续期周期 ＋ 1 个自然月缓冲」重算；替换前临期项只触发续期工单，不单独构成阻断（阻断仍由覆盖率与主体一致性决定）。
- **可达段三（准入包宣称与证据的匹配）**：对进入准入包与上架包的每一句对外宣称，逐条找支撑原件（检测报告、认证范围、法规许可），输出宣称证据覆盖率与无据宣称清单；健康、功效、安全三类宣称单独计数，**不给容差档**。
- 可达段三算式：`宣称证据覆盖率 = 有原件支撑的宣称条数 ÷ 准入包与上架包中的宣称条数`；`无据宣称数 = count(宣称 ∧ 无任何原件支撑)`。
- 取值：**宣称证据覆盖率 = 1.000（即 100%）**、**无据宣称数 = 0 条**；健康、功效、安全三类宣称**一条无据即判「不可上市」**（**业务侧默认**）。**替换条件**：宣称与支撑原件的对应关系由 AGT-044 的宣称台账逐条落库后，改用台账实测匹配率；替换前该结论只用于阻断，**不得**反向用于放宽任何宣称（本层没有「补一句免责声明就可放行」这一档）。
- **可达段四（法规变更的复评触达面）**：法规或平台规则变更生效时，算受影响的「SKU × 市场」格数与需重扫的格数，输出重扫工单；当准入矩阵本身作为能力交付对象（FLOW-06）时，要求库的条目口径、更新责任与验收判据写进 FLOW-06/STG-05 的〈数据/工具交付包〉。
- 可达段四算式：`复评触达面 = count(受影响 SKU × 市场格)`；`待重扫格数 = 复评触达面 − 已完成重扫的格数`。
- 取值：**法规变更生效日起 15 个自然日内**完成受影响格重扫（**业务侧默认**，来源＝经营者自述「新规落地半个月内先扫一遍再说」）；**待重扫格数 > 0 时，受影响格的新准入结论一律不得出具**（只出「重扫中」状态）。**替换条件**：AGT-027 的规则监测台账与法规原文到位后，重扫时限改用「该法规的合规过渡期 － 1 个自然月」重算；替换前重扫时限只作内部派单约束，不作为对平台或主管机关的承诺。
- **本段的能力边界**：只做四件事 —— 缺哪一项、凭证是否有效、宣称是否有据、法规变更影响哪些格；**不产出认证与注册、不产出检测结论、不产出法定宣称判定、不产出进入或放行的最终裁决**（见 §2 各条）。本层对 FLOW-05 的贡献仅限「产品适用性边界与对外表述边界」，不代替 FLOW-05 的服务与留存方案。

## 2 不可达部分

- 不可达①（需**外部事实 ＋ 实物回执**）—— 认证与注册的**发证事实本身**：证书是否真的签发、覆盖范围是什么、有效期到哪天、有没有被暂停或撤销。事实源在发证机构与主管机关，本层只能读到台账上的「已提交 / 未提交」与一张扫描件。
  → 替代路径：由 AGT-044 本岗在 FLOW-04/STG-04 结束前向发证机构或代理机构取回证书号与有效期、由 AGT-042 税务与跨境实体协作在 FLOW-04/STG-06 前补齐税号与实体注册结论；证书号还没回来时，矩阵里那一格只登记受理号与进度函日期并标「发证侧未回」，`合规覆盖率` 的分子按未取得计；证书号到位后逐格补录并重算该 SKU × 该市场的阻塞项数。在补录之前该 SKU 不得上市，只能出 NoActionRecord
- 不可达②（需**外部事实**）—— 法规与平台规则的**原文与生效版本**：要求库的全部条目都由它派生，而解释权与发布权不在本司。
  → 替代路径：由 AGT-027 店铺账号健康与规则在 FLOW-04/STG-04 结束前交出平台政策原文与生效版本号，法规原文与法律意见则由 AGT-043 法务与知识产权在 FLOW-04/STG-05 前交出；两份原文没到手时，要求库照旧可扫，但每条要求项的来源栏写「引用版本早于现行」并挂起，原文到手后按新版本号整条重录。在此之前可达段二的 `版本时效` 一律判不满足，依赖它的上架动作停在 Action Intent 加人工工单
- 不可达③（需**实物或回执**）—— 检测与验货的结论：婴幼儿产品的安全测试、材料与化学检测、包装与标签实物核对，只能由认可实验室与验货机构出具。

## 4 该格何时必须冻结

- 合规覆盖率 < 1.000（存在未取得原件的必需项）或阻塞项数 > 0 项 ⇒ 该 SKU 不得判「可上市」，不得推进到 FLOW-04/STG-07 的上架受控动作，只能形成 NoActionRecord。
- 要求项命中率 < 1.000（要求库对「该市场 × 该类目」有未录入项）⇒ 矩阵结论判「不可采信」，冻结该市场全部 SKU 的准入结论，回 STG-04 补库后重扫。
- 存在**无据宣称**（宣称证据覆盖率 < 1.000），而拟动作含健康、功效或安全类表述 ⇒ 冻结该上架包，删除或替换该宣称后方可重提。
- 凭证剩余有效期 < 90 个自然日且未提交续期受理 ⇒ 冻结该 SKU 在**新市场**的上架动作；已在售商品的续期工单同步开出，不得以「还没过期」放行新市场。
- 证书持有人与店铺主体或授权链不一致 ⇒ 该 SKU 一律判「不可上市」，不得以补充说明替代主体一致证明。
- 法规变更生效日起 **15 个自然日**内未完成受影响格重扫（待重扫格数 > 0）⇒ 受影响「SKU × 市场」格不得出具新准入结论，只出「重扫中」状态。
- 涉主体、税号与收款的结论缺位（AGT-042 未给结论或 AGT-050 未给权限清单）⇒ 该 Case 的 Assurance 接收门禁判 HOLD。
- 含未定宣称或对外承诺的包缺 AGT-043 法律意见 ⇒ 不得进入受控动作，只能出 Action Intent ＋ 人工工单。
- FLOW-05 的服务与留存方案中涉及「产品适用性」的表述超出本层准入结论的范围（例如据准入结论推断可治疗、可替代医疗器械）⇒ 冻结该表述，回 FLOW-05/STG-05 重写。
- 同一「SKU × 市场」在当周内已有一次未回填的上架尝试或准入重扫 ⇒ 不得重复发起；**已成功动作不得随整单重跑**。
- 自 FLOW-04/STG-05 的〈市场进入包〉提交起，至该 Case Charter 已写明的观察窗截止日仍未取得 §3 所列任一项证据 ⇒ 判 HOLD 并转人工，不得默认放行。
- 引用 §1 清单中任一条卡面案例数字（含 80 / 60 阈值、20 分制、4 个违禁词、¥3–8 万、3–8%、DE/JP 推迟 60 天、50 项要求、94% 准确率等）作为本业务取值 ⇒ 该方案不得放行。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | 需授权（认证与注册台账、检测报告、代理机构回执、法规原文）＋平台后台（卖家后台的政策通知与类目准入要求）＋自有埋点（Case/Event Ledger 的准入核对记录与合规状态标签） | 非缺口。若某市场的认证台账尚未建账、只有经办人邮箱里的扫描件：先按「受理号 ＋ 代理机构进度函」顶替并标「未建账」，该市场只出阻塞项清单、不出覆盖率；台账建账后替换为凭证级记录，替换前不得判「可上市」 |
| ② 粒度 | 单 SKU × 单市场 × 单要求项（一条 = 一个要求项的取得状态、凭证号与有效期）；宣称侧到 单条宣称 × 支撑原件 | 非缺口。若某源只到「认证包」级（把 FCC 与 UL 打包成一条记录）：先按包级粒度顶替并把该包标「粒度不足、不作逐项判定」，该包只出提示；逐项台账到位后替换，替换前该包内任一项缺失都按整包阻塞处置 |
| ③ 回溯深度 | 本业务**暂无该 SKU × 该市场的自有准入历史** —— 新品与新市场按定义没有自身记录，缺它算不出「这个品类在这个市场出过什么事」的复评先验，因而判不出要求项是否该加严，「该品类历史上没出过事」这句话也就没有任何数据支撑 | 本业务手上没有该 SKU × 该市场自己的准入历史，这一维目前只能用平台后台政策通知与公开召回公告拉一段外部先验：先按公告里能读到的近两年同品类下架与召回事件暂按加严依据并标「先验非台账」，〈准入核对台账〉建成并攒满 **2 个完整年度**后改用台账里的同品类历史下架、召回与整改记录。在改用之前这段先验只能让要求项变严，判不出「这个品类在这个市场没出过事」 |
| ④ 新鲜度 | 每次进入 FLOW-02/STG-04 或 FLOW-04/STG-04 前重扫一次；证书与要求库状态按「月度经营复盘」＝**1** 个自然月复核一次；进入 STG-06 接收门禁前须为「截至前一日 24:00」的完整快照 | 非缺口。证书状态若只由经办人按月手工汇总，当月的暂停与范围变更读不到，可达段二的 `剩余有效期` 与 `主体一致性` 就会拿旧值当现行值；此时先用代理机构回函加平台政策通知拼一份当月观察档并标「非官方复核」，由发证侧或平台给出的现行状态到位后整档替换。在此之前的结论只能用于开续期工单，不得写进「可上市」判定，FLOW-04/STG-08 也不得据它关闭 |
| ⑤ 口径归属 | AGT-045 指标契约与主数据（要求项的分子分母、市场与类目对象、合规状态标签的取值域）—— 其中合规状态标签的**权威取值域尚未由 AGT-045 定名**（现状是「已取得原件 / 已受理未持证 / 未申请 / 不适用」这套本层自定四态，各市场各人叫法不一），缺它算不出跨市场可比的阻断率，同一个「PENDING」在 A 市场指已受理、在 B 市场指没动过，两边的阻塞项数加不到一起；每条记录随带 AGT-046 的质量状态、来源与新鲜度 | 本层自定的「已取得原件／已受理未持证／未申请／不适用」四态先按〈准入证据矩阵〉里的写法暂按，每条再挂一个「枚举待归位」标记；`AGT-045` 把合规状态的权威取值域定名后，按映射表把这四态归位到权威枚举。在归位之前，同一批 SKU 的阻塞项数只允许在单市场内相加，跨市场求和一律不出，对外表述里也不得出现任何合规状态词 |
