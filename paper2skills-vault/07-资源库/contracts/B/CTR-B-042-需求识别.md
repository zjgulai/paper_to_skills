# 需求识别 · 供给契约

> **本契约的两部分，用法不同。** §1 算法可达部分 / §2 不可达部分 / §3 必须的外部证据与责任岗位 /
> §5 数据要求 / §6 适用 FLOW 是**作业口径** —— 据此产出方案：可达段给算式与取值，不可达段给替代路径；
> §4 该格何时必须冻结是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得整句抄成交付物的内容**。
>
> **本责任为什么是 B 类**（`_survey_org_model.md` §F.3 原文，别改判）：意图与槽位抽取可算法化，
> **但真实需求的确认依赖会话之外的外部证据** —— 这条理由就是本契约可达段与不可达段的分界线：
> 抽取结果（意图标签、四元槽位、一致性冲突）走可达段并给取值；
> 「客户到底要解决什么」落不可达段，它的证据在会话之外（订单事实、已购型号、宝宝实际月龄、许可状态）。
> 本责任的标准产物是 AGT-036 的〈有依据的售前答复与线索〉（岗位指标：问题解决与购买体验）；
> 岗位人格边界逐字为**「适合客户的选择比一次成交更重要」** —— 这条直接约束下面的追问上限与冲突处置。
>
> **格子边界**：本责任在 FLOW-04（〈市场进入诊断〉〈市场进入包〉〈市场进入关闭记录〉）、
> FLOW-05（〈客户问题诊断〉〈服务与留存方案〉〈客户旅程关闭记录〉）、FLOW-07（〈事件范围与根因诊断〉
> 〈重大事件处置包〉〈重大事件关闭与全动作对账记录〉）九个方法格上作诊断段、方案段与关闭段；
> 三个 FLOW 的 STG-01/02/03/06/07 是规则格，只放判据与门禁条件（含 STG-06 的 Assurance 接收门禁），
> 不承载本契约的任何方法实现。
>
> 本契约对同族方法卡通用（代表卡 `p2s-agent-memory-learning`；同族另有 `p2s-user-profile-long-memory`、
> `p2s-cs-ticket-intelligence`）；**换卡时只替换方法实现，算式、取值、外部证据与冻结条件不变。**

## 1 算法可达部分

- **本条责任里算法能承接的那一段**：把一段会话压成三样可核验产物 ——
  ① 每条会话的**意图标签**与**四元槽位**（品类／宝宝月龄阶段／使用场景／时间窗）抽取结果，缺哪一槽显式列出；
  ② 按「缺槽数 desc, 会话进入时间 asc」排出的**追问队列**；
  ③ 会话槽位与〈用户画像长期记忆〉（同族方法卡要求的分层画像存储，**尚未签发**：归属方与字段口径待
  AGT-045 定名，签发后以它的名称替换本契约的引用）以及〈订单事实〉的**一致性冲突标记**。
  三样写入本 Case 的标准产物（FLOW-04 落〈市场进入诊断〉与〈市场进入包〉；FLOW-05 落〈客户问题诊断〉
  与〈服务与留存方案〉；FLOW-07 落〈事件范围与根因诊断〉与〈重大事件处置包〉），并在三个 FLOW 的 STG-08 作关闭段提交。
- 算式：`槽位齐备率 = 四元槽位全部非空的会话数 ÷ 当期会话总数`；`追问轮次 = 同一 case 内的追问消息条数`；
  两者都按〈独立站埋点〉的会话事件与〈Amazon 卖家后台〉的买家消息逐条计，键为 `case_id` + 消息序号。
- 算式：`阶段推断区间 = [〈订单事实〉中该客户最近一次阶段型商品的首购日 + 该商品标签的起始月龄档,
  首购日 + 该商品标签的终止月龄档]`；输出**区间**，不输出点值。
  `冲突数 = count(会话槽位与〈订单事实〉或画像不一致的会话)`，冲突项逐条落到追问队列首位。
- 取值：**槽位齐备率目标线 ≥ 0.80（80%）**。该数是**业务侧默认值**（来源＝经营者自述
  「两轮追问内应能问全四元槽位，问不全的就该转人工，不要让客户填表」）。
  **替换条件**：〈独立站埋点〉的会话事件按消息级落库并跑满 **2 个完整年度**后，
  改用**实测**「追问 2 轮内齐备」的会话占比下界；替换前该值只用于追问队列排序，不作坐席考核项。
- 取值：**追问轮次上限 ＝ 2 轮**（来源＝**行业惯例**下的客服会话追问容忍度，与岗位人格边界同向）。
  **替换条件**：会话台账跑满 **2 个完整年度**后，改用实测「追问轮次—成单率」曲线的拐点；
  替换前超过 **2 轮**仍未齐备的会话一律转人工，不得由抽取结果替客户补齐槽位。
- 取值：**意图标签集收敛为 4 类** —— 咨询、订单异常、售后、获许可的生命周期事件，逐字取 STG-01 的事件类型；
  **越界标签数 ＝ 0 件**（二值判定，不给模型自造标签的自由度）。
- 取值：**阶段推断的允许误差档 ＝ ±1 个月龄档**（该数是**业务侧默认值**：经营者自述按阶段型商品的换阶窗口
  留一档余量，避免把「即将换阶」误判为「已换阶」）。**替换条件**：〈用户画像长期记忆〉台账跑满
  **2 个完整年度**后，改用实测换阶提前量与滞后量的分布上下界；替换前阶段推断只用于追问与排序，
  **不得**据此出换阶推荐或跨阶段营销承诺。
- 取值：**冲突数 > 0 件即转人工**，且同一 Case 的**画像改写数 ＝ 0 件**（二值；画像只由客户确认后的结果写入，
  Agent 不得自行改写 —— 材料 AGT-050 的同类约束：岗位只能提出变更、不能自行发布）。
- **不得移植的部分**（逐条来自实际读过的三张卡；任一条都不得作为本业务的判定线或阈值）：
  代表卡 `p2s-agent-memory-learning` 是**唯一有论文出处的同族卡**（arXiv:2310.08560，MemGPT），
  但下列数一律不得作为本业务取值 —— 卡面 ① 的上下文压力两档 **~70% 预警 / 100% 强制**
  （卡页自承「在本底本中零命中」，即**非论文实验参数**，属实现默认值）、Main Context 容量
  **8K-128K tokens** 与 Recall Storage「**数千条**」的容量档；论文 §3.1.2 Table 2 的
  深记忆检索成绩 MemGPT **82.4%** 对 gpt-4 summary **63.0%**（那是 DMR 任务的评测值，不是本业务的识别准确率）；
  ② 场景的 **0.3kg**（Spectra 9 Plus）、静音提及率 **34%→28%（−6pp）**、价格负面情感 **8%→15%**；
  ⑤ ROI 表的复购率 **+15-20%**／开发 **2-3 周**／ROI **15-25x**、分析效率 **+30%**／**2 周**／**12-18x**、
  跨会话一致性 **10-15x**；`references/implementation.py` **245 行**。
  同族卡 `p2s-user-profile-long-memory` 为 **legacy 预览版**（八段式，④⑤ 段是占位串、代码以
  `references/implementation.py`（**399 行**）随卡且为节选）⇒ **论文实验参数未随卡进入本包**；
  其卡面可见数字（Stage 1/2/3 的换阶示例、推断月龄「**2-3 月**」「**≈4 月**」「**≈8 月**」、
  时间节点 **Month 0/3/6**、⑥ 的「运行成本接近零」）同为示例场景，一律不得作为本业务的阶段推断规则。
  同族卡 `p2s-cs-ticket-intelligence` 同为 **legacy 预览版**（④⑤ 为占位串、
  `references/implementation.py`（**166 行**），卡页自承其 60 行节选语法不完整、不能直接运行）⇒
  **论文实验参数未随卡进入本包**；其卡面可见数字（每天 **50 条**买家消息、人工 **3-4 小时**、
  差评预警 **5%**／标准问题 **30%**／订单追踪 **65%**、响应 **8h→2h**、效率 **3-5 倍**、
  年化 **15-40 万元**、**¥3-8 万/年**、差评率降低 **15-25%**、每次挽回 **¥2-5 万**、
  规则引擎版 **1 周**、LLM 回复生成 **2-3 周**）一律不得作为本业务的意图分类占比或分流规则。
- 上下文压力与记忆换出触发线由**所选记忆实现**的默认值决定，**本契约不为它设业务常量**，
  它也不参与任何业务判定（见上一条：卡面的 70%/100% 不可移植）。
- 本段的能力边界：只做四件事 —— 意图归到哪一类、四元槽位缺不缺、追问按什么次序发、槽位与事实冲突在哪；
  **不产出「客户真正要什么」的结论、不替客户补齐槽位、不自行改写画像**（见 §2 第 1 条）。
- 本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变。

## 2 不可达部分

以下五段是算法到此为止的地方：两段属外部事实，一段属法定与治理判定，一段属人的专业判断，一段属治理事实。

- 真实需求的确认（客户说「随便看看」时到底要解决什么、这次是自用还是送人、预算是不是硬约束）：
  属**人的专业判断加会话之外的外部证据**，抽取结果只能给出候选，不能给出确认。
  → 替代路径：由 AGT-036 售前服务与购买指导的人工坐席在 STG-05 方案定稿前与客户完成一轮确认
  （岗位人格边界：适合客户的选择比一次成交更重要）；补不上时先用「抽取结果 + 待确认」双栏交付，
  抽取栏**不得**计入〈服务与留存方案〉〈市场进入包〉的可执行项，该 Case 只能停在 STG-06；
  后果是该会话不进复购实验、不发触达动作，并计入本期**未确认需求**数。
- 会话之外的外部事实（宝宝实际月龄、喂养方式、已购型号与购入时间、过敏史、家庭预算）：
  属**外部事实加需授权数据**，只能在会话之外取得，抽取结果推不出来。
  → 替代路径：由 AGT-034 CRM留存与复购在 STG-03 上下文装配时提供客户许可状态与〈订单事实〉字段清单；
  补不上时先在会话内**直接向客户询问**并把答案记为「客户自述」、与〈订单事实〉分开存放，
  二者冲突时以订单事实为准并转人工；后果是缺这些槽位的会话只能做通用推荐，不得作适用性或阶段判断。
- 渠道与订单事实的真相（买家消息的时间线、订单归属哪家店、退货与换货的实际状态）：
  属**外部事实**，只有各渠道主体能给出权威版本。
  → 替代路径：按决策 Q9 的渠道四选一分别由 AGT-021 Amazon业务经营、AGT-023 独立站经营与转化、
  AGT-024 其他平台与新市场经营、AGT-025 零售渠道与B2B拓展在 STG-04 结束前提供该渠道的事实确认，
  售后状态由 AGT-037 售后客诉与服务补救提供；补不上时先用〈平台后台〉订单报表与〈独立站埋点〉下单事件
  顶替并标「未确认渠道事实」，相关会话只出 Action Intent；
  后果是事实未确认的 Case 不进 STG-07，也不计入本周期需求识别覆盖率。
  （渠道四选一是一条规则：**不得**把某一个渠道实例的负责人写成整条 FLOW 的负责人。）
- 客户许可与隐私边界（这份画像能不能用于主动触达、能不能保留到下一个育儿阶段）：
  属**法定或治理判定**，不由抽取结果给出。
  → 替代路径：由 AGT-044 产品合规与隐私在 STG-05 定稿前出具许可判定，由 AGT-050 出具可见范围结论；
  补不上时按〈客户Case Charter〉里已写明的许可字段**逐条**判定，落在未判定档的客户一律按「不可触达」处理
  并把该 Case 标「许可档位未定」；该客户只允许被动答复、不得主动触达；后果是触达类动作只能出 Action Intent + 人工工单。
- 客户自述、订单事实与画像三者冲突时以哪一份为权威：属**治理事实**，抽取结果只能标记冲突、不能裁决。
  → 替代路径：由 AGT-045 业务口径与主数据在 STG-04 结束前给出字段级权威顺序，争议 Case 由
  AGT-005 内控审计与独立复核在 STG-06 前复核；补不上时先用「订单事实 > 客户本次自述 > 历史画像」的
  保守顺序顶替并逐条标「权威顺序未签发」；后果是冲突未裁决的 Case 不得改写画像、也不得出换阶推荐。

## 4 该格何时必须冻结

- 四元槽位缺任一且追问已达 **2 轮**上限 ⇒ 冻结自动推进并转人工；**不得**用模型推断的槽位代替客户确认，
  也不得把推断槽位写进本 Case 方案段的可执行项。
- 冲突数 > 0 件而权威顺序未由 AGT-045 签发 ⇒ 不得改写〈用户画像长期记忆〉，不得出换阶推荐或阶段型商品推荐。
- 阶段推断区间跨越了 **2 个及以上**月龄档（推断退化、无法定位档位）⇒ 该 Case 只出追问，不出推荐。
- 客户许可缺失（AGT-044）而拟动作含主动触达 ⇒ 不得进入 STG-07，只能出 Action Intent + 人工工单。
- 会话事件未按消息级落库（§5 ② 的缺口）而结论要作为坐席考核或 SLA 口径 ⇒ 冻结该用途，
  槽位齐备率只报「未检出」、不报百分比。
- 命中材料 EXC-WAITING-INPUT（必需输入缺失、过期或不可用）⇒ 该 Case 状态置 WAITING，
  依赖项与新鲜度复核通过后方可回到**同一**阶段，不得以跳过阶段的方式继续。
- 命中材料 EXC-POLICY-DENIED（Policy Gate 拒绝 Action Intent）⇒ 该 Case 状态置 REWORK_REQUIRED，
  退回 STG-05 或出 NoActionRecord 关闭，**不得以任何方式绕过拒绝**。
- 同一客户在当周内已有一次未回填的触达动作 ⇒ 不得对同一客户发起新触达；已成功动作不得随整单重跑。
- 外部证据时限：自 STG-05 产物提交起，至〈Case Charter〉写明的观察窗截止日仍未取得 §3 所列任一必需证据 ⇒
  判 HOLD 并转人工，不得默认放行。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | `自有埋点`（独立站埋点的会话与消息事件；Case/Event Ledger 的 Case Charter、Stage Acceptance Record）＋`平台后台`（Amazon 卖家后台的买家消息与订单报表）；〈订单事实〉对账数据、〈用户画像长期记忆〉与客户明细为 `需授权` | 非缺口。若某渠道的会话只在平台侧留存、本司取不到消息正文：本维的源只能退到〈市场进入Case Charter〉写明的渠道与时间窗，用平台侧消息的导出件**顶替**为会话源并逐条标「他方留存」；这种来源下 `槽位齐备率` 的分子（四元槽位全非空的会话数）判不了 —— 导出件缺「时间窗」那一槽，会把半截问询误算成齐备。故该批先只用于追问队列的排序，不并进齐备率的分母与分子；待 Case/Event Ledger 把该渠道的消息级事件**接入后**，改用本司自存源重算齐备率并解除标注 |
| ② 粒度 | 目标粒度 ＝ 一条消息一条记录（会话序号 + 角色 + 时间戳 + 抽取到的槽位），键为 `case_id` + 消息序号；但会话**尚未**按此粒度落库，存量只有工单级整单文本 | 缺口：缺消息级粒度就算不出「哪一条会话缺哪一个槽位」，槽位齐备率的分子（齐备会话数）与追问轮次都只能按整单近似。处置：**先按**整单文本做整单级槽位判定并把该批标「粒度不足、不可作单会话分母」；会话事件按消息级落库跑满 **1 个自然月**后**替换**为消息级粒度；**替换**前槽位齐备率只用于追问排序，不得作为坐席考核或 SLA 口径 |
| ③ 回溯深度 | 〈用户画像长期记忆〉台账的可用区间自其**建库首日**起；〈订单事实〉与平台消息为 **2 个完整年度**（业务处境给出的出海历史长度，决策 Q11），用于阶段推断与冲突比对 | 缺口：画像台账的建库首日普遍晚于客户在本司的首购日，客户育儿周期的前一段没进台账 —— 缺了它，§1 的 `阶段推断区间` 只能从首购日往后量，跨阶段（0–6 月到 6–12 月）那一段区间算不出来，`冲突数` 还会把首购前买过的阶段型商品误记成不一致。处置：**先按**该客户在本司的首笔订单日**顶替**为画像起点、区间只当**下限**用，逐条标「起点非真实首购」；等台账回填到早于客户首购（或 AGT-045 给出可用的历史起点）**到位后**，起点换成台账实际首建日并重算区间与冲突数；换之前不得据区间出换阶推荐 |
| ④ 新鲜度 | 装配 Context Manifest 时与进入 STG-04 判槽位前**各重读一次**；会话与订单事件须为截至**前一日 24:00** 的完整快照，画像字段的 `updated_at` 随取随报 | 非缺口。若画像为离线批量 T+1：先用〈独立站埋点〉与〈Amazon 卖家后台〉的当日会话事件做存在性判定并标「画像口径非权威」，画像按日可读后替换；替换前不得据画像判冲突 |
| ⑤ 口径归属 | `AGT-045`（业务口径与主数据）为四元槽位定义、意图四类标签、槽位齐备率与冲突数分子分母的归属方；每条会话与画像记录随带 `AGT-046` 的来源、质量状态与新鲜度 | 非缺口。四元槽位与意图标签现在是各渠道各一套叫法（平台侧记「售后」、独立站记「退换」），落到本契约就是 §1 的 **4 类** 意图标签集收不拢：同一段会话在两个渠道进两类，`越界标签数`（取值 0 件）与 `槽位齐备率` 的分母因此不可比。处置：**先按** STG-01 的事件类型原文**顶替**出渠道内标签，每条标「标签未定名」，本维只供追问队列排序与告警；等 AGT-045 把四元槽位与意图标签**签发**成一套命名后，把渠道内标签整批换掉再重算齐备率与越界数 |
