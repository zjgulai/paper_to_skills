# 用户访谈分析 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：可达段给算式与取值，
> 不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，**不得**整句抄成交付物的内容。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**访谈文本可用主题建模/LLM 编码，但需求真实性依赖样本设计与外部验证，模型判断不能替代实物回执。**
> 因此本契约的可达段只到「访谈文本被稳定地编码、每条结论都指得回原话」为止；
> 「用户是不是真的要买」这一段按 §2 交给受控外部验证 —— 材料口径同此：**未经验证的实物与宣称不能进入销售动作**。
>
> 材料对 AGT-006 的两条硬约束内嵌在本契约里：核心判断原则「**用户原话与研究者解释分别保存**」，以及边界「**不能把少数评论当作整个市场需求**」。

## 1 算法可达部分

- **访谈语段的编码与可溯源性**（落 FLOW-02/STG-04、FLOW-02/STG-05、FLOW-02/STG-08 与 FLOW-05/STG-04、FLOW-05/STG-05、FLOW-05/STG-08 六个 M 格）：把转写稿按发言人轮次切成语段，逐段编主题标签、抽原话证据、给结论挂原话编号，输出三个可复算的量 —— 覆盖率、可溯源率、主题饱和点。
- 算式 1：`编码覆盖率 = 已编码语段数 ÷（语段总数 − 明示的不可编码语段数）`；**不可编码语段** = 寒暄、确认、设备调试等不含需求信息的轮次，须逐条在台账里标出并保留原文，**不得删除**（分母不把不可编码轮次算成失败）。
- 算式 2：`原话—结论可溯源率 = 带原话编号的结论条数 ÷ 结论总条数`；**原话编号**指〈需求证据与问题地图〉里每条结论回指的受访者代号 + 轮次号 + 归档位置。
- 算式 3：`主题饱和点 = 累计新增主题曲线一阶差分连续为 0 的起始场次`（语段先按主题编码、再按场次累计去重计新增主题数）。
- **取值：原话—结论可溯源率 = 1.00（即 100%）** —— 依据不是默认值而是**材料已定名的规则**：AGT-006 的核心判断原则是「用户原话与研究者解释分别保存」，且其标准产物〈需求证据与问题地图〉必须「包含范围、输入版本、依据、建议或实际动作、结果与未解决项」，故本量是**二值口径** —— 没有原话编号的结论不允许存在，不存在「部分合格」档。
- **取值：每批访谈的强制留痕例数 = 1 例**（原话与研究者解释被分开保存的对照案例）—— 依据＝材料已定名的行为验收项：AGT-006 的行为验收「必须包含一次违反『用户原话与研究者解释分别保存』的诱导输入」，检查是否提出异议、保留证据并正确分派、复核或冻结范围。该例不进结论，只进留痕。
- **目标值：编码覆盖率 ≥ 0.95** —— 这是**业务侧默认值**，来源＝经营者自述（AGT-006 现行人工编码中约 5% 的轮次是寒暄/确认类语段，按算式 1 已从分母剔除，故可用语段的覆盖率取满值一档，0.95 是给「语段切分错误」留的余量）。**替换条件**：编码台账按批记录语段切分复核结果满 2 个完整年度（决策 Q11）后，改用**实测覆盖率**替换；替换前覆盖率只用于本批内部进度，不作为质量结论对外表述。
- **阈值：主题饱和点 = 新增主题数连续 3 场为 0** —— 这是**业务侧默认值**，来源＝行业惯例（定性研究的饱和判据通常取「连续若干单元无新主题」；材料与本包唯一的候选卡都没有给这个参数）。**替换条件**：AGT-005 抽样审计责任给出本项目的抽样方案后，按该方案规定的连续场数替换。
- **卡面数字不得移植**：本责任在本包只有一张候选卡（`p2s-personabot-rag-profiling`，源卡号 `Skill-PersonaBot-RAG-Profiling`，源域 14-用户分析，图谱 L3 含 `用户访谈分析`）。其卡面数字 —— 每 SKU 评论量门槛（① 段写 ≥ 50 条、③ 段写 ≥ 500 条，**卡面自相矛盾**）、差评分析「评分 ≤ 3 分、近 90 天、每 SKU ≥ 200 条」、关键词分群示例 `['上班','公司','背奶']`、检索参数 `top_k=5`、LLM API 100–500 元/月（按 10 万条评论/月）、存储 200 元/月、1 名数据工程师 2 周 ≈ 1.5 万元、年化显性成本 3–5 万元、年化价值 20–40 万元、`references/implementation.py` 238 行 —— **全部是该卡的示例口径，不是本业务的取值**。本卡为已装线卡（⑧ 段记 arXiv:2505.17156），但**卡面没有随卡进入本包的论文实验参数表**，故此处按卡面可见数字逐条列，不代填论文原值。
- 本段的能力边界：只做三件事 —— 语段是否被编码、结论是否指得回原话、访谈是否已到饱和；**不产出需求真实性结论、不产出市场规模的占比**（见 §2 第 1、2 条）。
- 本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变。

## 2 不可达部分

- 需求真实性（访谈里说的需求是不是真需求、值不值得投）：算法只能把文本编稳，真实性属**外部事实** —— 只能由后续受控外部验证（实物/试用回执、留资转化）证明，访谈文本本身证不了。
  → 替代路径：由 FLOW-02 主岗位 AGT-008 在 STG-06 接收门禁前发起受控外部验证，AGT-013 出具验证报告与缺陷闭合记录；补不上时访谈结论只能写成「假设」并标证据等级，不得进〈新品验证证据包〉的「已验证」栏；后果是该 Case 停在 STG-06，只能出 Action Intent 或 NoActionRecord。
- 样本代表性（被访者能不能代表整体市场）：属**外部事实** —— 招募口径、拒访记录与名单来源不在本司系统内的统一台账里，算法只能编文本、无法自证样本框。
  → 替代路径：由 AGT-045 在 STG-04 结束前签发访谈样本框与口径，AGT-005 在 STG-06 前给出抽样与代表性审计意见；补不上时先用「受访者来源清单 + 各自获取渠道」顶替并逐条标「未做代表性检验」，结论只写方向不写比例；后果是不得据访谈分布外推市场规模 —— 材料对 AGT-006 的边界正是「不能把少数评论当作整个市场需求」。
- 录音与转写的原件对应关系：属**实物或回执** —— 「这行字是不是用户原话」只能由录音原件与转写稿的逐条对应证明，编码模型不产生这个证据。
  → 替代路径：由 AGT-006 归档原始录音与转写稿并逐条对齐轮次号，归档与访问边界由 AGT-050 在 STG-06 前核对；补不上时先按现场笔记顶替并标「无原件」，该类语段不得作为逐字引用、不得挂原话编号；后果是无原件的结论只能进「研究者解释」栏，可溯源率按算式 2 自然下降并触发 §4 第 2 条。
- 受访者的许可与个人信息边界（录音授权、原话引用、跨境传输、未成年人相关信息）：属**法定或治理签署**，模型不得自行推定许可成立。
  → 替代路径：由 AGT-044 在 STG-04 开始前给出口径、AGT-050 在 STG-06 前核对访问与保留边界；补不上时先用「已书面同意的受访者子集」顶替，未获同意者只留匿名摘要、不进原话库；后果是缺许可的语段不得进入任何产物，相关触达动作一律不进 STG-07。
- 跨语言访谈的语义等值（同一问题在美/德/日语境下是不是同一个意思）：属**外部事实或专业判断**，机器翻译的一致性不等于语义等值。
  → 替代路径：由 AGT-028 本地化与市场适配在 STG-05 定稿前给出市场语境审查；补不上时先用双语并列 + 标注「未审」的方式留档；后果是未审语段不得用于跨市场对比，也不得据此改标签定义。
- 访谈记录的可用性本身（有没有按期做完、有没有中途退出）：属**外部事实**，算法只能看到已收到的转写稿。
  → 替代路径：由 AGT-034 在 FLOW-05 的 STG-02 前给出客户 Case Charter 的最小范围与许可状态、AGT-037 在 FLOW-05/STG-04 结束前提供历史问题的原始记录；补不上时先用「已收到的转写稿批次」顶替并标「批次不完整」；后果是该批只出观察记录，不做饱和判定、不进 STG-05。

## 4 该格何时必须冻结

- 原话—结论可溯源率 < 1.00（存在没有原话编号的结论）⇒ 冻结该结论，不得写入〈机会与可行性诊断〉与〈需求证据与问题地图〉；补齐原话编号并复检通过后才放行。
- 缺 AGT-044 的受访者许可判定，或受访者撤回同意 ⇒ 相关语段立即封存，该批不得进入 STG-05 产物，也不得发起任何触达动作（材料口径：撤销触达许可即时停止相应动作）。
- 访谈结论被用来表述市场规模、占比或外推比例，而 AGT-005 抽样意见或 AGT-045 样本框缺失 ⇒ 该 Case 的〈FLOW-02 Assurance Decision〉判 HOLD。
- 自 STG-05 产物提交起，至〈新品验证Case Charter〉写明的停止条件截止日仍未取得实物 / 试用回执 ⇒ STG-08 只能出「未闭合」记录并留观察窗，不得判「需求已验证」。
- 原始录音或转写原件缺失的语段占到该批结论的三分之一及以上 ⇒ 该批不得用于继续 / 转向 / 停止结论，只能作线索，重采后重做。
- 触达许可、个人信息或跨境传输边界未界定而访谈结论已进入对外内容 ⇒ 立即冻结该内容范围，并按 FLOW-05 的异常处理路径退回。
- STG-06 接收门禁未通过，或仍有未解决的语义发现 ⇒ 不得推进；发起方不得覆盖拒绝结论。

## 6 适用 FLOW

FLOW-02, FLOW-05
