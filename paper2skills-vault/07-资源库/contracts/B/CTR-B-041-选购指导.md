# 选购指导 · 供给契约

> **本契约的两部分，用法不同。** §1 / §2 / §3 / §5 / §6 是**作业口径** —— 据此产出方案：
> 可达段给算式与取值，不可达段给替代路径。§4 是**放行判据** —— 它规定的是「什么条件下不许自动走」，
> **不得整句抄成交付物的内容**。
>
> 本责任的判定理由（`_survey_org_model.md` §F.3）：**推荐排序与约束满足可产出候选，
> 但适用性与安全判断需产品事实与人工兜底。** 这句话就是本契约可达段与不可达段的分界线。
> 岗位 AGT-036 售前服务与购买指导（DOM-06 服务与体验 / PLN-OPS 业务运营），关键验收度量是
> **「问题解决与购买体验」**，适用 FLOW-04 市场进入与合规上架、FLOW-05 服务留存与复购、
> FLOW-07 重大质量与账号事件。
>
> **本契约覆盖的格**：方法格（kind=M）落在 FLOW-04/STG-04、FLOW-04/STG-05、FLOW-04/STG-08、
> FLOW-05/STG-04、FLOW-05/STG-05、FLOW-05/STG-08、FLOW-07/STG-04、FLOW-07/STG-05、FLOW-07/STG-08 —— §1 的三个算式
> 落在这些格，产物写进对应的〈市场进入诊断〉〈市场进入包〉〈市场进入关闭记录〉
> 〈客户问题诊断〉〈服务与留存方案〉〈客户旅程关闭记录〉〈事件范围与根因诊断〉〈重大事件处置包〉
> 〈重大事件关闭与全动作对账记录〉。规则格（kind=R/D）为上述三跳的 STG-01 信号接收、STG-02 范围确定与
> Case 创建、STG-03 上下文装配、STG-06 Assurance 接收门禁、STG-07 受控动作，**这些格只放判据与门禁条件**
> （§4 的落脚处），不接方法。
>
> **取值来源纪律（全文适用）**：本契约出现的每一个阈值、比例、时限与条数，来源只有三种 ——
> （a）业务处境或材料已给出的数（出海历史 2 个完整年度＝决策 Q11；增量主体＝决策 Q9 的独立站为主）；
> （b）业务侧默认（经营者自述或行业惯例，逐条附替换条件）；（c）§1 算式由命名数据系统直出的输出。
> **候选卡的论文实验参数不构成第四种来源**，卡面数字只在 §1 末尾登记、不作取值。

## 1 算法可达部分

- **候选卡状态（先读这一条再用本段）**：本责任 4 张候选卡中 **1 张是全文卡** —— `p2s-long-term-preference-memory`（⑧ 段记 `arXiv:2603.14864`，带逐字引文与章节号）；另 **3 张是 legacy 预览版**（④、⑤ 两段是占位串，代码只以同目录 `references/implementation.py` 形式随卡且为节选，⑧ 段的出处分别记「不可采信 ⇒ 视为无论文来源」与「未记录论文出处」）。故**论文实验参数未随卡进入本包**：本段取值一律由本业务算式直出，卡只供方法骨架（结构化偏好档案 → 偏好与排除项驱动的过滤排序 → 按阶段升级的主动推荐这条流程形状），逐条卡面数字登记在本段末尾，**任一条不得移植**。
- **可达段一（硬约束过滤：先把不可推荐的排除掉，再谈排序）**：把〈商品主数据〉的适用性字段与〈客户问题诊断〉写明的客户侧事实逐项比对，只有**零冲突**的商品才进候选集，输出候选清单与冲突项清单两项可核验产物。
- 可达段一算式：`硬约束命中率 = 1 − 冲突项数 ÷ 该 Case 写明的硬约束项总数`；硬约束项取〈客户问题诊断〉／〈市场进入诊断〉已写明的五类 —— ① 适用月龄与体重区间 ② 材质与过敏原 ③ 认证与警示要求 ④ 在售渠道与可售状态 ⑤ 客户自述价格带。源字段：〈商品主数据〉的适用区间／材质／过敏原／认证字段，〈平台后台〉的在售与库存字段。
- 取值：**冲突项数 = 0 项，硬约束命中率 = 1.000（100%）** —— 该值是**二值判据不是估计量**：STG-06 Assurance 接收门禁的最低接收条件是 `deterministic_checks_pass`（逐项硬校验通过），**不存在部分通过档**，故本项只有满值一档。替换条件：不替换；只有当〈客户问题诊断〉把某项从「必需」改判为「可选」时分子分母随之变化，判据本身不变。
- **可达段二（同族候选之间的偏好排序）**：把客户侧偏好折成可复算的排序分，输出 Top 候选次序与逐维命中说明。
- 可达段二算式：`排序分 = Σ_j ( w_j × 命中_j ) × 100`，j ∈ {品牌偏好, 价格带, 材质与过敏原, 尺码与月龄历史, 使用场景}，命中_j 取 0 或 1；偏好档案字段取自〈客户Case Charter〉与〈Case/Event Ledger〉的会话记录，字段口径由 AGT-045 定名。
- 取值：**排序分区间取 0–100 分**；权重在〈客户Case Charter〉写明该客户的敏感维度前取**等权 w_j = 0.20**（**业务侧默认**：不给未标定的偏袒）。**负向一票否决**：命中排除项（过敏原、材质、召回批次）的候选直接出局，不参与加权。替换条件：Charter 写明该客户的风险敏感维度（如已确认的过敏史）后，该维度按 Charter 加权、其余维度等权；替换前排序分只用于**会话内候选次序**，不得对外说成「最合适的那一款」。
- **可达段三（答复与推荐理由的依据回链）**：答复与推荐理由的每一句都必须指回一个可核验出处，输出带出处的答复包；这是 AGT-036 的验收度量「有依据的售前答复与线索」的可机检形态。
- 可达段三算式：`依据回链率 = 带可核验出处的答复条数 ÷ 答复总条数`；出处只认三类 —— 〈商品主数据〉字段值、〈平台后台〉官方公告与站内问答原文、〈平台后台〉评论原文（评论引文须随带 `review_id` 与时间戳）。
- 取值：**依据回链率 = 1.000（100%）** —— 同为二值判据：任一条无出处的答复不得进入对客发送队列（与 STG-04 门禁的 `claims_trace_to_evidence` 同一条纪律）。替换条件：不替换。
- **本段的能力边界**：只做三件事 —— 硬约束过滤、同族候选的偏好排序、答复依据的回链校验；**不产出适用性与安全定论、不产出库存与交期承诺、不产出对外宣称**（见 §2 第 1、2、5、6 条）。
- **卡面与论文可见数字登记（逐条，一律不得写成本业务取值或对外承诺）**：
  1. `p2s-long-term-preference-memory`：偏好档案 5 个字段（品牌偏好分 / 尺码历史 / 价格区间 / 排除特征 / 会话数）；排除特征命中扣 **2.0** 分；价格区间默认上限 **9999.0**；论文两阶段框架（偏好识别 → 购物执行）与双奖励；论文实验数字含 **1.2M** 真实商品、**1,000** 条指令（**800** 训练 / **200** 测试）、历史对话 **15–50** 轮、GPT-5 单任务 **75%**、组合凑单任务 **54%**、Qwen3-4B + 双奖励 + 工具奖励 **63.5%**、LLM-judge 与人工一致率 **>90%**；卡内 ROI 口径含复购 CTR **+10–15pp**、LTV **+20–30%**、凑单 AOV **+18–22%**、退货 **−30–40%**；
  2. `p2s-shopping-companion-agent`（legacy 预览版）：4B 小模型 **72.5%** ≈ GPT-5 **74.0%**、Lazada **120 万**商品、价格区间默认 **(0, 999)**、评分默认 **4.0**、示例偏好 `price_max=80`、导购成本节省 **45 万元/年** + 复购 GMV **400 万元/年** = **445 万元/年**、复购率 **+20%**、导购成本 **−60%**、落地周期基础版 **1 周** / 进阶版 **1–3 个月**；
  3. `p2s-conversational-commerce-agent`（legacy 预览版，⑧ 段判「出处不可采信」⇒ 本卡视为无论文来源）：独立站 bounce rate **65%**、对话路径转化率 **15–25%** vs 搜索路径 **3–5%**、澄清轮数 **3–5 轮**、月增收 **¥5–20 万**、年化 ROI **¥25–80 万**、规则状态机版 **2 周** / LLM 版 **4–6 周**、示例商品价格 **149.99 / 89.99 美元** 与噪声 **42 / 45 dB**；
  4. 4 张候选卡的共性：卡面所有百分比、金额、分值、轮数与条数均为**卡面案例口径或论文实验条件**；本业务的硬约束项、权重、排序分与回链率一律由本段三个算式直出。
- 本契约对同族方法卡通用；换卡时只替换方法实现，其余要求不变（不变的是数据要求五维、不可达边界与冻结条件）。

## 2 不可达部分

- 适用性与安全的**定论**（婴幼儿月龄与体重适配、过敏与窒息风险、是否属医疗器械或需专业指导）：算法只能给候选与逐维命中说明，定论须**产品事实 ＋ 专业/法定判断**，且材料为 FLOW-05/STG-06 写明要检查「健康风险」。
  → 替代路径：由 AGT-044 产品合规与隐私在 STG-05 定稿前出〈合规矩阵与证据缺口〉、AGT-013 产品验证与研发项目出检测报告；补不上时**先按商品包装标示的适用区间与警示语顶替**并逐条标「未持证」，涉健康类的问题一律不下结论、按材料 PB-005 口径转入 FLOW-07 或已配置的合格服务渠道；后果是该 Case 停在 STG-05/STG-06，不出 STG-07 的答复发送或触达 Intent。
- 实物与回执：样品与批次的实物核对（标称值、警示语、包装与实物是否一致、召回批次的实物处置）—— 只有实物与逐对象回执能证明，〈商品主数据〉里的字段只能读到「已登记」。
  → 替代路径：由 AGT-018 生产协同与质量控制与 AGT-013 在 STG-04 结束前提供批次记录与检测报告、AGT-020 仓储履约与退货处置提供召回批次的隔离与处置回执；补不上时先用包装照片与批次台账顶替并标「未实物核对」；后果是该商品只进候选、其推荐理由中不得出现适用性结论。
- 客户侧事实（宝宝实际月龄与体重、过敏史、使用场景）：只有**客户自述**，属外部事实，且采集与留存受许可与隐私边界约束。
  → 替代路径：由客户在会话中确认，确认结果与许可状态记入〈客户Case Charter〉；补不上时只给区间式指引（「以包装标示的适用区间为准」）**先行**，不得据自述下定论；后果是该次答复不得写入〈客户旅程关闭记录〉的适用性结论栏，也不得据此进入主动推荐。
- 平台侧的宣称与问答规则原文（产品描述禁用语、医疗器械与功效宣称边界、评论引用条款）：规则解释权在平台，本司只能观测公告文本。
  → 替代路径：规则原文与生效版本号由 AGT-027 在 STG-04 结束前提交、宣称边界由 AGT-044 给；这两样没到手时，可达段三认的那三类出处里就整类缺「官方公告与站内问答原文」，答复里带功效或器械意味的句子一条都回链不上，`依据回链率` 掉出 **1.000**，按 §4 该条答复不得进对客发送队列。处置：宣称句先整句摘出答复包、挂「边界未定」内部留档，只留商品主数据字段值与评论原文两类出处；规则原文与生效版本号**到位后**，把摘出的句子按新边界重判、判得过的放回并重算回链率。
- 库存与交期事实（能不能承诺到货）：本格无权承诺，只能读到快照。
  → 替代路径：可售状态由 AGT-017 给、履约与时效口径由 AGT-019 与 AGT-020 给；这三样不到位时，答复里的到货日期既不是商品主数据字段、也不是平台公告或评论原文，可达段三那三类出处一类都挂不上，`依据回链率` 取不到 **1.000**，排序分算得再高也换不来一句可发出去的承诺。处置：涉库存与交期的表述一律换成不含量值的「以结算页实时信息为准」**顶替**，该句不计入答复条数；三家口径**到位后**再按结算页快照重建带出处的交期句，重建的句子才计入回链率的分子。
- 命中重大事件口径时（产品伤害、质量异常、召回、严重客诉）的处置、补救与对外解释：属**法定与安全判断**，本格不得自行处置。
  → 替代路径：FLOW-07 的结果负责人（质量 AGT-018、账号 AGT-027）与 AGT-050 经 D-026 紧急保护通道接管；⚠️ 该通道的材料现状是 `confirmed_architecture_rules_not_compiled_no_instances` —— 规则已确认、**尚未编译、无实例**，所以本格现在没有可执行的 Guard 判据可依：命中召回、产品伤害或质量异常口径时，推荐理由里那句「可购买」该不该撤回、答复包该不该转人工，判不出来。处置：先按「该 Case 的候选与答复一律只留内部、逐次人工工单留痕」**暂按**冻结面处理；通道编译出实例**上线后**，冻结范围改由 Guard 规则自动收窄；在此之前本格对该 Case 一个字都不对外出。

| 数据质量与溯源（来源标识、新鲜度、缺填率） | AGT-046 数据工程与质量 | STG-04 证据收集开始时 | 缺来源标识或新鲜度字段的证据不进候选与排序的分母，该 Case 冻结在 STG-04 |
| 取数与访问权限（客户与订单数据、会话导出） | AGT-050 信息安全与权限 | STG-06 前 | 缺口时不得取用未授权数据源，改用订单 id 级最小范围只读副本并标「非全量」 |
| 结算与退款口径（若答复涉退款或补偿承诺） | AGT-040 GMV结算与会计对账 | 涉退款承诺的答复前 | 缺口时不得承诺金额与时限，只给流程说明与查询入口 |

## 4 该格何时必须冻结

- 硬约束冲突项 **> 0 项**却仍把该商品放进候选或推荐理由 ⇒ 不得推进到 STG-07 的答复发送与触达动作，只能出 NoActionRecord。
- 涉婴幼儿月龄/体重适配、过敏或窒息风险的问询，而 AGT-044 的合规判定或包装标示证据缺位 ⇒ 冻结该答复，只给「以包装标示与专业人员意见为准」的提示并按材料 PB-005 口径转合格渠道。
- 命中召回、产品伤害或质量异常口径 ⇒ 立即移交 FLOW-07（D-026 通道尚未编译，先按最小范围冻结 ＋ 人工工单 ＋ `REC-CASE-EXCEPTION` 留痕），本格不得自行对外解释、承诺补救或退款。
- 客户许可未在〈客户Case Charter〉写明或已撤回，而拟动作含主动推荐或触达 ⇒ 不得进入 STG-07；已发出的触达不得随整单重跑。
- 依据回链率 **< 1.000**（任一条答复无三类出处之一）⇒ 该答复不得进入对客发送队列。
- 〈商品主数据〉缺适用性字段，或字段新鲜度不满足 §5 ④ ⇒ 该商品冻结在 STG-04，不进候选集。
- 商品处于召回、下架或认证过期状态而推荐理由仍给「可购买」⇒ 冻结该商品的全部候选资格，直到 AGT-044 或 AGT-027 给出恢复结论。
- 同一客户在同一许可窗内已有未回执的主动触达 ⇒ 不得重发；已有成功动作不得随整单重跑。
- 引用 §1 登记清单里任一条卡面或论文数字（含 ROI、转化率、轮数、Top-N、评论量、扣分常数）作为本业务取值或对外承诺 ⇒ 该方案不得放行。

## 5 数据要求（五维 · 三列）

| 维 | 取值 | 缺值处置（**取值为缺口时必填**：先用什么顶替 + 什么条件下换成什么） |
|---|---|---|
| ① 获取路径 | 自有埋点（独立站埋点与〈Case/Event Ledger〉的〈客户Case Charter〉／〈客户问题诊断〉／Execution Attempt）＋ 平台后台（Amazon 卖家后台的买家消息与站内问答、在售页、账号健康与政策通知）＋ 需授权（商品主数据与合规矩阵） | 非缺口。若某渠道的会话不由本司留存（平台侧只给会话摘要或不给导出）：先按〈Case/Event Ledger〉的阶段产物与客服工单顶替并标「非权威副本」，会话导出开通后替换；替换前该渠道的「追问—推荐—成交」链只作线索，不进转化分母 |
| ② 粒度 | 客户 × 商品 × 会话（一条 = 一次问询或一次推荐动作）；适用性判定必须回到〈商品主数据〉的**字段级**证据，不得停在商品级 | 非缺口。若推荐动作只按批次日汇总：先按日粒度顶替并标「粒度不足、不可作单条适用性判定」，行为级落库到位后替换为单次动作粒度 |
| ③ 回溯深度 | 近 2 个完整年度（业务处境给出的出海历史长度＝决策 Q11）用于店铺级问询与转化基线；客户级偏好链回溯至该客户**首笔订单日与首次会话日中更早者** | 缺口：**客户级偏好链本业务暂无** —— 会话分散在平台站内消息、独立站会话与客服工单三处，未按客户 id 归并（决策 Q9 只把增量测量的主体定在独立站，未定会话归并主体），缺它算不出**跨会话偏好命中率**，主动推荐只能退化为单会话内推荐。处置：先按〈客户Case Charter〉写明的订单 id 顶替为「单 Case 内偏好」，客户级归并台账接入后替换；替换前不得做跨会话主动推荐与生命周期触达 |
| ④ 新鲜度 | 适用性与安全相关字段（适用区间、材质、过敏原、认证、召回状态）在每次进入 STG-04 或每次会话开始时重读；商品改版、下架与召回通知到达当次即时刷新 | 非缺口。若〈商品主数据〉只有批量更新：先按〈平台后台〉在售页当次快照顶替并标「非主数据版本」，主数据刷新到位后替换；替换前该快照只用于候选初筛，不得据它做适用性定论 |
| ⑤ 口径归属 | AGT-045 业务口径与主数据（〈数据口径与对象关系契约〉：适用区间、材质与过敏原、「有效问询」三类命名与版本）；每条记录随带 AGT-046 的质量状态、来源与新鲜度 | 缺口：「宝宝月龄/体重」与「商品适用区间」两侧的**对齐口径尚未由 AGT-045 定名**（月龄按自然月还是按矫正月龄、体重按 kg 还是按百分位，两侧命名不一致），缺它算不出可判定的**适用性一致率** —— 同一宝宝会在两个口径下被判成适用与不适用两档。处置：先按包装标示区间与客户自述取值并逐条标「口径未签发」，AGT-045 在〈数据口径与对象关系契约〉签发对齐口径后替换；替换前适用性结论只作会话内提示，不得写入客户档案或对外答复 |
