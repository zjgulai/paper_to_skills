# 模板 B · 完整性契约

> **拦什么：完整性虚报。** 一条 B 类责任里，算法只能承接其中一段 ——
> 但模型拿到卡后会把那一段讲成整条责任都解决了（「用 X 算法即可完成供应商评估」，
> 而供应商评估真正卡人的是验厂回执与资质原件）。
>
> 本模板的作用是**把「算法到哪为止」写成明文**：可达部分给算法，不可达部分点名外部证据与责任岗位，
> 并规定该格何时必须冻结。
>
> **成本低。** 判定理由在 `_survey_org_model.md` §F.3 已对 151 条逐条写好，可半自动生成 ——
> 这是它与 A 模板的分工：A 要读卡定标定规则（高成本），B 主要是把已有理由结构化（低成本）。

## 正文六段（每段都必须有内容，空缺即 J8 红）

### 1 算法可达部分

```
- <这条责任里，算法能承接的那一段；必须是一个可核验的量化值 / 排序 / 参数集>
```

> 判据：**写出来的东西必须是别人能拿数据复算的**。
> 「辅助判断」「提供参考」不算可达部分 —— 那是把整条责任都推给算法而没有任何一处可核验。

### 2 不可达部分

```
- <算法到此为止的那一段：人的专业判断 / 外部事实 / 实物回执 / 法定签署>
```

> 原件级判据：不可达部分必须**至少一条**属于下列三类之一 ——
> ① 需要**外部事实**（供应商产能、验厂结论、平台政策原文）
> ② 需要**实物或回执**（样品测试报告、报关回执、签收回单）
> ③ 需要**法定或治理签署**（合规签署、账号责任人、独立复核）
> 若一条都举不出来，说明这条责任的类别判定可能错了（应当复核 §F.3 的 A/B 归属，而不是把契约写虚）。

### 3 必须的外部证据与责任岗位

| 证据 | 由谁提供（AGT） | 何时必须拿到 |
|---|---|---|
| | AGT-0xx | |

> 责任岗位必须是**图谱 50 岗位之一**，且必须是真岗位号。
> 这一段是本模板与 A 模板最大的差别：**A 把取值算出来，B 把证据找出来。**

### 4 该格何时必须冻结

```
- <在什么条件下，该格不得推进到 STG-07 受控动作 / 必须转人工>
```

> 「冻结」是本材料的原生词汇（STG-06 Assurance 接收门禁 + FLOW-07 紧急保护通道），不是本层新造。
> 判据要写成**可判定的条件**（缺什么证据、超过什么时限、命中什么规则），不能写「视情况」。

### 5 数据要求（五维）

| 维 | 取值 |
|---|---|
| ① 获取路径 | 自有埋点 / 平台后台 / 第三方 API / 需授权 / **不可得** |
| ② 粒度 | |
| ③ 回溯深度 | |
| ④ 新鲜度 | |
| ⑤ 口径归属 | |

### 6 适用 FLOW

一行，逗号分隔，必须与 frontmatter 的 `flows` 一致。

## 一条实例（示意，非交付物）

```yaml
contract_id: CTR-B-0xx
responsibility: 供应商评估
serviceability: B
flows: [FLOW-02, FLOW-03]
```

- **1 可达部分**：按历史采购价、准时交付率、批次不良率三项算出供应商**排序分**（可取数据复算）。
- **2 不可达部分**：① 需外部事实 —— 真实产能与是否转包；② 需实物回执 —— 验厂报告与资质原件。
- **3 外部证据**：验厂报告（由 AGT-014 OEM 供应商开发与协同提供，进入 STG-04 前必须拿到）；
  资质原件（由 AGT-043 法务与知识产权核验）。
- **4 冻结**：排序分进入前 3 但验厂报告缺失时，**不得**进入 STG-07 下单动作；
  资质过期未续的供应商一律不进候选集。
