# FLOW-04 · 新市场、新渠道与合规上架 · 方案域

> **这份文档是什么**：FLOW-04 这一格的**作业总图** —— 八个阶段怎么走、20 个岗位各贡献什么、
> 54 份契约挂在哪、方法从哪些卡来、缺什么。
>
> **这份文档不是什么**：
> - 不是方案模板（真正的取值口径在 54 份契约里，逐责任的算式与冻结条件在那里）；
> - **不是喂给模型的资料**。F6/F7 两轮实测已证伪「契约/方案进提示词能提升产出」：
>   契约臂的量化判据中位数 3（对照 19.5 / 单卡 22），削到只剩取值仍只有单卡臂的 47%。
>   ⇒ 本层是**人的标定物**与**消费口闸门条件**（S12），不是载荷。
> - 不是「8 份方案」之一份成品方案 —— 它给的是**作业面**，具体一次 Case 的行动包由主岗位产出。
> - 不是 FLOW-01 的同构复制：本条的**主岗位规则与 FLOW-01 不同**（见 §1.1），
>   作业包里那句从 FLOW-01 平行过来的「渠道四选一」**对本条不成立**（已复算并登记）。

> ⚠️ **已知缺口（材料自述，不掩饰）**：选择器 `production_ready = false`、`runtime_instantiation.case_instances = 0`、

> 不是**投放构成** —— 用它去推「该在哪个渠道做增量实验」是**类别错误**。

### 1.2 本方案域不覆盖什么

- 不做存量经营（FLOW-01）、不做新品立项（FLOW-02）、不做补货采购与交付（FLOW-03）、
  不做服务留存与复购（FLOW-05）、不做数据产品交付（FLOW-06）、不做重大事件（FLOW-07）、不做组织复盘（FLOW-08）。
  本条里若发生「库存事件 / 质量事件 / 账号重大事件」，**转 FLOW-07**，不在本方案域内自行闭环。
- **不做「进入之后怎么经营」**：市场进入包交付并验证之后，日常经营回到 FLOW-01/FLOW-05。
  PB-004 的完成条件是「**验证**市场进入」，不是「把新市场经营好」—— 验收口径不在这里放大。
- **不承载账号申诉的法定程序**：`CTR-B-031 申诉材料准备` 只到「材料」为止；
  法律结论与签署在 AGT-043（B 类责任的可达边界，逐份契约 §2 已写）。

### 2.1 一条 Case 的走法（把上表连起来）

```
上线请求(D) → Case Charter：市场/渠道账号/商品集/时间窗/成功条件(R，零多匹配即 WAIT)
  → Context Manifest：按 SELECTOR-FLOW-04 定主岗位 AGT-024，装配机会/准入/IP/合规/本地化/履约/售后/结算/品牌能力(D)
  → 诊断(M)：20 个岗位各自按自己的契约做证据核对与偏差诊断，产出《市场进入诊断》
  → 市场进入包(M)：准入证据矩阵 + 商品内容版本 + 本地化内容，四类候选择一(进入/缩小范围/暂缓/停止)
  → Assurance(R)：适用策略 / 市场规则 / 账号主体 / 内容 / 履约 / 结算准备 六项检查 → HOLD 或放行
  → 受控动作(D)：仅提交策略允许的上架 Intent（具体市场与接口待配置）；不许动作时出 NoActionRecord
  → 关闭与学习(M)：逐商品上线回执、异常和初步经营结果 → 《市场进入关闭记录》
```

**三条不许绕过的规矩**（材料通用工单规则原文口径）：

1. **每项记录随带统计窗和新鲜度**；过期库存信息不能支撑加预算决定（本条同样适用于准入证据与账号状态）。
2. **缺关键输入时进入等待或自治异常，不把缺失值当作零。**
3. **已成功动作不得随整单重跑**（幂等；回执不明时先查询实际效果，再决定重试、补偿或冻结）。

**两条 PB-004 特有禁令**（材料原文，逐字可查）：

- 「**候选新市场不能仅因英文内容已有而被认定准备就绪。**」—— 这条直接否定了「翻译完就算进了」的偷懒路径；
- 「某一市场资料缺失时**只冻结相应范围**；**账号主体、币种或商品映射错误时阻止写入**。
  回退需要处理已产生订单和客户承诺。」—— 即 STG-07 的拦截条件里，账号主体/币种/商品映射是**三类硬拦**，
  而它们各自的**权威源在材料里没有点名**（见 §5 与 §8.1）。

## 4 方法从哪来（卡 ↔ 契约）

**契约按「责任」建，不按「卡」建**：一个责任的同族方法卡可以互换，换卡只换方法实现，
数据要求、标定规则与冻结条件不变。因此每份契约的 `cards` 只写 1–3 张**代表卡**。

### 4.1 两条卡语料与它们的口径（**不要混算**）

|---|---|---|---|
| **已装线**（消费口） | `dsh-paper2skills/data/classification.json` | 1338 张 | `cards` 优先写它的 **slug** —— S12 的预设白名单认这个键 |

## 6 停止条件与冻结（本 FLOW 的判据面）

**STG-06 Assurance 接收门禁六项检查**（逐项可判定；缺项即 HOLD，不设「部分通过」档）：

1. **适用策略**（该市场/账号/商品是否有已发布策略覆盖；无策略即不得进入 STG-07）
2. **市场规则**（目标市场的准入与标签要求是否逐条有据）
3. **账号主体**（主体、币种、商品映射是否正确 —— PB-004 明写**错误时阻止写入**）
4. **内容**（本地化内容与宣称是否过 `CTR-B-056 宣称审查` 的边界）
5. **履约**（履约与售后能力是否支撑该市场 —— PB-004 必须回放项之一）
6. **结算准备**（税务与结算路径是否就绪；法定判定在 AGT-042/AGT-043）

**必须冻结／不得自动进入 STG-07 的情形**（各契约 §6 / §4 逐条细化，这里只列共性）：

- 缺策略允许动作集、市场规则未确认、账号主体/币种/商品映射错误、内容宣称未过审；
- **准入与宣称：判定含法律风险时必须人签署**（`CTR-B-055` · `CTR-B-056` · `CTR-B-053` 的 B 类不可达段）
  —— 算法只可**预筛**，不得输出「合规」结论；
- **`CTR-A-048 内容实验` 当前标 `方法待启用`**（Q10：独立站 holdback 需先建）⇒
  在 holdback 建成前不得声称内容实验的增量结论；
- 资料缺失时**只冻结相应范围**（PB-004 原文），不得因一个市场缺资料而冻结整条 Case；
- 回执不明时先查实际效果，不得直接重试（重复写入）；**已成功动作不得随整单重跑**；
- 数据更新后原方案失效者，回 STG-04/05 重算，不得沿用旧取值。

**D-026 紧急保护通道**（材料原文口径）：允许已接收的权威信号命中一条**已发布互斥规则**且唯一 Case 绑定成立时，
由**模型外** Emergency Guard 固定场景、最小范围、保护模板、Policy、TTL、幂等与最大影响边界，
本地原子建单后交 Execution Broker 执行；**模型不能选参或扩围**。
绑定前若规则、主场景或范围不唯一，只生成 Pre-Case Exception 并冻结信号范围。
⚠️ 对 FLOW-04 而言，**「保护」能做什么在材料里没有定义** —— PB-004 只写了回退（处理已产生订单和客户承诺），
没有写「上架中途的紧急保护」。这一条**登记为缺口**，不自行发明。
