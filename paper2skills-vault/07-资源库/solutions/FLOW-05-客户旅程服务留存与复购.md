# FLOW-05 · 客户旅程：服务、留存与复购 · 方案域

> **这份文档是什么**：FLOW-05 这一格的**作业总图** —— 八个阶段怎么走、14 个岗位各贡献什么、
> 41 份契约挂在哪、方法从哪些卡来、缺什么。
>
> **这份文档不是什么**：
> - 不是方案模板（真正的取值口径在 41 份契约里，逐责任的算式与冻结条件在那里）；
> - **不是喂给模型的资料**。F6/F7 两轮实测已证伪「契约/方案进提示词能提升产出」：
>   契约臂的量化判据中位数 3（对照 19.5 / 单卡 22），削到只剩取值仍只有单卡臂的 47%。
>   ⇒ 本层是**人的标定物**与**消费口闸门条件**（S12），不是载荷。
> - 不是「8 份方案」之一份成品方案 —— 它给的是**作业面**，具体一次 Case 的行动包由主岗位产出。
> - **不是客服 SOP**。本条的主体是「客户旅程的验证闭环」，不是一套话术库；
>   真正的话术与规则在 `CTR-B-040/041/043/044/045` 五份契约里，且它们的可达边界都写着「须人工兜底」。

### 2.1 一条 Case 的走法（把上表连起来）

```
客户信号(D) → 客户Case Charter：客户/订单最小范围、问题类型、许可状态、完成条件(R，零多匹配即 WAIT)
  → Context Manifest：按事件类型二选一定主岗位（生命周期/留存→AGT-034；单一客诉→AGT-037），
    装配服务/体验/教育/CRM/隐私/质量能力(D)
  → 诊断(M)：14 个岗位各自按自己的契约核对客户与订单事实、历史问题、服务规则、许可与产品适用性
  → 服务与留存方案(M)：答复 / 补救 / 教育 / 复购实验 四类候选，各自带停止条件
  → Assurance(R)：许可 / 隐私 / 健康风险 / 质量事件 / 补偿 / 触达边界 六项检查 → HOLD 或放行
  → 受控动作(D)：仅提交策略允许的退款/补救/触达 Intent；不许动作时出 NoActionRecord
  → 关闭与学习(M)：问题解决回执、补救回执、根因反馈、复购结果 → 《客户旅程关闭记录》
```

**三条不许绕过的规矩**（材料通用工单规则原文口径）：

1. **每项记录随带统计窗和新鲜度。**
2. **缺关键输入时进入等待或自治异常，不把缺失值当作零。**
3. **已成功动作不得随整单重跑**（幂等；回执不明时先查询实际效果，再决定重试、补偿或冻结）。

**三条 PB-005 特有规矩**（材料原文，逐字可查）：

- 「**退款回执不明先对账，不重复退款**」—— 退款是本条最容易重复写入的动作，这条是硬拦；
- 「**撤销触达许可即时停止相应动作**」—— 许可不是「一次取得、长期有效」，撤许可是**即时生效**的冻结信号；
- 「服务解决、**触达效果和长期复购分别评估**」—— 三个口径不许合成一个「满意度/复购率」大数；
  这条与 F6 的教训同源（**合成一个总分会把最弱的一维平均掉**）。

## 4 方法从哪来（卡 ↔ 契约）

**契约按「责任」建，不按「卡」建**：一个责任的同族方法卡可以互换，换卡只换方法实现，
数据要求、标定规则与冻结条件不变。因此每份契约的 `cards` 只写 1–3 张**代表卡**。

### 4.1 两条卡语料与它们的口径（**不要混算**）

| 线 | 事实源 | 规模 | 契约怎么用它 |
|---|---|---|---|
| **已装线**（消费口） | `dsh-paper2skills/data/classification.json` | 1338 张 | `cards` 优先写它的 **slug** —— S12 的预设白名单认这个键 |
| **精选线**（精选前台） | `card-classification.json`（F5） | 146 张 | 与之按 `id` 建联的是 **93 张**；未换底的 53 张先按卡名引，S5 换底后替换为 slug |

> 📌 **本 FLOW 的卡覆盖（按 §3 同一套口径逐条现算）**：41 条责任里
> **41 条全部有候选卡**（其中 **20 条带全文卡**可取论文参数、**21 条只有 legacy 预览版**）；
> **0 条 `待卡`**。候选池规模（现算）：41 条共挂 **737 条候选条目** = 已装线 686 + 精选线 51，
> 其中 **114 条带全文**（已装线 63 + 精选线 51）；**按卡去重后 549 张**（其中带全文 81 张）。
>
> ⚠️ **「legacy 预览版」不是「缩水版」的模糊说法，它的形态是实测过的**（S1 第一批）：
> **④⑤ 段是占位串**、代码以 `references/implementation.py` 随卡且为**节选**、
> ⑧ 常写「未自动抽取/待人工判定」。⇒ 这 21 条责任的契约拿不到论文参数，
> 只能写「方法族 + 业务侧默认取值 + 替换条件」，**并在 §1 如实标注**。
>
> 📌 **这与缺口账的「精选卡」口径不是一回事**：缺口账问「有没有**精选**卡」（供给质量，分母 146 张
> 精选卡），契约问「方法**可以从哪些卡来**」（可用方法，分母 1338 ∪ 146）。
> **两个口径不许互相换算** —— 同一批 139 份契约，只认精选线时是 67 可写 / 72 待卡。
> 换一个透镜看本条：43 条责任按**缺口账口径**是 **仅 legacy 23 / 有精选卡 20 / 零供给 0**
> （零供给 0 条 ⇒ 本条在靶区二上完全没有条目）。

## 6 停止条件与冻结（本 FLOW 的判据面）

**STG-06 Assurance 接收门禁六项检查**（逐项可判定；缺项即 HOLD，不设「部分通过」档）：

1. **许可**（触达许可是否在有效期内、是否已被撤销 —— 撤销即**即时**停止相应动作）
2. **隐私**（客户数据是否满足「最小必要」；超范围即 HOLD）
3. **健康风险**（健康相关专业问题、潜在伤害 ⇒ **转 FLOW-07 或已配置的合格服务渠道**，
   本条不得自行答复）
4. **质量事件**（是否已构成重大质量事件 ⇒ 转 FLOW-07）
5. **补偿**（是否**超授权补偿** ⇒ 转 FLOW-07 或合格服务渠道；授权边界由具体动作策略给定）
6. **触达边界**（频次/时段/渠道是否落在策略允许的动作集内）

**必须冻结／不得自动进入 STG-07 的情形**（各契约 §6 / §4 逐条细化，这里只列共性）：

- 无许可 / 许可已撤回 / 客户数据超出最小必要范围 / 触达频次或时段越界；
- **健康相关专业问题与潜在伤害：不得自动答复**（`CTR-B-040 产品问答` 的 B 类不可达段逐条写了这条）；
- **超授权补偿与退款**：策略未覆盖即 HOLD；**退款回执不明先对账，不重复退款**（PB-005 原文）；
- **`CTR-A-056 实验设计` · `CTR-A-057 增量分析` 当前标 `方法待启用`**（Q10：独立站 holdback 需先建）
  ⇒ 在 holdback 建成前不得声称复购增量结论；
- **`CTR-B-048 改进验证`**：「改进是否成立与放行属质量体系判断」⇒ 算法只出统计量，不出放行结论；
- 重复客诉被并单后，**不得对同一客户重复触发同一触达**（幂等；已成功动作不得随整单重跑）；
- 数据更新后原方案失效者，回 STG-04/05 重算，不得沿用旧取值。

**D-026 紧急保护通道**（材料原文口径）：允许已接收的权威信号命中一条**已发布互斥规则**且唯一 Case 绑定成立时，
由**模型外** Emergency Guard 固定场景、最小范围、保护模板、Policy、TTL、幂等与最大影响边界，
本地原子建单后交 Execution Broker 执行；**模型不能选参或扩围**。
绑定前若规则、主场景或范围不唯一，只生成 Pre-Case Exception 并冻结信号范围。
⚠️ 对 FLOW-05 而言，**「保护」能做什么在材料里没有定义** —— PB-005 只写了转出与停止，
没有写「客户侧的紧急保护动作」。这一条**登记为缺口**，不自行发明。

### 8.1 ⚠️ 本批实测撞出的新增取数项（四条，其中三条是本条特有）

2. **「触达许可」没有载体（本条最硬的一条）**：PB-005 把「触达许可」列为**输入**，
