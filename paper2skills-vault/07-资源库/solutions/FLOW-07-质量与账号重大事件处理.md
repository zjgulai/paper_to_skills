# FLOW-07 · 质量与账号重大事件处理 · 方案域

> 批次里的 **55** 份契约挂在哪、D-026 紧急保护通道的边界在哪、方法从哪些卡来、缺什么。
>
> **这份文档不是什么**：
> - 不是方案模板（真正的取值口径在契约里，逐责任的算式与冻结条件在那里）；

>   契约臂的量化判据中位数 3（对照 19.5 / 单卡 22），削到只剩取值仍只有单卡臂的 47%。
>   ⇒ 本层是**人的标定物**与**消费口闸门条件**（S12），不是载荷。
> - 不是成品方案 —— 它给的是**作业面**；具体一次事件的处置包由主岗位产出。
>
> ⚠️ **读这一份最容易犯的错，写在最前面**：**FLOW-07 不是「只有 3 份契约」**。

### 1.1 主岗位是「按事件类型二选一」，不是固定一个，也**不是**按渠道四选一

材料原文（两处，逐字）：

- `FLOW-CATALOG.md` 表格「默认 AI 结果负责人」列 = **AGT-018**；
- `PB-007` 触发与责任段 =「明确质量异常、严重客诉或账号重大风险触发 FLOW-07；
  **质量由 AGT-018 担任结果负责人，账号事件由 AGT-027 负责相应实例**」；
- `FLOW-CATALOG.md` §FLOW-07 正文 =「**账号事件可指定 AGT-027 负责该实例**」；
- 图谱侧同口径：`FLOW-07/STG-03` 的业务步骤逐字是「**按事件类型选择主岗位**，
  装配产品、供应、服务、渠道、法务、合规和安全能力」——**图谱自己就写着「按事件类型」**。

| 事件类型 | AI结果负责人 | 依据 |
|---|---|---|
| **质量事件**（明确质量异常、严重客诉） | **AGT-018 质守 · 生产协同与质量控制** | `FLOW-CATALOG.md` 表格默认值 + `PB-007` |
| **账号事件**（账号重大风险） | **AGT-027 守店 · 店铺账号健康与规则（负责相应实例）** | `PB-007` + `FLOW-CATALOG.md` §FLOW-07 正文 |

> ⚠️ **材料 FLOW-CATALOG 的表格只写 AGT-018 —— 那是「默认位」，不是唯一负责人。**
> 正文与 PB-007 都补了账号事件由 AGT-027 负责该实例。
> **把 AGT-018 写成整条 FLOW-07 的负责人，等于让账号事件没有负责人** ——
> 这与 S1 第一批实测踩过的那个坑（把某个渠道实例的负责人写成整条 FLOW-01 的负责人）**同型**，
> 只是实例维度从「渠道」换成了「事件类型」。判据是同一句话：
> **默认值是默认值，实例负责人是实例负责人，两者都不等于「整条 FLOW 的负责人」。**
>
> ⚠️ **本条也不适用渠道四选一规则**（Amazon→AGT-021 / 独立站→AGT-023 / 其他平台→AGT-024 /
> B2B→AGT-025）。理由与 §1 的图谱证据一致：FLOW-07 的选择维度是**事件类型**，不是渠道。
> 本条批次里确实有 AGT-021 北辰（三条：渠道经营分析 · 行动组合 · 经营复盘），
> 它是**能力贡献岗位** —— 在渠道侧提供事件影响与联动证据，**不是**本条的结果负责人。

> ⚠️ **已知缺口（材料自述，不掩饰）**：`FLOW-CATALOG.md` §FLOW-07 末句逐字写着

### 1.2 本方案域不覆盖什么

- 不做存量经营（FLOW-01）、不做新品（FLOW-02）、不做补货采购与交付（FLOW-03）、
  不做新市场进入（FLOW-04）、不做服务留存（FLOW-05）、不做数据产品交付（FLOW-06）、
  不做组织复盘（FLOW-08）。
- **但与其它 FLOW 的关系是「升级」而不是「并列」**：`FLOW-CATALOG.md` §FLOW-05 明写
  「**重大质量事件转 FLOW-07**」；FLOW-01 §1.2 也把「库存事件 / 质量事件 / 账号重大事件」交给本条。
  ⇒ FLOW-07 是**升级通道的落点**。
- ⚠️ **转进来之后，两个 Case 是「关联但状态独立」，不是合并**：`FLOW-CATALOG.md` 首段逐字写着
  「**跨价值流信号拆成关联但状态独立的 Case**」。把原 Case 状态一并搬进 FLOW-07，
  会让「事件影响了多少在途经营动作」这件事失去记录。
- **恢复不等于回到原状**：恢复、重新开放、扩大范围、外部承诺、退款、召回、销毁和永久变更
  **只能在正常 STG-07 执行**，且**恢复需新证据，不因会话结束自动恢复业务**（PB-007 逐字）。

### 2.1 一条 Case 的走法（把上表连起来）

```
权威信号核验(D)：区分权威信号 / 非权威信号 / 误报；命中 D-026 候选条件 → 交模型外 Emergency Guard
  → 唯一 Case Charter(R)：按已发布规则形成**唯一** FLOW-07 Case；三不唯一则只出 Pre-Case Exception
  → Context Manifest(D)：按**事件类型**定主岗位（质量→AGT-018；账号→AGT-027 负责该实例）
  → 事件范围与根因诊断(M)：时间线 / 受影响批次·商品·账号 / 已发生动作 / 库存 / 客户范围
  → 重大事件处置包(M)：隔离 + 处置 + 客户影响 + 恢复方案
  → Assurance(R)：证据 / 范围 / 适用策略 / 外部承诺 / 恢复条件 五项 → HOLD 或放行
  → 正常处置(D)：正常处置 Intent 或 NoActionRecord；
        **恢复·重开·扩围·外部承诺·退款·召回·销毁·永久变更只在此格**
  → 关闭与对账(M)：紧急保护与正常处置的**逐对象权威回执** / 影响受控 / 根因 / 恢复证据
```

**D-026 紧急保护通道（模型外通道，语义逐字取自 FLOW-CATALOG §FLOW-07 与 PB-007）：**

> 已接收的**权威信号**命中一条**已发布互斥规则**且**唯一 Case 绑定成立**时，
> 由**模型外** Emergency Guard 固定**场景、最小范围、保护模板、Policy、TTL、幂等和最大影响边界**，
> 并在**本地原子建单**后交 Execution Broker 执行；**模型不能选参或扩围**。

**六条不许绕过的规矩**（PB-007 原文口径，逐条可判定）：

1. **绑定前若规则、主场景或范围不唯一** ⇒ 只生成 **Pre-Case Exception** 并冻结信号范围，
   **不创建 Guard Decision、残缺 Case 或任何动作记录**。
2. **零匹配** ⇒ 记录**无规则引用的 `NO_MATCH` 结论**后**继续正常建单**
   —— ⚠️ 这是「记录 + 继续」，**不是冻结**。把零匹配写成冻结，会让所有没配规则的事件停在入口。
3. **Policy 正常 `DENY`/`HOLD` 不产生 Outbox。**
4. **紧急派发 TTL 过期后禁止首次执行，且不会自动恢复。**
5. **本地事务结果不明**时，仍用 Pre-Case Exception **查询账本**；证明 Case 已提交后，
   **只有**「模板或紧急执行状态不明」才冻结受影响的 Case/对象。
6. **恢复、重新开放、扩大范围、召回、外部声明、退款、销毁库存和永久变更只能在正常 STG-07**
   由实际可用策略及受控执行主体完成；**恢复需新证据，不因会话结束自动恢复业务**。

## 6 停止条件与冻结（本 FLOW 的判据面）

**STG-06 Assurance 接收门禁五项检查**（逐项可判定；缺项即 HOLD，不设「部分通过」档）：

1. **证据** —— 事件证据是否**权威**且完整（非权威信号不得进入处置）；
2. **范围** —— 隔离/影响范围是否被划定且**最小**（对照 D-026 的「最小范围」与「最大影响边界」）；
3. **适用策略** —— 是否有**已发布**的动作策略覆盖本次动作。
   ⚠️ FLOW-07 自己的原文口径是：「**具体规则尚未配置，未匹配或校验失败时按记录进入正常流程、等待或冻结**」
   （`FLOW-CATALOG.md` §FLOW-07 末句逐字）。
   ⇒ **未匹配 = 记录 + 进正常流程**（这是零匹配的正确分支，见上表第 2 行）；
   **校验失败 = 等待或冻结**。两者**不是**同一处置。
   ⚠️ **不要**把 FLOW-08 的那句「无适用策略时记录建议并冻结相关写入」搬到这里 ——
   那是 FLOW-08 对自己「资源/技能/长期策略变更」的口径，搬到 FLOW-07 会让零匹配也被冻结。
4. **外部承诺** —— 对外声明/召回/退款等承诺是否有受控执行主体承接（§5.1 的 O-07 未到位时置 `数据待盘`）；
5. **恢复条件** —— **恢复需新证据**；恢复条件是否被明确定义且可判定。

**必须冻结／不得自动进入 STG-07 的情形**（PB-007 原文口径，逐条可判定）：

| # | 情形 | 正确处置 | 常见写错 |
|---|---|---|---|
| 1 | 规则、主场景或范围**任一不唯一**（绑定前） | 只出 **Pre-Case Exception** + 冻结信号范围；**不建** Guard Decision / 残缺 Case / 动作记录 | 写成「等规则补全后自动建单」——那是**自动恢复**，被禁 |
| 2 | 规则**零匹配** | 记录 `NO_MATCH`（无规则引用）后**继续正常建单** | 写成「冻结」——会把所有未配规则的事件堵在入口 |
| 3 | Policy 正常 `DENY`/`HOLD` | **不产生 Outbox** | 写成「生成 Outbox 但标记为拒绝」——重复派发的来源 |
| 4 | 紧急派发 **TTL 过期** | **禁止首次执行**，且**不会自动恢复** | 写成「过期后转人工」——材料没有这条通道 |
| 5 | **本地事务结果不明** | 用 Pre-Case Exception **查询账本**；证实 Case 已提交后，**仅当模板或紧急执行状态不明**才冻结受影响 Case/对象 | 一发现事务不明就冻结全部 —— 把「查一下」跳成了「停一片」 |
| 6 | **恢复 / 重开 / 扩围 / 外部声明 / 退款 / 召回 / 销毁 / 永久变更** | **只能在正常 STG-07**，由实际可用策略与受控执行主体完成 | 写进紧急通道 —— 违反「模型不能选参或扩围」 |
| 7 | **模型尝试改参** | 拒绝（在 §7 的必须回放清单里） | —— |
| 8 | **结果负责人不可用** | 冻结（在 §7 的必须回放清单里） | —— |

> ⚠️ **第 6 行是本条 FLOW 最容易被「善意优化」掉的一条**：
> 事件正在烧，最自然的冲动就是「先在紧急通道里把货下架/把范围扩大」。
> PB-007 把它明确堵死：**紧急通道只做「保护」，不做「处置」**，
> 而且 TTL 过期后连首次执行都禁止。方案域必须原样保留这个不对称。

## 7 必须回放的十四个场景（PB-007 原文）

| # | 场景 | 回放什么 |
|---|---|---|
| 1 | **误报** | 非权威信号是否在 STG-01 被拦掉，而不是进了处置 |
| 2 | **规则零匹配 / 多匹配** | 零匹配 → `NO_MATCH` 后继续建单；多匹配 → Pre-Case Exception（两条分支不许混） |
| 3 | **主场景或范围不唯一且未产生残缺 Case** | 原子性：**不许**出现半张 Case |
| 4 | **非权威信号** | 与第 1 条配对：判据是「权威」的定义，不是来源的熟悉度 |
| 5 | **范围扩大** | 扩围**只能走正常 STG-07**，不得经紧急通道 |
| 6 | **模板或 Policy 过期** | 过期模板不得用于首次执行 |
| 7 | **事务中断** | 用 Pre-Case Exception 查询账本，而不是重试写入 |
| 8 | **Outbox 重复派发** | 幂等：`DENY`/`HOLD` 不产生 Outbox |
| 9 | **TTL 过期** | 禁止首次执行；**不自动恢复** |
| 10 | **执行状态不明** | 冻结受影响 Case/对象（且**只**冻结那些） |
| 11 | **模型尝试改参** | 必须被拒；模型不能选参或扩围 |
| 12 | **紧急通道尝试恢复** | 必须被拒；恢复只走正常 STG-07 |
| 13 | **结果负责人不可用** | 冻结；不得由贡献岗位代签 |
| 14 | **部分渠道仍在售 / 历史处置被重复触发** | 范围与幂等交叉的两个边界：下架范围要覆盖部分渠道；历史处置不得二次触发 |

> **验收口径（PB-007 逐字）**：以**影响受控、事实完整及不复发**评价，
> **不能通过少报问题提高指标**。
>
> ⚠️ 最后半句值得单列：这是全库唯一一条**明写反向指标**的验收 ——
> 其它 FLOW 的验收指标（GMV、约束满足、从信号到行动的时间）都是**越大/越快越好**型的，
> 而本条的三项里，「影响受控」与「不复发」会在**压力下**鼓励少报。
> 因此本条的两条硬约束是：**① 影响受控的分子分母必须同口径；② 「不复发」必须有观察窗**，
> 否则「不复发」在事件关闭当天恒为真。
